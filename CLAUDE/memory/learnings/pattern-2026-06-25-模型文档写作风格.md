# 模型部分文档写作风格偏好（用户硬要求）

Type: pattern
Date: 2026-06-25
Tags: 文档风格, 模型设计, 命名规范, AdaLigand, Stage2, Stage3

## Context

用户在 AdaLigand 模型设计文档（`文档/未成熟或过时的讨论/模型总规划_v2.md`、`Stage2_Stage3_迭代运算设计_讨论.md`、`参照算法_迭代运算梳理_AF3_PocketXMol.md`）的多轮批阅中，反复纠正写作风格。以下是已确认的硬偏好，写任何模型/算法设计文档时默认遵守。

## Memory

1. **长名良定义，禁止密符号**。算子用 `PascalCase` 描述性长名（如 `SparseGraphInteraction`、`BiasedSelfAttention`、`CrossAttention`、`LearnedQueryReadout`），不用 `SA_geo`/`CA`/`PB` 这类缩写；特征张量用 `snake_case` + 后缀（`_features`/`_coords`/`_logit`/`_target`/`_index`/`_mask`）并标注 `[形状]`。用户原话："你写的我完全看不懂，算子和特征要良定义长命名。"

2. **算子词典 + 导言**。设计文档要有"算子词典"小节，每个算子给"签名 / 定义 / 是否用几何 / 是否等变 / 是否更新坐标 / 成本"，并在开头写导言解释为何这样分族选型。

3. **术语首次出现即定义**——在文档和对话里都是。绝不"直接丢一个术语"（max-over-occurrence、explaining-away、level-3 等都被点名批评过）。

4. **批量张量、无 Python 循环**。Stage2 在 `[n_blobs, n_slots]` 网格上批量；Stage3 堆叠 `[B_pairs]` × 扩散步。绝不写"for 遍历每个 (blob, slot) 对"的丑陋循环；"逐对"只是张量前置批维。

5. **复用感知 + 死条件**。明确写出复用 Emap2lig 哪些代码（`pairformer.py::PairFormer`、`selected_attention.py::SelectedCrossAttention`、`instance_seg.py::select_top_k_points`、`diffusion.py::AtomDiffusion`）。复用的死条件："原代码至多经一点修改就能满足需求"，否则不算复用、要自写。

6. **两文档分工，互为指针，各自尽量自包含**。`模型总规划_v2.md` = "是什么"（预测目标/损失/数据/解码/BOX）；`Stage2_Stage3_迭代运算设计_讨论.md` = "怎么算"（算子/迭代块/批量前向）。前者不重复运算细节，给指针指向后者。

7. **算子要统一、不堆近似重复件**。能归一就归一（如几何 cross-attn 与特征空间 cross-attn = 一个算子 + 可选几何偏置；几何自注意 = pair 偏置的特例）。

8. **参照他法要核实再写**，且用同一套算子词典表达，便于横向对照（AF3=注意力+pair；PocketXMol=gated 消息传递+等变坐标更新；DiffDock=等变张量场；Emap2lig=cross-attn）。核实手段：读真实源码/论文，不凭记忆。

9. **给权衡和多方案 + 推荐默认，不武断**。用户喜欢"我倾向 X，因为…；备选 Y"的写法，并自己拍板。

10. **乱码自查**：写中文 markdown 后检查是否混入替换字符/残留拉丁串（历史上出过 `的�forced` 这类）。bash 看 Desktop/OneDrive 下文件工具新写的文件可能显示 0 字节（文件工具与 shell 挂载视图不一致），核对用 Read 工具而非 bash。

## When To Use

下次为 AdaLigand（或同类研究项目）写/改模型、算法、迭代运算设计文档时，开写前先按本条目对齐风格；尤其是引入新算子、新模块、跨方法对照、或重组多份设计文档时。
