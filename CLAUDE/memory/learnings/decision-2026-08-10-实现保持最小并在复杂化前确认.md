# 实现保持最小并在复杂化前确认

Type: decision
Date: 2026-08-10
Tags: implementation-boundary, simplicity, user-confirmation

## Context

在确定 Pocket Plus Stage1 按 PDB 分组采样与加载的实现边界时，方案曾把运行参考值提升为代码约束，并准备为 `train.py` 增加不必要的报错保护。这超出了用户要求的最小改动范围。

## Memory

实现应优先采用满足已确认需求的最小逻辑。当方案开始引入复杂分支、额外保护层、硬编码约束，或者试图“顺手完善”未被要求的行为时，应视为实现边界可能已经偏离。此时必须立即停止扩展，向用户说明拟增加逻辑的必要性、影响范围和更简单的选择，并在得到明确确认后才能继续。

运行参考数值不得自动升级为代码不变量。非任务必需的文件和既有训练行为不得修改。

## When To Use

- 编写或审查 Pocket Plus、AdaLigand 与 AUTO 的代码和运行配置时。
- 准备修改 `train.py`、通用 Dataset、全局 batch 处理、梯度累积或其他共享入口时。
- 一个局部需求开始需要新增通用抽象、保护层、兼容分支或跨模块重构时。
