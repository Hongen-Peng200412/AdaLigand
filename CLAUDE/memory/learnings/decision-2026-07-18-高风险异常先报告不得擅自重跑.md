# 高风险异常先报告，不得擅自修复或重跑

Type: decision
Date: 2026-07-18
Tags: adaligand, approval, rerun, gate, risk-management

## Context

受控失败放行规则最初写明：系统性故障、科学风险、身份/schema 漂移或根因不明时继续 fail-closed。用户进一步澄清，fail-closed 不能被 Agent 理解为“默认修改代码并重跑”。长流水线中，自动重跑可能付出数小时或数天，而用户可能在完整知情后选择接受有限瑕疵以顾全整体进度。

## Memory

遇到任何可能阻断 gate 的异常，无论它是否满足受控失败 waiver：

- 先冻结当前状态、日志、产物、进程/锁和影响范围，不擅自终止仍正常工作的 producer。
- 向用户报告真实情况：失败规模、根因置信度、潜在科学/工程影响、兄弟样本是否可信、缺失或损坏产物、继续放行的风险、修复/重跑方案和时间成本。
- 明确给出“接受这一点瑕疵以顾全大局”与“严格阻断并修复/重跑”等可选路径和推荐理由，由用户决定。
- 在用户明确决定前，只保持门禁不放行；不得擅自修改运行中代码、迁移状态、创建 kill-lock 或启动昂贵重跑。
- 用户批准接受风险后，采用最窄、run-scoped、证据绑定且可退休的临时开路；用户选择修复时，才按受检流程修改、测试和重跑。

“严格阻断”是一个审批停点，不是自动修复指令；“发现问题”也不自动扩大 Agent 的服务器写入或资源权限。

## When To Use

- unknown、duplicate、silent missing、schema/身份漂移或科学风险可能阻断长周期 gate 时。
- 修复或重跑成本显著，而错误范围可能足够小、用户可能选择接受时。
- 根因尚未完全闭合，需要用户在速度与严格性之间作显式选择时。
