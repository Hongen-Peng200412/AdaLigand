# 临时运行脚手架须在最终收口清理

Type: pattern
Date: 2026-07-16
Tags: maintenance, cleanup, run-scoped, provenance, scientific-contract

## Context

长周期数据流水线会因一次性 repair、资源扩容、cutoff、补算、迁移、事故恢复和临时目标覆盖而增加许多运行期脚本、分支入口与证据工具。这些工具在任务进行中可能是安全推进和追溯所必需的，但若全部永久留在主线，代码库会逐渐难以阅读和维护。

## Memory

- 科学契约与临时执行脚手架必须分层：制作正式产物的长期生产逻辑保持清晰、最小且可独立理解；run-scoped repair、资源调度、补算、cutoff、事故恢复和一次性迁移不得悄然变成新的默认主路径。
- 临时工具在使用期间必须有精确适用范围、证据目录、退出条件和与正式产物的关系；需要长期保留的历史放在 ExecPlan、handoff、mapping、README、Git 历史或 run-scoped 服务器证据中，而不是依赖大量仍可执行的遗留脚本表达。
- A–G 和其后训练任务全部完成并验收后，必须单独执行维护收口审计：逐项分类为“长期生产代码”“仍需复用的运维工具”“只属于本轮的脚手架”。对最后一类应删除或移出活跃主线；若因审计价值保留，必须明确标为非生产、不可默认调用，并集中放置。
- 该审计是全项目回溯规则，不只约束今后新增代码。规则生效前已经写入的 source repair、长尾 cutoff、补算、动态 run command、资源覆盖、scratch 恢复、一次性迁移及类似脚本也必须进入盘点；不得因“已经存在”而默认豁免。
- 审计结论不要求机械删除全部脚手架。可以继续保留的工具必须逐项记录长期复用价值、适用边界、默认是否可调用、与科学主路径的隔离方式、退出或归档条件、测试覆盖和代码负责人可读入口；缺少这些说明的脚本不能继续作为活跃生产入口。
- 清理临时代码前先冻结证据和 Git checkpoint；清理后重新运行契约测试、全套测试和必要的真实 smoke，证明移除脚手架不会改变当前正式产物的科学行为、schema、身份或可复现入口。
- 不因“代码整洁”删除尚在运行作业、恢复链、审计账本或未闭合迁移所依赖的文件。维护收口发生在对应任务完成并解除依赖之后，不改变任何既有科学契约。

## When To Use

新增或审查一次性修复脚本、临时 CPU/GPU 资源覆盖、run-specific exclusion、补算/迁移入口、事故恢复工具时；以及 A–G、Stage1 训练前准备或长期任务最终收口时。
