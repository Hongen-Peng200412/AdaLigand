# 临时代码隔离与验收边界

Type: decision
Date: 2026-08-10
Tags: temporary-code, acceptance, isolation, verification

## Context

Pocket Plus Stage1 采样与加载改造需要使用一次性脚本核对 validation 文件、比较新旧请求顺序并测量数据加载性能。临时检验工具与正式主管线的验收对象必须严格区分。

## Memory

临时代码本身不由用户验收，也不得污染正式主管线。临时代码通常放在项目或任务的 `tmp/` 目录内，不得被正式包导入、不得被正式入口调用、不得成为生产运行依赖，也不得向正式数据或共享 BOX 池写入产物。

在上述隔离边界内，可以为了查清事实进行比正式测试更细的检验，包括新旧实现比较、参数组合测试、性能埋点、一次性 SHA 核对和额外一致性检查。向用户提交的是正式代码改动以及临时检验得出的结论和证据，不要求用户审查临时代码本身。

## When To Use

- 为正式实现编写一次性迁移、核对、基准测试或诊断脚本时。
- 需要做新旧实现对照、性能参数扫描或文件未改动核验时。
- 判断某段验证逻辑应进入正式测试还是只存在于临时检验目录时。
