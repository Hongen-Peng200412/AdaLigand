## Critical Correction

第一版曾在 `submit_task.sh` 调用 `sbatch` 前创建 release。该行为已经废止。

最终行为：

```text
提交时不创建 release
→ Job 获得资源
→ 每次真正执行 run_cmd 前，从当时最新发布源创建或复用 release
→ 建立绑定该 release 的 launch
→ 从 release 执行
→ try_lock 后重试时再次发布最新代码
```

因此排队期间修改代码会影响第一次运行，`try_lock` 期间修改代码会影响下一次
运行。训练脚本不含 release 逻辑。

`submit_task.sh` 默认发布自身上一层，也支持简单的 `--release-source PATH`
覆盖；没有 Pocket_Plus 绝对路径或复杂任务契约。

```text

├── launches/
```
