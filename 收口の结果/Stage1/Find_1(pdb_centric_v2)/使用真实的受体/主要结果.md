# Find_1（pdb-centric-v2，真实受体）Stage1 主要结果

本文汇报 `Find_1` 在 179-PDB `test_0` 上的主要结果，并列展示 F1 blobs+basic 与 F2 blobs+Gaussian 两条流水线。表中性能指标保留六位小数；服务器 JSON 保留完整精度。`test_0` 的 0.6 档实例指标和全部 top-K 成功率放在 [补充结果](./%E8%A1%A5%E5%85%85%E7%BB%93%E6%9E%9C.md)。

## 结果摘要

- 语义 micro F1：basic 为 `0.601479`，Gaussian 为 `0.603172`；语义 macro F1 分别为 `0.583242` 和 `0.584498`。
- Gaussian 相比 basic 降低语义 precision、提高语义 recall；两种汇总口径下的 F1 只有小幅上升。
- 在 0.3 和 0.5 两档中，Gaussian 的实例 macro F1 均高于 basic；micro F1 则持平或略低。这说明两种汇总口径对候选打分变化的反应不同。
- 两条流水线共用同一批完整图 probability map，因此语义 PRAUC 完全相同；语义 F1 使用不同语义阈值生成的最终入选 blobs 体素并集，因此可以不同。

## 评估口径

- basic 流水线使用 calibration 上最大化 PDB 等权 macro semantic F1 的阈值生成 F1 blobs，候选分数为 `source_probability_mean`。
- Gaussian 流水线使用 calibration 上最大化 PDB 等权 macro semantic F2 的阈值生成 F2 blobs，完成 centered 前向后使用 Find A 原子 Gaussian 正负项重新打分。
- `F2 blobs` 只表示 Gaussian 流水线用 F2 目标选择语义概率阈值；为了与 basic 直接比较，本文两条流水线的结果列均报告 P、R、F1 和 PRAUC，不把 F2 列为主要性能指标。
- 两条流水线的候选选参目标都是 `objective_beta=1`：最大化 calibration 上的 macro semantic F1、coverage F1@0.3 与 one-to-one F1@0.3 之和。
- P 表示 precision（精确率），R 表示 recall（召回率），PRAUC 表示 precision-recall 曲线下面积。micro 先合并所有 PDB 的计数再计算；macro 是逐 PDB 指标的算术平均。macro F1 通常不等于表中 macro P 与 macro R 的调和平均。零分母按正式契约记为 `0.0`。
- 语义 F1 使用最终入选候选的体素并集；语义 PRAUC 使用完整 probability map。实例 PRAUC 只应用冻结的 `prefiltered_min_voxel` 与 `min_voxels` 资格门槛，不应用最终 `score_threshold`。
- coverage 允许一个预测与多个真实 ligand occurrence 建立命中关系；one-to-one 使用最大一对一匹配。

## 直接观察

- Gaussian 评分将主要实例表中的 precision 系统性提高，同时使 micro recall 略降。在 PDB 等权 macro 口径下，coverage 和 one-to-one 的 F1@0.3/F1@0.5 均提高约 `0.012`。
- micro 与 macro 的变化方向不完全一致，表明改善不是由所有 PDB 均匀贡献。本文只报告描述性结果，不将该差异解释为显著性或因果证据。
- Gaussian 路径同时改变了语义阈值、候选集和候选打分，因此本表是两条完整流水线的对比，不是只替换打分函数的单因素消融。
