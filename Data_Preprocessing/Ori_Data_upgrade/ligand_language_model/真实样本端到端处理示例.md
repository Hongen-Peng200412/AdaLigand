# 配体语言模型真实样本端到端处理示例

PDB 是一份生物大分子三维结构记录；occurrence 是其中一次配体出现；LigandObject 是
Stage C 化学解析阶段保存的可复用配体模板；SMILES 是用一行字符表示分子原子与化学键的
文本。本文用 PDB `7d3f` 的真实 Stage C 产物说明代码如何从 occurrence 和
LigandObject 得到模型 SMILES。示例源字段只读提取自以下服务器文件：

```text
/storage/penghongen/AdaLigand/Ori_Data/parse/7d3f/occurrences.jsonl
/storage/penghongen/AdaLigand/Ori_Data/parse/7d3f/ligand_coords.npz
/storage/penghongen/AdaLigand/Ori_Data/ligand_objects/*.npz
/storage/penghongen/AdaLigand/Ori_Data/raw/rcsb_mmcif/7d3f.cif
```

CCD 是 PDB 化学组分字典中的单个标准组分，`CCD:HEM` 表示血红素模板；BRANCHED 表示由
多个残基分支连接的配体。RDKit 是把 SMILES 转成分子图并重新生成字符串的化学软件包；
sanitize 是它对价态、芳香性等属性的检查与整理；canonical SMILES 是按确定规则写出的
统一字符串；isomeric 版本保留立体化学标记，non-isomeric 版本不保留。mmCIF 是 PDB
三维结构记录的文本格式；pdbeccdutils 是读取该格式并处理化学组分的软件包；CLC 是它从
完整 PDB mmCIF 文件识别出的共价连接配体组分；
`present_{candidate_id}` 是与 `LigandObject.atoms` 逐原子对齐的布尔掩码，`True` 表示
当前 PDB 实际出现该模板原子，`False` 表示未出现。下文涉及的 CPU 和 GPU 正式产物均已
用当前实现和真实数据交叉核对；向量只展示少量真实数值和统计，不复制全部 768 个值。

JSONL 是每个非空物理行保存一个 JSON 对象的文本文件；NPZ 是按名称保存多个 NumPy
数组的压缩文件；tokenizer 是把 SMILES 拆成模型词表片段并转换成编号的程序；batch 是
模型一次共同计算的一组 occurrence；diagnostics 是只记录转换与异常事实、不参与自动
筛选的诊断对象；float32 是每个值使用 32 位保存的浮点数；L2 范数是把向量各项平方和
再开平方得到的整体大小。

## 先认识处理单位

一个处理单位不是“某种化学分子”，而是一个 PDB 中的一次配体出现：

```text
(pdb_id, candidate_id)
```

`object_key` 指向可复用的化学模板。两个 occurrence 可以共享一个 `object_key`，但
只要 `candidate_id` 不同，它们仍是两个处理单位。`7d3f` 的 candidate 4 和
candidate 6 正好展示这种情况。

## 示例一：candidate 8 的普通 CCD:HEM

### 1. occurrence 告诉代码“处理谁”

以下 JSON 是 candidate 8 的完整原始 occurrence，没有省略字段：

```json
{
  "pdb_id": "7d3f",
  "candidate_id": 8,
  "object_key": "CCD:HEM",
  "kind": "CCD",
  "type_tag": "small_molecule",
  "is_covalent": false,
  "components": [
    {
      "index": 1,
      "ccd_id": "HEM",
      "label_asym_id": "G",
      "label_seq_id": 1601,
      "auth_asym_id": "A",
      "auth_seq_id": 1601,
      "icode": ""
    }
  ],
  "inter_bonds": [],
  "n_heavy_atoms": 43,
  "polymer_length": 1
}
```

`kind=CCD` 使 `prepare_ligand()` 直接进入 CCD 分支。这个分支不读取
`present_8`，因为普通 CCD 的语言模型输入来自 LigandObject 自带的 SMILES。

### 2. LigandObject 告诉代码“这个化学模板是什么”

`ligand_objects/CCD_HEM.npz` 的真实关键事实为：

| 字段 | 真实值 |
|---|---|
| `smiles` | 下方完整字符串 |
| `atoms` | 43 个模板原子 |
| `bonds` | 50 个模板键 |

```text
[H]OC(=O)C([H])([H])C([H])([H])C1=C2C([H])=C3C(C([H])([H])C([H])([H])C(=O)O[H])=C(C([H])([H])[H])C4=[N]3[Fe]35[N]6C(=C4[H])C(C([H])=C([H])[H])=C(C([H])([H])[H])C6=C([H])C4=[N]3C(=C([H])C(=C1C([H])([H])[H])[N]25)C(C([H])([H])[H])=C4C([H])=C([H])[H]
```

这条字符串包含铁原子和显式写出的氢。代码不去金属、不去盐、不取最大组分，也不
删除这些氢；它只让 RDKit 尝试解析、sanitize 和规范化。

### 3. RDKit 把同一分子改写成确定的非异构 SMILES

本例的真实执行结果为：

| 操作 | 结果 |
|---|---|
| `Chem.MolFromSmiles(..., sanitize=False)` | 成功得到 RDKit 分子 |
| `Chem.SanitizeMol(...)` | 成功，没有异常 |
| `Chem.MolToSmiles(..., canonical=True, isomericSmiles=False)` | 得到下方字符串 |

```text
[H]OC(=O)C([H])([H])C([H])([H])C1=C(C([H])([H])[H])C2=[N]3->[Fe]45<-[N]6=C(C(C([H])=C([H])[H])=C(C([H])([H])[H])C6=C([H])c6c(C([H])([H])[H])c(C([H])([H])C([H])([H])C(=O)O[H])c([n]64)C([H])=C13)C([H])=c1c(C([H])([H])[H])c(C([H])=C([H])[H])c([n]15)=C2[H]
```

这就是 CPU 阶段交给模型的 `smiles`。代码没有声称这种金属配位写法一定拥有高质量
语言模型表示；“能够产生字符串”与“表示质量可靠”被明确分开。

### 4. prepared 文件保存身份、字符串和事实

`prepared/7d3f/prepared_smiles.jsonl` 中该候选的顶层字段逐项对应如下。表中的“第 2
步完整字符串”和“第 3 步完整字符串”只用于避免把上方长字符串原样复制第二遍；正式
JSONL 不保存这种占位文字，而是保存上方已经完整展示的真实字符串。

| 顶层字段 | 正式值 |
|---|---|
| `pdb_id` | `7d3f` |
| `candidate_id` | `8` |
| `object_key` | `CCD:HEM` |
| `kind` | `CCD` |
| `type_tag` | `small_molecule` |
| `is_covalent` | `false` |
| `smiles` | 第 3 步完整 canonical non-isomeric SMILES |
| `smiles_source` | `ccd` |
| `diagnostics.raw_smiles` | 第 2 步完整 LigandObject SMILES |
| `diagnostics.sanitize_error` | `null` |
| `diagnostics.model_smiles_error` | `null` |

本表是字段节选，只摘录了本例已经核实且解释主线所需的 diagnostics。省略字段的完整
路径为：`diagnostics.rdkit_parse_error`、`diagnostics.isomeric_smiles`、
`diagnostics.isomeric_smiles_error`、`diagnostics.stereo_removed`、
`diagnostics.chemistry.atom_count`、`diagnostics.chemistry.fragment_count`、
`diagnostics.chemistry.fragment_count_error`、
`diagnostics.chemistry.has_disconnected_components`、`diagnostics.chemistry.has_metal`、
`diagnostics.chemistry.charged_atom_count` 和
`diagnostics.chemistry.total_formal_charge`。逐项含义见
[产物字段参考.md](产物字段参考.md)。
如果 RDKit 在第 2 或第 3 步失败，但 LigandObject 原文仍非空，`smiles` 会保留原文，
异常进入 `diagnostics`，语言模型仍可尝试处理。

### 2. 同一个 PDB 的两个 CLC 用完整残基身份区分

pdbeccdutils 从 `7d3f.cif` 返回两个 CLC：

- 第一个 CLC 包含 E 链的十个糖残基。
- 第二个 CLC 包含 F 链的十个糖残基。

代码把每个残基转换成
`(ccd_id, auth_asym_id, auth_seq_id, insertion_code)`，再比较多重集合。candidate 4
的十个 E 链身份只匹配第一个 CLC。以下 JSON 是正式 diagnostics 的嵌套结构节选，
不是把 `read` 与 `selection` 字段压平后的新格式：

```json
{
  "clc": {
    "read": {
      "candidate_count": 2,
      "package_result_count": 2,
      "error": null
    },
    "selection": {
      "occurrence_component_count": 10,
      "exact_match_count": 1,
      "connection_check": {
        "matches": true,
        "declared_count": 9,
        "expected_count": 9,
        "observed_count": 9,
        "parse_errors": [],
        "used_for_smiles_selection": false
      }
    }
  }
}
```

本节选只省略 `diagnostics.clc.read.candidate_warnings`、
`diagnostics.clc.read.candidate_errors`、
`diagnostics.clc.read.package_charge_and_bond_order_are_not_treated_as_authoritative`，以及
稍后生成的 `diagnostics.clc.remove_h_error`、`diagnostics.clc.preparation_error` 和
`diagnostics.clc.molecule`。正式 JSONL 保留这些字段。

九条 `inter_bonds` 与选中 CLC 的九条连接也完全一致，但这项比较明确标记为
`used_for_smiles_selection=false`。即使连接比较出现差异，唯一精确 CLC 仍可提供
SMILES；差异只供后续研究者判断。

## 示例三：真实 present 图怎样形成后备 SMILES

candidate 4 正式运行时会选择上一节的唯一 CLC。本节只为学习 present 后备算法，
对同一份真实 LigandObject 和 `present_4` 单独执行后备步骤；它不是在声称 candidate
4 的正式 `smiles_source` 应为 `present_graph`。

真实输入数量为：

| 数组 | 数量 | 含义 |
|---|---:|---|
| `LigandObject.atoms` | 126 | 十个 CCD 模板拼接后的全部模板原子 |
| `LigandObject.bonds` | 135 | CCD 内部键和九条组分间单键 |
| `present_4=True` | 116 | 当前 PDB 实际出现的模板原子 |
| `present_4=False` | 10 | 十个残基各自缺少的一个 `O1` |

后备代码逐步执行：

1. 建立 `old_to_new`，把 116 个保留原子的 LigandObject 编号映射到新 RDKit 编号。
2. 删除十个 `present=False` 的 `O1`，不解释它们是离去原子还是普通缺失原子。
3. 检查每条模板键的两个端点；两个端点都在 `old_to_new` 中时才保留。
4. 最终图有 116 个原子和 125 条键，sanitize 成功。
5. RDKit 生成的非异构 SMILES 与上一节 CLC 路径的字符串完全相同。

这次相同是 `7d3f/candidate 4` 的实际观测，不是代码保证。其他 occurrence 的
present 图可能与 CLC 不同、可能断成多个片段，也可能 sanitize 失败；只要
`MolToSmiles` 仍得到非空字符串，代码仍保存该字符串并记录事实。

## 示例四：共享 object_key 仍然逐 occurrence 落盘

`7d3f/candidate 6` 与 candidate 4 共享：

```text
BRANCHED:NAG-NAG-BMA-MAN-MAN-MAN-MAN-MAN-MAN-MAN:2ae773
```

但是 candidate 6 的十个 `auth_asym_id` 都是 `F`，所以它精确匹配 F 链 CLC；
candidate 4 匹配 E 链 CLC。两条 occurrence 在本例中恰好生成相同 SMILES，仍分别
产生以下文件：

```text
prepared/7d3f/prepared_smiles.jsonl 中 candidate_id=4 的 JSON 对象
prepared/7d3f/prepared_smiles.jsonl 中 candidate_id=6 的 JSON 对象

molformer/7d3f/candidate_4.npz
molformer/7d3f/candidate_6.npz

smi_ted_289m/7d3f/candidate_4.npz
smi_ted_289m/7d3f/candidate_6.npz
```

这说明“全局出现次数最多的精确 SMILES”只能作为汇总统计，不能拿来替代 occurrence
身份，也不能让一个 occurrence 的向量文件覆盖另一个。

## 从 SMILES 到向量文件

CPU prepared 文件验收后，两个模型入口各自读取所有非空 `smiles`：

```text
当前 GPU 分片内所有未完成 PDB 的 prepared 记录
    → 跨 PDB 合并成一个 occurrence 列表
    → MoLFormer 由包装层按最多 256 项分 batch
    → MoLFormer 以 deterministic_eval=True 固定官方随机特征映射
    → SMI-TED 把官方规范化成功项组成完整跨 PDB 列表并传入 batch_size=min(100, 该列表数量)
    → 官方规范化失败项仍逐 occurrence 调用 encode，不进入含 None 的混合列表
    → 模型成功的位置得到一个 (768,) 分子向量，失败位置得到 model_failed
    → 按原位置的 pdb_id 和 candidate_id 分发向量或状态到逐 PDB 目录
```

例如正式生成的 candidate 4 MoLFormer 文件包含：

```text
pdb_id          = "7d3f"
candidate_id    = int32(4)
object_key      = "BRANCHED:NAG-NAG-BMA-MAN-MAN-MAN-MAN-MAN-MAN-MAN:2ae773"
model_name      = "ibm-research/MoLFormer-XL-both-10pct"
prepared_smiles = 上方完整糖链 SMILES
model_smiles    = MoLFormer 实际接收的同一字符串
embedding       = float32 (768,)
```

该真实向量的前八个数为
`[0.908486, 0.125456, 0.649888, 1.458286, -0.928027, -0.351891, 0.493155, 0.683636]`；
768 个值全部有限，最小值约为 `-2.162898`，最大值约为 `5.275097`，L2 范数约为
`17.576006`。这些数值来自启用 `deterministic_eval=True` 后正式覆盖写入的
`molformer/7d3f/candidate_4.npz`；这里仅列少量数值用于证明端到端路径确实完成。

SMI-TED 文件拥有相同字段，但 `model_name` 改为 `SMI-TED Light 289M`。独立调用
官方 `normalize_smiles` 成功时，`model_smiles` 保存该可确认的 tokenizer 输入；若该
诊断无法确认输入、但官方 `model.encode` 仍返回向量，则 results JSONL 中
`model_smiles=null`，NPZ 中保存空字符串。candidate 4 的 SMI-TED 向量前八个数为
`[0.417251, -0.513596, 0.028936, 0.427680, 0.639018, -0.654490, 1.020087, -0.002929]`；
它同样包含 768 个有限的 `float32` 值。两套模型的数值不同，代码也不要求它们相同。
