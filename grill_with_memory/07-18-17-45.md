Question: 是否把三种正式模型冻结为 Find_0（无 embed head、49 维受体特征硬 scatter，独立完成 CPC1→CPC2）、Find_1（MLP + 体素/点相对位置 MLP 编码 + 软投影，独立完成 CPC1→CPC2）和 unet_c1（纯密度单独训练），即最终 3 个正式 checkpoint、实际至少 5 个训练阶段？
Decision: 是，按上述定义冻结。
Reason: 两套 Find 必须分别用各自 CPC1 BEST 初始化各自 CPC2，保证 calibration 比较的是两个完整且独立的 Find 配方。

Question: 是否把所有 80³ BOX 的边界行为冻结为同一个向网格内部平移规则 actual_start=min(max(proposed_start,0),grid_size-80)，用于训练预定位、增强、全图滑窗、F1/CLG 居中和 selected-final；永不补零，任一整图轴小于 80 的 PDB 在 Stage1 划分前判为不合格？
Decision: 是，按上述规则冻结。
Reason: 统一裁剪行为，删除补零、voxel_valid_mask 和多套边界分支，同时保持训练与推理的数据分布一致。

Question: 是否冻结一份在 A–G 最终 release、Stage G 分布分析和正式质量过滤后生成的全项目共用 split：以 pdb_id 为不可拆分单位，train 约 75%、validation 固定 300、calibration 固定 100、其余为 held-out test pool，序列去冗余只从 test pool 选正式测试集；Find_0、Find_1、unet_c1、selector、Stage2 和 Stage3 全部复用？
Decision: 是，按上述规则冻结。
Reason: 保证模型比较、阈值标定和后续训练严格可比，并避免未完成的 A–G 清单污染正式划分。

Question: 是否把 occurrence 长尾规则冻结为：训练预定位池保留全部 occurrence；train 每个 epoch 对每个 PDB 最多无放回抽取 50 个 occurrence，不同 epoch 可轮换；validation 生成一份所有模型与训练阶段共用、每个 PDB 最多 50 个 occurrence 的冻结清单，并固定对应 center、bias 和 context；calibration 仍基于冻结 checkpoint 的全图推理？
Decision: 是，按上述修订版冻结。
Reason: 在不永久丢失长尾 occurrence 的前提下，让训练与 validation 尽可能同分布，并保持所有模型和阶段之间的验证可比性。

Question: Stage1 新代码是否采用职责分层、双仓库锁定：AdaLigand 负责 split、训练池、materializer、Dataset/collate、全图与局部推理及产物契约；Pocket_Plus 保留 Find/UNet、loss、训练循环和冻结规则；AdaLigand 以薄入口调用 Pocket_Plus，正式运行同时记录两个仓库 commit，只有现有配置无法表达时才最小修改 Pocket_Plus？
Decision: 是，按上述职责分层方案冻结。
Reason: 避免复制整套模型或把 AdaLigand 数据契约重新混入 Pocket_Plus，同时用跨仓库 parity 测试保证旧网络实际输入不变。

Question: 是否把 Pocket_Plus parity 冻结为默认逐项照搬、仅允许已批准例外：复用受体筛选、49 维特征、局部坐标、hardmask、56 维密度通道、同步旋转、collate 和模型直接输入；例外仅为向网格内部平移且不补零、Ada schema v3 union mask 标签、删除 voxel_valid_mask、新 split/训练池/资产路径以及 Find_0/Find_1 注入配置；清单外差异阻断训练，发现祖传 bug 先报告不擅改？
Decision: 是，按上述 parity 与例外清单冻结。
Reason: 保证新管线真正向旧网络提供相同表示，同时让每一项科学或工程差异都经过显式批准。

Question: 是否把三个模型的有效 global_batch_size 都定在约 64：H100/A800 单卡优先 batch 8，最大 recycle 下不稳则用 6；复用 Pocket_Plus 梯度累积基础设施，分别允许得到自然整除的 64 或 66；短 preflight 后把单卡 batch、设备数、累积次数和最终 global batch 写入正式配置，并统一使用 bf16-mixed？
Decision: 是，按上述修订版冻结。
Reason: 使用已有基础设施和可靠经验值，保持三个模型的有效 batch 接近一致，同时避免为强行凑整数重复开发复杂逻辑。

Question: 是否让 Find_0、Find_1 和 unet_c1 首轮统一沿用 Pocket_Plus 已有的全局梯度范数裁剪 gradient_clip_val=0.5，不列为首轮消融；只有出现更新长期被严重压缩、训练明显停滞等明确证据时才讨论提高到 1.0？
Decision: 是，首轮统一保留 0.5。
Reason: 0.5 是偏保守但常用的稳定配置，现有训练器已经支持，无需新增实现或提前扩展实验矩阵。

Question: Find_0、Find_1 和 unet_c1 每个 epoch 是否都运行 10 次完整、相同且冻结的 validation，并让 checkpoint 与 LR scheduler 使用这些完整验证结果？
Decision: 是，统一设置 val_per_epoch=10。
Reason: 旧数据量约为当前一半时已使用 5 次；300×10 约为实际训练样本约 9000 的三分之一，成本合理，且 CPC 候选集 C 的截断概率变化较剧烈，需要更密集地重新估计。

Question: Pocket_Plus 现有 C 截断概率系统已能在每次 validation 后更新阈值、保存和恢复 checkpoint 阈值，并在阈值缺失时拒绝生成 C；是否原样复用，不修改其生产代码，只做 AdaLigand 二值标签适配与集成验证，若验证发现不满足要求再先报告？
Decision: 是；若现有系统满足要求，就不做任何生产代码改动。
Reason: 避免对已经具备完整阈值生命周期的基础设施进行预防性重写。

Question: 在每个 epoch 含 10 次且间隔大量 BOX 的完整 validation 下，学习率调度是否冻结为：unet_c1 与两套 Find CPC1 使用 patience=3、factor=0.3、第 3 次实际降 LR 后停止；两套 Find CPC2 使用 patience=1、factor=0.3、第 1 次实际降 LR 后停止；max_epochs=15 仅作硬上限？
Decision: 是，按上述修订配置冻结。
Reason: validation 间隔已经包含大量参数更新，不应按巨大的 epoch 机械放大 patience；0.3 比 0.2 更适合作为三次衰减的强调整幅度。

Question: 是否原样保留成熟的初始优化配置：所有训练使用 AdamW、初始学习率 3e-5、权重衰减 0.01；unet_c1 使用 2.5% warmup、两套 Find CPC1 使用 6% warmup且起始系数均为 0.33；两套 Find CPC2 不做 warmup；plateau 的绝对有效改进阈值为 0.002；同时把 max_epochs 从 20 降为 15？
Decision: 是，保留上述优化器与 warmup，并把 max_epochs 冻结为 15。
Reason: 新数据与二值标签尚无证据支持同时改变成熟的初始优化参数；15 epochs 足以作为由验证与 LR 衰减主导训练之外的硬保护上限。

Question: BEST checkpoint 是否按职责选择：unet_c1 与两套 Find CPC1 分别按 validation voxel ligand PR-AUC；两套 Find CPC2 分别从自己的 CPC1 BEST 初始化并按现有 P 分支 pseudo_PRAUC；checkpoint 保存规则完全沿用 Pocket_Plus 默认值；CPC2 冻结正确性只补平凡测试，不增加生产流水线逻辑或运行制度？
Decision: 是，按上述最小改动版本冻结。
Reason: 让各阶段按实际训练分支选择 BEST，同时防止把普通契约测试过度扩张成新门禁、manifest 或生产分支。
