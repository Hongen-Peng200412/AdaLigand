Question: Find_0 与 Find_1 的点云前端、体素前处理、8 Å Dataset 边界、10 Å下游 A-pocket 和 A_feat_L0 应如何统一？

Question: Component forest 与 CLG 应如何同时满足正式盘上契约的可移植性和代码中树结构的直观性？
Decision: 采用“盘上数值 ragged、内存真正对象树”的双层表示。forest.npz 与 CLG.npz 继续使用不含 object array/pickle 的 parent_node_id、children_offsets+children_node_id、node_voxel_offsets+node_voxel_global_linear_index、candidate_offsets+candidate_node_id；每个 offsets 字段必须说明它切分的对应数组。加载后立即重建 ComponentForest、ComponentTree、ComponentNode 和 CLG 对象；Node 直接持有 parent 与 children:list[Node]，CLG 直接持有唯一 seed_node、oldest_node 与 candidate_nodes:list[Node]。枚举使用只复制拓扑、不复制 voxel payload、并回指只读原节点的 WorkingTree；ancestors、subtree、sisters、LCA 和 D(g) 只通过对象接口实现。成功或 node-cap 失败后都在当前 WorkingTree 对当前 seed 执行既定 D(g)=Ancestors(g)∪Subtree(g)。代码和正文统一使用大写 CLG，仅 shape 符号允许 N_clg；CLG_cover_node 改名为 CLG_oldest_node，盘上字段为 CLG_oldest_node_id；每个 CLG 只保存唯一 CLG_seed_node_id，删除 seed_candidate_offsets 与 seed_candidate_index，后续加入的姐妹只作为普通 candidate。
Reason: np.savez_compressed 直接保存嵌套 Python 列表会引入 object array/pickle；数值 ragged 适合正式压缩和跨环境读取。算法侧重建显式父子对象后，树操作和 D(g) 可以按真实拓扑书写与审计，而不必让业务逻辑直接操纵 offsets 或散落的索引循环。

Question: 每个 producer/split/PDB 的三类 Centered BOX 应采用一个 BOX 一个文件、part 分片，还是每个 role 一个聚合文件？
Decision: 每个 PDB 的 centered 目录最终只保存 F1_centered.npz、CLG_centered.npz 和 Selected_Refined_Centered.npz 三个压缩文件，不保留 index.npz+part_*.npz，也不按 BOX 生成小文件。每个 role 文件内部用 entry 主表及 offsets+values 表示变长 V/P/A，并作为独立原子发布单元；Selected_Refined_Centered 可以在 selector 完成后单独产生，不阻塞前两个 role。attempt 临时内容只存在于临时目录，正式目录只出现原子发布后的单个 role NPZ；下游不读取临时或半成品。
Reason: 上层已经按 producer、split 与 PDB 分区，再分 part 没有必要；一个 BOX 一个 NPZ 会产生大量小文件。每个 role 一个聚合 NPZ 同时控制文件数、保持 ragged 数据可压缩，并保留三个时间上独立的生产阶段。

Question: 当冻结 t_F1 后某个 producer/split/PDB 的合法 F1 blob 数严格大于 200，是否继续生成 CLG/centered，以及如何形成不会被其它 GPU 重跑且能与下游可用样本区分的终态？
Decision: 采用三个互斥状态：无状态原子取得任务后进入 _START；正常完成本阶段 probability、forest/CLG、F1/CLG centered 等必需产物后由 _START 原子转换为 _COMPLETE；按正式 F1 eligibility 计数得到 N_F1_eligible>200 时保留已经生成的 probability_map，但不生成 forest、CLG、overlap 或任何 centered 产物，并由 _START 原子转换为 _BLOB_EXCEED。_BLOB_EXCEED 文件保存最小 JSON，例如 {"N_F1_eligible":237,"limit":200}。_COMPLETE 表示 Selector、Stage2/3 可读取；_BLOB_EXCEED 表示该样本明确不可供这些下游使用。两者都是普通安全模式与补跑模式必须跳过的互斥终态；改变上限必须作为显式的新后处理运行处理，普通补跑不得自动复活。
Reason: 只缺失 centered 文件无法区分“尚未运行、运行失败与因异常 blob 数主动排除”，也会导致其它 GPU 反复重试。独立 _BLOB_EXCEED 终态既保留最昂贵且可供以后重新后处理的 probability_map，又明确阻止当前下游和调度器消费或重跑异常样本。

Question: 多 GPU 重叠清单下的并发锁应按 output_role 设置 _START，还是改用一个 PDB 级 _RUNNING，同时怎样保持各 role 分时可用？
Decision: output_role 仍是独立完成与消费单元，允许值为 probability、components、F1_centered、CLG_centered、Selected_Refined_Centered；各自保留 _COMPLETE，分别表示 calibration/components、F1-baseline/Stage2/3、Selector 或 Selected 路线可以读取。并发抢占不再使用 role 级 _START，也删除多个 attempt 竞争最终发布者的机制，改为每个 stage1_model_name/split/pdb_id 只有一个 PDB 级 _RUNNING 原子 mkdir 锁。worker 可先只读快速跳过已经满足本次目标的 PDB；仍有工作时原子创建 _RUNNING，成功后重新检查各 role，只依赖顺序运行缺失部分；其它 GPU 见 _RUNNING 立即跳过。每个 role 仍写独立临时文件，校验后原子替换正式文件并最后写自己的 _COMPLETE。正常完成、抢锁后发现无需处理、主动 continue 或写出 _BLOB_EXCEED 后，都在 finally 中立即移除自己持有的 _RUNNING。异常终止遗留的 _RUNNING 和 attempt 临时文件由显式低权重运维清理/重领工具处理，不进入科学主线。_BLOB_EXCEED 时保留 probability 的 _COMPLETE，不写 components/F1/CLG 的 _COMPLETE，并释放 _RUNNING。本决定以 _RUNNING 取代问题 5 中的 _START 抢占/转换细节，但不改变 _COMPLETE 与 _BLOB_EXCEED 的终态语义。
Reason: calibration、F1、CLG 和 Selected 必须在不同时间独立发布，因此 role 级完成状态不可合并；但同一 PDB 内没有必要并发生产多个 role。一个 PDB 级原子互斥锁足以处理 GPU 清单重叠，并显著简化双写、赢家发布和临时目录回收。训练或 selector 构造只扫描自己所需 role 一次并冻结清单，几个状态查询不会形成五倍数据读取。

Question: CCLN 中 candidate 到 V/P/A token 的 attention bias 应如何落实三套相对坐标与 probability，同时保持 P 无 candidate membership？
Decision: 对模态 m 的 token j 与 candidate i，bias MLP 输入固定为 r_ij^m=[(x_j-c_i^m)/s,(x_j-c_oldest^m)/s,(x_j-c_box)/s,p_j]∈R^10，其中 s 是 BOX 各轴物理半边长；不在进入 bias MLP 前做会改变 10D 语义的 Fourier 展开。每个模态使用独立 MLP_bias^m 输出各 attention head 的 bias，并额外广播加入 b_m*p_j；b_m 是该模态 attention 模块跨 head 共享、初始化为 0 的可学习标量。V 的 p_j 为 centered_probability，c_i^V 与 c_oldest^V 分别是 candidate voxel membership 与 CLG_oldest_node voxel 集中心；A 使用 A_probability，两个中心分别来自 candidate A membership 与 oldest A-pocket，空 A 走 learned null token且不伪造中心；P 使用 P_probability并继续读取完整 P 表，不建立 candidate_P_membership，其前两个几何锚改用 c_i^V 与 c_oldest^V。token value 表示仍可包含 probability feature，b_m*p_j 是额外显式可学习先验。
Reason: 九个归一化相对坐标加一个 probability 正好形成用户提出的 10D 输入；直接概率项提供可学习的显式置信度先验。P 本来没有 candidate membership，使用 candidate/oldest voxel 几何锚可保持 candidate-conditioned attention，同时不为 P 伪造不存在的实体中心或存储关系。

Question: Selector 第一版应实现哪些模型档位，L_blob 应在 tree-relative Transformer 前还是后计算，候选表示又应如何明确命名？
Decision: 删除 Nodewise pooled baseline；本轮只实现主模型 CCLN，BOX-wide learned latents 仅作为后续可选实验，不进入本轮实现与完成标准。候选完成 V/P/A 读取后，将 Q_i^(0)、实际存在的 Z_i^V/Z_i^P/Z_i^A 及 g_V/g_P/g_A 拼接并经内容 MLP 得到 E_i^content；随即计算 q_hat_i=sigmoid(MLP_blob(E_i^content))。q_i 是该候选与任一 GT occurrence 的最大 IoU；L_blob 对正、负 CLG 的全部候选计算，先在每个 CLG 内按候选数平均，再在 batch 内平均。E_i^content 随后进入 tree-relative Transformer 得到 E_i^tree；选择 logit z_i 与 CLG readout 均使用 E_i^tree。正文不再把三套训练式简称为“三种 gate”，而准确命名为 oracle-label 条件损失加权、停止梯度的预测有效性条件损失加权、联合预测有效性条件损失加权；现有三条损失公式保持不变。
Reason: 首版直接实现目标模型可避免为一次性 baseline 增加实现和试验负担，BOX-wide latents 也不是当前主线。把 IoU 回归头放在树传播前，能够直接监督候选自身的多源内容表示；谱系 Transformer 则专注于结构化选择与 CLG 判别。显式区分 E_i^content 和 E_i^tree 消除了原文 E_i 来源含糊，准确命名三种条件损失加权方式也避免把普通权重机制称作未定义的 gate。

Question: Selector 如何冻结并复用 CLG 粒度输入清单，同时尽量控制不同训练方案的随机性？
Decision: 将含义不准确的 input_pdb_list.json 改为 input_CLG_list.json，按 split、pdb_id、CLG_id 记录本次实际训练与验证样本并记录各 split 数量。未指定限制清单时，训练启动前只扫描一次已经完整发布的 CLG_centered，按固定顺序生成清单；清单作为该 Selector run 的不可变输入产物保存在其独立运行目录中，不使用或覆盖一个只表示“最新”的共享清单，运行中新增样本不进入本次 Dataset。可选 input_CLG_list_path 接受同一格式的既有清单；指定后必须使用其中的完整样本集合，任一条不存在或未完成都在训练前报告缺项，不静默取交集。同一份 CLG 清单只允许在同一 stage1_model_name 的 selector 方案之间复用；跨 producer 只能另行约束共同 PDB，因为 CLG 身份不跨 producer 等价。一个 selector_seed 统一控制模型初始化、样本打乱、分布式 sampler 和 DataLoader worker 随机种子；严格对照还保持 GPU 数和 global batch 相同，但不承诺跨硬件逐位一致。
Reason: run-scoped 不可变清单既能记录训练真正消费了哪些 CLG，也能被后续消融显式复用而不受后台继续生成 centered 产物的影响。限制清单缺项时报错可防止原本要求严格可比的实验悄悄变成不同样本集；统一主要随机源则以很小实现成本提高对照可信度。

Question: V5+D 的任务专属密度编码器应原样采用 Emap2lig MUNet，还是采用更适合反复调试 Selector 的弱化版本？
Decision: 首版采用 Pocket_Plus 内独立实现的 DensityMUNetLite，不建立对 Emap2lig 仓库的运行时依赖，也不加载其检测 checkpoint。输入是 density_input[B,1,80,80,80]=exp_clipnorm_nopost；四个分辨率层按 80^3→40^3→20^3→10^3 运行，实际下采样三次，通道固定为 [32,64,64,128]，每层一个 residual convolution block。encoder 与 decoder 不使用 Transformer，只在 10^3 bottleneck 使用一次 4-head、1-layer Transformer。解码后的全分辨率 32D 特征仅在实际 V voxel 坐标 gather，再线性投影 32→48 得到 c，不生成或落盘稠密 48D 图。Selector、Stage2、Stage3 各自持有随机初始化、端到端训练的实例。首版仍尝试 V5+D；若实测速度不可接受，再由人决定是否改试 V48，不自动降级。本轮不额外搜索或引入近期网络。
Reason: Emap2lig 原配置会在 20^3 的 8000 tokens 上执行 encoder、middle 与 decoder 共约四次全局 attention；将唯一 Transformer 放到 10^3 bottleneck，可把 attention 的核心二次计算量从约 4×8000^2 降到 1×1000^2，同时保留 BOX 级全局密度关系。卷积 skip path 继续保留局部形状，[32,64,64,128] 则维持较充足的密度表征容量，适合仍需大量迭代的 Selector。

Question: Find 与 unet_c1 的完整图及居中概率是否应使用 receptor hardmask 后处理，后处理又应放在哪一层？
Decision: Find_0 与 Find_1 的所有概率推理统一使用 p_Find=sigmoid(logit)·(1-hardmask)，覆盖第一次完整图与 F1_centered、CLG_centered、Selected_Refined_Centered 三类居中重跑。完整图先按既定 Gaussian 权重完成 float32 融合，再对最终 probability_map 乘一次全图 1-hardmask，随后才做 calibration、连通组件和落盘；居中路线也在新推理代码中对 BOX 概率应用同一规则。unet_c1 的概率永远不乘 hardmask。该规则只属于新推理层的 producer-specific probability 后处理，不改变通用 model/wrapper 的 logits 或训练 loss。hardmask 严格沿用“core 内受体原子的 home voxel 为 1”的现有定义，不增加膨胀半径或新参数。
Reason: Find 已经消费受体原子，排除受体 home voxel 不引入额外信息；在 Gaussian 融合后统一清零实现最简单，并与逐窗口使用同一二值 mask 等价。unet_c1 是 density-only 基线，若使用由受体坐标构造的 hardmask 就会泄漏其输入契约之外的信息。后处理留在新推理层还能避免为这一运行规则修改通用模型与训练 wrapper。

Question: 任一轴小于 80 的输入是否需要独立 Stage1 eligibility 工程，还是在 split 与 BOX 池生成时顺手处理？
Decision: 删除 stage1_preparation/eligibility 及 eligible_pairs.json、excluded_pairs.json、summary.json，不再建立独立 eligibility 入口、版本或清单；本决定取代上一轮“全量 eligibility 后再 split”的方案。主 split 保留 train 约 floor(0.75N)、validation 固定 300、calibration 固定 100、其余 held-out pool及 PDB 不跨 split 的原稿约定。选择 validation 300 与 calibration 100 时顺手要求完整图三轴均不小于 80。train 不做额外全量 eligibility 扫描；生成冻结 train BOX pool 时直接要求不补零的 resolved crop shape 恰为 80^3，不满足的 pair 不产生 BOX 记录，正式 Dataset 不在 __getitem__ 内临时跳过或崩溃。train 完整图与居中推理只消费实际进入冻结 train BOX pool 的 pair。BOX pool 自身的普通 summary.json 可以记录因 crop 不足而未产出记录的数量，但不另建排除清单。held-out pool 当前只保留 split 身份，不检查小图、不去冗余、不进入近期运行。
Reason: 当前只必须保证 validation 与 calibration 共 400 张 map 能运行，而 train 的 BOX 预定位本来就会访问并验证真实 crop；单独再扫一遍全量 eligibility 只会拉长流程。让 Dataset 只消费已经成功预定位的记录，仍能保证训练中不崩且跨模型输入一致；held-out 的尺寸与去冗余可以在以后构建严格测试集时一次处理。

Question: 第一次完整图推理应直接运行完整 forward，还是新增严格受控的 voxel-only 入口以跳过 Find 的 point/P/A 后半段？
Decision: 保持现有训练 forward 原样，不抽取共享 _forward_voxel_branch，也不借机重构 recycle 主链；只新增独立 forward_voxel_probability(batch)，复制最短必要的 voxel 构造与固定三次 recycle 逻辑并返回最终 voxel ligand logits。unet_c1 执行 density→voxel backbone；Find_0 直接执行 raw49 core hard scatter，不运行 point-side embed；Find_1 只执行无 Transformer 的 voxel MLP/centroid/residual/soft-splat，不运行 [8,4,0] point blocks。仅在确有必要时给 Stage1EmbedHead 增加一个默认保持原完整行为的内部 branch 选择参数，供 voxel-only 调用跳过 point branch；不得扩大成通用执行模式框架。新完整图推理调用该入口，三类居中推理仍调用完整 forward。测试至少覆盖三个 producer 在 eval、固定三次 recycle 下与完整 forward 的 voxel_logits_ligand 逐元素等价；用调用计数或 mock 证明 point blocks、point backbone、P candidate、atom/P heads 与 sparse-refine 未执行；覆盖 checkpoint 完整加载后的等价性、不同 batch size/原子数/空原子或边界 BOX、输出 shape/dtype/finite，以及每个 producer 一个真实 BOX smoke。任何无法达到严格等价的差异必须先解释并由用户决定，不能以宽松 tolerance 掩盖。论文只能在同硬件、同窗口清单 benchmark 后表述“第一次完整图 ligand-area 概率推理几乎不受点云分支影响”，不得泛化为包含居中推理的总管线零开销。
Reason: 完整 forward 的 fail-fast 有价值，但可以由完整 forward 与真实 centered smoke 专门覆盖；若在每个完整图窗口重复运行 point/P/A，会显著增加 Find 的时间和显存，而且这些分支不回写 voxel logits。独立的短入口以少量受测试约束的重复代码换取完整图吞吐，同时不触碰已经调好的训练路径；严格多角度等价与未调用证明用于控制双路径漂移风险。

Question: 精确树 DP 测试中的 MAP 与 partition 分别是什么，怎样与 GT oracle 区分？
Decision: 正文首次出现时将 MAP 明确写为“预测 MAP（Maximum A Posteriori，最大后验）反链”：CLG 门控通过后，在非空反链集合 A_+(G) 中使模型条件概率最大、等价地使 score_theta(S)=sum_{i∈S}z_i-lambda_count|S| 最大的反链 S_hat_MAP。partition 首次出现时明确写为“非空反链配分函数/归一化常数” Z_theta(G)=sum_{T∈A_+(G)}exp(score_theta(T))，用于把预测能量归一化为训练期条件概率。oracle 则是使用 GT 派生 q_i、在包含空集的 A(G) 中最大化 Q_GT 的 S*，与预测 MAP 不得混称。小树穷举分别验证 partition 数值、预测 MAP 最优分数、GT oracle 最优分数及训练损失梯度；若存在多个同分最优反链，只要求 DP 返回合法最优解且最优分数一致，不增加 tie-break 政策。
Reason: 只展开 MAP 缩写仍无法告诉冷读者它优化哪个集合和哪套分数；partition 若不在公式首次出现处解释，也无法理解条件分布分母和 logsumexp DP 的目的。把预测、GT 与归一化对象分别命名后，测试目标和训练/推理解码边界都变得可直接实现。

Question: n_CLG_cap、n_CLG_completed、CLG_cap_reached 与平均 CLG node 数分别应表示什么？
Decision: n_CLG_cap 是当前 PDB 按 min(300,3·max(2,n_f1_eligible_seeds)) 算出的成功 CLG 数量上限，不是已生成数量。n_CLG_completed 是成功完成枚举、通过单 CLG node 上限并实际写入 clg.npz 的 CLG 数，恒等于文件 N_clg；node-cap rejected 尝试不计入。CLG_cap_reached 只有在 n_CLG_completed==n_CLG_cap、工作树仍有未处理 active seed、枚举因此提前停止时为 true；若 seed 恰好自然耗尽时数量等于 cap，仍为 false。n_CLG_rejected_by_node_cap 是候选数将超过 depth1/depth2 的 32/64 上限而整体放弃的 CLG 尝试数。新增 mean_candidate_nodes_per_completed_CLG=N_candidate/n_CLG_completed，表示成功落盘 CLG 的平均 candidate node 数；没有成功 CLG 时为 0.0。
Reason: 原字段把“允许上限、成功产物数、达到上限而截断”混在一起，冷读者无法据此判断枚举是否自然结束。把 cap reached 限定为确实造成提前停止，并令 completed 与盘上 N_clg 对齐，可让统计直接反映产物和截断原因；平均 candidate 数补充每个 PDB 的实际 CLG 规模。

Question: Stage1 calibration 的 component/GT 指标应保留 Pocket_Plus 既有 coverage 与 Hungarian 逻辑，还是改成 IoU 阈值图上的最大基数匹配？体素 PR-AUC 是否排除 hardmask 区域？
Decision: 保留 Pocket_Plus 既有指标定义和计算顺序，不改成 IoU 阈值匹配，也不改成阈值图上的最大基数匹配。对预测 component P_i、GT occurrence G_j 及交集 I_ij，定义 c_pred(i,j)=I_ij/|P_i|、c_GT(i,j)=I_ij/|G_j|。coverage precision 的分子是至少对一个 GT 满足 c_pred>=tau 的预测数，coverage recall 的分子是至少被一个预测满足 c_GT>=tau 的 GT 数，随后由二者计算 coverage F1。one-to-one 先在完整矩阵上用 score(i,j)=sqrt(c_pred(i,j)·c_GT(i,j)) 做一次最大总分 Hungarian 匹配，再在这组固定匹配中分别统计同时满足 c_pred>=tau 且 c_GT>=tau 的配对；不得改为先按 tau 删边再最大化达标配对数。top-K 不做 Hungarian，而是在既定候选排序的前 K 项与全部 GT 之间检查是否存在同时满足两项 coverage 阈值的配对。tau 固定报告 0.3/0.5，替换旧默认值中的 0.6；当前文档把这些阈值写成 IoU 阈值属于术语错误，重写时改正。Selector 回归目标 q_i 所使用的最大 IoU 不受本决定影响。复用既有交集、体素数、coverage 矩阵与高层算法，只按新模块输入输出做必要适配。体素 PR-AUC 使用标准 Average Precision：每个 PDB 在包含 hardmask 的完整网格上独立计算 AP，再对存在有效 AP 的 PDB 做宏平均，并同时报告参与平均的 PDB 数；不把全部 PDB 体素拼接为 micro AP。
Reason: 旧指标分别刻画预测区域纯度与 GT 覆盖程度，并且已有明确、可配置的实现；固定 Hungarian 先确定不依赖 tau 的稳定一对一对应关系，tau 只在同一组对应上判定是否达标，因此不采用会随 tau 改变匹配关系的阈值图最大匹配。阈值从 0.3/0.6 调整为 0.3/0.5 只改变报告档位，不改变算法。PR-AUC 纳入 hardmask 可保持全网格评价域；逐 PDB macro AP 避免体素更多的大图支配汇总结果，并沿用现有推理评估口径。

Question: calibration、validation/train 的 probability/F1/CLG 生产与 Selector 后置的 Selected 重跑，应采用怎样的入口和时间顺序？
Decision: producer 推理采用先 calibration 全图定阈值、后 calibration/validation/train 生产下游产物的两段运行。每个 producer 的第一段由单 GPU 入口只完成 calibration 100 的全图 probability、阈值冻结与指标汇报；此时不要求同步完成 calibration 的 components、F1_centered 或 CLG_centered。阈值冻结后进入第二段：提供 cal-produce-F1-CLG、val-produce-Prob-F1-CLG 与 train-produce-Prob-F1-CLG 三个清楚区分 split/职责的入口，共用同一底层 runner；cal 入口复用第一段已经发布的 probability，只补齐 components、F1_centered 与 CLG_centered。薄调度脚本支持 array 任务和每任务多 GPU，不写死卡数，并让每个 worker 先消费分配给自己的 validation 与 calibration 份额，再消费 train 份额。资源增加、缩减或重启时，重新扫描未完成 PDB，并依靠 PDB 级 _RUNNING 与 role 级 _COMPLETE/_BLOB_EXCEED 安全续跑。对尚无 probability 的 PDB，按 probability、components、F1_centered、CLG_centered 顺序独立发布，无需等待整个 split 完成。Selector 启动时只扫描一次当时已完成的 CLG_centered，按 split 冻结当前 run 的 input_CLG_list.json，因此允许在 train 推理只完成一部分时开始训练，同时让已完成的 calibration 产物用于 Selector 校正与评估。Selected_Refined_Centered 不属于 producer 的上述第二段入口；必须等 Selector 训练完成后，再由独立入口生成。主计划只简述该时间线，入口参数、分片与测试放在低权重细节手册。
Reason: calibration 完整图概率与冻结阈值是所有 split 后续 component、F1 与 CLG 生产的前提，但 calibration 自身也必须在阈值冻结后补齐这些产物，供 Selector 校正与评估使用。把 calibration 的第一次运行限制为概率、阈值和报告，可避免循环依赖；第二段把 validation/calibration 置于 train 之前，可尽早获得完整评估与校正输入。split 专属入口便于审计和补跑，共享 runner 避免重复实现；按 PDB/role 发布和启动时冻结 Selector 清单，使部分产物可立即消费，同时保持单次训练样本集合稳定。Selected 依赖已训练 Selector，时间上必然与 producer centered 推理分离。

Question: A_feat_L0–L4 与 P_feat_L2–L4 应分别绑定到哪些真实模型出口，A 特征又应覆盖 centered BOX 中的哪些原子？
Decision: A 的正式实体集合是“来源 blob 的 10 Å 包络与当前 80³ BOX 的交集”；只为该集合中的原子记录或索引 A 特征与 A_probability，BOX 外原子不进入 centered entry。A_feat_L0 是由 A_global_index 从每 PDB receptor 表现场无损索引的原始 49D float32，不在每个 centered 文件重复保存。A_feat_L1 是 point-side Stage1EmbedHead 输出、尚未加入 real-atom density-cube 调制的特征；两个 Find 均存在。A_feat_L2 是 A_feat_L1 与原子局部 density-cube 编码经过现有 combine 后、真正进入 point backbone 的 A 输入，不是孤立 density 特征。A_feat_L3=real_feat_before_interaction，是 point backbone 最终输出且尚未经过 A↔P cross-attention 的 A 特征；A_feat_L4=real_feat_after_interaction，是 P→A cross-attention 残差后的 A 特征和 A 分类头输入；A_probability 是该分类头 logit 的 sigmoid。P_feat_L2=pseudo_density_feat，是局部 density cube 编码、类别条件化和接口归一化后真正进入 point backbone 的 P 初始特征；P_feat_L3=pseudo_feat_before_interaction，是 point backbone 最终输出且尚未经过 A↔P cross-attention 的 P 特征；P_feat_L4=pseudo_feat_after_interaction，是 A→P cross-attention 残差后的 P 特征和 P 分类头输入；P_probability 是该分类头 logit 的 sigmoid。L1–L4 学习特征以 float16 落盘；每个字段必须逐项说明来源、语义与对齐实体。
Reason: 现有模型已经暴露 density 调制前后、point backbone 后及 cross-attention 后的真实张量，直接把 L 编号固定到这些出口可避免“多层特征”随实现漂移。A 的 10 Å 包络只定义当前 BOX 内的下游 pocket；Dataset 的 core+8 Å model view 已覆盖 BOX 内原子，因此无需读取或伪造 BOX 外学习特征。L0 通过全局索引复用，兼顾原始信息和磁盘预算。

Question: calibration 的七个 alpha 阈值是否应继续使用去重物理层数 R 与 K→R 映射，还是用扫描整数直接统一阈值身份？
Decision: 扫描分辨率从 16384 提高到 32768，固定 t_j=j/32768，j=0,...,32768。thresholds.json 保存 threshold_grid_denominator=32768、固定 alpha_values[7]、每个 alpha 实际选中的 alpha_threshold_grid_index[7]（值就是 j）、便读的 t_alpha[7]=alpha_threshold_grid_index/32768，以及 alpha=1 对应的 t_F1；删除 physical_threshold_values、alpha_to_threshold_index 及显式 R。构造 component forest 时现场计算 level_j=sorted(set(alpha_threshold_grid_index), reverse=True)：若七个 alpha 中有 k 个重复扫描整数，自然只产生 7-k 个真实阈值层，不伪造相同 mask 的重复 level。forest.npz 的 threshold_index 全局改名为 threshold_grid_index，直接保存实际 j；clg.npz 的 candidate_threshold_index 同步改名为 candidate_threshold_grid_index；threshold_value=j/32768 继续作为便读冗余值。代码通过逐图累计长度 32769 的正/负体素 int64 histogram 并反向累积，计算全部阈值的 TP/FP/FN，不物化“体素×阈值”张量。上述字段、名称、分母与派生规则必须在四件套文档、配置、代码和测试中全局一致。
Reason: 直接用扫描整数 j 同时消除了 float 相等判断、去重后稠密下标和 K→R 映射；重复阈值仍只生成一个物理层，不会制造重复 mask、候选或反链状态。32768 是 2 的幂，阈值可精确表示；histogram 累计让加倍扫描分辨率几乎不增加内存或主要计算复杂度。

Question: Selector 的 `scores.npz` 与 `selection.npz` 应如何区分质量预测、选择能量、CLG 门控和候选索引，并保证冷读者能够从字段直接恢复语义与对应关系？
Decision: `scores.npz` 按来源 `CLG.npz` 的 CLG 顺序保存 `CLG_id[N_clg]`；`CLG_id` 是当前 producer/split/PDB 内的 CLG 局部身份，值和顺序必须与来源文件逐项一致。`CLG_logit[N_clg]` 是 Selector 对“该 CLG 是否包含值得进入结构化选择的有效候选”的未归一化门控 logit；`CLG_valid_probability[N_clg]=sigmoid(CLG_logit)` 是用于 calibration 选择并冻结 `tau_G` 的门控概率。`candidate_offsets[N_clg+1]` 与来源 `CLG.npz` 完全一致，并同时切分后述两个候选级数组。`predicted_max_iou[N_candidate]` 即 `q_hat_i`，是仅由 `E_i^content` 回归得到、位于 [0,1] 的候选与任一 GT occurrence 的最大 IoU 估计；它用于 `L_blob`，也作为已选候选排序或 top-K 质量评估的连续分数。`selection_logit[N_candidate]` 即 `z_i`，是基于 `E_i^tree` 得到的未归一化结构化选择能量；它只进入 `sum_{i∈S}z_i-lambda_count|S|` 及精确反链 DP，不得解释为概率或候选质量分数。

`selection.npz` 同样保存与来源逐项一致的 `CLG_id[N_clg]`。`CLG_gate_pass[N_clg]` 表示冻结阈值下 `CLG_valid_probability>=tau_G`；门控失败的 CLG 必须对应空选择。`selected_candidate_offsets[N_clg+1]` 切分 `selected_candidate_index[N_selected]`；每个 `selected_candidate_index` 是该 CLG 自身 candidate 区间内的局部下标，绝对候选行号由 `candidate_offsets[g]+selected_candidate_index` 得到，再由该行的 `candidate_node_id` 找到 forest node。每个 CLG 内的 selected index 按来源 candidate 原始顺序保存，不另造 tie-break 排序。门控通过时保存精确 DP 得到的非空预测 MAP 反链，门控失败时保存空集。

时间顺序固定为：先按 validation 总损失选择 Selector BEST；再用该 BEST 为 calibration 清单生成 `scores.npz` 并据此冻结 `tau_G`；随后在冻结阈值下为所需 split 生成 `selection.npz`；只有最终选定的 Selector 方案继续产生 `Selected_Refined_Centered`。上述每一个字段的名称、shape、对齐对象、数值语义、派生关系与使用位置，都必须写进计划正文和 BOX-level 数据契约的 schema 表，不得只留在低权重细节手册或代码注释中。
Reason: `q_hat_i` 回答“这个 blob 本身可能有多好”，`z_i` 回答“在当前树约束下选它有多有利”，而 `CLG_valid_probability` 回答“整个 CLG 是否值得解码”；三者训练来源和消费位置不同，不能共用含糊的 score 名称。显式写出 ragged offsets、局部下标到绝对候选行及 node identity 的恢复路径，可以避免下游把局部 candidate index 错当 forest node ID。先冻结 checkpoint、再校正门控阈值、最后发布选择与 Selected 产物，也防止 calibration 反向参与模型方案或 checkpoint 选择。

Question: 旧版到当前四件套的实质信息审计应恢复哪些有效内容，又应明确不恢复哪些已被后续决定替代或不再被主线消费的内容？
Decision: 恢复三类仍有效但在上一轮重写中静默漏掉的信息。第一，恢复几何与 batch 的冷读硬契约：网格 `origin_xyz` 是物理 BOX 下角点，体素中心为 `origin_xyz+(index_xyz+0.5)*voxel_size_xyz`；训练计划的字段表补回当前 Pocket_Plus 模型实际消费的 `box_shape_zyx`、`atom_coord_centered_world`、`atom_batch_index`、原子 offsets/counts 等，并逐项解释坐标轴、shape、dtype 与派生关系。第二，恢复路径同构验证：同一 resolved crop 在 targets 开/关时全部模型输入逐元素一致；训练、完整图与居中推理的 crop、坐标和 collate 同构；collate、同步增强与真实一步反传等测试细节进入低权重细节手册。第三，恢复不改变科学语义的工程性能提示：按总字节限制的 per-worker PDB 只读资产缓存、有界完整图概率组装队列，以及 Dataset wait/GPU utilization/吞吐/内存/磁盘记录；这些只进入细节手册。

不恢复已经由本轮明确决定替代的 10 Å Dataset 加载后再裁 8 Å、独立 eligibility 目录与排除清单、run/addon/proposal ID、checkpoint hash 与复杂 manifest、`index.npz+part_*`、threshold rank map 和 R/K 映射、旧 Selector baseline/cover latents/旧 2×2 实验矩阵及其已失效文献论证。也不恢复当前主线不消费、只增加通用层次的 `target_available`、`atom_instance_target`、`source_kind/source_key/request_version`；各 role 的必要来源身份直接由其正式 typed schema 表达。四份源文档中只要某条批注或决定在其它文档有同类表意，重写/局部修改时必须同步处理；不得以“批注只落在一份文件”为由保留跨文档矛盾。
Reason: 几何公式、实际模型输入键和模式同构是冷读实现与数值等价的前提，性能提示也仍能直接降低训练/推理等待；它们的缺失属于真正的信息回归。其余旧结构要么已被更简单的固定路径、状态与扫描整数契约取代，要么对应已取消的模型档位或无人消费的泛化字段；复活它们会重新引入本轮专门消除的复杂度。跨文档同步是四件套作为同一 Stage1 契约成立的必要条件。
