# Find 体素分支辅助监督端到端设计

本文记录 Find 网络新增辅助监督的原始意图、已经核实的代码事实、尚未决定的问题和逐项讨论结论。讨论结束后，本文将作为一个端到端主任务的输入；该主任务覆盖标签生产、Pocket_Plus 训练代码、代码快照、测试和服务器训练提交，并由一个受限 subagent 实现对应的推理加载升级。在用户明确确认讨论完成并授权实施以前，本文不是实现命令。

## 原始意图

用户希望在 Find 网络的体素分支增加三组辅助监督，让共享体素特征学习受体结构和配体邻近关系：

1. 蛋白主链原子类别，最初设想为 `CA`、`C`、`N`、`O` 和非蛋白主链原子。
2. 核酸主链原子类别；讨论开始时类别尚未决定，当前已经固定为背景、`P`、`O5'`、`C5'`、`C4'`、`C3'`、`O3'`。
3. 每个受监督体素中心到最近配体原子的距离，用回归损失训练；讨论开始时配体范围、距离范围和有效体素范围尚未决定，当前定义见本文后续决定记录。

这些标签只用于新增辅助预测头及其损失和监控，不作为模型输入，不改变现有 ligand probability、C、P、forest、CLG、Selector、calibration 或正式推理结果的科学语义。新 Find_1 会把 `voxel_final` 从 48 改为 64 通道，因此正式产物读写和 Selector 输入层必须接受由实际模型决定的通道数；这项接口适配不改变特征本身的意义。实现使用独立配置、checkpoint、W&B run 和输出目录，不覆盖已有训练与产物。

最终实施由一个主 AI agent 端到端负责，避免标签契约、Dataset 读取、模型输出、损失函数和服务器训练分别形成不一致的接口：

- 主 agent 负责 AdaLigand 标签生产、Pocket_Plus Dataset 与运行时标签构造、输出头、损失、指标、配置、完整 `src/` 代码快照、测试、两仓库 Git 历史和服务器正式训练提交。
- 一个 subagent 只负责与快照格式对应的推理加载器、64 通道正式产物读写、Selector 可变输入通道适配和专项测试，不独立决定快照目录、模型输出或 Dataset 契约。主 agent 负责审查、合入和最终端到端验收。
- 正式训练必须在推理升级已经合入以后提交，使该训练保存的完整 `src/` 快照同时包含新版推理代码。

A–G 行为等价整理已经在独立工作树中完成，通过最终等价核验并推进 `Learn/CUMULATIVE`。当前主工作区已经切换到更新后的 `Learn/CUMULATIVE`；辅助标签实现直接从整理后的目录结构开始。

## 已经核实的代码事实

- `Data_Preprocessing/Ori_Data/parse/{pdb_id}/receptor_tokens.npz` 已保存逐受体原子对齐的 `coords`、`element`、`res_type`、`is_backbone`、`atom_name`、`res_index`、`chain_index` 和 `feat`。
- 当前解析代码把蛋白的 `N`、`CA`、`C`、`O` 标记为主链原子；这只是已有字段的生成规则，不代表辅助目标必须采用这些类别。
- 当前解析代码把核酸的 `P`、`O5'`、`C5'`、`C4'`、`C3'`、`O3'` 标记为主链原子；第一版核酸辅助头已经决定沿用这六种前景类别。
- 现有 `feat` 是 49 维人工特征；`atom_name`、`res_type` 和 `is_backbone` 没有作为 Find 的辅助监督目标使用。
- `receptor_tokens.npz` 已经保存逐原子对齐的坐标、元素、残基类型、主链标志、原子名称、残基编号和链编号；新增标签不得复制这些字段。它目前没有显式的逐原子聚合物类别，但标准蛋白、RNA 和 DNA 可以由 `res_type` 确定；`UNK` 只能在训练时派生为 `unknown`。
- `labels/{pdb_id}/atom_labels.npz` 已保存每个受体原子到全部已接受配体重原子的 `nearest_dist`，单位 Å；它不是每个体素中心到最近配体原子的距离。
- `occurrences.jsonl` 用 `type_tag` 区分 `small_molecule`、`sugar`、`peptide_like`、`nucleotide_like`、`ion` 和 `other`；当前 `ligand_area.npz` 为其中每个成功配体实例生成区域，`union_mask` 是全部实例区域的并集，没有按 `type_tag` 排除某一类。
- Pocket_Plus `src/datasets/stage1_dataset.py` 当前在线构造 `hardmask` 和二值 `voxel_label`。`hardmask` 表示 core receptor 原子的 home voxel 集合。
- 两个受体原子落入同一体素的情况几乎不会发生。本轮不为它增加检测、统计、屏蔽、报错或优先级逻辑；普通散射留下哪个类别就使用哪个。
- 当前 BOX 起点的选择规则保证每个 `80×80×80` BOX 都完整位于原始密度图内，因此 BOX 中不存在因越界补齐而产生的 padding 体素。
- 当前正式标签没有保存三组新增辅助目标。
- `文档/讨论/配体类型多分类标签与Find最小改造调研.md` 研究的是另一项设计：把现有原子头、受体体素头和配体区域体素头改成背景加五种配体类型的六分类输出。它与本次“新增蛋白主链、核酸主链、配体距离三个辅助目标”不是同一件事，本轮已经明确不纳入。
- Pocket_Plus `src/model/stage1_voxel_backbone.py` 当前构造两个最高分辨率体素头：`voxel_aux_head` 预测受体结合区域，`voxel_ligand_head` 预测配体区域。两者都是“配置指定数量的 `3×3×3 Conv3d + ReLU`，最后接 `1×1×1 Conv3d`”；当前正式配置各使用一层 `3×3×3` 隐藏卷积。
- 同通道数下，`3×3×3` 相对 `1×1×1` 的参数量与乘加量是 27 倍；两者的输出激活形状相同，因此不能把 27 倍直接解释为固定的峰值显存倍数。尽管如此，最高分辨率 `80³` 特征上的 `3×3×3` 隐藏卷积仍带来明显且没有必要的计算和卷积工作区成本。
- 当前单通道 sigmoid 头已经分别支持 `prior_prob_voxel_receptor` 与 `prior_prob_voxel_ligand`；多通道 softmax 路径却把同一组 `prior_probs` 同时用于两个体素头，尚不支持每个新增头独立配置先验。
- `src/train.py::_load_model_only_checkpoint` 使用 `load_state_dict(..., strict=True)`。把现有体素头的 `3×3×3` 权重改成 `1×1×1`，或新增输出头，都会使旧 checkpoint 直接加载失败；兼容方式必须显式决定，不能依赖当前加载器自动处理。
- 当前 `AdaptiveClassificationCompositeLoss` 的多分类路径已经实现 softmax Focal 与前景 Tversky 的组合：Focal 在全部有效体素上求平均；Tversky 排除背景类别并在各前景类别之间求平均；`tversky_alpha=tversky_beta=0.5` 时就是 Dice。现有正式损失配置已经普遍采用 `w_focal=0.7`、`w_tversky=0.3` 和 `focal_gamma=2.0`。
- 当前 `stage1_unet_c1` 配置使用 `voxel_ligand_loss_weight=1.0` 和 `voxel_aux_loss_weight=0.1`，即配体区域与受体结合区域为 `10:1`。`stage1_find_cpc1` 还包含权重为 `1.0` 的受体原子损失和权重为 `0.1` 的 P 级配体区域归属损失，因此“主损失”必须点名具体损失，不能把不同现有分支静默合并为一个数值。
- `ligand_dist.npz` 允许保存正无穷，但有限神经网络输出与 MSE 不能直接拟合正无穷。距离 MSE 必须作用于有限训练目标，例如由原始距离即时计算的 `1/(1+distance)`；不同变换会改变损失数值与梯度尺度，因此距离损失外层权重不能脱离训练目标定义单独解释。
- Pocket_Plus 已有 `src/utils/bias_init.py::init_classification_head_bias()`。该函数对单通道头接受一个 sigmoid 初始概率，对多通道头接受一组 softmax 初始概率，并自动找到最后一层卷积或线性层。因此两个结构 softmax 头和单通道反距离头可以直接复用同一个现有函数；反距离头传入 `1/11` 即对应约 10 Å 的初始语义，不需要新增初始化框架。
- Pocket_Plus `src/utils/experiment_manager.py` 会在训练任务创建运行目录时保存 `config.yaml`、`train.yaml`，并把当时的整个 `src/model/` 复制到 `src_snapshot/src/model/`。它没有保存 `src/wrappers/`、`src/datasets/`、`src/modules/`、`src/inference/` 或整套 Python 环境，因此准确名称应是“模型代码快照”，不能解释为“完整训练代码快照”。
- 已在服务器逐项核验当前三项正式训练：Job `321107`、`321540` 和 `321743` 的运行目录都已经存在 `config.yaml`、`train.yaml`、`src_snapshot/src/model/stage1_model.py` 与 `src_snapshot/src/model/stage1_voxel_backbone.py`；对应模型快照分别包含 48 或 49 个文件。因此当前正在训练的 checkpoint 具备模型代码快照，不是只根据本地代码推断。
- Pocket_Plus 的 Stage1 训练不直接读取 `final_keep_list.jsonl`。现有数据链依次为：`final_keep_list.jsonl` 冻结 PDB 划分；`stage1_box_pool.py` 为 train/validation 生成逐 PDB BOX 池；`box_pool/manifest.json` 精确列出训练和验证使用的 PDB 池文件；`validation_selection.npz` 再保存固定验证 BOX 对这些池文件的索引。训练集由 `Stage1TrainingRequestSet` 在每个 epoch 从 `box_pool/train` 中确定当轮 center、bias、context BOX，验证集则展开固定的 `validation_selection.npz`。因此距离图生产失败时只改 `keep_list` 不能改变实际训练样本，必须同时保持 BOX manifest 与验证索引的一致性。
- 当前训练顺序还有两层 epoch 相关随机过程：`Stage1TrainingRequestSet.set_epoch()` 使用 `request_seed` 与 epoch 共同重建具体 BOX 请求，单卡 `SeededEpochRandomSampler` 和多卡 `DistributedSampler` 又使用训练 seed 与 epoch 共同打乱 Dataset 索引。因此若要让每个 epoch 使用完全相同的 BOX 和读取顺序，必须让这两层在固定样本模式下都忽略 epoch；仅让比例选择本身可复现仍然不够。
- 已有 BOX 池可以在不重新计算几何位置的条件下复用。若全部 `ligand_dist.npz` 成功，新的训练直接读取原有 BOX 池；若少量 PDB 确认生产失败，只需派生一套排除这些 PDB 的小型清单和验证索引，逐 PDB BOX NPZ 本身无需重建。原有正式 `keep_list`、PDB 划分、BOX manifest 与 `validation_selection.npz` 不能原地改写，否则当前训练、历史复现和新训练会共享一份被事后改变的样本定义。
- 现有正式 BOX 生产确实属于高成本步骤：已有执行记录显示该阶段使用 32 个进程、约 26 分钟并累计读取约 1.48 TB；最终发布 train 13,715 个 PDB、validation 200 个 PDB 和 29,529 个固定验证 BOX。本轮没有理由因为新增距离标签而重跑这一步。
- Pocket_Plus 当前 `src/inference/checkpoint.py` 会自动寻找 checkpoint 所在运行目录旁的 `config.yaml`，但仍使用工作区当前的 `src/model/` 实例化模型；它没有读取 `src_snapshot/`。旧提交 `857a547` 的 `src/inference/get_pred.py` 曾在实例化模型前把 `src.model` 的导入位置切换到该运行目录的 `src_snapshot/src`，所以恢复“checkpoint 使用自己的模型代码快照”可以集中修改当前 checkpoint 加载器，不需要重写整条推理管线。
- 当前双卡 H100/H200 sbatch 默认把启动时的 Pocket_Plus 仓库复制到任务专属的节点本地目录，Job `321540` 与 `321743` 因而有机会从各自仍在使用的代码副本补齐缺失的 `src/` 文件。Job `321107` 的启动记录则明确把科学源码固定在提交 `de6a89f38e48553edfd440c76bf61823229d9205`。历史快照补齐不得从之后继续变化的 Windows 工作区或服务器共享仓库盲目复制；必须优先读取该 Job 实际执行的代码副本，或由已经记录且可核验的启动提交重建。
- 当前 `Stage1VoxelBackbone` 在最高分辨率体素预测头之前已经进行了大量空间卷积。紧邻 `voxel_final` 输出的路径包含并行的 `3×3×3`、`5×5×5`、`7×7×7` 卷积，拼接后还经过一层 `3×3×3` 卷积；编码和解码路径中也有多层 `3×3×3` 卷积。因此把最终预测头改为两个 `1×1×1` 卷积不会让每个体素只看到自身输入，空间信息已经由体素主干混合。
- `src/artifacts/io.py`、`src/inference/centered.py` 和 `src/selector/model/input_fusion.py` 当前分别把正式 `voxel_final` 产物及 Selector 输入写死为 48 通道。当前尚未训练任何 Selector，因此本轮无需兼容既有 Selector 权重；正式读写代码应按实际模型通道数检查数组，Selector 的第一层投影可以使用 `nn.LazyLinear` 在第一次接收 `voxel_final` 时确定输入通道数。
- 当前 Find_1 是 CPC1→CPC2 两段训练。CPC2 严格加载同名 CPC1 的最佳 checkpoint，冻结体素主干等模块，并把现有两个体素损失的权重设为零；因此新增辅助监督的主要训练阶段是 CPC1。

## 模型改造提案

以下内容与标签生产一起由同一个端到端主任务实施；讨论阶段先固定科学语义和接口，尚未得到最终实施许可：

- 第一版固定建立两个结构分类 softmax 头，不提供任意属性规则、动态头数量或 `class_id` 配置。标签构造代码直接生成蛋白和核酸两张固定标签，类别顺序只在一个权威位置定义。蛋白头固定为背景、`N`、`CA`、`C`、`O` 五个通道；核酸头固定为背景、`P`、`O5'`、`C5'`、`C4'`、`C3'`、`O3'` 七个通道。两个头彼此独立，因此不会在模型结构上强制“同一体素不能同时预测为蛋白和核酸”，但训练标签中的蛋白与核酸目标保持分离。
- 现有受体结合区域头、现有配体区域头以及新增的蛋白、核酸和配体反距离头统一为逐体素两层 MLP：`1×1×1 Conv3d(C,C) -> ReLU -> 1×1×1 Conv3d(C,C_out)`。`C` 直接取 `voxel_final` 的通道数，不新增隐藏宽度或卷积层数配置；本轮新 Find_1 的 `C=64`。距离头最后输出一个 logit，计算 MSE 前再经过 sigmoid。
- RAUNet 的多尺度输出块新增 `enable_multiscale_output` 开关。Python 构造函数缺省为开启，使没有该字段的旧配置仍申请并运行 `3×3×3`、`5×5×5`、`7×7×7` 三个并行卷积及拼接后的 `3×3×3` 卷积；本轮新增的 Find_1 实验以及以后新建的实验配置显式关闭。关闭时这些多尺度卷积不得申请参数或参与运算，直接令 `voxel_final=c0`，并把新配置的 `feature_channels` 从 48 改为 64；不增加 64→48 投影，也不在新版代码中兼容旧的 48 通道接口。
- 每个头需要独立的输出初始化。现有配体区域与受体结合区域头沿用当前先验；蛋白与核酸 softmax 分别令每个非背景类别的先验概率为 `0.01`，背景类别先验为 `1-0.01K`，其中 `K` 是该头固定的非背景类别数。距离头经过 sigmoid 输出 `[0,1]`，传入初始概率 `1/11` 表示约 10 Å。三个新头统一调用现有 `init_classification_head_bias()`；若实际接线无法直接复用该函数，取消距离头的特殊初始化，不新增另一套初始化机制。
- 配体距离训练目标固定为 $t=1/(1+d/(1\,\text{Å}))$，其中 $d$ 是从 `ligand_dist.npz` 读取并转为计算精度的原始欧氏距离。MSE 在完整 `80³` 网格上求平均；正无穷距离转换为目标 `0`，不截断、不增加有效掩码，也不排除无配体样本。
- 蛋白与核酸分类损失统一使用 `0.7×Focal + 0.3×Dice`，Focal 的 `gamma=2`，`focal_alpha=None`，即所有类别的 Focal 权重均为 1。Focal 对小批次内全部 `B×80³` 个体素取平均。Dice 对每个固定前景类别分别执行一次“一对其余类别”计算：在全部 `B×80³` 个体素上汇总真阳性、假阳性和假阴性，再对全部固定前景类别等权平均；背景不单独计算 Dice。即使某个前景类别在当前小批次不存在，该类别仍纳入 Dice，并通过假阳性项惩罚错误预测出的前景概率。配体反距离 MSE 同样对全部 `B×80³` 个预测值取平均。
- 总损失比例确定为“配体区域硬分类 : 受体结合区域 : 配体反距离 MSE : 蛋白原子 : 核酸原子 = `10:1:2:1:1`”，配置权重写为 `1.0:0.1:0.2:0.1:0.1`，从而保留当前配体区域主损失的梯度尺度和学习率含义。该比例是首轮固定起点；实现只需使用已有的逐分支损失日志核对数值，不为自动调权增加复杂机制。
- 新增监控保持克制：W&B 只增加配体反距离、蛋白原子和核酸原子三条组合损失曲线。验证阶段为蛋白头和核酸头各记录一个 PR-AUC 标量：排除背景类别，分别计算各非背景类别的 one-vs-rest PR-AUC，再对验证集中存在正样本的类别等权平均。训练阶段不计算 PR-AUC，也不记录逐原子类别 PR-AUC。距离回归不增加得分；不单独记录 Focal、Dice 等内部分项，不新增图像、直方图或本地诊断产物。
- 除新增可关闭的 RAUNet 多尺度输出块外，不改变编码器、解码器、循环精化、已有候选生成语义或正式推理输出。
- 旧 checkpoint 由各自运行目录中的模型代码快照实例化和推理；新版模型代码不保留旧体素头、旧体素主干或其他旧结构的兼容分支。该决定解决历史 checkpoint 的推理，不自动决定新训练是否选择性迁移旧 checkpoint 中未改变的权重。

### 代码快照、推理加载与未来体素主干替换

- 主 agent 把训练代码快照从 `src/model/` 扩大为完整 `src/`，保存 resolved 配置和来源清单，并保证恢复训练不会静默覆盖已有快照。subagent 根据该固定格式升级推理加载器，使 checkpoint 优先使用自身快照、相邻配置和严格权重加载。
- 正式 `voxel_final` 产物不再以 48 作为全项目常量。产物写入和读取代码从实际模型配置或数组形状取得通道数，并核对同一文件中的数组一致性；Selector 的基础投影使用惰性线性层，在第一次接收 `voxel_final` 时确定输入通道数。由于当前没有已训练 Selector，本轮不建设旧 Selector 权重兼容分支。
- 模型快照导入会改变当前 Python 进程中的模块状态。简单且可靠的使用边界是一个推理进程只加载一套模型快照；若同一进程连续加载来自不同运行目录的 checkpoint，需要另行实现进程隔离或更严格的模块卸载，不能把它当作本轮的免费能力。
- 当前模型快照只覆盖 `src/model/`。只要体素头或体素主干的改动留在该目录，并保持当前 wrapper 调用接口、输出字段和配置实例化方式兼容，旧 checkpoint 可以由自己的快照推理。若 Dataset 字段、wrapper 构造参数、损失或推理调度也随版本改变，现有模型快照不足以复原整条历史运行链路。
- 已有 `src/selector/model/density_munet_lite.py::DensityMUNetLite` 是 Selector 使用的网络，不是 Stage1 体素主干的直接替代项。它当前只接收单通道密度并返回一张特征图；Stage1 还要求可配置输入通道、`voxel_final` 特征登记、体素预测输出、循环精化输入与输出等接口。因此以后采用 MUNet 时，合理工作是复用其计算主体并增加 Stage1 适配层，工作量属于中等，不是只改一个 `_target_`，也不需要重写整个 Find 网络。若直接继续从 `src/selector/model/` 导入它，当前模型快照不会保存该文件；应把 Stage1 使用的实现放入 `src/model/`，或另行扩大快照范围。

## 决定记录

Question: Focal、Dice 和配体反距离 MSE 分别怎样归约为标量损失？
Decision: Focal 对小批次内全部 `B×80³` 个体素取平均。Dice 把每个固定前景类别分别视为唯一正类，把背景和其他前景类别视为负类，在全部 `B×80³` 个体素上汇总真阳性、假阳性和假阴性，计算该类别的 Dice 损失，再对全部固定前景类别等权平均；背景不单独计算 Dice，当前小批次没有目标原子的固定前景类别仍参与平均。配体反距离 MSE 对全部 `B×80³` 个预测值取平均。三种损失均不以未归一化求和作为最终标量。
Reason: 这种归约保持现有多分类损失语义，并使损失尺度不随小批次体素总数线性增大。Dice 是基于整个小批次重叠量的类别宏平均，不应在计算类别 Dice 后再次除以体素数量。

Question: 当前小批次没有某个前景类别的目标原子时，Dice 是否仍计算该类别？
Decision: 是。Dice 始终计算分类头的全部固定前景类别；某个类别没有目标原子时，其真阳性和假阴性均为零，错误预测出的前景概率仍作为假阳性受到惩罚。验证 PR-AUC 仍跳过没有正样本的类别。
Reason: 没有目标原子的样本仍提供“该分类头应预测背景”的有效监督。沿用现有 `AdaptiveClassificationCompositeLoss` 的归约方式还可以避免增加空类别开关和专项分支。

Question: 第一轮蛋白与核酸分类头是否需要使用 Focal 的逐类别 `alpha` 权重？
Decision: 不需要。两个分类头均设置 `focal_alpha=None`，即背景和每个前景类别的 Focal 权重都为 1；第一轮不使用按类别频率计算的权重。
Reason: `gamma=2` 已经抑制容易判断的背景体素，输出初始化也把每个前景类别的初始概率设为 `0.01`。在没有本任务类别统计的情况下再叠加逐类别权重，会引入无法验证的第二重不平衡校正。

Question: 第一版核酸 softmax 使用哪些固定类别？
Decision: 类别顺序固定为背景、`P`、`O5'`、`C5'`、`C4'`、`C3'`、`O3'`。RNA 与 DNA 共用这些类别；`OP1`、`OP2`、`C1'`、`C2'`、`O2'`、`O4'`、碱基原子、修饰或未知残基原子、蛋白原子和空体素均归入核酸头的背景。
Reason: 这六种前景原子沿用当前解析代码已经采用的核酸主链定义，每个类别对应一个明确且互斥的原子名称，不需要扩大标签定义或增加动态类别机制。

Question: 三个新增头是否需要分别建设初始化机制？
Decision: 不需要。蛋白、核酸和反距离头统一复用现有 `src/utils/bias_init.py::init_classification_head_bias()`。蛋白与核酸传入 softmax 类别先验；反距离头传入 `1/11`，表示约 10 Å 的初始语义。若实际接线不能直接复用该函数，放弃反距离头的特殊初始化，不新增第二套初始化机制。
Reason: 现有函数已经同时实现单通道 sigmoid 和多通道 softmax 的 bias 换算。直接复用不会增加抽象层；为一个辅助回归头再设计初始化接口不符合本次最小改动原则。

Question: 第一版蛋白 softmax 使用哪些固定类别？
Decision: 类别顺序固定为背景、蛋白主链 `N`、`CA`、`C`、`O`。匹配蛋白标准残基中对应的主链原子；蛋白侧链、核酸原子、未知聚合物和空体素归入该头的背景。
Reason: 这四种原子具有明确且互斥的名称，可以提供比只预测 Cα 更完整的蛋白主链监督；类别只属于首轮固定训练任务，不要求建设通用规则系统。

Question: `ligand_dist.npz` 的原始距离怎样用于训练？
Decision: 磁盘继续保存 float16 原始 Å 距离。Dataset 读取后按 $t=1/(1+d/(1\,\text{Å}))$ 构造有限目标；距离头经过 sigmoid 输出 `[0,1]`，在完整 `80³` 网格上计算平均 MSE。正无穷转换为 `0`，不截断距离、不增加掩码，也不排除没有配体原子的样本。
Reason: 原始距离是稳定、可复用的事实标签，但有限网络输出和 MSE 无法直接拟合正无穷。反距离变换保留距离顺序，把配体附近映射到较大数值、远处映射到接近零，并让无配体样本得到全零有限目标。

Question: 新增三项辅助监督使用什么权重和监控？
Decision: 以现有 `voxel_ligand` 配体区域硬分类损失为主损失，总损失权重按“配体区域硬分类 : 受体结合区域 : 配体反距离 MSE : 蛋白原子 : 核酸原子 = `1.0:0.1:0.2:0.1:0.1`”配置。W&B 只新增三项组合损失曲线。蛋白和核酸分类各自在验证阶段记录一个排除背景、只平均存在正样本类别的宏平均 PR-AUC；不计算训练 PR-AUC，也不记录逐类别曲线。距离回归不增加得分，也不增加内部分项、图像、直方图或本地诊断产物。
Reason: `1.0:0.1` 沿用当前配体区域与受体结合区域的相对尺度，距离 MSE 提高到 `0.2`，两个结构分类头各为 `0.1`。只记录直接回答训练是否正常和原子定位是否改善的标量，可以限制实现改动和 W&B 面板数量。

Question: 标签、训练代码、代码快照和推理升级由几个任务负责？
Decision: 一个主 AI agent 端到端负责 AdaLigand 标签生产、Pocket_Plus Dataset 与运行时标签构造、输出头、损失、指标、配置、完整 `src/` 代码快照、测试、两仓库 Git 历史和服务器正式训练提交。推理加载器升级作为边界明确的 subagent 任务：subagent 只读取主 agent 固定的快照格式并修改推理加载与专项测试；主 agent 负责接口决定、审查、合入和最终验收。正式训练必须等推理升级合入后再提交。
Reason: 标签、训练代码和快照写入共同决定新 checkpoint 的结构与可复现范围，需要由一个责任主体贯通。推理加载器具有明确输入和输出，可以独立实现，但不能反向决定快照格式或模型契约。让 subagent 隶属于同一主任务，可以并行处理代码，同时保留唯一的集成责任。

Question: 历史 checkpoint 与新版模型代码如何共存？
Decision: checkpoint 存在相邻 `src_snapshot/src/model/` 时，推理必须使用该模型代码快照；缺少快照时默认明确报错，只有用户显式指定后才允许尝试当前模型代码。一个推理进程只加载一套模型代码快照。旧 checkpoint 由各自快照继续推理；新版模型代码不保留旧体素头、旧体素主干或其他旧结构的兼容分支。
Reason: 历史模型的结构事实已经保存在各自运行目录中，应由对应快照负责复原。把全部旧结构继续保留在新版代码中会扩大每次重构的修改面和测试组合，也无法解决 Dataset、wrapper 或推理步骤发生变化时的完整复现问题。模型快照推理与新训练是否迁移旧权重是两个独立问题，后者仍需单独决定。

Question: 辅助标签工作是否必须等待 A–G 整理稳定文件接口后才开始？
Decision: 否。辅助标签现在可以在独立工作树和独立目录中实现、测试并运行；A–G 与辅助标签最终按先 A–G、后辅助标签的顺序进入 `Learn/CUMULATIVE`。辅助标签最终代码按 A–G 整理后的目录重新落位，可能发生的文件移动冲突属于收口成本，不构成启动阻塞。
Reason: 两项工作的运行目录、分支、配置和产物可以隔离；标签的科学定义与测试可以先行稳定。Git 只要求最终累计分支一次接纳一个经过核验的端点，并不要求所有实现活动串行进行。

Question: 第一轮辅助标签实现是否同时包含已有调研中的六分类配体类型标签？
Decision: 否。第一轮只处理蛋白主链原子类别、核酸主链原子类别和体素中心到最近配体原子的距离；六分类配体类型标签作为独立未来任务，不进入本轮标签文件、实现分支或验收范围。
Reason: 六分类设计会改变现有原子头、受体体素头、配体区域体素头、P 监督和推理适配，超出三个新增辅助头且不改变现有推理行为的目标。

Question: 蛋白和核酸主链辅助标签是否在完整 80×80×80 网格上把空体素当作负样本？
Decision: 是。蛋白和核酸辅助任务用于从完整密度图定位具有明确结构意义的原子或区域；默认在 BOX 的全部 `80³` 个体素上计算监督，目标之外的体素作为负样本。此前的“只监督 home voxel”决定已经撤回。独立 Cα 实验不属于当前项目，因此不要求先在当前仓库中找到或复现它。
Reason: 既有独立实验表明直接预测 Cα 体素曾取得超过 80% 的 precision 和 recall，说明完整网格监督可以工作；只监督受体原子 home voxel 会把“定位原子”改成“在已知原子位置判断类别”。当前 BOX 又始终完整位于原始密度图内，不存在需要排除的越界补齐体素。

Question: 蛋白辅助标签是否已经确定为 `CA/C/N/O/非主链`，核酸标签是否已经确定为对应类别？
Decision: 已确定。蛋白头固定为背景、`N`、`CA`、`C`、`O`，不设置“非主链”前景类别；核酸头固定为背景、`P`、`O5'`、`C5'`、`C4'`、`C3'`、`O3'`。已知多种蛋白和核酸主链原子可以被模型有效定位，不要求每种原子重新证明“值得预测”。

Question: 蛋白辅助监督是否可以写死为只预测 Cα？
Decision: 不可以。蛋白和核酸的其他主链原子分别进行二分类空间定位时也已有较高正确率。第一版蛋白头固定同时预测 `N`、`CA`、`C`、`O`，不提供按运行选择其中一部分的配置。
Reason: 本任务不是复刻单个 Cα 实验。固定预测四种蛋白主链原子既覆盖预期用途，也避免为首轮实现增加动态类别机制。

Question: 蛋白和核酸原子定位应使用独立 sigmoid 二分类，还是使用包含背景的 softmax？
Decision: 使用两个固定且彼此独立的 softmax：一个预测蛋白背景或固定蛋白原子类别，另一个预测核酸背景或固定核酸原子类别。此前以体素碰撞为主要理由推荐 sigmoid 不成立。
Reason: 每个头内部的类别互斥，softmax 可以直接表达这一点；蛋白和核酸使用两个头，则不需要把两种聚合物的类别塞进一个大 softmax，也不需要动态类别配置。

Question: 蛋白和核酸的网格标签是否作为固定稠密数组落盘？
Decision: 不这样做，也不新增逐原子标签文件。训练时读取现有逐原子坐标和属性，依据两个固定分类头的类别表，把目标类别散射到当前 BOX 的 `80³` 网格。类别表和类别顺序只在一个权威代码位置定义，并随完整 `src/` 快照保存。
Reason: 现有逐原子事实已经足够，运行时散射无需重跑或复制整套标签。首轮目标集合固定，因此不需要用训练配置承担类别规则。

Question: 训练配置如何把受体原子属性映射为 softmax 类别？
Decision: 第一版不通过训练配置映射类别，也不提供 `class_id`。代码固定构造蛋白和核酸两张标签；每个头的类别顺序及原子属性匹配只在一个权威代码位置定义。未匹配固定类别的原子和空体素映射到该头的背景类别 0。
Reason: 任意属性规则会把小范围辅助监督改造成动态标签框架，并迫使 Dataset、模型、损失、指标和配置共同处理可变类别。首轮类别已经固定，直接实现更小、更容易核验；以后改变类别时修改代码并由新的完整快照保存版本。

Question: 两个不同受体原子极少数情况下散射到同一体素时是否需要特殊处理？
Decision: 不需要。实现不为这种情况增加检测、统计、`ignore_index`、报错或类别优先级；使用普通散射自然得到的结果即可，先写入或后写入的类别均可接受。
Reason: 这种情况几乎不会发生，对训练的影响可以忽略；为它增加独立契约和分支代码的复杂度高于实际收益。

Question: 标签构造器是否必须在第一版支持配置调用任意次数？
Decision: 不需要。第一版固定构造蛋白和核酸两张分类标签，并固定连接两个 softmax 头；不接受配置调用任意次数，也不支持动态头数量。
Reason: 两个固定目标已经覆盖本轮需求。删除动态装配可以显著减少 Dataset、模型、损失、指标和配置的共同改动；以后若需求改变，再修改代码并生成新的完整快照。

Question: 为蛋白和核酸原子定位是否必须新增 `polymer_type` 或复制现有原子字段？
Decision: 当前不需要。坐标、元素、`res_type`、`is_backbone` 和 `atom_name` 已经足以构造第一版目标；标准残基的 `polymer_type` 在训练时由 `res_type` 派生，`UNK` 派生为 `unknown`。不复制现有字段，也不为尚未证明重要的极少数未知残基重跑正式数据管线。
Reason: 这使改动集中在运行时标签构造和训练配置，启动快、与 A–G 重构冲突小。若代表性统计或训练误差以后证明 `UNK` 不能忽略，再根据证据增加来源更可靠的聚合物字段。

Question: 配体距离是否按 BOX 实时计算，还是保存完整密度网格上的距离场？
Decision: 保存完整距离场。每个 PDB 生成一张与重采样实验密度图空间网格完全对齐的 `float16` 距离标签；训练时裁切 BOX。该文件作为独立派生产物生成，不修改已经核验的 A–G 正式文件。
Reason: 距离的科学定义覆盖完整密度图；全图一次生成后可以被重叠 BOX、多个训练周期和多次实验反复使用，避免重复查询全部配体原子。`float16` 的原始数组体量是同形状 `float32` 实验密度数组的一半。

Question: `ligand_dist.npz` 的最近配体原子集合包含哪些原子？
Decision: 纳入 `occurrences.jsonl` 中全部成功配体实例，不按 `type_tag` 排除 `small_molecule`、`sugar`、`peptide_like`、`nucleotide_like`、`ion` 或 `other`；每个实例只使用 `present_{cid}=True` 的实际重原子。缺失坐标的模板原子不参与计算。文件名固定为 `density/{pdb_id}/ligand_dist.npz`。
Reason: 现有 `ligand_area.npz` 为每个成功配体实例生成区域，Stage D 也使用全部实际存在的配体重原子。新距离场沿用同一集合，可以避免同一体素在配体区域标签中属于配体、在距离标签中却被视为没有配体。

Question: `ligand_dist.npz` 是否在落盘前截断或变换距离？
Decision: 不截断、不归一化，也不进行对数等变换。文件保存每个体素中心到最近目标配体重原子的原始欧氏距离，单位 Å，数组类型为 `float16`。训练需要的上限、归一化或变换由训练配置和 Dataset 在读取后完成。
Reason: 原始距离是稳定、可解释且可复用的事实标签。把训练表达写入磁盘会使每次调整损失尺度都需要重新生成全套距离图，也无法从截断结果恢复远处体素的真实距离。

Question: `ligand_dist.npz` 的主数组使用什么名称和形状？
Decision: 主数组命名为 `distance`，类型为 `float16`，形状为 `(1,Z,Y,X)`；空间轴顺序及长度与同一 PDB 的 `exp.npz.grid` 完全相同。
Reason: `distance` 比泛称 `grid` 更直接地说明数组内容；保留单通道维度则与现有 `exp.npz.grid`、`sim.npz.grid` 和 `ligand_area.npz.union_mask` 一致，Dataset 可以使用相同的 BOX 裁切方式。

Question: `ligand_dist.npz` 如何记录生成它的来源？
Decision: 保存 `source_exp_identity_sha256`、`source_occurrences_sha256` 和 `source_ligand_coords_sha256`。第一个字段复用现有 `experimental_density_identity`，覆盖实验网格形状、体素尺寸、原点和重采样规则；后两个字段分别是 `occurrences.jsonl` 与 `ligand_coords.npz` 的文件 SHA-256。`ligand_objects` 和实验密度数值不进入距离标签的来源摘要。
Reason: 距离只由网格几何、成功配体实例集合以及实际配体坐标决定。保存三个独立摘要既能指出具体变化来源，也不会让与计算无关的文件变化触发整套距离图重建。

Question: `ligand_dist.npz` 是否保存完整的空间定义？
Decision: 是。文件保存 `grid_shape_zyx`、`voxel_size_xyz`、`origin_xyz`、`origin_semantics="pocket_plus_corner"`、`voxel_center_offset_xyz=[0.5,0.5,0.5]`、`voxel_center_formula="origin_xyz+(index_xyz+0.5)*voxel_size_xyz"`、`distance_unit="angstrom"` 和 `schema_version`。
Reason: 这些字段复用 `ligand_area.npz` 已有的坐标定义。即使文件离开生成代码，读者和 validator 仍能明确数组轴顺序、世界坐标原点、体素中心位置和距离单位，不需要从其他文件猜测。

Question: 某个 PDB 没有任何 `present=True` 的配体重原子时，是否省略 `ligand_dist.npz`？
Decision: 否。文件仍须生成，`distance` 的全部体素写成 `float16` 正无穷。此前“不生成文件并排除整个 PDB”的建议已经撤回。
Reason: 没有配体不会使同一 PDB 的蛋白或核酸结构监督失效。正无穷还是可变换的标签事实，例如反距离变换 `1/(1+distance)` 会得到全 0 的有限目标，因此不应在数据契约中规定必须屏蔽这些体素。

Question: 当前 `main@817940a` 的未提交修改如何随主工作区切换到新的 `Learn/CUMULATIVE`，且不产生额外残留？
Decision: 不整体提交，不创建备份分支或 stash。先移除已经确认干净、仅占用 `Learn/CUMULATIVE` 的辅助工作树，再在主工作区执行三方合并切换。切换已完成：主工作区现在位于 `Learn/CUMULATIVE@799293c`；共同的 `AGENTS.md` 和删除 `CLAUDE.md` 已变为干净状态，独有的讨论文档、W&B 同步脚本和服务器 README 新增说明仍保留为未提交修改。
Reason: Git 可以在切换分支时把当前未提交修改与目标分支进行三方合并。这里没有路径冲突，因此无需制造临时分支或副本；A–G 的新目录和 README 修改也没有被旧版本覆盖。

Question: 新训练读取到缺失、来源摘要过期或契约不合法的 `ligand_dist.npz` 时是否允许回退？
Decision: 不允许。对最终训练和验证清单中的全部 PDB 先做集中检查，任何缺失、过期或契约错误都直接终止；Dataset 读取时再做必要的轻量检查。不在线计算距离、不制造零值或正无穷替代文件，也不在训练中静默跳过样本。若标签生产阶段有最终失败 PDB，必须在训练开始前通过一份明确且可审计的样本清单处理，不能把处理逻辑藏在 Dataset 的异常分支中。
Reason: 训练时回退会让同一配置在不同文件状态下使用不同监督目标，而且多进程 DataLoader 中的即时修复或跳过难以复现。把失败处理提前到清单冻结阶段，可以保证一旦训练开始，每个保留样本都具备同一标签契约。

Question: `box_sample_fraction` 是否改变比例为 `1.0` 时的现有逐 epoch BOX 重选和训练乱序行为？
Decision: 不改变。省略配置或取值 `1.0` 时，训练 BOX 继续由 `request_seed + epoch` 动态确定，训练读取顺序继续由 `train_seed + epoch` 决定。只有比例小于 `1.0` 时，才从完整 BOX 来源一次性生成并保存固定训练与验证 BOX 清单；后续所有 epoch 读取同一组具体 BOX，但训练 DataLoader 仍按 `train_seed + epoch` 对固定集合重新排列。若同一比例、seed 和来源身份对应的冻结清单已经存在，则直接复用。
Reason: `box_sample_fraction<1.0` 用于一次消融试跑，需要定义一份固定且可重复使用的缩小数据集；默认值则必须保持正式训练已经验证过的动态 BOX 多样性与逐 epoch 乱序，不能让新增开关在未配置时改变既有行为。

Question: 比例小于 `1.0` 时，缩小后的 BOX 数量以原始 BOX 池还是正常训练请求序列为分母，并使用哪个 epoch 生成该序列？
Decision: 以正常训练请求序列为唯一分母，并固定使用 `epoch=0`。生成冻结清单时，先让现有 `Stage1TrainingRequestSet` 按 `request_seed + epoch=0` 完成 occurrence 上限、每个 occurrence 的 1 个 center、5 个 bias 和 3 个 context 选择，得到与 `box_sample_fraction=1.0` 在该 epoch 对应的正常训练请求数；缩小后的目标数量再由该请求数乘 `box_sample_fraction` 得到。不得直接对保存全部候选的原始 BOX 池取比例。
Reason: 原始 BOX 池包含每个 occurrence 的 30 个 bias 候选和数量更大的 context 候选，它的规模远大于单个正常训练 epoch 实际读取的请求数。直接以原始池为分母会使 `box_sample_fraction<1.0` 生成的样本数反而可能超过正常的 `1.0` 训练，违背比例开关的直观含义。固定 `epoch=0` 还保证首次训练、恢复训练和重复生成得到同一基准请求序列。

Question: 缩小正常请求序列时，怎样同时保证目标总数准确并尽量保持 center、bias、context 的组成？
Decision: 目标总数取 `floor(box_sample_fraction × 正常请求总数)`，保证缩小后的 BOX 数不超过指定比例。先统计 epoch 0 正常请求序列中 center、bias、context 的实际数量，再按照三类实际占比分配目标总数：分别向下取整后，把尚未分配的少量名额依次给小数余数最大的类别。随后在每个类别内部使用由 `request_seed` 派生的稳定随机流无放回选择。最终 BOX 总数严格等于目标总数，三类组成在整数条件下最接近正常请求序列。
Reason: 现有语义通常产生接近 `1:5:3` 的组成，但极少数 PDB 可能没有可用 context，不能为了凑理想比例凭空增加 BOX。按正常请求的实际组成分配，既保留训练任务比例，又能精确控制消融试跑的总样本数。

Question: 比例小于 `1.0` 的冻结 BOX 清单是否需要建设独立目录和通用缓存管理？
Decision: 不需要。直接在现有 `box_pool` 中保存 `train_selection_<比例>_seed<request_seed>.npz` 和 `validation_selection_<比例>_seed<request_seed>.npz`。两份文件沿用现有冻结请求字段，并只增加比例、`request_seed`、固定 `selection_epoch=0`、来源摘要和契约版本等最少复用检查字段；验证文件再记录原始验证清单摘要。存在且字段匹配时复用，损坏或不匹配时报错；生成时使用临时文件加原子改名。
Reason: 本轮主线是增加辅助标签、辅助预测头和损失并启动训练，比例开关只服务少数消融试跑。为少数 `0.1`、`0.3` 等取值增加目录包、JSON 元数据、完成标记和缓存注册机制会扩大修改范围，却不增加本轮必要能力。

Question: `box_sample_fraction=1.0` 时是否仍执行一次比例选择并保存训练 BOX 清单？
Decision: 否。省略该字段或取值为 `1.0` 时完全不进入比例选择和冻结清单落盘代码，训练继续在每个 epoch 按现有规则确定 BOX；只有取值小于 `1.0` 时才生成或复用带比例与 seed 的训练、验证 NPZ。
Reason: `1.0` 表示沿用正式训练行为，不是创建一份包含全部请求的冻结数据集。

Question: 首次新 Find_1 使用什么 `box_sample_fraction`？
Decision: 使用 `1.0`。训练集在每个 epoch 继续选择不同 BOX，不生成带比例的冻结清单；验证集继续使用现有固定验证选择。

Question: 新版最高分辨率体素预测头采用什么固定结构？
Decision: 现有受体结合区域头、现有配体区域头以及新增蛋白、核酸和配体反距离头统一使用 `1×1×1 Conv3d(C,C) -> ReLU -> 1×1×1 Conv3d(C,C_out)`；`C` 为 `voxel_final` 通道数，不新增隐藏宽度或卷积层数配置。距离头输出 logit，计算 MSE 前经过 sigmoid。
Reason: 五个头共享一个很小的构造函数即可，同时删除最高分辨率特征上的可配置大卷积，不为本轮引入动态头框架。

Question: 新 Find_1 是否从旧 checkpoint 选择性加载未改变的主干权重？
Decision: 否。新 Find_1 从头训练，不新增部分权重迁移机制；旧 checkpoint 继续由各自代码快照推理。
Reason: 选择性加载需要额外定义允许缺失和允许改变的参数集合，而且会把“从已有模型继续训练”与本轮架构和辅助监督改动混在一起。

Question: 距离图生产最终仍有失败 PDB 时如何处理？
Decision: 先断点续跑并重试。最终失败数为零时不增加过滤行为；仍有失败时写出 `ligand_dist_failures.json`，在建立训练和验证 Dataset 前按其中的 PDB ID 排除样本，随后再进行可能的比例选择。正式 keep list、BOX manifest、验证选择文件和逐 PDB BOX 文件保持不变。
Reason: 训练实际读取 BOX manifest 与验证选择，单独改 keep list 不会改变样本；原地改写正式文件又会影响正在运行的任务和历史复现。

Question: 辅助监督实现需要哪些最小验收与统计？
Decision: 用纯蛋白、纯核酸、蛋白—核酸混合物、修饰或未知残基、没有目标配体和可直接核对最近距离的普通配体样本验证标签；运行 Dataset 小批次及一次完整前向—反向测试。标签生产只报告生成、复用、失败和没有实际配体原子的 PDB 数量，代表性样本记录各固定前景类别的目标体素数量；不建设额外统计或 W&B 面板。

Question: 推理 subagent 是否补齐当前三个正式训练的完整 `src/` 快照？
Decision: 是。只处理 Job `321107`、`321540`、`321743`，只从各 Job 的实际代码副本或可证明的启动提交向相应 `src_snapshot/src/` 增加缺失文件，不覆盖已有运行产物，并保存来源与 SHA-256 清单；准确来源不可得或已有文件不一致时停止相应 Job 的补齐。

Question: RAUNet 末端多尺度输出块是否继续固定存在？
Decision: 不固定存在。新增 `enable_multiscale_output` 开关，Python 构造函数缺省开启，本轮 Find_1 及以后新实验显式关闭；关闭时不得申请或运行三个并行空间卷积及拼接后的空间卷积，直接令 `voxel_final=c0`。本轮新配置把 `feature_channels` 改为 64，不建立 64→48 投影。
Reason: 这些卷积位于 `80³` 最高分辨率上，尤其是 `5×5×5` 和 `7×7×7` 分支成本很高；体素编码器和解码器此前已经进行了充分的空间信息混合。

Question: 首次新 Find_1 使用哪项 GPU allocation？
Decision: 使用 Job `321540` 当前持有的两张 H100，不提交其他 GPU 训练作业。正式接管前必须重新核实该 Job 实际运行的是 Find_1；核实无误后用该运行目录自己的 `kill_lock` 终止旧 Find_1 进程，但保留 `after_lock` 和 allocation，再在同一 Job 中启动新 Find_1。任何身份或锁状态不符合预期时停止操作并报告。`ligand_dist.npz` 生产所需的 CPU 作业另受 192 核总上限约束，不属于这里禁止的额外 GPU 训练。
Reason: Slurm 的 `JobName=adaligand_s1_find2_h100x2` 是 allocation 创建时的旧名称；本地执行记录显示该 allocation 后来改为承载 Find_1，因此不能只凭 JobName 决定要终止的进程。

Question: 新 Find_1 启动后采用什么监控节奏？
Decision: 先用短命令检查约十分钟，确认配置、指标、标准错误和 GPU 状态符合预期；随后把现有暂停的 `adaligand-stage1` heartbeat 改为触发当前任务 `019f8834-8b48-7082-a9f0-1a7b86af1f5b`，每 30 分钟检查一次，连续三次无异常后改为每 5 小时一次。heartbeat 只可修复本轮新代码、配置、W&B 与 Job `321540` 内部锁问题；不得改变科学定义、触碰其他 Job、释放 allocation 或提交新作业。新 Find_1 正常结束并记录最终状态后删除 heartbeat。

Question: 关闭多尺度输出后，是否为了保持旧接口增加 64→48 的 `1×1×1 Conv3d`？
Decision: 否。新配置直接把 `voxel_final` 改为 64 通道并令其等于 `c0`，不增加末端投影，也不要求新版代码兼容旧的 48 通道模型结构。

Question: 新 Find_1 使用什么学习率？
Decision: 把 Find_1 CPC1 基线中的 `optimizer.lr` 从 `5e-5` 改为 `1e-4`；其余优化器和学习率调度设置不随本决定改变。

Question: 新 Find_1 真实发生 CUDA 显存不足时按什么顺序调整？
Decision: 先把 `configs/model/sparse_refine/density_cube/both.yaml` 中伪原子和真实原子两个密度立方体编码器的 `hidden_channels` 从 64 改为 48并重新测试；仍然显存不足时才降低单卡 `batch_size`，同时提高梯度累积以保持全局批量不变。不因显存占用百分比高而提前执行这些调整。

Question: W&B 联网失败是否阻止新 Find_1 启动？
Decision: 不阻止。优先尝试把指标写入 W&B 联网服务；联网不可用时允许使用 offline 并完整保留本地日志，后续再同步。显式设置 `WANDB_MODE=online` 不是验收要求。

Question: 本任务怎样保存可跨任务恢复的外置记忆？
Decision: 实施前建立自包含的 ExecPlan，工作中持续维护 Progress、Surprises & Discoveries、Decision Log 和 Outcomes & Retrospective，并更新 `文档/mapping/计划执行映射.md`。阶段暂停或移交时在 `CLAUDE/memory/handoffs/` 新增 handoff，并向 `CLAUDE/memory/projects/adaligand.json` 追加简短进展。删除和停用的只有根目录 `CLAUDE.md`；既有 `CLAUDE/memory/` 全部继续有效，也允许新增。

Question: 新 `voxel_final` 改为 64 通道后，正式产物和 Selector 怎样接入？
Decision: 本轮同步取消正式产物读写、居中推理和 Selector 输入中的固定 48 通道假设。产物代码按模型配置或实际数组形状取得并核对通道数；Selector 的基础投影使用 `nn.LazyLinear`，在第一次接收 `voxel_final` 时确定输入通道数。当前尚未训练任何 Selector，因此不需要兼容旧 Selector 权重，也不增加 64→48 投影。
Reason: `voxel_final` 的通道数是模型结构的一部分，不应成为正式产物和 Selector 中互相复制的常量。惰性线性层能够用很小的修改接受 48、64 或以后其他合法通道数。

Question: 新 Find_1 只运行 CPC1，还是运行完整 CPC1→CPC2？
Decision: 运行完整 CPC1→CPC2。三项新增辅助损失和两个验证 PR-AUC 只在 CPC1 启用；CPC2 严格加载 CPC1 最佳 checkpoint，冻结包含新增输出头在内的体素主干，并把三项新增辅助损失权重设为零。两段最高学习率均为 `1e-4`，CPC2 正常结束并记录状态后才判定新 Find_1 完成。
Reason: 当前 Find_1 的正式训练制度本来就是两段式。辅助监督负责塑造 CPC1 的体素表示，CPC2 保留现有只训练 interaction 与 A/P 尾部的职责，不应让已经冻结的体素头继续影响总损失。

Question: 全量生成 `ligand_dist.npz` 使用什么 CPU 并行与监控边界？
Decision: 同时分配和运行的 CPU 总数不得超过 192。先查看实时空闲节点；96 核整节点不能立即取得时，允许改用每项约 16 核的 Slurm array，并在每项内部使用 joblib loky 并行，设置 array 并发上限保证总申请量不超过 192。必须检查工作进程、CPU 利用率、完成速率和分片进度，证明资源正在有效工作。运行时间较长时使用 heartbeat 定期检查；完成或终止后记录结果并停止该阶段 heartbeat。
Reason: CPU 分区由多个 96 核节点组成，整节点申请容易因少量占用而排队。较小 array 项更容易利用碎片资源，而总并发上限、分片互斥、断点续跑和实际利用率检查可以同时保证资源纪律与生产速度。
