Decision: Find_1、Find_0 和 unet_c1 各自形成一条顶层 producer 训练线；允许一个 sbatch/allocation 直接引导同一 Find 的 CPC1→CPC2，也允许根据现场采用其它正确安排。任务未完成且 allocation 仍可用于运行、修复、重试或后续阶段时，不删除其 after_lock，不 scancel 该作业；需要时可通过 run_cmd、try_lock、kill_lock 等钩子调整命令并复用已排到的资源。只有全部五段训练完成或用户明确指示时，才释放相关 allocation。从执行最终提示词的 agent 开始工作时计时，连续 72 小时内，除非全部任务提前完成或用户明确允许，不得主动休眠、结束任务或设置 heartbeat 形成间接休眠；应持续推进、检查和处理，刚启动时高频检查，稳定后可以降低频率。外部平台中断不改变任务状态，恢复后依据活 ExecPlan 和 handoff 继续。W&B 默认开启；发生错误先尝试恢复或重试，只有反复失败且确实阻断训练时才允许关闭，并记录原因。任务完成必须以数据准备产物可训练、共同 global batch 与显存证据冻结、unet_c1 BEST 可加载、两个 Find 均完成 CPC1→CPC2 且 checkpoint 来源正确、五段配置/日志/停止原因可审计、活 ExecPlan 与最终 handoff 收口为准，不能把“已经提交作业”当作完成。本决定取代此前“训练完成后即可主动删除 after_lock/allocation”的宽泛表述，也以 72 小时持续执行取代原提示词中的健康运行 3 小时后即可休眠。
Reason: 顶层资源目标是三个 producer，而两个 Find 在训练上各含两个顺序阶段；保留已获得的 allocation 并允许动态修改命令，可以避免故障后重新排队。72 小时活跃窗口、W&B 默认开启和以实际产物/checkpoint 为完成依据，可防止 agent 在只完成提交或短时 smoke 后提前退出；外置记忆负责覆盖平台可能发生的外部中断。
