Question: 是否把训练、验证、全图滑窗、F1 居中、CLG 居中和 selected-final 全部收敛到“请求提供者 → 统一 BOX 请求解析与裁剪器 → Stage1BoxDataset → Stage1BatchCollator → 模型 → 用途专属输出端”的唯一生产架构，并禁止第二套推理专用 Dataset、样本字典或 collate？
Decision: 同意。所有 Stage1 forward 共用唯一生产数据路径；不同用途只允许请求来源和输出端不同。旧 Pocket_Plus 推理整体入口不再作为生产入口，只有通过等价性测试的底层几何、密度通道、样本构建或 collate 叶函数可以复用。
Reason: 这样可以把模型直接输入、坐标、边界处理和模态表示的训练—推理一致性变成可测试的硬约束。

Question: 唯一 Stage1 生产管线应由哪个仓库拥有，以及旧 Pocket_Plus Dataset/推理代码如何处理？
Decision: 大部分采用“数据资产与冻结清单由 AdaLigand 管理，模型面对的统一裁剪、Dataset、Collator、训练和推理运行代码由 Pocket_Plus 管理”的分工；但不在生产分支长期保留旧 Dataset/旧推理入口作为只读参照。应在 Pocket_Plus 创建 AdaLigand 项目专用新分支，只维护当前项目需要的代码；完成等价性验证并冻结证据后，可删除旧推理管线等不再需要的代码，由 Git 历史承担备份和回溯。
Reason: 运行代码与模型、训练包装层和配置保持同仓，同时避免新分支长期背负两套 Dataset/推理编排。删除前后必须有迁移证据与回归测试，防止在清理旧路径时改变科学输入输出。

Question: Find_1 的 embed head 是否应复用现有代码结构但新建 AdaLigand 专用配置，将 trunk、voxel、point 三类 Transformer block 数全部设为 0，并在零 block 路径中启用 MLP、residual、occupancy、centroid encoding 与 soft splatting？
Decision: 是。Find_1 新建独立配置，复用 Stage1EmbedHead 的代码结构；num_trunk_blocks、num_voxel_blocks、num_point_blocks 全部为 0。保留输入 MLP、voxel/point 输出投影、residual、occupancy、centroid encoding 和 soft splatting。禁止的是 embed head 内的 Transformer block，不影响 Find 原有 U-Net 与主 point backbone。
Reason: 这准确对应所需的轻量 embed 组合，不夹带 clipbig 等现有实验配置中的 Transformer 结构，同时保留原始受体信息、软占据量和亚体素几何。

Question: Find_0 是否应严格实现为 embed_head=null，由 point backbone 直接读取原始 49 维受体特征，并将同一原始 49 维特征按局部体素坐标 floor 后以 sum 聚合做 hard scatter，追加给 U-Net；同时关闭 soft splatting、MLP、residual、occupancy 与 centroid encoding？
Decision: 是。Find_0 不放置零输出或 passthrough 型占位 embed head；point backbone 直接读取原始 49 维受体特征，U-Net 读取密度通道与原始 49 维 hard-scatter 体素特征。hard scatter 采用 floor 定位和 sum 聚合，不带其他 embed 或几何辅助编码。
Reason: 这才是“完全无 embed head”的字面实现，也与当前 VolumePointStage1Model 已原生支持的 embed_head=None + online legacy hard scatter 路径一致。

Question: 两种 Find 是否应形成两条完全独立的 CPC1→CPC2 训练链，其中 CPC1 各自从头训练，CPC2 只能从同名 Find 的 CPC1 BEST 初始化；两条链之间不共享权重，并允许按资源并行运行？
Decision: 是。Find_0-CPC1 与 Find_1-CPC1 分别从头训练；Find_0-CPC2 只接 Find_0-CPC1 BEST，Find_1-CPC2 只接 Find_1-CPC1 BEST。两条链可以并行，CPC1→CPC2 仅表示各自内部依赖。unet_c1 是第三条独立训练链。
Reason: 这样两个 embed 方案的最终 Find 都经历完整且同构的训练过程，不会因交叉初始化或人为串行而污染比较或拖慢启动。

Question: Find_0 与 Find_1 是否应构成严格的 embed-path 对照，即除已确认的 embed/scatter 差异外，共享完全相同的密度通道、主干、loss、数据划分、BOX 采样、增强、优化器与训练预算；其密度输入是否固定为构建器 enabled_channels=[all] 所代表的最强 56 通道？
Decision: 是。两种 Find 只允许在已定义的 embed/scatter 路径上不同；其余科学与训练条件相同。两者密度输入均固定为最强 56 通道，配置等价为 enabled_channels=[all]。
Reason: 这是可解释的单变量比较，同时保留当前最强密度表示。运行期仍需把 all 展开成有序的 56 通道清单写入 resolved config/checkpoint manifest，防止别名随代码变化。

Question: Find_1 是否应沿用完整 embed 结构的非 block 维数与融合方式，即输入 MLP 49→128→128；voxel 路径把 hidden 与 6 维 centroid 内部偏移投影到 49 维，再与原始 49 维 identity residual 以固定 gate=1 相加，按三线性 sum soft splatting 并追加 2 维 occupancy；point 路径投影到 64 维，再与原始 49→64 residual 以固定 gate=1 相加；同时三类 block 全为 0？
Decision: 是。Find_1 的 U-Net 输入为 56 个密度通道加 51 个受体体素通道，共 107 通道；主 point backbone 接收 64 维点特征。centroid 的 6 维只进入 voxel 输出投影，不作为额外输出通道。不存在 Transformer block 计算。
Reason: 这把“复用 embed head 代码结构、只把 block 变成 0”落实成无歧义的张量契约，并与已确认允许的 MLP、residual、occupancy、centroid encoding 和 soft splatting 一致。

Question: 三类 embed block 为 0 时，两种 Find 是否仍应使用现有测试表现较好的 8 Å receptor buffer？
Decision: 是，但 8 Å buffer 只属于 Find 的 point 路径。Stage1BoxDataset 从每个 BOX 的完整 receptor table 选出 core+10 Å receptor context，同时从中形成 core+8 Å model view；只有 model view 的标准 atom_* 字段进入 Find。voxel 路径只消费 core 原子：Find_0 对原始 49 维做 hard scatter；Find_1 对 core 原子执行 centroid encoding、MLP/投影、residual 与 soft splatting。Stage1EmbedHead 在任何配置下执行 voxel scatter 前都默认应用 atom_is_in_core_box，不增加 voxel_scatter_core_only 开关。point 路径保留 core+8 Å，并交给原有主 point backbone。10 Å context 只保存全局原子索引，坐标与原始 49 维特征由该索引回读 PDB 级 receptor table；Find 输出的 binding probability 与学习后 A 特征仅覆盖实际进入模型的 8 Å 子集，并通过全局原子索引回指 10 Å context。8–10 Å 外层原子不补零、不伪造学习后 A 特征。Find_1 的 trunk、voxel、point 三类 embed Transformer block 仍全部为 0；实现需把 voxel-core 筛选与 point-8 Å 保留从 Block 后裁剪循环中解耦。
Reason: 10 Å context 保证 F1_centered 与 CLG_centered 能构造完整的 10 Å receptor pocket；8 Å model view 保持 Find 已验证的输入。两层通过全局原子索引连接，既不重复保存 PDB 级 receptor 数据，也不把模型未处理的原子伪装成具有学习后特征。

Question: unet_c1 的最终科学结构是什么，以及 Find 与 unet_c1 的 voxel 输出头/辅助头前是否保留额外 3×3 Conv3d block？
Decision: unet_c1 从头训练，唯一模型输入是 [1,80,80,80] 的 exp_clipnorm_nopost；保留现有 RAUNet-64 voxel backbone。训练时随机运行 1–3 次 recycle，验证、校准和所有推理固定 3 次 recycle，跨 recycle detach。它不把 receptor、sim、P、point、embed 或 fusion 特征送入模型，也不构造 atom head；但启用 voxel auxiliary head，Dataset/Collator 必须提供 voxel_label 与 hardmask 作为仅用于监督和评估的张量。ligand-area target 直接使用 schema v3 union_mask 的二值 crop。Find_0、Find_1 和 unet_c1 的 voxel ligand 输出头及已启用的 voxel auxiliary 输出头均设置 num_conv3d_ligand=0、num_conv3d_aux=0，不在输出 1×1 Conv3d 前保留任何 3×3 Conv3d+ReLU block；单通道 logit 仍由 voxel_final 到 logit 的 1×1 Conv3d 产生。
Reason: RAUNet 已完成空间混合；额外 3×3 输出 block 的边际收益未被证明，却在 80³ 网格和多次 recycle 下带来显著计算成本。Find 当前成熟设置本就为 0；统一成直接 1×1 输出既简化模型，也不会删除预测头。

Question: 三种正式模型及五个训练阶段的 batch、精度、优化器、warmup、plateau、停训和 epoch 硬上限如何统一？
Decision: 全部正式训练使用 bf16-mixed、AdamW(lr=3e-5, weight_decay=0.01) 和全局梯度范数裁剪 gradient_clip_val=0.5；每个 epoch 运行 10 次完整冻结 validation，并让 checkpoint 与 plateau 调度器消费每次完整验证结果。unet_c1、Find_0-CPC1、Find_1-CPC1 的 warmup_ratio 统一为 0.025，warmup_start_factor=0.33；Find_0-CPC2 与 Find_1-CPC2 的 warmup_steps=0、warmup_start_factor=1.0。warmup 后统一使用 ReduceLROnPlateau：mode 跟随各阶段 BEST 指标方向，factor=0.3，threshold=0.001，threshold_mode=abs，cooldown=0；unet_c1 与两套 Find CPC1 使用 patience=3，并在第 3 次实际降低 LR 时停止；两套 Find CPC2 使用 patience=1，并在第 1 次实际降低 LR 时立即停止。所有阶段 max_epochs=20。patience 按 validation 事件计数：3 表示第 4 次连续未达到改进阈值时降 LR，1 表示第 2 次；达到 stop_after_lr_reductions 的那次降低只作为停训信号，不保证再用降低后的 LR 执行 optimizer step。

三种模型、五个阶段使用同一个 effective global batch G。先在正式硬件、真实 80³ 输入、Find 的 8 Å receptor buffer 和最大 3 recycle 下做短显存 preflight：若 Find_0 与 Find_1 都能稳定使用相同的 per-device batch=8，则 G=64；若任一只能稳定到 6，则两种 Find 统一使用 per-device batch=6，G=66。两种 Find 不得因显存差异使用不同的物理 batch。unet_c1 也必须达到同一个 G；它选择不超过实测安全上限且能整除 G 的最大 per-device batch，并用梯度累积补到 G，优先在 G=64 时直接 batch=64、在 G=66 时直接 batch=66，若不稳定则依次选 G 的更小因数。正式配置关闭自动 batch 搜索，显式写入 per-device batch、设备数、accumulate_grad_batches 与 effective global batch，并断言三种模型的 G 相同。
Reason: 统一有效 global batch 便于比较并稳定优化尺度；两种 Find 进一步统一物理 batch，避免 micro-batch 与归一化行为污染 embed-path 单变量对照。0.025 warmup、0.001 绝对改进阈值和 20 epochs 硬上限是本轮明确修订后的共同设置。

Question: 五个正式训练阶段的损失矩阵、直接二值监督来源以及 Pocket_Plus 中未被本项目实例化的模型能力应如何处理？
Decision: unet_c1 使用 L = 1.0 × L_voxel_ligand + 0.1 × L_voxel_aux；Find_0-CPC1 与 Find_1-CPC1 均使用 L = 1.0 × L_atom + 0.1 × L_voxel_aux + 1.0 × L_voxel_ligand + 0.1 × L_P；Find_0-CPC2 与 Find_1-CPC2 均使用 L = 1.0 × L_atom + 0.1 × L_P。CPC2 中被冻结体素分支的 ligand 与 auxiliary loss 只作为诊断指标计算，不计入 total loss。所有启用的分类损失项统一采用 0.7 × Focal + 0.3 × Tversky：Focal gamma=2、alpha_neg=alpha_pos=0.5；Tversky alpha=beta=0.5、smooth=1；w_mse=0。L_voxel_ligand 直接消费 BOX 内 schema v3 union_mask 的二值 crop，不再从 ligand_dist_map 经 1.7 Å 阈值生成；L_P 从同一个 union 二值张量按 P 的 home voxel 取样。L_atom 使用结合原子标签；L_voxel_aux 使用 voxel_label，并在 Find 与 unet_c1 中一律由 hardmask 限定有效监督区域。

五套 AdaLigand 正式配置不得实例化 sparse-refine head，也不得把 sparse-refine loss、ranking loss 或相应权重调度加入本项目训练图。但这只是“本项目配置不启用”，不是删除 Pocket_Plus 的通用能力：不得删除或借机重构 model、wrapper 层的 CPC、sparse-refine、ranking、调度等实现，也保留承载这些能力的通用配置。允许在等价性证据与回归测试齐备后删除的范围，仅限已被统一生产管线取代的重复 Dataset、旧推理入口及其纯编排代码；被模型、wrapper、测试或新管线复用的底层组件仍应保留。
Reason: L_P 统一为 0.1，避免不同 CPC 阶段对 P 分支采用不一致的监督尺度。unet_c1 的 auxiliary head 可在不增加受体输入通道的情况下提供受体标签辅助监督；voxel_label 与 hardmask 是监督张量而不是模型输入。冻结分支的 loss 不影响 CPC2 梯度，把它们排除出 total loss 可避免污染优化日志和 BEST 解释。清理重复数据/推理编排可以收窄生产主线，而保留通用模型与 wrapper 能力避免因当前实验未启用某模块而自废功能或触发无收益重构。

Question: 五个训练阶段如何选择 BEST，三个 producer 又如何在 calibration 上完成最终比较，二者是否使用同一职责与指标？
Decision: 二者严格分工。unet_c1、Find_0-CPC1、Find_1-CPC1 均以固定 validation BOX 上 val_score/global/voxel_ligand_PRAUC 最大为 BEST；Find_0-CPC2 与 Find_1-CPC2 均以同一固定 validation BOX 上 val_score/global/pseudo_PRAUC（P AP）最大为 BEST。voxel auxiliary AP、receptor-atom binding AP 与各分支 loss 全部记录，但不参与组合打分或替代主 monitor。所有 BEST 冻结后，unet_c1、Find_0、Find_1 分别在 calibration 100 上生成自己的完整 P_global，并报告 ligand-area PR-AUC、使用各自 t_F1 得到的语义 Dice、coverage F1、one-to-one F1 及 top3/top4/top5。候选级 IoU 阈值维持原规格 0.3/0.5，不改为 0.3/0.6；coverage F1、one-to-one F1 和 top-K 都分别在这两个阈值下报告。Find_0 与 Find_1 不以人工拼合的单一综合分自动决胜，而由用户依据完整 calibration 指标表确定正式 Find 主路线。calibration 不反向重选 epoch checkpoint，只用于比较已冻结模型、确定正式 Find 和标定推理阈值。
Reason: 训练期 monitor 应直接对应当前阶段能够被优化的主任务，并保持阈值无关；calibration 承担模型级方案比较和阈值选择，不能把两种选择职责混在一起。保留 0.3/0.5 可避免无必要地改变既有候选评估协议。

Question: 主数据划分、长尾 PDB 的 occurrence 上限以及该上限在训练池、validation 与全图评估中的作用域如何定义？
Decision: Stage G 冻结最终 keep-list 后，以 PDB–EMDB pair 为基本单位冻结唯一主划分：train 为 floor(0.75 × N) 个 pair，validation 固定 300 pair，calibration 固定 100 pair，其余全部进入 held-out test pool；同一 PDB 的所有 EMDB、occurrence、训练位置和下游产物必须继承同一 split。训练预定位池对所有 occurrence 完整生成，不因单个 PDB 的 occurrence 数超过 50 而删减。每个训练 epoch 内，对每个 PDB 从其全部 occurrence 中无放回选择最多 50 个；超过 50 时使用受显式 epoch/采样 seed 控制的重新抽样，使其余 occurrence 能跨 epoch 被看到。该 epoch 的 N_occ_epoch 按截断后的 occurrence 总数计算，center:bias:context=1:5:3 也据此组织。validation 对每个 PDB 同样最多选 50 个 occurrence，但只在冻结 validation_selection 时选择一次，之后不增强、不 shuffle、不逐 epoch 重抽；所有模型与训练阶段共用完全相同的固定清单。calibration 与 held-out test 使用完整全图及全部 GT occurrence，不应用 50 上限。
Reason: 预定位池保留全部数据，避免永久丢弃长尾 occurrence；训练期重抽兼顾 PDB 间权重与长期覆盖；validation 固定 cap 可防止极少数长尾 PDB 支配 checkpoint 指标，同时保持跨模型严格可比。全图 calibration/test 的目标是评估真实完整任务，因此不能套用训练采样上限。

Question: 80³ BOX 在训练预定位、随机 jitter、全图滑窗和三种局部居中推理中如何统一处理边界；完整图任一轴小于 80 时如何处理？
Decision: 所有来源共用唯一 BOX 起点解析器。对 ZYX 每个轴，resolved_start = clamp(requested_start, 0, full_shape - 80)。center/bias/context 先生成 requested start，在线 jitter 后再次解析；全图滑窗每轴包含 0 与末窗 L-80；F1、CLG Group-parent、selected-final 先按目标质心求理想起点，再调用相同解析器。Dataset、materializer、collator 与落盘描述子只消费解析后的 box_start_zyx，所有 crop 恒为完整真实 80³；允许截断后目标不再严格位于 BOX 中心。不做任何空间补零，不生成 voxel_valid_mask，也不因理想居中 BOX 越界而删除候选。若完整图任一轴小于 80，则该 pair 判为 Stage1 不合格。

小图过滤必须发生在训练之前而不是 Dataset __getitem__ 内，但它不是藏在训练启动脚本中的附属检查。Stage1 input eligibility、主 split、训练 BOX 预计算/筛选，以及未来才执行的 held-out test pool 去冗余，是四项并列的冻结数据准备工程；各自拥有独立入口、manifest、版本、输入哈希、统计与验收。依赖顺序仍是 Stage G 最终 keep-list → Stage1 input-eligibility scan → 主 split → 各 split 所需 BOX 池/validation_selection；held-out 去冗余以后只消费冻结的 held-out test pool，不阻塞当前 Stage1 训练。input-eligibility scan 产生 eligible manifest 与带原因 grid_axis_lt_80 的 excluded manifest，三个模型共用同一 eligible 清单。训练启动只校验并消费这些冻结产物，不现场生成、筛选或修补它们；正式训练循环不临时 skip、补零或因已知小图崩溃。
Reason: 向内移动起点可保证网络始终看到真实完整密度，消除补零带来的伪边界；统一解析器保证训练、全图和居中推理的几何一致。把不合格样本在 split 前冻结排除，既防止训练中途失败，也避免不同模型看到不同数据或运行期跳样本破坏 batch 与复现性。

Question: 三个 Stage1 producer 的第一次完整图 ligand-area 概率推理应采用什么统一窗口、融合、输出命名和保存边界？
Decision: 正式产物统一命名为 probability_map[D,H,W] float32，不再使用可能与 P token 混淆的 P_global。Find_0-CPC2 BEST、Find_1-CPC2 BEST 与 unet_c1 BEST 各自产生独立 probability_map。窗口固定 80³、stride=40；每轴起点为去重升序序列并强制包含 0 与 L-80。所有模型推理固定 3 次 recycle，窗口值取 ligand head logit 的 sigmoid 概率；不得把 ligand 概率乘以 1-hardmask，受体原子所在体素也保留原始模型预测。每个窗口的完整 80³ 都参与融合，不丢弃边缘 5 voxel。窗口权重为固定三维 Gaussian：局部索引 i=0…79 映射为 u_i=2i/79-1，sigma=0.5，w=exp(-(u_z²+u_y²+u_x²)/(2sigma²))。CPU 组装器维护 float32 probability_sum 与 weight_sum，逐体素相除后保存 float32 probability_map，并断言所有体素 weight_sum>0。第一次全图推理只保存最终 probability_map、完整图几何和必要来源信息，不保存逐窗口概率或 voxel/P/A 中间特征。CPC2 从 CPC1 BEST 加载后、执行 optimizer step 前的输出等价性由普通自动化测试使用小型模拟输入覆盖，不属于训练或推理启动前的额外检验流程。
Reason: 统一命名消除 probability 与 P token 的歧义；完整 Gaussian 融合在保证全图覆盖的同时降低窗口接缝。禁止 hardmask 后乘法可避免旧推理入口擅自改变模型输出；常规测试负责守护 CPC1/CPC2 的冻结与加载契约。

Question: 三个 producer 完成 calibration 后，哪些模型继续生成 F1 与 CLG 居中推理产物，各自保存哪些模态，是否为落选 Find 继续生成全套局部产物？
Decision: Find_0、Find_1、unet_c1 都先完成 calibration 100 的全图 probability_map、阈值扫描和完整指标评估，再由用户选出唯一正式 Find_selected。落选 Find 保留 checkpoint、probability_map、manifest 与评估结果，但第一轮不继续生成大规模局部产物。随后 Find_selected 与 unet_c1 各自同时启动 F1 居中推理和 CLG Group-parent 居中推理，形成 Find-F1、Find-CLG、unet-F1、unet-CLG 四条可并行流水线。F1 路线使用该 producer 自己的 probability_map 与 t_F1，对 F1 层全部合法组件逐个居中，不依赖 selector，优先供 Stage2/3 试跑；CLG 路线使用同一 producer 自己的多阈值森林，每个 CLG 只对 Group-parent forward 一次，为 selector 提供整组共享特征。Find_selected 保存实际导出的 voxel、P、A/receptor 具名特征及对应概率、坐标与索引；unet_c1 只保存实际存在的 voxel 特征、概率、坐标与索引，不伪造全零 P/A 字段，selector 与 Stage2/3 通过显式模态配置适配。两类居中输出使用分离的角色/命名空间和写入目标，可以并行但不得相互覆盖。第一次完整图上的 Global Proposal Mask 始终是候选身份与形状的权威来源；居中 forward 只补特征，不替换该 mask。
Reason: 先用 calibration 淘汰一个 Find 可避免为落选模型支付大规模局部推理与存储成本；同时保留 unet_c1 的 voxel-only 路线，使 selector 和下游模型能够比较不同模态组合。F1 与 CLG 并行可让 Stage2/3 基线和 selector 开发同时推进。

Question: F1 blob 与多阈值节点使用什么连通性、体积和 BOX 容纳规则；max_voxels 与 calibration 阈值又如何以最低工程复杂度冻结？
Decision: 所有阈值层统一使用 26-连通，不做腐蚀、膨胀、闭运算或边缘裁切。每个组件按全图体素质心求 requested start，再用统一向内截断规则得到真实 80³ BOX。节点可选择当且仅当 min_voxels ≤ voxel_count ≤ max_voxels，且其完整全图 bbox 被该真实 BOX 的闭区间完整包含；允许组件恰好贴着 BOX 面或完整图边界，只拒绝真实落在 BOX 外、无法由该 BOX 完整承载的组件。不把 touches_full_grid_boundary 保存或用作独立过滤条件。F1 层保存全部合法组件，不受 CLG cap 影响；组件森林各层复用同一合法性函数。min_voxels 固定为 32；max_voxels 是三个 producer 共用的一个预先冻结整数。

max_voxels 不建设正式统计管线，也不要求永久 manifest。代码实现前，由用户另行提示 AI 根据 Data_Preprocessing/Ori_Data/code/readme.md 在服务器端一次性统计全部 GT occurrence 的 ligand-area 体素数分布，报告 Q95 与 1.5 × Q95；该任务只允许使用临时落盘文件。用户据此冻结最终 max_voxels 标量并写入正式配置。训练本身不依赖该值；F1/CLG proposal 生产在该标量尚未冻结时不得冒用猜测默认值。

calibration 100 的第一版只为每个 producer 选择固定 alpha 集合 {1/2,2/3,4/5,1,5/4,3/2,2} 的概率阈值，不额外调 min/max_voxels、形态学或边界参数。AP 是阈值无关的报告/模型比较指标；每个阈值实际按 micro-F_alpha 最大化选择。扫描分辨率改为 1/16384，即候选阈值 t_j=j/16384，j=0…16384；alpha=1 的结果为 t_F1，相同数值的物理阈值层去重。
Reason: 向内截断后只需检查完整 bbox 是否能由真实 BOX 承载，不再需要旧的越界可观察区公式。GT Q95 × 1.5 提供一个足够直观的首版体积上限，而把它作为一次性人工冻结值可避免为单个标量引入用户无暇审查的持久统计系统。更细的 1/16384 扫描在 100 张 calibration 图上成本可控，也降低粗网格对阈值与同分判断的影响。

Question: 训练预定位池的 center、bias、context 与在线空间增强如何用一条足够简单、可直接实现的规则冻结？
Decision: 每个上游产出的 GT occurrence 都进入预定位池，不因 ligand-area mask 大小、bbox、图边界或能否被 80³ 完整容纳而过滤。center 的 requested start 由该 occurrence 的 ligand-area 稀疏 mask 体素质心按统一整数起点 helper 得到，再经统一图内起点解析器截断。每个 occurrence 预生成 30 个 bias 初候选；令 K_occ 为该 occurrence 的 ligand-area 体素数，直接按近 1 Å 重采样网格把它视为 voxel-space 体积，定义等体积球半径 R_voxel=(3*K_occ/(4*pi))^(1/3)。每个 bias 在该 ZYX voxel-space 球体内按体积均匀采样：方向由三维各向同性随机向量归一化得到，半径为 R_voxel*U^(1/3)，U~Uniform(0,1)；连续偏移经项目统一整数 rounding helper 转成 delta_start_zyx，加到未截断的 center requested start 后，再调用统一图内起点解析器。固定保留 30 个采样结果，即使边界截断后起点重复也不做额外拒绝、去重或补抽；每个 epoch 从中选 5 个。

context 在每个轴的合法图内起点范围均匀随机采样；只要求裁剪后的 80³ core 内 receptor 重原子数至少 1000，不因 BOX 是否含 ligand 而过滤。每个 PDB 目标保留 500 个 context 起点，最多尝试 3000 次；耗尽后保留实际合格数量。center、bias、context 均不做在线平移 jitter。训练期只复用 Pocket_Plus 已有的 voxel/target/point 同步随机 90° 旋转；validation 与所有推理关闭旋转。三个模型共用相同预定位池、epoch occurrence 选择和位置选择结果。
Reason: 等体积球把偏移尺度自动绑定到 occurrence 大小，同时比高斯场、比例项和 floor 分布更容易实现与审查。直接使用 voxel 数避免为近 1 Å 网格引入不必要的物理体积换算；30 选 5 增加跨 epoch 多样性。取消在线 jitter 后，所有平移多样性由冻结 bias/context 池提供，训练与验证位置身份更清楚。

Question: Find 的 CPC1→CPC2 是否需要为 AdaLigand 重新设计训练阶段控制与冻结机制，CPC1/CPC2 输出等价性又应放在哪一层验证？
Decision: 不重新设计。Find_0 与 Find_1 直接复用 Pocket_Plus 已有的一键 CPC 阶段逻辑：CPC1 通过独立 experiment 配置从头启动；CPC2 继承同名 CPC1 的完整模型结构，通过现有 init_from 机制从该链自己的 CPC1 BEST 做 model-only 初始化，并通过现有 frozen_module 阶段配置表达既定的可训练/冻结边界。AdaLigand 只新增承载本项目模型结构、Dataset、损失、调度与阶段参数的 experiment 配置，并让它们接入现有 CPC 入口；不得平行实现第二套阶段状态机、checkpoint 加载器或冻结控制器。配置中未实例化的模块按现有配置机制表达为缺席，不为满足通用旧配置而创建无用模块。CPC2 初始化后的输出等价性写成 tests 下的普通模拟测试，与其他模型/配置测试同等运行；它不是正式训练前的真实数据 preflight、运行期闸门或额外人工验收步骤。
Reason: Pocket_Plus 已经具备可一键调用的 CPC1/CPC2 配置继承、model-only 初始化和阶段冻结逻辑；本项目只需接好新契约与新配置。把等价性放在普通自动化测试中即可长期守护该既有契约，不应增加正式运行流程的特殊分支。

Question: 三类居中推理输出及其来源应如何命名和寻址，哪些内容才需要 hash？
Decision: 模型来源字段固定为 stage1_model_name，枚举值按原样使用 Find_0、Find_1、unet_c1。三类居中推理输出角色固定命名为 F1_centered、CLG_centered、Selected_Refined_Centered；采用首字母大写形式，使角色枚举与普通变量名清楚区分。固定产物由 stage1_model_name、split、pdb_id、输出角色及 PDB 内 centered_box_index 直接寻址；不设置 probability_run_id、proposal_run_id 或 materialization_run_id，也不使用 row、materialization 等含糊名称。完整图或居中推理直接消费调用时已经选定的 checkpoint；新产物不重复保存 checkpoint 身份、路径或 hash，也不为 checkpoint 或阈值表另建登记系统。CLG_hash 仅在确实需要让多套 CLG 枚举规则并存、且仅靠固定路径无法区分时启用；若当前只有一套冻结规则，则不制造该字段。现有输出目录与配置记录能力足够时直接复用，不另造运行登记、哈希或说明文件框架。实现优先复用 Pocket_Plus 已有训练入口、阶段逻辑与 wrapper；除非新数据契约或必要输出无法接入，否则不修改训练/wrapper 代码。
Reason: 固定流程可由清楚的模型名、数据集合、PDB 与输出角色唯一表达，额外 run ID、重复 checkpoint 信息和 hash 只会增加追溯负担。只有 CLG 规则真正成为可并行实验轴时，CLG_hash 才提供必要的区分能力；复用已有训练/wrapper 能力可避免无必要重构。

Question: Find 居中推理是否只保存交互后的最终 P/A 特征，还是保留当前已有明确语义的多层次特征？
Decision: 保留当前契约中每个实际产生且语义明确的多层次特征，不以简化导出或节省空间为由只保存最终层。P 特征固定包括 density-box 特征 P_feat_L2、交互前特征 P_feat_L3、交互后特征 P_feat_L4；receptor/A 特征固定包括 embed head 输出 receptor_feat_L1、density-box 特征 receptor_feat_L2、交互前特征 receptor_feat_L3、交互后特征 receptor_feat_L4。Find_0 没有 embed head，因此不产生 receptor_feat_L1；Find_1 保存 receptor_feat_L1。两套 Find 都保存其实际产生的 P_feat_L2/L3/L4 与 receptor_feat_L2/L3/L4。不存在的层不保存、不补零。P 的 L2/L3/L4 与 receptor 的 L1/L3/L4 直接读取现有模型出口；receptor_feat_L2 在模型内部已有计算，只增加最小输出透传，不改训练或 wrapper 机制。voxel 特征继续作为具名 V 来源单独界定；unet_c1 仍只产生 V 类特征。
Reason: L1/L2/L3/L4 分别保留 embed、局部 density、跨模态交互前和交互后的不同表示，没有消融证据证明最终层能够无损替代其它层。完整保留这些真实特征，才能让 selector、Stage2 与 Stage3 在输入端学习选择和融合互补信息。

Question: 多层 V/P/A 特征应在什么位置进入下游模型，居中推理特征采用什么落盘精度与物理容器？
Decision: 所有消费 Stage1 特征的下游模型，包括 selector、Stage2、Stage3 以及未来实际消费这些特征的精修模型，都在任何主干、图网络、树网络或跨实体交互之前执行一次输入表示前导。同一实体的全部实际 V/P/A 多层来源先逐源编码并融合为唯一初始表示 H_V、H_P、H_A；不存在的来源不参加融合、不补零。各消费模型拥有自己的融合器参数，不要求跨模型共享权重。P→PP、P/A→配体等跨实体交互仍按各模型原有架构在输入前导之后执行。该规则不要求 Stage1 producer 在同一次前向中把自己刚产生的 L* 特征回灌给自身。

居中推理导出的学习特征，包括 voxel_feat__*、P_feat_L* 与 receptor_feat_L*，统一以 float16 逻辑 dtype 落盘；probability_map、P/A 概率、坐标与几何参数保持 float32，索引、offset 和 mask 继续使用其适当整数或布尔 dtype。第一版直接复用无损的 np.savez_compressed 物理保存，不另建压缩系统。项目优先把 A–G 全图处理管线之外的全部产物控制在 25 TB 磁盘预算内；30 TB、35 TB 或更高容量可以作为后续人工选择，但不预先依赖。存储 dtype 与前向计算精度分开：float16 落盘不强制前向使用 FP16，压缩也只减少磁盘占用，不作为运行内存或 GPU 显存优化。
Reason: 同实体的多层特征在模型入口融合，既让每个消费者自行学习各层贡献，也避免在主干多处重复注入形成不同语义。学习特征改用 float16 可把其未压缩字节数减半，使五路 V、P/A 多层特征和三类居中产物更有机会落在优先的 25 TB 预算内；概率、坐标与几何仍用 float32 保住阈值和空间语义。

Question: 同实体多源输入使用什么统一融合算子；额外的计划手册在现有文档体系中拥有什么边界？
Decision: selector、Stage2、Stage3 及未来消费 Stage1 特征的模型统一使用 MultiSourceInputAdapter，默认模式固定为 residual_swiglu。对每个实体的实际来源先分别执行 LayerNorm 与来源专属 Linear 投影，再按配置中的固定来源顺序与该实体的坐标、概率等基础属性编码拼接；拼接结果同时经过线性 skip 投影和 SwiGLU 非线性分支，输出为 LayerNorm(skip + residual)。该算子在同实体内部联合融合全部来源，不使用纯 FiLM 的主特征/条件特征不对称，也不增加 source-axis Transformer。各消费模型复用实现但不共享参数；缺失来源不补零。不同实体之间的 P→PP、P/A→配体等交互仍在该输入融合之后执行。

计划手册只作为当前 Stage1 文档整理中的特例性、低权重附属材料，不新增文档基本范式，不修改现有 skill、AGENTS.md 或 plan/log/contract/mapping 的职责规定。主计划继续保持自包含；不得把精确公式、张量流、配置值、模块落点等类别整体迁往手册。手册第一类内容是用户通常不会阅读的测试用例与 AI agent 工作顺序；这些内容只能派生自主计划，不能反向新增、删改或解释正式要求。第二类内容是抽出后不影响主文档连续阅读的独立细节，例如主文档明确说明先融合并指向 residual_swiglu 的独立实现说明。手册不是主入口，发生冲突时主计划与 BOX 数据契约优先。任何把原始三件套现有正文迁入手册的操作，都必须先向用户列出拟迁移的具体章节、内容和理由，并取得批准；未获批准时原文留在主文档。
Reason: residual_swiglu 在固定、少量、同位对齐的多层来源上能够从第一个非线性层联合建模全部信息，同时保持线性成本和残差稳定性。把手册限制为非核心、可独立抽离的补充材料，可以减轻局部臃肿而不破坏主计划的冷读自包含性，也不改变项目既有文档治理制度。

Question: V 分支如何同时保证多尺度特征与重新训练的小型密度 U-Net 真正增加信息、能够退化到 48 维末层基线，并在全量生产前控制磁盘和训练成本？
Decision: 第一版正式设计为 V5+D。voxel_final 经独立投影形成完整的 48 维末层基线 value 分支 b；voxel_ds_2、voxel_ds_3、voxel_ds_4、voxel_c4 在消费模型内部按当前 V/PP 坐标三线性采样，并经 residual_swiglu 形成多尺度 value 分支 m；重新训练的小型密度 U-Net 现场读取 raw density，产生不落盘的下游任务专属 density-context value 分支 c。模型从 [b,m,c,meta] 产生相互独立的逐通道 gate g_m 与 g_c，最终表示为 LayerNorm(b + g_m*m + g_c*c)。小型 U-Net 不再只控制 gate，也不作为与五路 V 平铺的第六个同级来源；它以自己的 value 分支补充 Stage1 ligand 分类目标可能丢失的原始密度信息。关闭两个附加分支时，模型严格退化为 V48 基线。

盘上以 float16 保存四张原生低分辨率网格 voxel_ds_2[256,20,20,20]、voxel_ds_3[256,10,10,10]、voxel_ds_4[256,5,5,5]、voxel_c4[256,5,5,5]；不保存它们按 K_v 行预采样后的重复结果。voxel_final 已是 80^3 分辨率，只保存权威 parent/final voxel 行上的 [K_v,48] 稀疏值，不保存完整 [48,80,80,80] 网格。三线性采样属于消费模型 forward，不由外部导出器预计算。完整图推理仍只保存 float32 probability_map，不保存 V 特征。

在支付全量居中特征存储前，允许用小规模数据比较 V48、V5 与 V5+D：V5 不优于 V48 时不全量保存四张中间网格；V5 有效而 V5+D 无增益时去掉小型 U-Net；V5+D 最好时保留正式设计。实操默认先尝试 V5+D；若以后实际训练速度令人无法接受，可以人工尝试 V48 等 mini 版本。H100 上是否能在约三天量级内收敛只是一条模糊的运行体验参考，不是当前 grill 冻结的硬阈值、自动回退条件、验收标准或配置分支；具体是否切换留待后续由用户或执行 AI 根据真实运行决定。
Reason: 多尺度分支保留不同感受野与瓶颈前后信息，小型 U-Net 以重新训练的 raw-density value 提供不同训练目标下的补充，而独立 gate 允许模型关闭无效或冗余分支。完整 V48 残差主路既提供稳定基线，也使 V5+D 的价值可以通过小规模比较验证；原生低分辨率网格加稀疏 final 避免把 1072 维采样结果按每个 parent voxel 重复落盘。

Question: V5+D 中密度分支的输入语义、正式通道名以及小型密度 U-Net 的归属如何界定？
Decision: 密度分支不引入第二套 density-context 数据产物。其原始输入固定为当前 80³ BOX 裁剪后的实验密度通道，先裁剪 BOX，再按现有通道逻辑执行 clip-normalize，且不做额外空间后处理；正式名称沿用 Pocket_Plus 已有的 exp_clipnorm_nopost，不新增 raw_clipnorm_none 同义别名，也不混入 simulated density、difference density、receptor 通道或 Stage1 学习特征。文档和代码中严格区分 density_input 与 density_context_feature：density_input 的形状为 [B,1,80,80,80]，表示上述 exp_clipnorm_nopost；density_context_feature=SmallDensityUNet(density_input)，表示消费模型内部现场计算且不落盘的学习后特征。selector、Stage2 与 Stage3 各自拥有自己的 SmallDensityUNet 参数，并随各自任务端到端训练；它属于相应消费模型 checkpoint。不得引入 Find 与 unet_c1 联合输入、联合训练或因此共享密度分支的假设。
Reason: 复用现有 exp_clipnorm_nopost 既准确对应当前 BOX 级输入处理，也避免为同一语义维护 raw/exp、none/nopost 两套名称。把原始密度输入与其学习后特征分开命名，可以防止实现者误以为需要预计算或落盘新的 density-context artifact；各消费模型独立训练则让密度编码适配 selector、Stage2 与 Stage3 的不同目标。

Question: 居中重跑产生的局部概率应如何保存，Selected-final 如何重新定形并与来源全图节点对应，以及是否继续使用 Proposal 术语？
Decision: 第一次全图滑窗融合得到的 probability_map 及其全图组件节点始终是 F1_centered 与 CLG_centered 的权威形状来源。这两类居中重跑产生的额外局部连通组件不形成新候选、不改变原全图组件掩码，也不保存稠密 threshold_rank_map 或 auxiliary_prob_mask；只在相应输出的权威 voxel index 集合上保存逐项对齐的 centered_probability[K_v] float32。当前计划不需要 threshold rank，因此文档不写未来派生或预留逻辑。

Selected_Refined_Centered 具有不同语义：selector 选择一个候选节点，该节点携带其在全图组件树中的原始阈值；以该节点体素质心解析新的 80³ BOX 后，使用同一 Stage1 producer 重新推理，并在完整局部概率上使用该原始阈值二值化和执行 26-连通组件划分，不重新搜索阈值。若得到多个局部组件，选择与投影到当前 BOX 的来源全图组件掩码 IoU 最大者；完全同分接受普通 argmax 的现有返回结果。选中的局部组件成为新的 refined_blob 和该 Selected_Refined_Centered 输出的权威 voxel 集合；其 V/P/A 特征与 centered_probability 均对齐新 refined_blob，而不是旧组件掩码。局部额外组件仍不进入全图组件树或 CLG。

每个 Selected_Refined_Centered 记录使用 stage1_model_name、split、pdb_id、source_tree_id、source_node_id 明确指回 selector 选中的来源全图组件节点。成功时一个来源节点只对应一个 refined_blob；empty、no-overlap 或执行失败时仍保留来源身份和 refine_status，形成明确的一对零失败记录。refined_blob 是来源节点的派生局部形状，不伪造新的 tree_id/node_id。来源全图掩码由全图组件表解析，不在 Selected-final 中重复复制。

三件套与新代码不再把 Proposal 当作泛化占位术语：全图组件树中的原始对象称为全图组件节点 global_component_node 及其 global_component_mask；进入 CLG、可供 selector 选择时称候选节点 candidate_node；selector 选中后称 selected_node；Selected-final 产生的局部组件称 refined_blob。删除 Global Proposal、proposal_run_id、proposal_config、proposal mask、proposal–GT overlap 等名称，分别改为全图组件/候选节点及其具体配置、掩码和 overlap 名称。规划文档是现在式规范，不为旧 proposal_* 字段保留兼容叙述。

Selected_Refined_Centered 必须保存一份下游可独立消费的完整居中 BOX 产物，而不只是 refined_blob 掩码补丁。它保存 BOX 几何与来源身份、新 refined_blob 的 voxel index/mask 表示，以及该 producer 在此次居中 forward 中实际产生的全部既定 V/P/A 学习特征和概率：V 包括已冻结的 voxel_final 稀疏特征、四张原生低分辨率特征网格及与 refined voxel 对齐的 ligand centered_probability；Find 保存完整 P 坐标、P_feat_L2/L3/L4 与 P probability，以及实际进入模型的 A 全局索引、坐标、A probability 和其真实产生的 receptor_feat_L*；Find_0 不伪造 L1，Find_1 保存 L1。unet_c1 只保存其真实 V 特征和已启用的 voxel 概率，不伪造 P/A。实际启用的 voxel auxiliary 概率不保存完整 80³ 图，而保存 voxel_aux_index_local_zyx[K_aux,3] 与逐项对齐的 voxel_aux_probability[K_aux] float32；K_aux 是 hardmask 中唯一 receptor home voxel 的集合。Find 与 unet_c1 都按此保存；对 unet_c1，它仍是 V 类辅助概率，不表示模型读取或产生 A 特征。该辅助概率当前不被 selector、Stage2 或 Stage3 默认消费，只为完整保留已启用头的真实输出，不得据此扩大当前下游输入契约。所有学习特征按已定 float16 落盘，概率和几何按 float32 落盘；完整 exp_clipnorm_nopost 仍由整图密度按 BOX 几何读取，不在每个 BOX 重复保存。
Reason: 稀疏保存 centered probability 保留居中观察带来的置信度信息而不为每个 BOX 复制 80³ 概率图；F1/CLG 只补观察特征、Selected-final 才在固定原阈值下重新定形，避免三类角色混淆。来源 tree/node 身份让 refined_blob 无歧义对应到 selector 选择的原全图节点，即使精修失败也能审计。使用 component、candidate、selected 和 refined 等具体名词取代 Proposal，可以让字段名直接表达真实数据结构。Selected-final 保存完整实际模态与概率后，Stage2/3 可以把它当作独立 BOX 使用，而无需回读旧居中 BOX 或伪造缺失模态。

Question: Find 的 validation 自适应 P 候选阈值如何跨 CPC1→CPC2 与正式推理恢复，是否需要新增公共 helper？
Decision: 不新增阈值公共 helper、状态层或额外校验框架。现有 VoxelPointStage1Wrapper 已在每次正常 validation 结束后更新 p_best_by_class 与 p_sampling_by_class，并通过现有 on_save_checkpoint/on_load_checkpoint 保存和恢复；缺失值、非有限值与类别数约束继续由现有 hook 和 candidate builder 负责。CPC1→CPC2 保持 model-only 语义，只在现有 _load_model_only_checkpoint 完成 state_dict 加载后增加一行或数行最小调用，让 model.on_load_checkpoint(checkpoint) 恢复 wrapper 已有的候选阈值状态；不恢复 optimizer、scheduler、global_step 或其它训练续跑状态，也不另建 CPC 状态机。普通模拟测试检查 CPC2 第一次更新前的阈值与全部输出和来源同名 CPC1 BEST 一致。

正式推理不修补或复用旧 get_pred.load_model 的裸 backbone 加载路径，而在 AdaLigand 新生产分支重写 Stage1 推理加载器。新加载器从调用时选定的 checkpoint 及其邻近 resolved config 实例化完整 Stage1 wrapper，严格加载完整 state_dict，并按标准 checkpoint 生命周期执行现有 on_load_checkpoint，使 Find 自然恢复候选阈值；它统一支持 Find_0、Find_1 与 unet_c1，后者无候选状态时 hook 自然为空操作。加载器不增加 checkpoint registry、hash、额外说明文件或重复阈值校验，也不把候选阈值写成另一个用户配置。p_best/p_sampling 是 Find 内部 P 候选生成状态，与 calibration 100 冻结的全图 t_alpha 阈值严格分开。
Reason: 当前 checkpoint 已经保存所需阈值，真正缺口只是 model-only loader 与旧裸 backbone 推理 loader 没有执行 wrapper 的既有恢复生命周期。CPC 链增加现有 hook 调用即可修补；正式推理从完整 wrapper 加载器重写，可以同时避免继承旧推理入口及其丢状态问题，而无需围绕两个现成字段再造抽象。

Question: 第一次全图滑窗推理是否需要执行 Find/unet_c1 的完整 A/P 后半段，voxel-only 入口及其文档细节放在哪里？
Decision: 新增一个明确的公共模型入口 forward_voxel_probability(batch)，供 Find_0、Find_1 与 unet_c1 的第一次全图滑窗推理共同使用。该入口执行与完整 forward 完全相同的 embed/scatter、voxel input 构建和固定 3 次 voxel recycle，返回最终 voxel_logits_ligand；不生成 P 候选，不运行 point backbone、atom/P 分类头或 sparse-refine，也不导出 A/P/V 居中特征。当前模型中这些后半段不存在回写 voxel 分支的路径，因此这不是近似或另一模型。F1_centered、CLG_centered 与 Selected_Refined_Centered 仍使用正常完整 forward。两条入口使用同一 checkpoint；普通模拟测试在 eval、固定 3 recycle 下逐元素断言两条路径的 voxel_logits_ligand 一致。

主计划保留上述行为契约：全图推理使用 voxel-probability 专用入口、执行哪些科学分支、与完整 forward 的输出等价性，以及三类居中推理仍走完整 forward。新增加且可独立抽离的方法名、内部调用顺序、伪代码、文件落点和逐元素测试写入本轮特例性的低权重细节手册；这属于新增内容的分层，不迁移三件套既有正文，也不改变计划、契约、exec log 或 mapping 的既有文档范式。
Reason: 全图概率只依赖 voxel 分支，跳过不会反馈的 P/A 后半段可显著减少大规模滑窗的无效计算，同时避免让全图概率生产依赖只为 P 生成服务的内部候选阈值。把不可省略的行为与等价性留在主计划、把代码落点和测试步骤放入手册，既保持冷读自包含，也符合手册只能承载可独立抽离实现细节的边界。

Question: selector 三种条件损失如何比较、oracle 是否落盘，validation/calibration/test 各自承担什么职责；全图与居中推理如何允许部分产物先供下游训练并适应运行卡数变化？
Decision: selector 实现三种可配置 gate，且三者同属第一梯队并可并行训练。令 L_cond=w_blob*L_blob+w_antichain*L_antichain，默认三个静态权重均为 1：oracle_gate 使用 L=w_CLG*L_CLG+1[y_CLG=1]*L_cond；detached_pred_gate 使用 L=w_CLG*L_CLG+stopgrad(p_G)*L_cond；joint_pred_gate 使用 L=w_CLG*L_CLG+p_G*L_cond。oracle_gate 是条件概率分解最直接的默认参考；detached_pred_gate 检验软置信度加权；joint_pred_gate 必须运行但需报告 p_G 通过下降来减小条件损失的退化风险。比较三种 gate 时固定 lambda_count=0.05、gamma_focal=0；第二梯队只围绕胜出 gate 分别尝试 lambda_count=0.03 与 gamma_focal=2，不做完整笛卡尔积。

q_i、最优非空/空反链 S* 与 y_CLG 由已保存的候选节点–GT overlap 和当前 lambda_count 在 Dataset worker 内现场计算，不落盘 oracle 标签或反链缓存。改变 lambda_count 会改变 oracle；CLG 规模约 20–32 时 CPU 动态规划足够轻，持久缓存只会引入训练目标身份与失效管理。主计划保留完整公式；测试与 AI 实施顺序进入细节手册。

固定 validation 300 只用于每个 selector 训练内部选择自己的 BEST checkpoint。BEST 冻结后，每个模型在 calibration 100 上选择自己的 tau_G，并直接汇报同一 calibration 100 在该最优阈值下的 CLG、blob、反链和最终实例指标；三种 gate 的近期工程判断主要比较这些 calibration 拟合后结果。它们必须明确标为 calibration 结果而不是独立测试结果。held-out test pool 当前不做去冗余、不运行，也不作为实现完成或近期实验推进门槛；论文最终结果所需的严格去冗余测试集留待后续建设。

selector 的训练输入不在 epoch 中动态增长。每个 selector run 启动前只扫描一次已经完整发布的 CLG_centered，冻结本次实际使用的 train PDB/CLG 清单；同一梯队方案应在大体相同时间启动，以控制可用训练数据差异。运行期间新增的居中产物不进入当前 Dataset/DataLoader；以后可基于更多已完成样本另启一轮训练。每个 run 直接保存实际读取的 PDB 清单与数量，不计算 hash或建设数据版本系统。正式 checkpoint 选择要求固定 validation 300 已完整可读；validation 尚未齐备时只能试跑，不产生正式 BEST。

全图与居中推理采用两阶段运行。阶段一先完成每个 stage1_model_name 的 calibration 100 全图 probability_map，并冻结该模型的 t_alpha 阈值表；这是其它 split 开始 F1/CLG 构造的前置条件。calibration 的 F1_centered/CLG_centered 可在阈值冻结后立即补齐，但不阻塞其它卡进入阶段二。阶段二共同处理 validation 与 train：每张可用卡获得一部分尚未完成的 validation 和一部分尚未完成的 train，优先推进自己的 validation 份额以尽快凑齐固定 300，随后持续处理 train。阈值已冻结后，一张 PDB 原则上按 probability_map→全图组件/CLG→F1_centered→CLG_centered 连续完成并分别发布，使 F1 下游和 selector 可以在全量推理结束前使用已经完成的部分样本。

文档不冻结 GPU 数量、固定 worker 编号或永久分片公式。生产任务以 stage1_model_name、split、pdb_id 和输出角色为独立、可重入、幂等的完成单元；每类 per-PDB 输出只在全部必要文件成功后原子发布 _COMPLETE。运行卡数增加、减少或任务被中断时，运维入口重新扫描未完成单元并按当前资源重新划分或重跑即可；已完成单元跳过，重复尝试不得破坏已发布结果。允许用停止后重新扫描并重提任务等简单手段收口，不要求第一版建设动态共享队列、永久锁服务或全局任务数据库。主计划只略述 calibration-first/val+train-second、部分产物可消费与资源变化不影响正确性；具体重扫、临时目录、原子发布和当前卡数下的任务切分示例进入低权重细节手册。
Reason: 三种 gate 在其它因素固定时并行比较，能把条件损失的门控方式作为单一实验变量；在线 oracle 避免 lambda 专属缓存。validation、calibration 和未来严格 test 分工清楚后，近期实验可以用 calibration 拟合后结果快速判断苗头，而不被尚未完成的去冗余测试集阻塞。calibration 先行使所有后续卡一开始就拥有冻结阈值；per-PDB 幂等与原子完成语义则让 val/train 推理能随资源变化重分配、续跑和提前供下游消费，而无需把偶然的卡预算写成科学规范。

Question: CLG 节点上限超限时如何处置，depth1/depth2 的上限是多少，以及组件森林是否采用树专属数据结构？
Decision: depth1 固定 max_split_events=1、max_merge_events=1、max_nodes_per_CLG=32；depth2 消融固定 max_split_events=2、max_merge_events=2、max_nodes_per_CLG=64。split/merge 的全部直接相关节点仍是不可拆分的原子事件；加入后节点数恰好等于上限时允许，超过上限时不保留截断或部分 CLG，而把当前 CLG 尝试整体判为失败。失败 CLG 不编号、不落候选表、不做 CLG_centered；对当前选中的节点直接应用已经定义的删除算子 D(G)，并只在当前工作副本树中删除 D(G)。不得为超限分支另造 tentative cover、merge-parent 特例或第二套删除公式。每个 PDB 记录 n_CLG_rejected_by_node_cap 等直接诊断计数，不保存失败半成品。

完整全图组件森林采用树专属数据结构：每个 tree_id 对应一棵标准 arborescence，每个 node_id 具有唯一直接父节点或 -1，并通过 children offsets+indices 维护直接子节点集合；姐妹由共同父节点的 children 现场派生，不重复存储。原始森林只读；CLG 枚举为每棵树建立带 active/removed 与必要 frontier/CLG-membership 状态的工作副本，种子、扩展和 D(G) 删除都在该副本上执行。不得用散落布尔判断和“不能穿过”等口头规则替代树操作。原称 Group-parent Node 的对象统一改名为 CLG_cover_node，定义为覆盖该 CLG 全部候选组件的唯一最低阈值祖先节点；它与节点的直接 parent、整棵树的 root 严格区分。
Reason: 32/64 为 depth1/depth2 提供更宽松但仍明确的极端规模保护。超限后淘汰整个 CLG 才使上限承担过滤异常分支的职责，而不是悄悄改变谱系深度；复用既有 D(G) 避免给失败路径发明新的删除语义。显式 arborescence 与工作副本使父子、姐妹、frontier 和删除都由数据结构保证，减少含糊状态描述与重复拓扑字段。
