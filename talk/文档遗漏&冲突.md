## 结论先行

现在可以立即开始：建立干净实现分支、Ada 数据适配、几何/损失契约测试、单 batch backward、center-only 小集过拟合和少量 C/D/E 成功样本 smoke。

1. 本地证据尚未给出 A–G final keep-list/release evidence；
2. Ada↔Pocket 的坐标、标签与 core-loss 接缝未实现；
3. P head/loss 与正式训练 curriculum 尚未冻结；
4. train/val、box_index 与正式 run config 尚未冻结。

calibration 不一定是提交 Find 权重训练的技术依赖，但其来源、用途和是否进入 development forbidden pool 应预注册，并在任何阈值/后处理调优前冻结。test manifest 不阻塞 Find 权重训练；它必须在正式盲测/报告前完成。

## 二、有害冲突

### H-01：中心原点与角点原点相差半个体素（硬阻塞）

- Ada：`BOX-level数据契约.md:119-137`、`Stage1训练实现计划.md:39-49,63` 把 origin 定义成局部 `[0,0,0]` 体素中心。
- Pocket：`src/datasets/box_geometry.py:27,39-44,97-103` 把 origin 当 BOX 外侧下角；模型文档 `src/model/stage1_model.py:13-16` 要求 corner 语义 local voxel 坐标。
- BOX 契约 `:621-625` 却把现有 `box_geometry` 称为可直接复用的纯叶子。

若直接调用，会使所有坐标整体偏 `0.5 voxel`，并改变边界原子/core 归属。适配层必须执行：

```text
origin_corner_xyz = origin_center_xyz - 0.5 * voxel_size_xyz
```

磁盘继续保存中心原点，只有 Pocket 模型视图使用角点原点。该转换、home voxel、边界成员关系和往返必须逐值测试。

### H-02：边界补零已经冻结，实现计划仍写未决（硬阻塞）

- BOX 契约 `:120-137,635-636` 与主计划 `:331-350`：允许 start<0 或 end 越界，不 clamp；exp/sim/GT 图外补 0，图外无 receptor，origin 按整数 start 外推。
- 实现计划 `:256-266,371`：仍说常数扩展、坐标和受体范围等待决定，只允许完整 BOX。

这是同一行为的两套答案。实现应服从 BOX/主计划；之后由收口流程把实现计划的“待定”改为测试要求。

### H-03：二值 union mask 与旧 distance-map loss 不兼容（硬阻塞）

- 新资产：`Data_Preprocessing/Ori_Data/code/readme.md:385-391` 只有 `union_mask bool` 与稀疏 occurrence masks。
- 实现计划 `:108-140` 直接输出 `ligand_area_target bool`，却要求复用“现有 voxel 主损失”。
- Pocket `voxel_point_stage1_losses.py:178-217` 与 wrapper `:370-385,824-829` 只从 `ligand_dist_map` 构造 dense target。

“复用旧损失”现在不是可执行契约。建议新增直接 binary-target 接口；若要从 mask 转 distance，必须另写数学定义并经用户批准，不能为兼容 key 静默伪造 1.7 Å distance map。

### H-04：buffer/core 的监督语义自相矛盾（硬阻塞）

- 实现计划 `:103,106`：buffer 仅作上下文、不重复计核心指标。
- 同文档 `:128` 又让 receptor loss 对所有 batch receptor atoms 计算，并在 `:369` 把 core-loss 列为未决。
- Pocket 模型与 loss 已明确用 `atom_is_in_core_box`（`stage1_model.py:8,16`；`voxel_point_stage1_losses.py:64-92`）。

建议第一版冻结为“buffer 只参与消息传递；binding loss 和核心指标仅对 core mask 计算”。否则相邻 BOX 会重复监督外围原子并改变样本权重。

### H-05：“两项总损失”与保留 P head/P_probability 不一致（硬阻塞正式配置）

- 主计划 `:169-180` 保留 P head、P anchor、real/P cross-attention。
- BOX 契约 `:326-336` 和主计划 `:524-543,678-680` 要求后续保存可解释的 `P_probability` 与 P features。
- 实现计划 `:121-140,270-278,351-359` 把总损失/训练 step 写死为 voxel+receptor 两项。
- 旧 CPC1 有 `ligand_pseudo_loss`，用于直接监督 P。

若取消 P auxiliary loss，必须证明 P head 如何获得有效监督；否则后续不能把 `P_probability` 当已训练概率。建议明确 CPC1→CPC2 和 P auxiliary 的保留/权重，或明确删除 P probability 依赖。两者不能同时含糊保留。

### H-06：两个不同的“diff”存在同名碰撞风险，不应先做二选一

- BOX 契约 `:64,505-506` 独立列出原始 `diff = exp - sim`。
- Pocket `density_channel_builder` 的 56 通道 recipe 会先在每个 BOX 内拟合 `a*sim+b`，再生成拟合残差及 Gaussian/DoG 派生通道。
- 两者可以同时存在并服务不同消费者；现有问题是名称和消费者映射没有写清，而不是已经证明必须二选一。

建议分别命名 `raw_exp_minus_sim_cube` 与 `legacy_fitted_residual_*`，先画出模型输入/产物消费者与 provenance。只有实现计划把二者映射到同一个通道时，才需要用户选择或定义同时消费的 ordered recipe；任何一方都不能同名替换另一方。

### H-07：`hardmask` 与“不要 voxel_valid_mask”可能被错误合并

- 新计划正确地不想持久化 BOX padding 有效区 mask。
- Pocket 的 `hardmask` 是 receptor voxel occupancy，`density_channel_builder.py:405-449` 的部分通道使用它。

两者不是同一字段。实现计划应明确“没有 `voxel_valid_mask`”不等于删除在线 receptor occupancy；否则 56 通道和旧模型输入会静默改变。

### H-08：用户要求 0.3/0.5，主计划仍是 0.3/0.6

- 本轮用户明确要求 covF1、1to1F1 在 0.3/0.5。
- 主计划 `:914-927,1096-1098` 使用 0.3/0.6。
- Pocket 旧 evaluator 默认也是 0.3/0.6，但其数学口径还不是 IoU。

用户已经冻结**报告**必须包含 0.3/0.5；这不阻塞 Find 权重训练，但正式指标文档和 evaluator 必须同步。0.6 可作为具名诊断。selector gate 的 `M_instance` 是否也从当前 0.3/0.6 改为 0.3/0.5 是另一项决策，不能因报告阈值改变而自动跟改。若 checkpoint 主指标采用 threshold-free full-map voxel average precision，则不受该阈值漂移阻塞；若采用 Dice/cov/top-K，则还要先冻结所有候选共享的阈值政策。

### H-09：同名 coverage / one-to-one 指标数学定义不同

- 主计划 `:922-925`：统一 IoU 阈值；one-to-one 是阈值图最大匹配。
- Pocket `voxel_evaluator.py:132-275`：两个非对称 coverage；先最大化 `sqrt(pred_cover*gt_cover)`，再过滤固定匹配。

不能直接复用旧 evaluator 并仅改阈值。可复用计数骨架，IoU、matching 与 top-K 必须重写。

### H-10：`exp` 被写成“1 Å”，实际 voxel 只接近 1 Å

- BOX 契约 `:54` 写“已重采样 1Å”。
- A–G code-near README `:359,365-371` 明确 target=1.0 Å，但实际 `voxel_size_xyz` 由偶数 shape/物理长度决定，通常不逐轴精确等于 1.0。

实现计划已有 `voxel_size_xyz` 字段，这是好的；文案应改成“target 1 Å，必须读取 artifact 实际 voxel size”，避免模型或增强硬编码 1.0。

### H-11：现有 h200 单卡脚本的注释与真实命令不一致

Pocket Plus `sbatch/h200/1gpu.sbatch:5-6` 声称可传 experiment；但 `:48-55` 的 custom hook 实际硬编码 `+experiment=emb_unet`。若照注释提交 Find，会跑错实验。

Find 必须新建/修正专用 sbatch，并以冻结后的 run command hash 验收；不得把现有模板视为安全启动器。

## 四、全图推理、selector 和评估的遗漏

### U-DOWN-01：滑窗 request 没有合法身份

`Stage1BoxRequest` 强制 box_type/box_id，但 runtime sliding window 不是 center/bias/context/infered_box，也不应自动成为盘上 BOX。应有 run 内 `runtime_window_id/request_kind=sliding_window`，只有物化时才创建持久 box_id。

### U-DOWN-02：全图拼接契约还不能直接编码

主计划给出了 Gaussian 与 sum/weight 公式，已明确 window 输出是 sigmoid probability，并指定 probability accumulator / `P_global` 为 float32；仍缺：

- 每轴 starts/stride 枚举和覆盖保证；
- adapter 在模型 logit 后执行 sigmoid 的确切边界，以及 writer 如何拒绝误传 logit；
- `weight_sum` dtype、累加/reduce 顺序和跨 rank 确定性；
- `weight_sum==0` 的失败政策；
- receptor window 输出丢弃还是归并；
- 大图 memmap/chunk 与原子落盘；
- 失败/部分图 inventory。

旧 Gaussian 的 `sigma_ratio*max_dim` 也不等于新规格 normalized-coordinate `sigma=0.5`，不能直接复制参数。

### U-DOWN-03：正式指标契约不完整

用户已要求正式报告 IoU 0.3/0.5；还需要同步正式文档并冻结 Dice macro/micro、top-K 排序与统计单位、空 GT/空预测、阴性图、最大基数匹配 tie-break 和测试集综合规则。PDB bootstrap CI 是推荐的正式报告增强项，并非本轮用户或三份核心文档已经要求。旧 evaluator 还有 top-K 候选 ID `searchsorted` 后才验相等的潜在越界，应在重写时覆盖。

### U-DOWN-04：feature-source 字段仍是“具名但未命名”

BOX/主计划正确要求 producer module、checkpoint、channel、dtype、frame，但尚未选择实际导出层。它不阻塞 Find 权重训练，阻塞正式首次局部物化和 Stage2 数据发布。

### U-DOWN-05：selector gate 与最终报告阈值尚未调和

Stage1 selector 的 independent-max oracle 已经冻结，不属于待决项。仍待调和的是：主计划用 `M_instance` 的 0.3/0.6 选择 `tau_G`，而用户要求最终报告使用 0.3/0.5。必须决定 gate 是否随新指标重标定，并把 oracle 训练标签、gate calibration 和最终 report 的职责分开。

### U-DOWN-06：测试期 GT 隔离未规定

BOX overlap addon 可以提供 occurrence IoU；Stage1 训练侧只据此派生 independent-max `q_i`，不消费 Stage2 A/B 矩阵，也不运行 Hungarian。Stage2 训练侧才从 occurrence overlap 派生 A/B/O 并执行身份内匹配。train/val loss 侧与 calibration scorer/evaluator 侧可以读相应标签；Find/proposal/selector 的 test inference 必须完全 GT-blind，评分另起 evaluator。Stage2 统一用 `gt_blind_regime=fully_gt_blind|spatial_overlap_gt_blind`，并另记 `ccd_candidate_source`、`count_source` 与 `oracle_side_information`；GT-derived identity/count 只能进入后一档。两档都不得让 occurrence mask/overlap 进入模型侧。仅靠“代码不要用”不足，建议 inventory 或权限层隔离。

## 五、Stage2 计划遗漏

### U-S2-01：用户所说“同样验证集和指标”不能字面套用

Stage2 输出 coverage 矩阵和 `(proposal, CCD, prompt)` 配对，不输出新 mask（`模型总规划_v2.md:35-45`）。因此：

- 可以复用同一 PDB split/test family 和上游固定 mask；
- 可报告 Stage2 接受后的端到端几何 Dice/covF1/1to1F1；同一 blob 被多个 slot 使用时几何上只计一次；
- Dice 不是 Matcher 的内在训练指标；
- Find top-K blob 与 Stage2 top-K pair 是两种对象，不能共用一个字段名。

Stage2 还缺正式评价表：O 的 PR-AUC/F1，A/B 回归误差与校准，身份+几何同时正确的 decoded-pair F1，假阳拒绝、merge/split、seen/unseen CCD、count 分层。

### U-S2-02：Stage2 train 材料是否 OOF 未决

用 final Find 在它见过的训练 PDB 上产材料不会直接泄漏 test，但会造成堆叠分布偏乐观。cross-fit（以及 selector 的对应 cross-fit）是更严谨但高成本的推荐路线，尚未被当前计划或用户冻结；另一个选择是保留独立 downstream-train，但它必须在 Find train 冻结前预留并从 Find train 排除。若选择 in-sample，manifest 必须标记并说明结论边界，但在用户作成本/科学取舍前，不应先绝对宣告它“不能用于任何正式结论”。

### U-S2-03：CCD candidate list/count 的难度契约缺失

Stage2 计划假设推理期用户提供身份候选与 count（`模型总规划_v2.md:19-21,228-230`）。测试若使用 GT identity/count，应明确叫 `oracle-candidate-list/oracle-count`，并固定难负 CCD 配方；否则不同 run 的匹配难度不可比较。

### U-S2-04：当前只有 Stage2 设计，没有实现计划/代码

## 六、有益一致与有意差异

以下设计已经对齐，修订时不应破坏：

- **新 NPZ 压缩与 A–G 未压缩 helper 是有意的 artifact 范围差异**：BOX 契约 `:14,162-174,647` 要求 Stage1 新 NPZ 压缩；A–G `code/io_utils.py:8,87-104` 则冻结未压缩 `np.savez`。Stage1 应使用独立压缩 writer，不直接复用也不全局修改 A–G helper。这是复用风险，不是科学契约冲突。

- **Stage1 independent-max 与 Stage2 Hungarian 是有意的阶段分工**：Stage1 selector 以 `q_i=max_o IoU(M_i,G_o)` 和加性反链质量解决“选哪些几何候选”，不引入 A/B 或 occurrence 唯一分配；Stage2 Matcher 再以 A/B/O 和身份内 slot↔occurrence Hungarian 解决“候选与哪个 CCD occurrence 对应”。最终 `1to1F1` 只是 evaluator 指标。三者不互相推导，也不是待二选一的冲突。

- `probability_run` 与 `proposal_run` 分离，一张正式 `P_global` 可复用多套阈值/CLG。
- 全图概率与首次局部物化绑定同一 Find checkpoint/config source。
- F1 baseline、Group-parent、selected-final 三个物化角色分离；selected-final 可关闭且不是 Stage2 基础输入前提。
- oracle 构造、selector score、selection decode 和 optional refinement 分 run/addon，不原地覆盖。
- 训练与推理同一 materializer 的总体方向正确。
- zero-padding 在 BOX 与主计划中已经一致。
- `infered_box` 是有意冻结的历史 schema 拼写，属于中性差异，不应被代码自动“纠正”。
- `pin_memory` 默认关闭、无 `voxel_valid_mask`、`infered_box` 初始训练权重为 0 都是合理的基线选择；它们需要配置/测试，而不是额外争论。

## 七、建议的解决顺序

1. 用户先冻结 Find 权重训练必需项：binary target 处理、core-loss scope、P auxiliary/CPC curriculum、两个 density diff 的消费者/命名和 train/val 划分原则。calibration 的具体 manifest/去冗余关系不是权重训练门禁；若还想保留独立 downstream-train 选项，须在 train 冻结前预留该集合。
2. 确认文档权威关系，建立 Stage1 execution log/mapping。
3. 从干净 Pocket Plus `4d798c9` 建实现分支。
4. 先解决 origin、binary target、core mask、hardmask 四个接口。
5. 用 center-only + 无增强完成 parity、backward、tiny overfit。
6. 完成 F/G/final keep-list、正式 train/val 与 box_index。
7. 冻结完整 baseline config，运行 CPC1→CPC2（若获确认）。
8. 全图引擎与指标 toy 实现可和上述步骤并行；checkpoint 正式选择前冻结其 full-map monitor。任何阈值/后处理调优前，再冻结 calibration manifest/去冗余关系，并把用户已要求的报告 0.3/0.5 同步正式指标文档。
9. MAT-CLG/selector 按已冻结的 independent-max oracle 实现并通过小树穷举 reference test；另行冻结 selector gate metric 和 dense-rank storage。它们不阻塞 `P_global` 或基础 metric 实现。
10. 另建 Stage2 实现计划，决定 cross-fit/in-sample/独立 downstream-train 与 CCD/count 评价协议。

只有第 1–7 项中与 Find 权重训练相关的内容完成后，一次 GPU 长训练才应被称作正式 Find；test family、independent-max oracle 的实现与验证、selector gate、rank storage 与 Stage2 路线不阻塞 Find 权重训练，但分别阻塞它们所属的正式下游阶段。此前的运行应明确标成工程 smoke 或 pilot。
