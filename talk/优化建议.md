# Stage1 / BOX 审阅：优化建议

> 本文只给结构、存储、实现与运行优化建议；它不替换 `Stage1训练实现计划.md`，也不把尚未实现的模块写成既成事实。所有涉及科学语义的改动都应先在正式规格中冻结，再进入执行日志和代码。

## 总体建议

最值得优先做的不是换网络，而是建立一个明确的 **AdaLigand→Pocket Plus 兼容边界**。当前最大风险都聚集在这个接缝：半体素 origin、二值 mask 对旧 distance loss、core/buffer、P head 监督、旧 hardmask。把这些转换封装在一层并用 parity 测试钉死，之后的训练和全图推理才能真正共用一条路径。

优化顺序建议为：

1. 先保证语义 parity 和可复现；
2. 再记录真实 CPU/GPU/IO profile；
3. 最后针对被测出的瓶颈优化。

本文的 `P0/P1` 是**相关阶段内**的优先级：`P0` 表示进入该建议所针对的阶段前必须处理，`P1` 表示重要但可在正确基线后推进；它不是全项目统一时间线。例如 half-voxel 是 Find forward 前的 P0，dense rank 是首次 CLG 物化前的 P0，二者都不等于“今天同时阻塞 Find smoke”。

## 1. 模块与框架

### O-P0-01：增加 anti-corruption adapter，不让遗留字段渗入新契约

建议新建一个很薄的 Find adapter，职责仅包括：

- `origin_center_xyz → origin_corner_xyz` 的确定性转换；
- `receptor_* → atom_*` 的逐字段映射；
- 生成模型必需的 `atom_coord_centered_world`、corner 语义 local voxel 坐标、core mask 与 receptor occupancy mask；
- 把二值 `ligand_area_target` 接到明确的 binary-target loss 接口；
- 把 Pocket Plus 的复杂输出裁成带具名语义的 `FindOutput`；
- 导出后续真正需要的 P/receptor feature hook。

它不应重新实现主干，也不应让 Dataset 假装产出旧式 `ligand_dist_map`。这样 Pocket Plus 版本变化只需在 adapter 的 parity 测试里暴露，而不会静默污染 BOX 契约。

### O-P0-02：为 head/loss 建一张可机读矩阵

主计划保留 candidate C、P anchor、density cube、typed P、P head 和 real/P cross-attention，又取消 sparse-refine final head；实现计划却把总损失固定成 voxel+receptor 两项。建议把每个 head/loss 的状态写进配置并保存到 manifest：

```text
module_or_loss                  state
voxel_ligand_head               train
receptor_binding_head           train
P_head / P_probability          train | frozen | inference_only
P_pseudo_aux_loss               enabled | disabled
voxel_aux_receptor_grid_loss    enabled | disabled
candidate C / P anchor          train | frozen
real/P cross_attention          train | frozen
sparse_refine_final_head        delete
sparse_refine_loss              disabled
```

正式建议是先复现 CPC1→CPC2 的两阶段结构、保留 P 的直接辅助监督、关闭最终 sparse-refine；但这属于需用户冻结的科学/训练决定，不能由实现者暗中加入。若最终只保留两项损失，则必须证明 `P_probability` 仍具有可解释训练信号，否则下游不能把它当有效概率使用。

### O-P0-03：训练、验证、窗口推理共享“样本物化函数”，不是只共享类名

把无随机性的核心实现成纯函数：

```text
materialize_find_sample(asset_view, geometry, target_mode, augmentation_state)
    -> FindSample
```

训练 provider、固定验证 provider、滑窗 provider 只负责产生 request；裁剪、密度通道、受体选择、坐标与 collate 只走这一个函数。测试应证明同一 resolved geometry 在三种 provider 下输入逐元素一致。仅让三条路径都叫 `Stage1BoxDataset`，但内部有条件分支复制逻辑，并不能防漂移。

### O-P0-03A：保持 Stage1 selector 与 Stage2 Matcher 的监督边界

Stage1 selector 的任务是从一棵候选树中选择合法反链。继续使用已冻结的 independent-max 质量

```text
q_i = max_o IoU(M_i, G_o)
Q_GT(S) = sum(q_i for i in S) - lambda_count * |S|
```

可以保留逐节点加性结构和高效精确树 DP。多个候选可各自对同一 GT 取得高 `q_i`，这是该选择目标的有意性质；冗余选择由反链约束与数量惩罚共同控制。不要为了“看起来更像匹配”而把 Stage2 的 A/B 覆盖矩阵或 Hungarian 引入 Stage1，这会增加标签、数据和求解复杂度，却不直接服务于 Stage1 的选择职责。

Stage2 Matcher 再对选出的 blob 与 CCD/occurrence 做 A/B/O 监督及 identity 内 slot↔occurrence Hungarian，用于身份、merge/split 与 slot 置换消歧。最终报告的 `1to1F1` 是第三条独立 evaluator 路径。建议在包边界、配置键和单元测试名称中都保留这三种前缀，防止以后再次串线。

若要观察 independent-max 是否在特定数据上过度偏爱同一 occurrence，可只读报告 `same_best_occurrence_multi_selected_rate`、每个 GT 的 selected-candidate 数量分布及数量惩罚敏感性；这些是诊断和消融，不得在未改正式规格时暗中变成一对一训练目标。

### O-P1-04：把 request geometry 与 materialized geometry 分层

BOX identity 应保存冻结 request；jitter/rotation 形成一次临时 resolved geometry。建议结构为：

```text
FrozenBoxRequest -> resolve_augmentation(seed, epoch) -> MaterializedGeometry -> crop
```

这样增强不会回写 box_id/provenance，也能明确“先改变裁剪几何再读资产”，避免裁完后只旋转部分张量。

### O-P1-05：给 train/infer/eval 各自定义严格的输入 inventory

- train：允许 GT target 与 overlap label。
- Find/proposal/selector inference：只允许原始整图资产和冻结配置，完全 GT-blind。
- evaluator：读取预测产物与 GT，但不再执行模型。

尤其在 selector/Stage2 阶段，测试模型/featurizer 进程应物理上不装载 overlap addon，防止无意读取空间 oracle 字段。Stage2 统一记录 `gt_blind_regime=fully_gt_blind|spatial_overlap_gt_blind`、`ccd_candidate_source`、`count_source` 与 `oracle_side_information`；GT-derived identity/count 只能归入后一档。

## 2. 存储结构

### O-P0-06：不要为每个 CLG 无条件保存 dense `threshold_rank_map`

`80³ uint8` 是 512,000 bytes，约 0.488 MiB。若一张图达到 300 个 CLG，上限约 146.5 MiB/PDB；22,386 张图的理论上界仅该字段就约 3.44 TB（十进制）。而第一版 selector 实际主要读取 parent voxel 处的 rank，BOX 契约 `:275-277` 也承认 `rank_at_parent_voxel` 可确定性派生。

建议按以下顺序验证：

1. 第一版只存 `rank_at_parent_voxel[K_v]` 和重建所需的阈值/局部概率引用；
2. 若确有消费者需要完整局部形态，再按 run 可选保存 chunked dense map；
3. 在正式冻结前实测压缩率、随机读取和总量，不用 `N_abs×PDB 数` 的最坏值直接设计整个存储。

这是一项**需要先修改 BOX 正式契约的优化提案**。当前契约仍强制保存完整 dense map；在用户批准收口前，实现不得自行用稀疏字段替换它。可先用真实 calibration 数据做只读体量/压缩基准，再提交是否改契约的决策。

### O-P0-07：逻辑 schema 与物理容器解耦

当前 per-PDB compressed NPZ 对小型不可变 add-on 很简单。需要准确区分成本：读取一个 NPZ member 只解压该 member，不会解压整个 archive；但压缩 member 不能直接 mmap，读取一个很大的 member 通常要把该 member 完整解压。BOX 的新 add-on 位于新 namespace/file，不会重写旧 add-on；只有修改同一个 NPZ 时才需重写该文件。大量 ragged 大 member 或高频局部随机读仍值得基准。建议 BOX 契约继续只拥有字段、shape、dtype、ID 和引用关系；物理容器通过一个小型基准后冻结：

- 小规模基线：原子写入的 immutable compressed NPZ shard；
- 大规模候选：评估 chunked/sharded 容器或“索引+不可变数据块”；
- 无论容器是什么，都由 manifest 给出内容 hash、schema version 和 inventory。

不要在没有 profiling 前直接全局换格式，也不要把某个容器的限制写成科学契约。

### O-P0-08：为跨 run `box_id` 建持久且并发安全的分配方案

当前 BOX 契约要求 `box_id[int64]` 在 `(pdb_id, box_type)` 内跨 run 唯一且永不复用，现有 add-on join 也只携带该 `box_id`。因此当前 schema 下可选的是：

- 持久 registry/原子 allocator，把自然身份映射为永不复用的 int64，并支持失败恢复与冲突测试；或
- 由自然身份稳定派生 int64，同时保存 collision table、显式处理碰撞并保证旧 ID 永不再分配。

“run 内连续 local ID + run scope”只能作为 **schema-v2 变更提案**：必须把所有 join key 改成 `(source_run_id, local_box_id)`，同步修改 BOX 契约和消费者后才合法；在当前契约下不能直接采用。

### O-P1-09：保留现有“概率 / proposal / selector / selection / refinement 分 run”设计

这是三份文档中最好的结构之一：`probability_run_id` 与阈值/CLG 解耦，使一次昂贵 GPU 全图概率可供多套 CPU proposal 配方复用。实现时应继续保持 append-only add-on，而不是把新阈值、新 selector 分数写回旧文件。

### O-P1-10：新 Stage1 writer 独立于 A–G 旧 helper

BOX 契约要求新 NPZ 压缩；A–G 的 `io_utils.py` 当前有明确的未压缩 writer 和回归要求。建议 Stage1 新建“临时文件→fsync/close→原子提升→hash/validate”的独立 writer，避免为了 Stage1 改坏已完成的 A–G artifact 语义。

## 3. 数据读取与缓存

### O-P0-11：LRU 用字节预算，不用固定 PDB 个数

实现计划 `:296-308` 建议 worker 缓存整图对象，旧配置 `cache_size=128`。整图 exp/sim 可非常大，按“128 个 PDB”缓存可能直接耗尽 RAM。建议缓存：

- 已打开的只读 handle / mmap / chunk reader，而不是必然 materialize 整图；
- 按估计 resident bytes 淘汰；
- 分别统计 hit rate、resident bytes、打开文件数和单 PDB 峰值；
- 极大图可绕过 cache，不能把它们挤进统一条目。

### O-P1-12：按 PDB 分组调度以复用资产，但保持采样统计可控

训练可在“来源配额已经确定”后把短小的一段请求按 PDB 分组，降低反复开图与建 receptor 索引的成本；验证和全图推理更应让一个 rank 在一段时间内独占一个 PDB。要记录这是否改变 batch 相关性，并用固定 seed 保持请求集合不变。

### O-P1-13：密度通道先做 parity，再做消融

旧 `enabled_channels: [all]` 实际是 56 通道。单样本 `56×80³×float32` 约 114.7 MB（109.4 MiB），batch、prefetch 与多 worker 会成倍放大 host RAM/H2D。建议：

1. 先区分并分别命名契约独立产物 `raw_exp_minus_sim_cube=exp-sim` 与 56 通道 recipe 内部的 `legacy_fitted_residual_*`，画出各自消费者；只有两者确实映射到同一模型通道时才形成科学决策冲突；
2. 冻结 exact channel names/order/normalization，并在一组旧 fixture 上逐元素 parity；
3. 记录每个通道构建耗时、H2D、显存和模型增益；
4. 再比较精简通道集、低精度传输或按 PDB 可复用中间量；
5. 任何精简都作为显式实验，不在 adapter 内偷偷改变基线。

## 4. 训练与 checkpoint 选择

### O-P0-14：正式基线从干净、已固定的 Pocket Plus commit 起步

当前本地 Pocket Plus HEAD 为 `f4c3e5c`，工作树里的冻结 BN/Dropout 修改与远端 `origin/大重构` 的 `4d798c9` 相符，另有无关删除/记忆改动。不要从当前脏 clone 直接开始正式适配；应从干净的 `4d798c9` 建分支，并在 Ada manifest 同时记录：

- AdaLigand commit；
- Pocket Plus commit；
- 两仓配置 hash；
- 若确需 dirty run，则保存 diff hash 并显式标成非正式。

### O-P0-15：两级 checkpoint 选择

旧 CPC1 配置监控 `pseudo_PRAUC`，不适合作为新 Find 的唯一主指标。建议：

1. 训练内按冻结的 BOX-level threshold-free 指标保存 top-K，例如 ligand-area PR-AUC，receptor 指标独立报告；
2. 对少量 top-K checkpoint 在固定 validation PDB 做完整图推理，按冻结的 full-map 指标选正式 checkpoint；
3. calibration 只选阈值/后处理，不用来更新权重或替代 validation 选 checkpoint；
4. test 从不参与上述选择。

### O-P1-16：pilot 与 formal 两套运行等级

不要把运行成熟度、上游是否见过样本、checkpoint 角色塞进同一个枚举。建议 manifest 固定三个正交字段：

- `run_tier=unit|pilot|formal`
- `producer_fit_relation=in_sample|out_of_fold|held_out`
- `checkpoint_role=phase_candidate|fold|final`

这样 A–G 尚未放行时仍可高效推进代码和过拟合测试，又不会把临时 C/D/E 子集训练误标成正式 Find。

## 5. 全图推理与多阈值

### O-P0-17：一张 PDB 一个逻辑 owner，数组使用 chunk/memmap

按主计划保留单逻辑写者。调度层让一个 PDB 只归属一个 rank；窗口 batch 在该 rank 内运行，CPU writer 通过有界队列累计到 chunked array 或 memmap，防止 `probability_sum`、`weight_sum` 和多份窗口同时常驻。若必须拆一张超大图，定义 partial sum 的确定性 reduce，而不是多个进程无锁写同一文件。

### O-P1-18：辅助通道与窗口几何分开 profile

全图推理瓶颈可能不是 GPU，而是每个重叠窗口重复构造 56 通道。应分别计时：asset read、crop、density channel、receptor query/collate、H2D、forward、writer。只有确认某些通道可从全图中间量等价切片时，才提升为 per-PDB cache。

### O-P1-19：首次局部物化按 Group-parent 去重 forward

一个 CLG 只应运行一次 Group-parent Find；多个 candidate 只通过 membership 读取共享表。同一几何若被不同逻辑对象引用，可建立 materialization request 去重表、只执行一次 forward，再让多个不可变身份引用同一 feature block。F1 baseline 与 Group-parent 的逻辑身份仍不能合并。

### O-P1-20：overlap 用稀疏集合统计

proposal 与 GT 都已有稀疏 voxel index。预排序/编码后用线性 merge、哈希或压缩位图统计交集，生成 `intersection/|pred|/|gt|/IoU` 标量；避免为每一对候选×occurrence 反复 materialize 80³ dense mask。

## 6. 评价与测试集

### O-P0-21：新建 Ada 指标层，只复用旧 evaluator 的计数骨架

可复用旧代码的 TP/FP/FN、标签压缩和全局累计结构；必须重写 IoU 矩阵、每阈值最大基数匹配、top-K 语义和空样本政策。指标实现本身应有 version/hash，并以构造小图覆盖：一对多、多对一、匹配冲突、空 GT、空预测、同分排序。

### O-P1-22：top-K 主指标外增加 GT Recall@K

PDB 级“任一成功”在有多个 occurrence 时过于宽松。保留用户要求的 top3/4/5-success-ratio，同时增加 occurrence 级 GT Recall@K 和阴性图 false positives/PDB，能更早发现模型只命中一个容易配体的问题。

### O-P1-23：test master pool 只建一次

用户已要求 test 相对 train/val 去冗余并在 test 内去冗余。**推荐默认、待用户确认**的是再把 calibration 纳入 development forbidden pool：随后对剩余候选聚类选代表，得到 master test pool；多个测试家族从它切成互斥集合。若用户不把 calibration 纳入，必须在看 test 结果前预注册原因和风险。若为了诊断允许家族交叠，manifest 明确 membership，综合统计不得重复计数。

## 7. selector 与 Stage2 的分布优化

### O-P1-24：对正式下游材料评估 cross-fitting（高成本、待用户决策）

用一个在训练 PDB 上见过 GT 的 Find 生成该 PDB 的 selector/Stage2 输入，不是测试泄漏，但会让下游训练材料偏乐观。cross-fit 是更严谨的推荐路线，**不是现有正式计划已经冻结的硬要求**；先 profile 一个 fold 的 wall-time、存储和收益，再由用户在 OOF、in-sample 或独立 downstream-train 间选择：

- 若选择 cross-fit：K-fold Find 为各自未见过的 fold 生成 `P_global/proposal/materialization`；
- 若选择 cross-fit：selector 对 Stage2 train 的 selection 也做 cross-fit；另一条路线是预先保留独立 downstream-train；
- 仅在 cross-fit 路线中，final Find/selector 不负责 OOF train，只为 val/calibration/test 生成正式评估材料；若用户选择 formal in-sample，final 模型还会生成具名 train 材料；
- 选择 in-sample 时，必须用 `producer_fit_relation=in_sample` 标记并限定可支持的结论；不能在用户尚未决策前把它绝对写成“不可用于任何正式结论”。

每条材料记录 `producer_fold_id` 与各级 checkpoint hash。

### O-P1-25：Stage2 manifest 只引用上游大数组

Stage2 dataset manifest 应保存 `split/probability/proposal/materialization/selector/selection/feature-source/CCD-list` 的 run ID/hash 和 route，不再复制 voxel/P/receptor 大数组。这样 F1 baseline、多阈值 selection 和不同 Stage2 配方可以共享上游 artifact，又不会混淆来源。

## 8. 推荐优先级

| 批次 | 建议 | 原因 |
|---|---|---|
| 立即 | adapter、几何/target/core parity、head/loss 矩阵、干净依赖 commit | 决定训练是否正确 |
| Find smoke 前 | 字节预算 cache、56通道 profile、两级 checkpoint、run tier | 决定能否稳定运行和复现 |
| 正式 Find 权重训练前 | final keep-list、train/val、box index、baseline config、manifest/hash；若保留独立 downstream-train 选项，须先预留并排除该集合 | 决定权重训练是否正式、可复现，并避免事后伪造 held-out 下游集 |
| 阈值/后处理调优前 | calibration manifest 与用途、是否纳入 dedup forbidden pool | 防止调参边界漂移 |
| selector/Stage2 正式材料前 | cross-fit/in-sample/独立 downstream-train 决策与一 fold 成本 profile | 决定堆叠分布与结论边界 |
| 全图前 | 单 PDB owner、chunk writer、指标 v1、小图匹配测试 | 决定全图和报告可信度 |
| selector/Stage2 前 | dense-rank 契约是否变更、物化去重、feature source、GT-blind inventory | 决定体量、可追溯与测试隔离 |

最重要的取舍是：先交付一个可证明语义正确的 center-only pilot，再扩到三源、全图；cross-fit 是否进入正式路线由成本 profile 和用户决策决定。这样不会让“迫切启动”变成带着半体素错位和错误 loss 跑一场昂贵训练。
