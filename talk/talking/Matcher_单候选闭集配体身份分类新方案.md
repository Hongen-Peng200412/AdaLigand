# Matcher 单候选闭集配体身份分类新方案

> 状态：科学设计讨论稿，尚未进入工程实施。  
> 最近更新：2026-08-08。  
> 本文记录新 Matcher 的当前有效方向、已经确认的建模决定、可选变体和待决定事项。本文不表示相应代码、数据清单、训练或评估已经完成。

## 1. 文档结论与边界

新 Matcher 不再把一个 PDB 的全部候选与全部配体实例组成约为 $N\times M$ 的匹配矩阵，也不再使用匈牙利算法求全局一一分配。新任务一次只接收一个候选 $c$，再接收该 PDB 中按化学身份去重后的配体集合，判断候选属于哪个配体身份，或判断候选是假阳性。

这项任务应称为**候选到已知配体清单的闭集身份分类**。这里“闭集”表示模型只能从当前 PDB 已知的有限配体身份中选择，不能把它描述成仅凭密度从整个化学空间识别未知分子。

新路线的直接目标是降低当前 Matcher 的优化难度。旧 Matcher 在训练集上的粗分支和细分支都没有表现出令人满意的收敛；测试集中的同身份匹配错误可能低估指标，但不能解释训练损失本身难以下降。因此，新路线首先改变任务定义，而不是只继续调整旧网络的容量或损失权重。

旧文档 [`Matcher_输入与产物概览.md`](Matcher_输入与产物概览.md) 和 [`Matcher_模块结构概览.md`](Matcher_模块结构概览.md) 描述的是旧 O/O′、多候选—多槽位和匈牙利匹配实现。它们继续作为历史实现说明存在，但其中下列假设不再自动进入新 Matcher：

- 一个样本必须同时处理整份 PDB 的全部候选；
- 主要输出是 occurrence 槽位与候选组成的二维矩阵；
- 需要通过匈牙利匹配建立一一分配；
- 必须保留原来的四加四粗—细 Block 结构；
- O/O′ 是最终任务的唯一主要监督。

当前只讨论科学任务和模型边界。Git 分支、文件删除范围、正式目录、训练脚本、服务器资源接管和端到端执行方式，等用户明确提出“讨论具体非科学的实施性细节，之后端到端实现、训练和评估”时再集中决定。

## 2. 样本、配体清单与分类目标

### 2.1 基本实体

对一个 PDB，定义按化学身份去重后的配体清单：

$$
\mathcal I=\{\ell_1,\ell_2,\ldots,\ell_M\}.
$$

$\ell_i$ 表示第 $i$ 个配体身份，$M$ 是该 PDB 中去重配体身份的数量。同一个配体身份在 PDB 中出现多次时，清单中仍只保留一个身份。候选 $c$ 表示当前要分类的一个空间候选区域。

单候选标签暂按下式表达：

$$
y_c\in\{\mathrm{FP},1,2,\ldots,M\},
$$

其中 $y_c=i$ 表示候选属于配体身份 $\ell_i$，$y_c=\mathrm{FP}$ 表示候选是假阳性。最终分类概率暂时采用一个带掩码的 $(M+1)$ 类 softmax：

$$
p(y_c\mid c,\mathcal I)
=
\operatorname{softmax}
\left(
s_c^{\mathrm{FP}},s_{1,c},\ldots,s_{M,c}
\right).
$$

$s_{i,c}$ 是候选 $c$ 与配体身份 $\ell_i$ 的相容性分数，$s_c^{\mathrm{FP}}$ 是仅由候选自身多模态信息产生的假阳性分数。不同候选独立分类，多个候选可以选择同一个配体身份，因此 Stage1 把同一真实区域错误分裂成多个候选时，不会被一一匹配约束强行改成不同身份。

### 2.2 已确认的简化

- 每次前向只处理一个候选和当前 PDB 的去重配体清单；批量计算可以把多个这样的样本合并，但科学定义仍是逐候选分类。
- 不使用匈牙利匹配。
- 同身份的多个真实 occurrence 不再是不同输出类别；新任务只判断化学身份，不判断该身份的第几个空间副本。
- 测试、验证和推理使用同一套逐候选解码定义。
- 如果配体清单经过过滤，真实目标身份不能被过滤后再把样本改标为假阳性；应保留目标身份或剔除该训练样本。

### 2.3 尚未冻结的标签边界

以下事项直接改变监督含义，实施前必须决定：

1. 候选与一个真实配体身份达到什么空间关系时记为正类。可使用体素重叠、原子覆盖、中心距离或它们的组合，但阈值尚未决定。
2. 一个候选同时覆盖两个不同配体身份时，是剔除歧义样本、选择覆盖最大的身份，还是改成多标签监督。第一版优先考虑剔除或选择唯一主身份，避免立刻改变为多标签问题。
3. 假阳候选来自哪些正式来源，以及如何避免“过于容易的背景框”主导训练。
4. 配体清单允许进行哪些过滤，以及金属、溶剂、小分子辅因子等类别是否全部进入清单。
5. 是否保留旧 O/O′ 或几何覆盖值作为辅助监督。它们不再承担全局匈牙利匹配，但仍可能帮助候选—身份相容性学习。

## 3. 两种数据模式与通用模型

当前仍保留两种数据模式。名称用于减少“模式一、模式二”的歧义；最终配置名可以在实施阶段确认。

### 3.1 `ground_truth_context`：模式一

模式一不依赖 Stage1 正式推理产物。它从已有真实标注和候选构造中建立训练样本，至少可以提供受体原子 A、受体伪原子 P 和以候选中心裁剪的实验密度 Map。模式一也可以由 Map U-Net 产生与 PP 相同生态位的采样点，但这些采样点不应伪装成 Stage1 产物。

### 3.2 `stage1_inference`：模式二

模式二读取 Stage1 推理候选及其特征，可增加 V 和由预测概率采样的 PP。模式二需要独立的数据装配和推理/评估入口，因为它的候选、口袋和假阳性定义可能与模式一不同。

### 3.3 模型的严格退化要求

两种模式使用同一套核心模型参数。模式二在模式一基础上增加输入和可训练增量，而不是建立互不相关的第二个模型。缺少 V、Stage1 派生 PP 或未来新增模态时，与这些模态对应的网络增量必须严格为零；提供这些模态后，相同模块才产生非零增量。

严格退化不能依赖“输入全零后模型大概学会忽略”。注意力层、线性层偏置和归一化都可能把零输入变成非零输出。更可靠的做法是在完整增量分支的出口乘显式门控或存在掩码，并使该门控在基线模式下精确为零。

模式二可以从已经训练好的模式一参数继续训练，同时增加新数据、新模态参数和原有参数更新。这不是只冻结主干、训练一个小适配器的传统微调。

## 4. 配体侧的三种表示

### 4.1 原生语言模型表示

对配体身份 $\ell_i$，先离线计算冻结配体语言模型输出 $e_i^{\mathrm{LM}}\in\mathbb R^{768}$，再通过可训练 MLP 得到原生表示：

$$
L_i^{\mathrm{native}}
=
\operatorname{MLP}_{\mathrm{native}}
\left(e_i^{\mathrm{LM}}\right).
$$

这一路是第一版的稳定基线，始终参与候选—配体打分。语言模型保持冻结，原始 768 维向量应离线物化并保留模型身份、SMILES 规范化方式、序列长度、是否截断和失败原因。

### 4.2 清单上下文表示

同一个 PDB 的其它配体身份为 $\ell_i$ 提供上下文：

$$
\widetilde L_i^{\mathrm{inventory}}
=
\operatorname{CrossAttn}_{\mathrm{inventory}}
\left(
L_i^{\mathrm{native}},
\{L_j^{\mathrm{native}}:j\ne i\}
\right).
$$

这一路让模型学习“当前 PDB 的候选配体清单中，哪些身份彼此容易混淆”。查询必须排除自身。若 $M=1$，没有其它身份可读，清单上下文分支应精确返回零，而不是建立一个虚假的空 token。

### 4.3 自身完整配体图表示

配体图编码器把 $\ell_i$ 的完整原子图编码成未塌缩原子 token 集合 $G_i$。随后由配体原生表示读取自身原子图：

$$
\widetilde L_i^{\mathrm{graph}}
=
\operatorname{CrossAttn}_{\mathrm{graph}}
\left(L_i^{\mathrm{native}},G_i\right).
$$

语言模型向量提供大规模 SMILES 预训练先验，完整配体图提供原子、键和项目已有结构字段。图分支不能只把图提前 readout 成一个 token；若键值集合只有一个 token，注意力 softmax 恒为 1，查询对读取结果的选择作用会消失。

为简化后续公式，候选读取前的两个增强表示分别记为 $L_i^{\mathrm{inventory}}=\widetilde L_i^{\mathrm{inventory}}$ 和 $L_i^{\mathrm{graph}}=\widetilde L_i^{\mathrm{graph}}$。它们仍是彼此独立的表示，不先与 $L_i^{\mathrm{native}}$ 相加或拼接成一个 token。

### 4.4 零初始化门控

清单上下文分支和完整配体图分支必须以零增量起步，避免训练初期未经验证的信息破坏原生语言模型基线。仅把门控放在候选读取之前仍不充分，因为后续注意力层可能根据候选键值重新产生非零输出。建议在两条完整的候选条件分支出口应用门控：

$$
Z_{i,c}^{\mathrm{inventory}}
=g_{\mathrm{inventory}}\,
\widetilde Z_{i,c}^{\mathrm{inventory}},
\qquad
Z_{i,c}^{\mathrm{graph}}
=g_{\mathrm{graph}}\,
\widetilde Z_{i,c}^{\mathrm{graph}},
$$

其中 $g_{\mathrm{inventory}}$ 与 $g_{\mathrm{graph}}$ 初始化为 0。门控本身可以先学习离开零点，再逐步允许相应分支更新最终分数。不要同时把门控和分支最后一层全部初始化为严格零，否则二者可能互相阻断梯度。

## 5. 候选侧保持未塌缩的显式模态

候选不能先被写成一个笼统的 `CandidateEncoder(A, PP, V, Map)` 摘要。A、P、PP、V 和未来受体语言模型 token 都具有空间位置和各自语义，应在配体查询读取之前保持为未塌缩 token 集合。

| 符号 | 当前语义 | 第一版或未来状态 |
|---|---|---|
| A | 候选附近的受体原子 token，包含三维坐标和原子/图特征 | 第一版正式模态 |
| P | 代表受体局部结构的伪原子 token；P 与 PP 是不同实体 | 第一版正式模态，精确盘上来源需在数据契约中复核 |
| PP | 从概率场采样得到的点；模式二优先由 Stage1 概率 top-k 采样，模式一可由 Map U-Net 派生同生态位采样点 | 第一版是否启用及点数仍待决定，不单独提前落盘 |
| V | Stage1 预测得到的带特征候选团块或掩码，可转换为带坐标点 token | 模式二新增模态 |
| Map | 以候选中心裁剪的实验密度网格 | 第一版正式模态，但由独立 U-Net 编码 |
| R | 未来按受体残基对齐的语言模型 token，例如 Luca 或 ESM-2 输出与残基坐标组成的 token | 后续新增模态，与 P 并列，不融合进 P 的定义 |

每种点化模态使用一个短小、显式的输入 stem 投影到共同维度，同时保留坐标、模态身份和存在掩码。第一版不建立注册器、通用插件系统或动态工厂；模型接口可以直接点名 `A_tokens`、`P_tokens`、`PP_tokens`、`V_tokens`，以后需要 R 时再增加一个明确参数。

## 6. 三种配体表示分别读取每一种候选模态

第一版采用**显式逐模态读取**，而不是把 A、P、PP、V 全部拼成一个无约束 token 集合后只做一次注意力。

对配体表示类型

$$
r\in\{\mathrm{native},\mathrm{inventory},\mathrm{graph}\}
$$

和候选点模态

$$
m\in\{A,P,PP,V\},
$$

分别计算：

$$
U_{i,c}^{r,m}
=
\operatorname{CrossAttn}_{r,m}
\left(L_i^r,T_c^m\right),
$$

其中 $T_c^m$ 是候选 $c$ 的第 $m$ 种未塌缩 token 集合。未来受体残基语言模型 token 作为新的 $m=R$ 模态自然加入这组显式读取，而不是修改 P 的含义。

每一种配体表示在读取候选后分别通过自己的小 MLP：

$$
\widetilde Z_{i,c}^{r}
=
\operatorname{MLP}_{r}
\left[
L_i^r,
U_{i,c}^{r,A},
U_{i,c}^{r,P},
U_{i,c}^{r,PP},
U_{i,c}^{r,V}
\right].
$$

缺失模态对应的整项必须精确为零并由存在掩码隔离，不能让空 token 参与 softmax。三种候选条件表示最后才拼接进入配对打分 MLP：

$$
s_{i,c}
=
\operatorname{MLP}_{\mathrm{pair}}
\left[
Z_{i,c}^{\mathrm{native}},
Z_{i,c}^{\mathrm{inventory}},
Z_{i,c}^{\mathrm{graph}}
\right].
$$

这里 $Z_{i,c}^{\mathrm{native}}=\widetilde Z_{i,c}^{\mathrm{native}}$；另外两项使用上一节的零初始化出口门控。这样，三种配体表示都真正读取了相应候选，而不是只有原生向量与候选交互、另外两个向量被动拼接。

显式逐模态读取会增加注意力模块数量，但它保留了清楚的科学含义，也便于单独关闭 A、P、PP 或 V 做消融。实施时应优先共享统一的短小计算函数，而不是为每一组合建立层层包装类；是否在不同 $r$ 或不同 $m$ 之间共享注意力权重仍未决定。

## 7. Map U-Net、V 调制与 Map 预训练

### 7.1 U-Net 输入不写死为单通道 48³

第一版保留独立的三维 U-Net 编码 Map，但 `Unet(Map)` 是概念简称，不等同于“固定接收一个单通道 48³ 数组”。一种重要备选是仿照 Stage1，把实验密度与体素化的受体原子编码特征在通道维拼接后送入 U-Net：

$$
F_c^{\mathrm{map}}
=
\operatorname{UNet}
\left[
\mathrm{DensityCrop}_c,
\mathrm{VoxelizedReceptorFeature}_c
\right].
$$

裁剪边长暂不固定为 48。数据记录必须保存候选中心、裁剪中心、体素尺寸、原点和实际窗口大小，使窗口变化不会改变空间语义。是否输入受体体素特征、输入哪些通道以及 U-Net 宽度均属于后续实施前的显存与消融决定。

### 7.2 第一版优先用 Map 特征调制 V

模式二中，V 是可点化的 Stage1 候选对象。U-Net 的多尺度特征可以在 V 点坐标处插值采样，并产生 V 的特征增量。具体调制形式可以是加法、FiLM 或短小 MLP；当前只确认“Map 特征调制 V”，尚未冻结算子。

模式一没有 Stage1 V 时，V 调制分支严格为零。Map U-Net 仍可通过 Map 摘要、预训练监督和 Map 派生 PP 获得作用，不需要伪造一个 V。

### 7.3 Map U-Net 的两类预训练任务

当前倾向让 Map U-Net 在正式 Matcher 之前接受两个层级的监督：

1. **逐体素多分类辅助任务**：类似 Stage1 的密集预测，但目标改为多类别。精确体素类别集合尚未决定；需要明确背景、五类配体和可能的受体体素如何编码。
2. **候选级主要任务**：从 U-Net 产生 `MapSummary`，通过 MLP 预测整个候选的宽类别。当前候选级类别至少考虑 `FP、小分子、糖、多肽、核酸配体、金属` 六类。

这两个任务的作用不是直接替代最终配体身份分类。它们为 U-Net 提供局部形态监督，并让 `MapSummary` 对候选是否为空、候选更接近哪一类配体具有可解释先验。

以下实施选择尚未决定：

- 先独立预训练 U-Net 再接入 Matcher，还是预训练后继续联合多任务训练；
- 候选级六分类是否对五类配体做类别重加权；
- 逐体素类别是否与候选级类别完全相同；
- Map 派生 PP 的采样规则、点数和初始特征；
- U-Net 的 Map 摘要取哪一层以及是否结合多尺度 decoder 特征。

## 8. 假阳性分数

假阳性不是某个配体身份的属性，因此不能由某个 $L_i$ 单独决定。第一版正式假阳性分数由候选自身的 Map 摘要和其它候选模态信息产生：

$$
s_c^{\mathrm{FP}}
=
\operatorname{MLP}_{\mathrm{FP}}
\left[
\mathrm{MapSummary}_c,
\operatorname{Readout}(A_c),
\operatorname{Readout}(P_c),
\operatorname{Readout}(PP_c),
\operatorname{Readout}(V_c)
\right].
$$

不存在的模态对应零增量。未来的受体残基语言模型模态可以增加自己的 readout。公式只表达当前科学边界；第一版是否需要所有 readout、采用何种 readout、是否让 Map 候选级预训练头初始化正式 FP 分支，仍需实验决定。

Map U-Net 可以预训练候选为 FP 的概率，但最终 Matcher 中的 $s_c^{\mathrm{FP}}$ 不应只读取 Map，因为受体原子、伪原子、Stage1 候选形态和其它点模态也能提供真假候选证据。

## 9. 配体语言模型候选

第一轮只考虑 MoLFormer 与 SMI-TED$_{289M}$。小分子必做；糖、多肽、核酸配体和金属是否进入最终训练尚未决定，但当前倾向先为五类中所有能合法编码的配体离线计算两套冻结向量，以免后续更换类别范围时重复准备。

### 9.1 MoLFormer

- 正式候选 checkpoint：`ibm-research/MoLFormer-XL-both-10pct`。
- 模型是 12 层、隐藏维 768 的 SMILES 编码器，使用掩码语言建模、线性注意力和旋转位置编码；`pooler_output` 可直接作为单个 768 维配体向量。
- 公开 checkpoint 使用 ZINC15 的 10% 与 PubChem 的 10%，约一亿条分子。论文中的完整规模实验使用最多约 11 亿条 SMILES，但不能把完整论文训练规模误写成当前公开 checkpoint 的训练规模。
- 训练前使用 RDKit canonicalization，移除了 isomeric information；超过 202 token 的分子被剔除。官方模型卡也明确说明没有对约 200 原子以上的大分子进行测试。
- 论文主要通过对 MoleculeNet 等任务微调证明表示能力；冻结向量也可用于相似度、可视化和下游预测器，但不能把论文结果表述为“冻结向量对所有任务都像 ESM-2 一样普遍优越”。

### 9.2 SMI-TED$_{289M}$

- 正式候选 checkpoint：`ibm-research/materials.smi-ted` 的 289M 参数版本。
- 模型是 SMILES Transformer encoder-decoder。编码器先接受掩码语言建模训练，再通过 encoder-decoder 的 SMILES 重建目标塑造 768 维潜在表示；官方接口 `model.encode(..., return_torch=True)` 直接返回单个配体向量。
- 训练语料是从 PubChem 整理的 9100 万条 SMILES，约 40 亿 molecular tokens；预处理最大长度为 202 token。
- 官方代码与示例的默认 SMILES 规范化使用 `isomeric=False`。因此默认冻结向量不会完整保留糖、多肽和核苷酸中非常关键的立体化学。
- 论文在小分子性质、反应产率、少样本学习和潜在空间结构上给出较强结果，但独立复现和社区使用积累少于更成熟的蛋白质语言模型。

### 9.3 五类配体的输入与训练覆盖

“能输入”只表示 tokenizer 和 202-token 上限允许该 SMILES 完成编码；“训练时用过”需要语料按类别统计。MoLFormer 与 SMI-TED 的公开材料都没有给出本项目五类标签的精确训练数量，因此不能把“PubChem 中大概率存在”写成已经量化的训练覆盖。

| 配体类别 | 能否输入 | 预训练覆盖能够确认到什么程度 | 主要风险 |
|---|---|---|---|
| 小分子 | 支持，是两个模型的核心目标域 | MoLFormer 明确训练于 ZINC/PubChem 小分子；SMI-TED 明确训练于 PubChem 分子 | 最稳妥，仍需处理盐、多个组分和规范化一致性 |
| 糖 | 短链、合法 SMILES 且不超长时可以输入 | PubChem 语料中应包含单糖、寡糖和糖苷，但官方未给类别数量 | 默认去除异构信息会丢失糖的关键立体化学；较长寡糖可能超长 |
| 多肽 | 短肽可输入；长肽常超过 202 token | PubChem 中可能含短肽和肽样小分子，没有专门肽序列预训练证据 | 长度、端基、修饰和立体化学；不应当成蛋白质语言模型使用 |
| 核酸配体 | 碱基、核苷和核苷酸通常可输入；寡核苷酸容易超长 | PubChem 中可能含碱基、核苷和核苷酸，没有专门核酸序列预训练证据 | 糖环立体化学、磷酸状态、长链超长；不适合替代核酸序列模型 |
| 金属 | 单离子和 tokenizer 已知的括号金属 token 可以输入，部分配位化合物也可写成 SMILES | PubChem 中含金属条目，但没有金属类别数量或配位覆盖保证 | 单离子向量信息量很低；SMILES 难以可靠表达三维配位几何、配位键和氧化态环境 |

五类都计算向量不等于五类都适合直接进入同一个监督任务。正式数据准备应为每个配体身份记录：

- 原始结构身份和原始 SMILES；
- 送入模型的规范化 SMILES；
- 模型名称、checkpoint revision 和 tokenizer revision；
- token 数；
- 是否超过上限、是否发生截断、是否解析失败；
- 是否包含断开的多个组分、金属或电荷；
- 立体信息在输入规范化时是否被删除；
- 输出向量的 dtype 和维度。

任何超过 202 token 的配体都不应静默截断后当成完整配体表示。优先策略是标记为不支持，再决定改用图分支、片段聚合或专用生物聚合物语言模型。

### 9.4 运行时间与存储预算

公开资料没有给出在本项目 SMILES 长度分布、A100 型号、batch size 和精度下的两模型可直接比较结果，因此以下时间只能作为资源预算，不能作为验收事实。

一个可复核的外部参考是：OSMI-SSM 论文在单张 V100 32 GB 上用 SMI-TED$_{289M}$ 对一千万条 PubChem 分子预测 HOMO，报告 20,606.76 秒，约为 485 个分子/秒。若直接线性换算，20 万条约需 412 秒，即 6.9 分钟。该数字包含性质预测流程，不是本项目纯 `encode` 的 A100 基准，但足以说明离线全量编码不是训练周期的主要成本。

当前数据量上界按约 $10{,}000\times20=200{,}000$ 个配体 occurrence 估算。实际应按配体身份去重后编码一次，再由 occurrence 引用身份向量。建议第一轮为两模型分别预留 5—30 分钟 A100 运行窗口，并以真实 token 长度、批量分桶、RDKit 规范化和磁盘写入的端到端实测替代估计。不要逐配体启动一次 GPU 前向。

若完全不去重，20 万个 768 维 `float32` 向量约占 586 MiB；两模型合计约 1.17 GiB。使用 `float16` 或 `bfloat16` 可减半，但第一版是否压缩应在核对向量稳定性后决定。按 `object_key` 去重通常会进一步显著减少计算和存储。

### 9.5 第一轮对照建议

- 为所有合法、未超长的五类配体同时计算 MoLFormer 与 SMI-TED$_{289M}$ 原始冻结向量。
- 训练时至少做 `MoLFormer only` 与 `SMI-TED only` 两组，其余网络、随机种子和数据清单保持一致。
- 小分子是必做主结果；其它四类先报告可编码率、超长率和立体信息丢失率，再决定是否纳入主训练。
- 如果成本允许，增加 ECFP 等非神经指纹作为 sanity baseline，防止把语言模型参数规模误认为表示必然更有效。该基线是建议，不是当前已决定范围。
- 配体图分支不是语言模型失败后的临时补丁。即使语言模型向量表现良好，图分支仍承担恢复项目原子/键字段、立体信息和完整结构细节的职责。

## 10. 第一版训练与评估建议

### 10.1 先验证任务是否可学

在加入全部模态前，应按复杂度递增验证：

1. 只用 `MLP(frozen LM vector)` 和最简单的候选摘要，在极小训练子集上过拟合；
2. 增加 A 与 P 的显式逐模态读取；
3. 增加完整配体图分支，但保持零初始化门控；
4. 增加清单上下文分支，但保持零初始化门控；
5. 增加 Map U-Net、PP 和模式二 V。

如果第 1 步仍不能在极小数据上明显过拟合，应优先检查候选—身份标签、清单索引、掩码和假阳类别，而不是继续堆叠模型模块。

### 10.2 损失

当前最自然的主要损失是逐候选 $(M+1)$ 类交叉熵。配体身份数量 $M$ 随 PDB 变化，batch 内必须用清单掩码隔离无效类别。Map 预训练的候选级分类损失与逐体素多分类损失应单独记录，不与最终身份分类混成一个难以解释的数字。

假阳性与真实配体候选的比例、五类配体比例以及同一 PDB 候选数量都可能影响梯度。第一版是否使用类别权重、focal loss 或分层采样仍未决定；应先测量实际分布。

### 10.3 评估

至少分别报告：

- 全部候选的 $(M+1)$ 类 top-1 accuracy；
- 仅真实配体候选的身份 top-1 accuracy；
- 假阳性检测的 precision、recall、F1 和 PR-AUC；
- 五类配体分层结果；
- 模式一与模式二分层结果；
- 候选来源、候选质量和配体清单大小 $M$ 的分层结果；
- 训练集极小子集的过拟合曲线，用于区分优化失败和泛化失败；
- 测试身份在训练中出现过与未出现过的分层结果，或至少报告身份重叠率。

候选级指标不能宣称已解决 PDB 级计数、同身份 occurrence 定位或 Stage3 最终结构生成。这些属于后续系统级评估。

## 11. 对 Stage3 的复用边界

新 Matcher 应为 Stage3 提供可直接复用的稳定组件，而不是提前实现整个 Stage3：

- 冻结配体语言模型原始向量及其身份索引；
- 配体完整图 token 编码；
- A、P、PP、V 和未来 R 的显式点 token stem；
- Map U-Net 的多尺度特征、`MapSummary` 和可能的 Map 派生 PP；
- 配体表示逐模态读取候选的 cross-attention；
- 模式一缺失 V 等额外模态时的严格零增量契约；
- 模式一与模式二各自独立的数据装配和后处理边界。

Stage3 agent 应能够调用这些组件，但不要求沿用 Matcher 的 $(M+1)$ 分类头。Stage3 如何把条件信息送入生成模型、是否更新位置、如何约束受体和如何使用语言模型残基 token，由 Stage3 自己决定。

## 12. 后续可选变体

以下内容有明确科学动机，但不属于第一版已冻结实现：

1. 把不同候选点模态在第二版合并成 typed point attention，以减少注意力调用次数；第一版先保留显式逐模态读取。
2. 为受体残基增加 Luca、ESM-2 等语言模型特征，形成独立 R token 模态。
3. 让 Map 候选级宽分类结果作为配体身份类别的先验偏置，例如只对相同宽类别的身份分数增加零初始化偏置。
4. 使用 Map U-Net 概率场在模式一和模式二统一构造 PP，但保持概率来源可追溯。
5. 对超过 202 token 的多肽或核酸配体使用专用序列语言模型、片段池化或层级图编码。
6. 将候选同时覆盖多个身份的问题扩展为多标签分类，而不是丢弃歧义候选。
7. 在候选级分类稳定后，再研究 PDB 级全局一致性、计数先验或轻量集合后处理；这些不应重新引入旧匈牙利训练难题。
8. 把连续几何质量、原子覆盖或旧 O/O′ 变成配对辅助头，为 Stage3 提供质量和空间先验。

## 13. 实施前仍需决定的少量问题簇

### 13.1 监督定义

- 正候选、假阳候选和歧义候选的精确标签算法；
- 旧 O/O′、覆盖率或距离是否作为辅助目标；
- Map 逐体素多分类与候选级六分类的精确类别和标签来源；
- 配体清单过滤规则以及过滤后如何保证目标身份存在。

### 13.2 配体输入

- MoLFormer 与 SMI-TED 的规范化 SMILES 是否完全沿官方 `isomeric=False`，还是额外保存并实验保留异构信息的输入；
- 多组分、盐、金属配合物和超长配体的正式失败策略；
- 配体图的节点、边、三维参考构象和立体字段；
- 三种表示的维度，以及不同 cross-attention 是否共享权重。

### 13.3 候选模态

- P 的正式盘上来源、字段和第一版可用率复核；
- PP 是否进入第一版、top-k 数量、概率来源和初始特征；
- Map U-Net 窗口大小、受体体素输入通道、宽度和 V 调制算子；
- 空 A、空 P、空 PP 或空 V 的显式掩码与零增量测试。

### 13.4 训练和评估

- 假阳比例、类别不平衡处理与 batch 预算；
- 两个语言模型是分别训练完整模型，还是共享一次训练后只替换离线向量做对照；
- 模式一训练到何种门槛后引入模式二；
- checkpoint 选择指标以及身份准确率与假阳 PR-AUC 的权衡；
- 独立测试中如何报告已见身份和未见身份。

### 13.5 工程与 Git

新 Matcher 倾向从一个干净的普通 Git 分支开始，当前旧 Matcher 分支作为历史保留；不建议创建没有共同祖先的 orphan 分支，也不建议把旧代码复制到仓库内的 archive 目录。此项尚未执行，具体分支基点、删除范围、双线历史、正式脚本和服务器训练方式按用户指定的后续实施讨论再决定。

## 14. 当前最重要的风险与建议

1. **任务边界必须写进论文表述。** 新 Matcher 解决的是给定 PDB 配体清单后的闭集分类，不是开放化学空间识别。
2. **先查标签，再查网络。** 旧模型训练集难收敛提示数据索引、监督冲突或任务对称性可能存在问题；新任务仍需要极小数据过拟合作为第一道门禁。
3. **立体信息不能被语言模型向量静默抹去。** 两个官方流程都以非异构规范化为主要训练/示例路径，糖、多肽和核酸配体尤其敏感。原始结构图必须保留，预计算清单也必须记录规范化变化。
4. **三种配体表示都要真正读取候选。** 不能只让原生向量与候选交互，再把另外两项当静态附加特征。
5. **门控放在完整分支出口。** 这样才能保证 inventory、graph、V 和未来新模态在关闭时严格退化为零增量。
6. **Map 与点模态职责不同。** Map 先由三维 U-Net 编码；A、P、PP、V、R 保留可点化 token。不要为了统一接口过早把所有信息压成一个候选摘要。
7. **先双模型离线计算，后决定主模型。** 二十万 occurrence 的规模不足以让冻结向量计算成为瓶颈，按身份去重后成本更低；因此先保留 MoLFormer 与 SMI-TED$_{289M}$ 两套原始向量比过早二选一更稳妥。
8. **模式一必须保留密度进入身份分数的实际通道。** 当前第一版倾向让 Map 特征调制 V，但模式一没有 V。如果模式一又不启用 Map 派生 PP，Map 只会影响假阳性分数而不会帮助区分正候选的配体身份。实施前应在“模式一启用 Map 派生 PP”或“允许候选—身份分支读取 Map token/摘要”之间至少选择一条，不能让模式一的正类身份判断事实上看不到密度。
