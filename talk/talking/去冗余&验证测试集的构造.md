请实现并运行“PDB 序列去冗余与 train/validation/calibration/test 划分”管线。本任务只覆盖已经取得 polymer entity 序列之后的去冗余和 split 构建；不要重新设计 mmCIF 序列提取，也不要修改已有 box_pool、已有 split 或正在使用的数据目录。

一、目标

从全部合格 PDB 样本中选出固定数量的 held-out 集合。held-out 是 validation、calibration（可选）和 test 的并集，必须满足：

1. held-out 内部不存在达到冗余阈值的 PDB 对；
2. held-out 与 train 之间不存在达到冗余阈值的 PDB 对；
3. train 内部允许存在冗余；
4. 与 held-out 冗余但未被选入 held-out 的 PDB 进入 excluded_near_heldout，不得进入 train；
5. 同时产生 greedy 和 random 两种划分，保留完整中间产物，以便未来改变阈值、held-out 数量或随机种子时快速重算；
6. validation、calibration、test 先作为统一 held-out 集合选择，确认内部无冲突后再拆分，避免三个留出集合彼此泄漏。

held-out 总数、validation/calibration/test 各自数量和固定随机种子属于运行配置。不得自行猜测未给出的正式数量；先从现有任务记录中核实，仍不存在时向用户确认。calibration 数量允许为0，但建议把它保留为显式配置字段。

二、输入契约

输入至少包括：

1. protein FASTA；
2. RNA FASTA；
3. DNA FASTA；
4. polymer entity 映射清单。

每条序列必须有稳定且唯一的 sequence_id。映射清单至少包含：

- sequence_id；
- pdb_id；
- entity_id；
- chain_ids；
- polymer_type；
- sequence_length。

同一个 polymer entity 只输入一次；不能因为相同 entity 在结构中有多个 chain instance 而重复输入。蛋白质、RNA、DNA 分开运行 MMseqs2，不进行蛋白质—核酸比较。DNA、RNA 和 DNA/RNA hybrid 的实际分类必须写入配置和结果说明，不能隐式混合。

如果上述序列输入或映射清单尚不完整，停止正式划分并报告具体缺失项，不得根据坐标残基临时拼接另一套序列。

三、MMseqs2 科学配置

蛋白质使用：

- minimum sequence identity = 0.30；
- bidirectional coverage = 0.80；
- cov-mode = 0；
- 使用 alignment-mode 3 计算实际序列一致性，不使用默认估计值。

核酸使用：

- minimum sequence identity = 0.80；
- bidirectional coverage = 0.80；
- cov-mode = 0；
- 使用直接核苷酸比对和 alignment-mode 3。

蛋白质的30% identity + 80% bidirectional coverage 对应已有 PDB 数据划分文献做法，例如 Seq2Symm。RNA 使用80% identity 去冗余也是已有 RNA 数据集的常见做法。Metal3D 提供了“优先从与任何其他蛋白无合格序列匹配的孤立样本中选择 validation/test”的直接先例。

使用 MMseqs2 easy-cluster 或等价模块生成聚类，同时使用 all-vs-all easy-search 或等价 search 模块输出可审计的直接匹配。搜索结果至少包含：

- query；
- target；
- pident 或 fident；
- qcov；
- tcov；
- alnlen；
- qlen；
- tlen；
- evalue；
- bits。

检查 --max-seqs、--max-accept 等上限，确保高度冗余序列的邻居没有因为默认上限而静默截断。记录是否有查询触及上限。保存 MMseqs2 版本、完整命令和运行参数。

四、PDB 冲突图

以 PDB 为顶点建立无向冲突图 G=(V,E)。

如果两个不同 PDB 满足以下任一条件，就建立冲突边：

1. 至少一对同类型 polymer entity 被分入同一个符合正式阈值的 MMseqs2 cluster；
2. 至少一对同类型 polymer entity 在直接 MMseqs2 搜索中达到正式 identity 和 bidirectional coverage 阈值。

蛋白质只与蛋白质比较；RNA、DNA按冻结的同类型规则比较。

每条 PDB 冲突边必须保留至少一个 witness，即造成该冲突的具体实体对及其指标：

- pdb_id_a；
- pdb_id_b；
- polymer_type；
- sequence_id_a；
- sequence_id_b；
- entity_id_a；
- entity_id_b；
- identity；
- qcov；
- tcov；
- evalue；
- conflict_source：same_cluster、direct_hit 或 both。

同一 PDB 内部的实体匹配不产生 PDB 自环。

五、held-out 选择模式

设 held-out 总数为 K。

模式A：greedy

目标是优先保留尽可能多的 train PDB。

1. 优先选择冲突图中 degree=0 的孤立 PDB；
2. 若孤立 PDB 少于 K，则在当前候选图中选择有效 degree 最低的 PDB；
3. 选中一个 PDB 后，其邻居不得再进入 held-out；
4. 更新剩余候选的有效 degree；
5. degree 相同时使用固定随机种子打破平局；
6. 直到选出 K 个 PDB或证明当前候选不足。

如果孤立 PDB 数量大于 K，也使用同一固定随机种子从孤立 PDB 中选择，不按 PDB ID 或数据质量暗中排序。

模式B：random

这里的 random 是固定种子的随机顺序贪心，不要求从所有独立集合中均匀采样。

1. 使用固定随机种子打乱全部合格 PDB；
2. 顺序扫描；
3. 当前 PDB 与已经选入 held-out 的任一 PDB 都没有冲突边时接受；
4. 否则跳过并记录拒绝原因；
5. 达到 K 后停止。

固定种子无法获得 K 个样本时，报告实际数量和原因，不得静默更换种子、修改阈值或降低覆盖率。

六、集合生成

对每种模式分别计算：

- H：完整 held-out 集合；
- N(H)：与 H 中至少一个 PDB 存在冲突边的邻居；
- excluded_near_heldout = N(H) \ H；
- train = V \ (H ∪ N(H))。

随后使用固定随机种子把 H 拆成目标数量的：

- validation；
- calibration；
- test。

拆分前后都必须验证三个留出集合的并集精确等于 H。

八、验收标准

每种模式都必须证明：

1. train、validation、calibration、test、excluded_near_heldout 两两不重叠；
2. 五者并集精确等于全部合格 PDB；
3. held-out 数量和各子集数量符合配置；
4. held-out 内部不存在冲突边；
5. held-out 与 train 之间不存在冲突边；
6. train 内部允许存在冲突边，不得据此判错；
7. excluded_near_heldout 中每个 PDB 至少有一条连接到 held-out 的证据边；
8. 每个与 held-out 冲突的非 held-out PDB 都进入 excluded_near_heldout，没有遗漏；
9. 使用相同输入、配置和随机种子重跑时，结果完全一致；
10. greedy 和 random 共用同一份序列输入、MMseqs2 结果和 PDB 冲突图，不得分别重新定义冗余关系；
11. 对两种模式分别报告 train 保留数量、excluded 数量、held-out degree 分布、孤立样本占比和连通分量覆盖情况；
12. 若输入数量、阈值、结果上限或映射关系存在异常，先保留证据并报告，不得自动改变科学配置。

九、实现边界

- MMseqs2 负责序列搜索和聚类；
- 一个尽可能小且可读的脚本负责 entity→PDB 映射、冲突图、greedy/random 选择、split 落盘和验收；
- 不引入结构相似度、口袋相似度、配体相似度或模型预测结果；
- 不重新生成 box_pool；
- 不覆盖任何旧版 split；
- 不用数据质量指标选择 held-out 代表；
- 不在发现 held-out 数量不足时自动降低去冗余阈值；
- 中间结果必须保留，使未来能够只重跑图选择与 split 阶段，而不重复运行 MMseqs2。
