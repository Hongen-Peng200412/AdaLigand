# 配体语言模型可读性重构清单

本文规定 `Data_Preprocessing/Ori_Data_upgrade/ligand_language_model/` 的当前科学契约、正式文件职责和验收方法。PDB 是一份生物大分子三维结构记录；occurrence 是一个 PDB 中的一次配体出现；LigandObject 是可复用配体化学模板；SMILES 是用一行字符表示分子的文本；CCD 是 PDB 化学组分字典中的单个标准组分；BRANCHED 是由多个残基分支连接的配体；RDKit 是解析和生成 SMILES 的化学软件包；mmCIF 是 PDB 三维结构记录的文本格式；pdbeccdutils 是读取该格式并处理化学组分的软件包；CLC 是它识别出的共价连接配体组分；`present_{candidate_id}` 是与 LigandObject 原子逐项对齐的当前 PDB 原子存在掩码；tokenizer 是把 SMILES 拆成模型词表片段并转换成编号的程序；NPZ 是按名称保存多个 NumPy 数组的压缩文件；JSONL 是每个非空物理行保存一个 JSON 对象的文本文件。实施操作与验证证据写入 `文档/exec_plan/AdaLigand_v3基础数据升级实施.md`。

split 是训练、验证和测试样本名单；BOX pool 是围绕配体位置预先建立的 Stage1 局部三维
区域池；CUDA 是 NVIDIA GPU 执行模型计算所用的软件与设备接口；one-hot 是只有一个
位置为 1、其余位置为 0 的类别向量；Slurm 是服务器用于排队和分配 CPU/GPU 的调度系统。

正式 CPU、GPU 和汇总任务均由用户手动提交。代码不得自动修改 `all_valid.json`、`info.json`、split 或 BOX pool，也不得建立发布门控。

## 科学契约

1. 一个处理单位是 `(pdb_id, candidate_id)`。共享 `object_key` 的 occurrence 仍分别准备、编码和落盘。
2. 只处理 `ion`、`nucleotide_like`、`peptide_like`、`small_molecule` 和 `sugar` 五类正式配体；`type_tag=other` 只进入 CPU 数量统计。
3. `kind=CCD` 使用 `LigandObject.smiles`。RDKit 能生成字符串时采用 canonical non-isomeric SMILES，即按确定规则生成且不保留立体化学标记的统一字符串；RDKit 失败但源字符串非空时保留源字符串。
4. `kind=BRANCHED` 先从完整 PDB mmCIF 读取 pdbeccdutils CLC，再按 `(ccd_id, auth_asym_id, auth_seq_id, insertion_code)` 残基身份多重集合选择唯一精确候选。
5. BRANCHED 没有唯一精确 CLC、CLC 转换异常或 CLC 没有生成非空 SMILES时，使用 `present_{candidate_id}` 删除 LigandObject 中未出现的原子，并只保留两端原子都存在的已有键。
6. RDKit sanitize（化学合法性检查与属性整理）、CLC 连接比较、词表覆盖、token 长度、金属、形式电荷和断开片段只记录事实。token 是模型词表中的一个文本片段。只要模型官方接口返回数值 `(768,)`，即使含 NaN（不是有效数值）或 Inf（正负无穷）也保存。
7. batch 是模型一次共同计算的一组分子。MoLFormer 使用 FP32（32 位浮点数）、默认 batch_size 参数 256、`truncation=False`，并以官方特征提取示例的 `deterministic_eval=True` 固定随机特征映射。SMI-TED 使用官方 `model.encode`、默认 batch_size 参数 100、官方规范化和官方截断；实际内部批量由冻结的官方源码决定。
8. GPU batch 在当前数组分片的全部 PDB occurrence 范围内组成，不按单个 PDB 切分。
9. 每套模型只保存 `float32 (768,)` 分子级向量，不保存 token 级或原子级向量。

## 本轮具名函数授权

用户只授权下列低调用次数函数按当前职责保留；相似函数、新函数、改名函数或职责扩张不自动获得授权。

- 产物契约：`PreparedLigand.to_dict()`、`PreparedLigand.from_dict()`、`ModelResult.to_dict()`、`ModelResult.from_dict()`、`read_prepared()`、`write_prepared()`、`read_model_results()`、`write_model_results()`、`write_embedding()`、`_read_jsonl()`、`_write_jsonl()`。
- 科学与外部接口：`prepare_ligand()`、`build_present_molecule()`、`read_clc_candidates()`、`select_exact_clc()`、`_connection()`、`diagnose_tokens()`、`encode_batch()`、`official_encode()`。
- 执行边界：`prepare_one_pdb()`、`load_model_work()`、`finish_model_work()`、`write_model_report()`、`run_molformer()`、`run_smi_ted()`、`cuda_facts()`、`shard_report_path()`，以及四个 Python 命令入口各自的 `main()`。

两个模型统一通过 `record_embedding_result()` 写入向量和状态；最高频精确 SMILES 只在各阶段汇总主线中计算。

## 注释和文档验收

- 模块开头点名唯一职责、承担主流程的入口、输入来源和落盘产物。
- 冷读工具函数位于正式主流程之前，并仅使用一条 `# ================================================================================================` 分隔线。
- 每个结构化字段说明保持单行；嵌套 JSON 继续展开到字段类型、出现条件、空值语义和对齐关系明确。
- `present` 说明 `bool (N,)`、N 的实体含义、True/False 语义及其与 `LigandObject.atoms` 第一维的逐原子对齐。
- MoLFormer 说明 `input_ids` 与 `attention_mask` 均为 `(B,L)`，并解释掩码 1/0；SMI-TED 明确官方 `model.encode` 不向本项目暴露内部 `(B,L)` 张量。
- `model_smiles` 区分 MoLFormer 的直接输入、SMI-TED 的官方规范化 tokenizer 输入和规范化失败时的 `null`。
- README 直接回答主线与核心产物；`产物字段参考.md` 单独回答必需字段、条件字段、空值语义和跨文件对齐。
- 真实示例不虚构尚未运行的 GPU 向量；所有节选明确列出省略字段的完整路径。

## 验证

- 临时测试覆盖 CCD 规范化与原文保留、CLC 多重集合、插入码字段、CLC 异常后的 present 后备、有效 CLC 不依赖后备输入、严格 present 掩码、one-hot 回退、`other` 双边排除、跨 PDB batch、SMI-TED 规范化失败、NaN/Inf、错误向量形状、旧向量清理、续跑完成标志和汇总未知值。
- 使用本地真实 `7d3f.cif` 缓存核对两个 CLC，并证明 candidate 4 只匹配 E 链 CLC。
- 正式 Python 文件通过 Black、Pyflakes 和 `compileall`；四个 shell 入口通过 `bash -n`。
- 独立结构、注释和科学审计只读取冻结候选版本；发现问题后回到实现线修正并重新验证。
- 当前可读性候选工作树与重建后的学习端点运行相同验证并通过完整 tree 等价核验后，才能更新本地 `Learn/CUMULATIVE`；既有 `codex/ligand-language-model` 实现分支保持原样。
