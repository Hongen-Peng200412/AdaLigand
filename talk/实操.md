> 本文是 `文档/规划文档/Stage1训练实现计划.md` 的执行伴随说明：补充当前代码现实、门禁、任务拆分、验证命令契约和后续里程碑；不替换该计划，也不改写 `Stage1训练与多阈值推理.md` 或 BOX 契约的权威职责。

## 0. 现在到底能不能启动 Find？

结论分两层：

- **今天可以启动 Find 实现**：干净基线、Ada 数据 adapter、坐标/裁剪/loss 测试、单 batch backward、center-only tiny overfit、少量真实 PDB smoke。
- **依据本轮可见的本地仓库与历史状态记录，不能直接启动并命名为正式 Find 长训练**：Ada 仓库当前没有 Find Dataset/adapter/config/train/full-map 代码；本地证据尚未给出 A–G final keep-list；正式 split/box_index/head-loss 配置未冻结。F/G 的服务器实时状态必须在未来执行前另行核验，本文不把历史 job 状态冒充 live 状态。

不要直接运行旧 `+experiment=CPC1/trunk_main` 并把它叫 Ada Find。它读取 Pocket Classic 的预切 BOX、distance map 和旧标签，只能复现旧任务。现有 `sbatch/h200/1gpu.sbatch` 也在 custom hook 中硬编码 `+experiment=emb_unet`，传入新 experiment 名不会按注释生效。

建议把用户所说的“四步”落成以下四个可验收阶段：

```mermaid
flowchart LR
    A["1. Find 适配、训练、冻结 checkpoint"] --> B["2. 全图概率、单阈值基线、测试评估"]
    B --> C["3. 多阈值 CLG、首次物化、selector、selection"]
    C --> D["4. Stage2 Matcher 训练与评估"]
```

其中 proposal selector 是 Stage1 内的小网络，Stage2 Matcher 是 proposal↔CCD 的下游网络；两者不是同一个“二阶段小网络”。

### 本文短词汇表

| 词 | 本文中的确切含义 |
|---|---|
| manifest | 描述一次数据划分、运行或产物的版本、输入、配置、hash 与来源关系的机器可读清单；不是大数组本身。 |
| inventory | 某次运行实际读写了什么、成功/失败/跳过了什么的逐项清单。 |
| parity | 两条实现路径在约定容差内产生相同几何、输入、输出或梯度的对照验证。 |
| OOF / cross-fit | out-of-fold / 交叉拟合：每个训练样本的上游特征由未见过该样本的 fold 模型产生；它不等于最终全量 checkpoint。 |
| GT-blind | manifest 只用 `gt_blind_regime ∈ {fully_gt_blind, spatial_overlap_gt_blind}`。前者要求所有模型侧输入均非 GT-derived；后者只保证无 occurrence mask/overlap/空间 oracle。另用 `ccd_candidate_source`、`count_source` 记录 side-information 来源。空间评分均由独立 evaluator 在预测落盘后完成。 |
| DDP / H2D / CI | 分布式数据并行 / host-to-device 传输 / 置信区间。 |
| qcov / tcov | 序列比对中 query / target 被覆盖的比例；必须连同 identity 和工具版本一起冻结。 |
| BEST / last | 按预注册 validation monitor 选出的最佳 checkpoint / 最近一次保存的 checkpoint。 |
| A/B/O | Stage2 的 GT 覆盖率、blob 精确率式覆盖率和匹配分类目标；详见 S2-1.5，不能与受体点 `A` 混用。 |
| `lambda_pseudo` / `lambda_count` | P auxiliary loss 权重 / selector oracle 的节点数量惩罚；是两个完全不同的量。 |
| independent-max / Stage2 Hungarian / `1to1F1` | 分别是 Stage1 selector 训练 oracle、Stage2 身份内 slot↔occurrence loss matching、最终 evaluator 指标；三者不可互换。 |

## 3. Find 训练的详细启动路线

### M0：建立干净、可复现的源码基线

动作：

- 在 Pocket Plus 从 `origin/大重构@4d798c9` 建新分支/worktree；
- 保留该提交中的 frozen BN/Dropout eval 修复；
- Ada 当前三份文档的 staged/unstaged 状态先做只读快照，不清理用户改动；
- 定义 run manifest 同时记录 Ada/Pocket commit、配置 hash、数据 hash、dirty diff hash（正式 run 要求 clean）。

通过条件：两个仓库的 baseline、依赖环境和 import 路径可由另一 agent 重建；没有把本地无关 PDF 删除或记忆改动混进实现 commit。

### M1：实现整图资产读取器

输入来自 A–G code-near contract：

- `exp.npz`: `grid/origin/voxel_size`，实际 voxel 不硬编码 1.0；
- `sim.npz`: 与 exp 同 grid identity；
- `receptor_tokens.npz`: coords + 49 维 feature；
- `atom_labels.npz`: `binding_atom/instance_id`；
- `ligand_area.npz`: `union_mask` 与 occurrence sparse masks。

`Stage1WholeMapAssets` 应：

- lazy/open-on-demand，不在构造时复制整图；
- 验证 exp/sim shape、origin、voxel_size 一致；
- 验证 receptor 行数与 atom labels 一致；
- 保存 schema/version/hash；
- 对缺失 sim 只在配置不需要 sim/diff 时允许继续；
- 返回明确的失败类别，不用零数组兜底。

通过条件：少量成功 PDB 可冷读；每个失败都绑定字段/path/schema，不吞异常。

### M2：实现唯一 BOX materializer 与半体素兼容

单一数据流：

```text
Stage1BoxRequest
→ resolve geometry（第一版 augmentation=identity）
→ crop exp/sim/union_mask with zero padding
→ select receptor in core+buffer
→ center-origin 转 Pocket corner-origin
→ build density channels + receptor occupancy
→ assemble FindSample
```

硬规则：

- start 可为负，end 可越界；不 clamp origin；
- exp/sim/GT 图外补 0；图外没有 receptor atom；
- `origin_corner = origin_center - 0.5*voxel_size`；
- core 使用 world 半开体积；buffer 只扩受体查询；
- `require_targets=False` 只移除 targets，所有模型输入逐元素不变；
- 同一 resolved geometry 在 train/predict provider 下输出一致。
- 第一版只接受 `augmentation=identity`；非平凡旋转、轴交换、平移另设 `AUG-01`，必须先冻结世界坐标/非等方 voxel 规则并通过同步变换测试，不能夹带进 baseline materializer。

通过条件：几何、裁剪、home voxel、边界和 targets on/off parity 测试全部通过。

### M3：接入模型、输出与 loss

`FindModelAdapter` 至少输出：

```text
ligand_area_logit      [B,1,80,80,80]
receptor_binding_logit [N_real]
P_probability          [N_P]                 # 仅在 P head 被明确训练时有效
named P/receptor feature hooks               # 先声明接口，正式层可稍后冻结
```

建议第一版损失如下；只有 `DOC-DEC` 正式冻结 `target_semantics=binary_union_direct` 与 `core_loss_scope=core_only` 后，才能把它当生产 baseline：

```text
L = λ_voxel * L_voxel(binary union_mask)
  + λ_atom  * L_atom(binding_atom, core_mask)
  + lambda_pseudo * L_Paux(P home-voxel sampled union_mask)   # 是否启用及权重待用户确认
```

若用户接受该建议 baseline，要求：

- dense ligand loss 直接接 bool target；
- atom loss 只看 core；
- `voxel_aux_loss` 不冒充 atom loss；
- sparse-refine/delta/final refine head 全关；
- P auxiliary 若关，manifest 明确 `P_probability_semantics=untrained/not_exported`；
- 每个输出 shape、dtype、坐标帧有测试。

通过条件：单 batch forward/loss/backward 有限；目标全空、receptor 为空、全 buffer 等边界样本不产生 NaN 或错位。

### M4：实现 provider、collator、sampler 和 box index 接口

先实现逻辑接口，再定物理容器：

- center provider；
- bias provider；
- context provider；
- fixed validation provider；
- lazy full-map window provider；
- DDP deterministic quota sampler。

采样顺序应由 `global_seed, epoch, world_size, rank, source quota` 确定；同一正式配置必须可重放请求清单。box_type 不进 loss。

在 bias/context 数值未冻结时：

- 允许 center-only pilot；
- bias/context provider 可以先用合成 fixture 测接口；
- 禁止把 agent 临时选的分布写成生产默认。

通过条件：单卡/多卡合并后的全局配额正确、无重复/漏样本规则可解释、固定 seed 可重放。

正式配置至少包含：

```yaml
  box_index_manifest: ...

  legacy_model_origin_semantics: box_corner
  atom_buffer_radius: ...

  channel_recipe_version: ...
  ordered_channel_names: [...]

  pocket_plus_commit: 4d798c9...
  curriculum_id: cpc1_only | cpc1_cpc2 | joint_v1 | <versioned_other>

  voxel: {...}

  pseudo_P: {...}

  seed: ...
  precision: ...
  devices: ...
  batch_size: ...
  workers: ...
  prefetch_factor: ...

  monitor_metric: ...
```

仅当冻结的 `curriculum_id` 含第二阶段时，第二阶段从第一阶段 BEST **只加载模型权重**，不继承 optimizer/scheduler/step；冻结 pattern 必须命中非零，并验证冻结 BN/Dropout 保持 eval。若是 `cpc1_only` 或 joint/其它路线，必须使用对应的具名 handoff policy，不能套用 CPC2 文字。

checkpoint 建议两级选择：训练内保存 BOX-level ligand-area PR-AUC top-K，再对 top-K 做固定 validation PDB 全图评价，选正式 Find checkpoint。为避免“每个候选先用 calibration 调阈值、再用 validation 选权重”的循环与额外选择偏差，建议 checkpoint 主判据使用预注册的 threshold-free `full_map_voxel_average_precision_micro_global`；最终 checkpoint 冻结后，才在 calibration 冻结 `t_F1` 和 gate。若用户坚持用 Dice/cov/top-K 选 checkpoint，则必须另行冻结所有候选共用的阈值来源，不能逐候选在 calibration 调参。receptor 指标独立报告；不要继续把旧 `pseudo_PRAUC` 自动当唯一 monitor。

这个新指标也不能只留一个名字。建议正式定义为：在固定 validation manifest 上，对每个 PDB 的**原始整图 shape 内所有 voxel**（不含 padding window，不以 receptor occupancy 排除 voxel）读取 `P_global` 与 union GT；主值汇总所有 PDB 的 `(score,label)`，按 non-interpolated average precision（sklearn `average_precision_score` 语义或等价公式）计算 `full_map_voxel_average_precision_micro_global`，不把梯形 PR-AUC 与 AP 混名。无 GT 的 PDB 仍贡献负例/假阳分布；另报只对有 GT PDB 逐图计算的 `full_map_voxel_average_precision_macro_positive_pdb` 和阴性图 false-positive 诊断。若整个 validation 没有正 voxel，主指标未定义并 hard fail。实现库/version、同分 score 处理、浮点精度和 checkpoint 同分 tie-break（建议依次用 BOX AP、validation loss、稳定 checkpoint ID）都写进 metric manifest。该定义仍需在正式计划中冻结后才可作为权重选择规则。

这要求 **全图 inference 实现先于正式 checkpoint 冻结**，不能把它排在 Find 全部完成之后。应在 M6/M7 期间先完成 `INF-00`（toy + 单 PDB full-map smoke），正式训练后再按“候选 checkpoint→validation 临时概率→冻结 checkpoint→生产概率”运行。

### M6：正式或长时 GPU 作业之前的硬测试门

最低测试清单：

1. center-origin↔corner-origin 往返；
2. 体素中心 home-voxel 映射为 `i+0.5`；
3. 六个越界方向、短于 80 的轴、负 start 精确补 0；
4. exp/sim/GT crop 对齐；
5. receptor core/buffer 与 atom label index 对齐；
6. receptor occupancy 与 `voxel_valid_mask` 不混；
7. targets on/off 输入逐元素相等；
8. train/predict 同 geometry parity；
9. ragged collate，包括 0 receptor；
10. 56 通道名称/顺序/golden 数值；
11. Hydra compose；
12. 单 batch forward/loss/backward；
13. frozen module 的 `requires_grad/eval/BN state`；
14. 若冻结 curriculum 含第二阶段：第一阶段→第二阶段 model-only load；
15. 8–32 固定 BOX tiny overfit；
16. manifest 冷读与 hash 验证；
17. **旧入口→新 adapter golden parity**：在同一个无标签物理 BOX、同一祖先 density recipe 和冻结 checkpoint 下，比较旧/新模型输入与 logits。允许的差异只来自事先声明的 Ada target/loss 变更；origin 转换、无标签 forward 不应漂移。

tiny overfit 的通过标准不要只看总 loss：voxel、atom、P auxiliary（若开）都应按预期下降，预测图与 target 的空间位置可视化一致。

### M7：少量真实数据 smoke 与容量冻结

在 final keep-list 前，可从已有 C/D/E 成功样本中选少量 PDB，显式标：

```text
run_tier=pilot
producer_fit_relation=in_sample
checkpoint_role=final
data_release=pre_G_engineering_smoke
not_for_scientific_reporting=true
```

运行顺序：

1. 单 batch、1 step；
2. 8–32 BOX 过拟合；
3. 少量 PDB、几十/几百 step；
4. 记录 GPU peak、host RAM、worker wait、H2D、forward、BOX/s；
5. 调整 batch/workers/prefetch/pin；
6. 验证重启、BEST/last、manifest 和失败清理。

56 通道每个样本约 109 MiB，仅看 GPU 显存不够；必须观察多 worker+prefetch 的 host RAM。缓存用 byte budget，不用 `cache_size=128 PDB`。

### M8：按正式冻结的 curriculum 训练与选 checkpoint

正式启动前 checklist：

- F release/QC 完成；
- G analyze 完成且用户冻结 schema-v2 数值配置；
- G filter 生成 final keep-list；
- train/val manifests 冻结；calibration 的来源、用途和与 development 的关系先预注册，实际 manifest 最迟在任何阈值/后处理调优前冻结；
- center/bias/context box index 冻结；
- head/loss/density/curriculum 冻结；
- 代码、配置、数据均有 hash；
- pilot capacity 通过。

正式运行不是“一次 train 完了再写 inference”，而是以下闭环：

1. `INF-00` 已在 toy 与单 PDB 上完成全图实现和拼接验证；
2. 冻结 curriculum 的第一阶段训练按预注册 BOX monitor 保存 top-K；
3. `INF-VAL-1` 对每个 top-K 在固定 validation PDB 产生**临时**全图概率与指标；
4. `CKPT-PHASE1-FREEZE` 默认以预注册的 validation `full_map_voxel_average_precision_micro_global`（threshold-free）及 tie-break 选第一阶段权重；若改用阈值指标，先冻结一个对所有候选相同的阈值政策；临时概率不提升为正式生产 run；
5. 仅当 curriculum 含第二阶段时，从冻结的第一阶段 checkpoint model-only 初始化并保存新的 top-K；
6. 若有第二阶段，`INF-VAL-2` 重复固定 validation 全图比较；否则显式记录 `curriculum=cpc1_only`；
7. `CKPT-FIND-FREEZE` 选出最终 `find_checkpoint_id/hash`；
8. calibration/test manifests 在各自使用前完成冻结后，`INF-PROD` 用最终 checkpoint 生成 validation、calibration 和各 test family 的正式 `P_global`；下游 train 材料按已冻结的 producer 路线另产：OOF 用 fold checkpoint，in-sample 用 final checkpoint 但显式标关系，独立 downstream-train 用未见过它的模型；
9. 以后首次局部物化只能引用该 checkpoint 和同一 forward config。

若最终决定不使用 CPC2，也必须显式记录 `curriculum_id=cpc1_only`（或其它获批值），不能跳过步骤后仍把 checkpoint 叫 CPC2 完成。

## 4. 目标命令契约

以下是实现完成后应成立的命令形态，**不是当前已经存在的命令**。

### 4.1 本地/服务器轻验证

```powershell
python -m pytest tests/stage1_find -q
# 在 Pocket Plus 仓库根目录执行：
python src/train.py +experiment=AdaLigand/find_cpc1_smoke --cfg job
```

## 5. split、测试集去冗余与 manifest

### 5.1 固定顺序

用户已经明确“先选 train/validation，二者内部不去冗余，再反向选择 test”。下面把 calibration 纳入 development forbidden pool 是**推荐默认、待用户确认**，不是本轮已经冻结的事实：

在第 1 步前做一个不改变用户顺序的条件预注册：若希望保留“独立 downstream-train”作为 cross-fit 替代，就必须先从 final keep-list 预留该集合，并保证它不进入 Find train；若没有预留，Find 训练完成后该路线自动不可选，只剩 OOF 或 in-sample。可以先只预留集合、不立即决定最终采用哪条路线。

1. 从 final keep-list 冻结 train；
2. 冻结 validation；
3. train/validation 内部不做序列去冗余；
4. 从剩余 PDB 冻结 calibration；若用户接受推荐默认，它属于 development data；
5. 推荐以 `train∪val∪calibration` 的序列簇为 forbidden pool；若用户另选政策，必须在看 test 结果前预注册并说明风险；
6. 从剩余候选构建 test master pool，排除与 forbidden pool 超阈值者；
7. 对 test master pool 内部聚类，按固定 tie-break 选代表；
8. 再切成互斥测试家族；若允许交叠，只能叫诊断视图，综合统计不重复计数。

train/val 内部不去冗余意味着 val 更适合早停而不是“新序列泛化”结论；真正泛化由去冗余 test 报告。

### 5.2 尚需用户冻结的 sequence 规则

至少要决定：

## 6. Find 全图推理、粗单阈值和正式评估

### P1：冻结 `P_global`

输入：冻结 Find checkpoint、同一 density/geometry/collate config、split manifest。

流水线：

```text
lazy windows → CPU materialize → GPU Find → bounded queue
→ one logical writer/PDB → probability_sum + weight_sum
→ P_global float32 → atomic write + checksum
```

实现要求：

- window start/stride 保证每个原图 voxel 被覆盖；
- 输出 sigmoid probability，不能混 logit；
- Gaussian 在每轴 normalized `[-1,1]` 坐标，`σ=0.5`；
- 不丢窗口边角 5 voxel；
- 不乘旧 `(1-hardmask)`；
- 大图超过 RAM 门槛使用 memmap/chunk；
- 每个 PDB 一个 owner，失败写 inventory；
- 推荐先断言原图每个 voxel 的覆盖次数大于 0，并把未覆盖计为运行失败；在当前主计划尚未收口前，分母中的 `epsilon_weight_sum` 仍保留为数值保护，不能把它当成掩盖窗口枚举错误的回退。`weight_sum` dtype、累加/reduce 顺序也必须冻结。

产物：`probability_run_id`、每 PDB `P_global[Z,Y,X] float32`、manifest、inventory、hash。

通过条件：常数窗口/拼接 toy test、不同 batch size 一致、边界全覆盖、冷读 hash、单 PDB 真实 smoke。

同一个 full-map 引擎要服务不同 run kind；不能只对 test 跑一次：

| run kind | `run_tier` | `producer_fit_relation` / `checkpoint_role` | PDB 范围 | 用途 | 是否正式保留 |
|---|---|---|---|---|---|
| `checkpoint_selection` | `formal` | `held_out` / `phase_candidate` | 固定 validation | 冻结 checkpoint | 临时 inventory，可按政策清理 |
| `oof_train_fold_k` | `formal` | `out_of_fold` / `fold` | train fold k | selector/Stage2 OOF 训练材料 | 是，带 producer_fold_id |
| `final_validation` | `formal` | `held_out` / `final` | validation | 下游 validation 与复现 | 是 |
| `final_calibration` | `formal` | `held_out` / `final` | calibration | t_F1、多阈值、tau_G/decoder | 是 |
| `final_test_<family>` | `formal` | `held_out` / `final` | 各 GT-blind test family | 一次性正式评测 | 是 |
| `pilot_in_sample_train` | `pilot` | `in_sample` / `final` | 少量 train | 工程诊断 | 标非正式 |
| `formal_in_sample_train` | `formal` | `in_sample` / `final` | Find train 中被下游训练使用的 PDB | 用户批准的便宜正式路线 | 是；必须标分布风险/结论边界 |
| `independent_downstream_train` | `formal` | `held_out` / `final` | 预先保留且未进入 Find train 的 PDB | 不做 K-fold 的下游训练 | 是；绑定独立 split hash |

如果正式路线取消 cross-fit，必须显式记录 `oof_train_fold_k` 被什么替代，不能让 selector/Stage2 的 train PDB 材料来源为空或靠临时脚本补。

### P2：独立 calibration 与单阈值 F1 baseline

只在 calibration：

- 以全图 GT union mask 统计 micro-Fα；
- 扫七个 α，F1 对应的阈值 `t_F1` 作为粗单阈值 baseline；
- 冻结 threshold grid、tie-break、min/max voxels 与连通性；
- test 不重新调阈值。

calibration 只负责冻结 `t_F1` 和 component recipe；随后必须把同一冻结 recipe 应用到每条实际 producer route 的 train/val/calibration/test `P_global`。OOF train 用 fold 产物，in-sample/独立 downstream-train 用各自具名产物；test component 生成不读 GT，评价另起进程。不能只在 calibration 生成 components 后就声称 F1 route 已可供 selector/Stage2 使用。

单阈值路线：

```text
P_global >= t_F1
→ 26-connected components
→ 统一合法性/边界规则
→ 所有合法 F1 blob
→ 排序与评价
```

不要偷偷加入形态学、边缘裁剪或旧 min-size；任何过滤必须在 proposal recipe 中显式。

### P3：正式 Find 指标 v1

以 PDB 全图为单位，不以 window/BOX 为单位。

#### Dice

```text
dice_macro_pdb = mean_pdb(2TP/(2TP+FP+FN))
dice_micro_global = 2ΣTP/(2ΣTP+ΣFP+ΣFN)
```

二者都报；阈值使用 calibration 冻结的 `t_F1`。

#### IoU coverage F1

对 `τ∈{0.3,0.5}`：

```text
hit_pred = # {prediction i | exists GT j: IoU(i,j)>=τ}
hit_gt   = # {GT j | exists prediction i: IoU(i,j)>=τ}
precision = hit_pred / n_pred
recall    = hit_gt / n_gt
covF1     = harmonic_mean(precision, recall)
```

允许多个 prediction 命中同一 GT。正式字段至少区分 `covF1_iou03_micro_global`、`covF1_iou05_micro_global`、`covF1_iou03_macro_pdb`、`covF1_iou05_macro_pdb`。

#### IoU one-to-one F1

本小节只定义 evaluator 指标；它不参与 Stage1 selector oracle，也不等同于 Stage2 loss 中的身份内 Hungarian。

对每个 τ 单独在 `IoU>=τ` 二分图上求最大基数匹配，得到 `m`：

```text
precision=m/n_pred
recall=m/n_gt
1to1F1=harmonic_mean(precision, recall)
```

总 IoU 只能作最大基数同分后的确定性次级 tie-break，不能先做一次连续分数 Hungarian 再过滤多个阈值。

正式字段至少区分 `1to1F1_iou03_micro_global`、`1to1F1_iou05_micro_global`、`1to1F1_iou03_macro_pdb`、`1to1F1_iou05_macro_pdb`。one-to-one 匹配始终先在**每个 PDB 内**独立完成；`micro_global` 只汇总各 PDB 的 `m/n_pred/n_gt` 计数，绝不把不同 PDB 的节点放进同一张匹配图。

#### top3/4/5-success-ratio

建议官方定义：

- 粗单阈值 candidate 按 `probability_mean` 降序；同分按 F1 component 的稳定身份排序。正式 proposal tree 已存在时使用合法的 `(source_tree_id,source_node_id)`（它不是伪造 CLG ID）；若先做独立 F1 prototype，则使用规范化 component ID，例如最小全图 voxel + mask hash，并在提升为正式 proposal 时验证一一对应；
- 对每个有至少一个 GT 的 eligible PDB，top-K 中存在任一 `IoU>=τ` pair 则成功；
- 分别报告 `K=3,4,5`、`τ=0.3,0.5` 的命中数、eligible PDB 数和比例；
- 额外报告 `GT Recall@K`，避免一张多配体图只命中一个仍得满分。

指标 v1 建议现在就冻结以下空样本/聚合政策，而不是留给实现者：

- `n_gt>0,n_pred=0`：该 PDB 的 cov/1to1 precision、recall、F1 均记 0；top-K 记失败。
- `n_gt=0`：不进入正例 top-K 或 per-PDB instance-F1 macro；另报 `negative_pdb_false_positive_rate` 与 predictions/PDB。
- `n_gt=0,n_pred>0`：这些 prediction 进入全局 instance precision 的分母，也进入 voxel micro Dice 的 FP。
- `n_gt=0,n_pred=0`：记录 true-negative/empty-empty 计数，不人为赋 Dice=1 来抬高 macro；per-PDB Dice 可记 NA。
- cov/1to1 **primary** 为跨 PDB 累计 `hit_pred/matched/n_pred/n_gt` 后计算的 global F1；同时报告只在正例 PDB 上逐 PDB 计算再平均的 macro 诊断。
- Dice 同时报 global micro 与可定义样本上的 PDB macro；原始 TP/FP/FN 必须保留。
- 若采用推荐的 bootstrap CI，以 PDB 为重采样单位，重复数与 seed 写进 metric manifest；10,000 次可作为起点。这是报告增强项，不是用户已冻结的核心指标门槛。

每个测试集必须分别输出 macro/micro 与原始计数；建议再输出 PDB bootstrap CI。只有互斥 test family 才能合并汇总。

### P4：GT-blind 运行

正式 test 分成两个进程：

1. inference/postprocess 只读输入和冻结 recipe，不能装载 overlap/GT；
2. evaluator 在预测完全落盘后读取 GT 评分。

metric manifest 保存 checkpoint/probability/proposal run、split hash、metric implementation hash、IoU thresholds、top-K、排序/tie-break、空样本政策和聚合；若启用推荐 CI，再保存 bootstrap 单位、次数与 seed。

## 7. 多阈值、首次居中物化与 selector

### C1：proposal recipe

先在 calibration 完成 `PROP-CLG-CAL`，冻结七个 Fα 阈值、物理阈值去重、legality/event/cap 与确定性 recipe。然后 `PROP-CLG-PROD` 对每条实际 producer route 的 split-scoped `probability_run_id` 应用**同一个冻结 recipe**：

1. 读取 calibration 已冻结的七个 Fα 阈值并去重成 physical threshold levels；
2. 每层 26 连通组件；
3. 建完整组件森林；
4. 应用统一 node legality；
5. F1 层优先枚举 CLG，再向低阈值；
6. 应用 event budget 与 PDB cap；
7. 为该 split/producer 写独立 `proposal_run_id`、树/CLG/inventory。

train（OOF/in-sample/独立 downstream-train）、validation、calibration 与每个 test family 都需要对应 proposal run；test 生产不读 GT。calibration 产物不能代替其它 split 的 proposal/materialization。

组件森林、CLG 枚举必须有确定性、非法节点不穿越、原子事件、退休集合和 cap 测试；详见主计划 §6–§7，本文不重写算法。

### C1.5：`FEATURE-00` 冻结实际导出层

首次物化开跑前，用 1–3 个 PDB 的 forward inventory 列出候选字段，再由用户冻结最小集合。每个字段逐项回答：

```text
logical_name
producer module + exact hook
before/after real-P interaction
shape/channel/dtype
coordinate frame
是否在当前 CPC phase 中实际训练
P/F1/Group-parent 两条 route 是否同源
checkpoint/config hash
```

建议候选是 `voxel feature before ligand head`、`P before/after interaction`、`real receptor before/after interaction`、坐标和各自概率；但不能只写“具名 feature”后让 agent 自选层。golden test 应证明 F1 与 Group-parent 对同一几何调用同一个 hook recipe，未执行的层不填零。

### C2：两条“首次局部物化”

#### F1 baseline

- 每个合法 F1 blob 建一个居中 `infered_box`；
- `materialization_role=f1_baseline`；
- 重跑同一 Find checkpoint，保存稳定 feature source；
- 不创建假 CLG/selector/selection ID。

#### Multi-threshold Group-parent

- 每个 CLG 只运行一次 Group-parent 居中 Find；
- `materialization_role=clg_group_parent`；
- 保存共享 voxel/P/receptor 与 candidate membership；
- 不为每 candidate 重复跑网络；
- 先对完整 dense rank map 做真实体量/压缩基准；当前 BOX 契约未修改前仍按契约保存。只有用户批准 schema 修订后，才可改为优先稀疏 `rank_at_parent_voxel`。

两者都必须保留原始全图 candidate identity；局部重跑只补特征/观察，不替换全图 mask。

feature-source manifest 至少写：字段名、producer module 出口、before/after interaction、channel、dtype、坐标帧、Find checkpoint/config hash。缺字段就判不兼容，不能填零。

### C3：selector

顺序固定：

```text
materialized CLG
→ selector train dataset + online stage1_independent_max_antichain_oracle
→ freeze checkpoint
→ score all CLG (selector_run_id)
→ calibration scan tau_G
→ non-empty max-DP decode (selection_run_id)
```

SEL-01 按已经冻结的 Stage1 independent-max oracle 实现：

```text
q_i = max_o IoU(M_i, G_o)
Q_GT(S) = sum(q_i for i in S) - lambda_count * |S|
```

同一 GT occurrence 可以成为多个候选各自的最大 IoU 对象；这是当前 Stage1 选择目标的有意性质，由反链约束与 `lambda_count` 控制冗余。Stage1 不构造 A/B 覆盖矩阵，也不运行 Hungarian。硬验收为：

- overlap→`q_i` 的逐节点计算与手算 fixture 一致；
- 小树枚举全部合法反链得到的最优 `Q_GT` 与 oracle tree DP 逐值一致；
- selector 学习分数上的 MAP、log-partition 与梯度使用另一套小树穷举逐值验证，不能拿 oracle DP 测试替代；
- 负 CLG 的 antichain loss 严格为 0；
- gate 未过才允许空结果；通过后必须非空；
- test 只用 calibration 冻结 `tau_G`；
- 最终 report 固定输出用户要求的 0.3/0.5；`tau_G` 的 `M_instance` 则服从独立冻结的 gate metric。当前主计划仍是 0.3/0.6，在正式收口改变前不能由实现者自动替换。

后续报告中的 `1to1F1` 仍按每个 PDB、每个 IoU 阈值的最大基数匹配计算；它只评价输出，不反向改写 Stage1 oracle。

### C4：并行推进方式

`P_global` 冻结后可并行：

- 路线 A：F1 baseline → 首次物化 → Stage2 baseline；
- 路线 B：组件森林/CLG → Group-parent 物化 → selector → selection。

两条路线必须共享 split、Find checkpoint、feature recipe 和 metric v1，这样才能做公平比较。selected-final refinement 是 selector 后的可选 2×2 消融，不在关键路径。

## 8. Stage2 Matcher 的实操

### S2-0：先明确输入 route

Stage2 dataset 只允许两条正式 route：

- `f1_baseline`：全部合法 F1 blob；
- `multi_threshold`：指定 `selection_run_id` 的 selected Global Proposals。

无预测材料时可用 GT ligand atom envelope 做早期 featurizer/model smoke，但必须标为 `gt_envelope_pilot`，不能伪造成 predicted blob 或正式 Stage2 结果。

### S2-1：正式材料 manifest

只保存引用：

```text
split_manifest_id/hash
route
probability_run_id
proposal_run_id
materialization_run/addon
selector_run_id / selection_run_id
feature_source_manifest_hash
overlap_label_addon              # train/val loss；calibration scorer/evaluator side 可读
CCD candidate-list/count manifest
producer_fold_id
schema/code/config hash
```

test 的模型/featurizer inventory 不含 overlap、occurrence mask 或空间 oracle labels。manifest 冻结三个正交字段：

```text
gt_blind_regime: fully_gt_blind | spatial_overlap_gt_blind
ccd_candidate_source: ground_truth | user_supplied | retriever | fixed_catalog
count_source: ground_truth | user_supplied | predictor | none
```

任一 source 为 `ground_truth` 时，只能标 `gt_blind_regime=spatial_overlap_gt_blind`，同时设 `oracle_side_information=true`；不能称 fully GT-blind。`fully_gt_blind` 的 candidate/count 必须来自用户在不知道 test GT 时给出的输入、冻结 retriever/predictor 或固定 catalog，并记录 producer/hash。难负身份配方也必须固定。

### S2-1.5：featurizer、target 与 batch 的落地

对一个 PDB，先形成：

```text
M 个 route 决定的 blob / Global Proposal
J 个 CCD identity，身份 j 带 count N_j
Σ_j N_j 个模型 slot
O 个 GT occurrence，每个 occurrence 绑定 object_key/identity
```

训练标签不把 slot 预先钉死到某个同身份 occurrence。数据侧从 overlap addon 生成 occurrence 级：

```text
alpha[i,o] = intersection(blob_i, gt_o) / |gt_o|        # recall target A
beta[i,o]  = intersection(blob_i, gt_o) / |blob_i|      # precision target B
O[i,o]     = 1[IoU(blob_i,gt_o) > tau_O]                # 密度档分类 target
```

collate 保留 `occurrence_identity_index` 和 `slot_identity_index`；loss 在每个 identity 内用 Hungarian 把 `N_j` 个 slot 与该身份 occurrences 配对。跨 identity 不匹配，假阳 blob 通过“所有 slot 列都低”学习拒绝。Stage2 当前收敛设计规定密度档 `O=1[IoU>tau_O]`（严格 `>`）和纯受体档 `O=1[distance<rho]`（严格 `<`）；待冻结的是 `tau_O`、`rho` 数值，不能借用 Find 评测的 0.3/0.5 而不声明。正式实现计划仍需把该比较符号提升为可执行契约。

Stage2 Hungarian 的最小测试集还应证明：同身份 occurrence 顺序任意置换后最小 loss 不变；任何配对都不跨 identity；Phase 1 的 assignment cost 只含 O；Phase 2 的 cost 按正式权重组合 A/B/O；vectorized/chunked loss 与逐 PDB reference loop 的 assignment、loss 和梯度一致。

建议最小 batch 逻辑视图：

```text
blob/PP features + coords + padding/membership       [B, M, ...]
receptor A features + coords                         ragged/padded per blob
CCD atom/pair features                               [B, N_slot, L, ...]
identity/count/slot indices                          [B, N_slot]
alpha/beta/O occurrence targets                      [B, M, N_occ]   # train/val loss；calibration scorer side
occurrence identity + target padding masks           [B, N_occ]
blob/slot/pair masks                                 [B, M], [B,N_slot], [B,M,N_slot]
```

实现同时做一个逐 PDB reference loop，与 `[n_blobs,n_slots]` outer-batch 输出/损失逐值对齐。`n_blobs=0` 的 PDB 不伪造背景 blob：保留在数据/评价 inventory；训练是显式 skip pair-loss 并计数，还是进入另一个 sample-level 拒绝头，必须由 Stage2 计划决定。

负样本分三类并分别计数：自然假阳 blob、同图错误 CCD/slot cell、配置采样的难负 CCD identity。难负来源、比例、是否按化学相似度采样和 count 生成方式进入 dataset manifest；不能让每个 worker 自行随机补身份。

### S2-2：cross-fit（推荐的高成本路线，待用户冻结）

cross-fit 不是当前正式计划已经冻结的硬要求。`XFIT-00` 应先用一个 fold 的 wall-time/存储 profile 估算 K-fold 总成本，再由用户选择：

- `producer_fit_relation=out_of_fold`：推荐的严谨正式路线；
- `producer_fit_relation=in_sample`：便宜路线，manifest 明确堆叠分布偏乐观及适用结论；
- 独立 `downstream_train`：不做 K-fold，但该 split 必须在 Find train 冻结前预留并从 Find train 排除，牺牲一部分上游训练数据。

若选择 cross-fit，执行图为：

```text
XFIT-00              冻结 K folds、fold hash、calibration/gate 规则和资源预算
→ XFIT-FIND          每 fold 训练一个没见过 held-out fold 的 Find
→ XFIT-INF/MAT       为 held-out fold 生成 P_global、proposal 与首次物化；合并成全 train 的 Find-OOF materials
→ XFIT-SEL-TRAIN-k   对每个 k，只用非 k fold 的标签及其 Find-OOF materials 训练 selector_k
→ XFIT-SEL-SCORE-k   selector_k 对 held-out fold k 评分并 selection
→ XFIT-MERGE         验证每个 train PDB 在 Find 与 selector 两级都恰有一个 producer_fold_id，再合并 Stage2 manifest
```

公共 calibration 是否服务所有 fold，或每 fold 只用非 held-out 数据标定，必须在 `XFIT-00` 冻结；任何阈值/gate 都不能读取正在被生成材料的 held-out fold GT。还要冻结 final selector 的训练分布：推荐在全 train 的 **Find-OOF materials** 上训练；若改用 final-Find in-sample train materials，manifest 必须标 `producer_fit_relation=in_sample` 并说明分布变化；若采用独立 downstream-train，则只用 final Find 从该未见集合产生的 held-out materials 训练。这个具名 final selector 再消费 final Find 为 val/calibration/test 生成的材料。

### S2-3：phase 1 与 phase 2

依据现有 Stage2 设计：

- **Phase 1**：O-only；训练前导/stem、前 m trunk 与全部 m+n 粗分支；后 n 可训练粗分支 rep-rep/打分，但不跑 trunk 更新且不开实体回吸。loss 是配置冻结的 O focal/CE + 获批的粗分支/表示辅助项。先完成 toy overfit、全图 `[n_blobs,n_slots]` batch parity。建议 checkpoint 主 monitor 为 validation O average precision，并同时保存 loss/F1；不在 test 选阈值。
- **Phase 2**：从 phase1 只接权重；冻结 phase1 前导/stem（含 repr seed）、前 m trunk 和前 m coarse；后 n trunk 从头训练，后 n coarse 训练并使用具名的零初始化实体回吸门，fine 只在当前收敛设计允许的末块/末段训练。总损失由 O 分类、A/B 软回归和获批 auxiliary 组成，权重必须显式。Smooth-L1 可作训练 loss；正式回归报告用 MAE、分位误差和 calibration error。
- **Phase 2 门调度**：后 n 实体回吸门在前 `k` epoch 固定为 0，之后按冻结 warmup 令 `g(step)` 从 0 ramp 到 1；从第 m 块冻结 trunk 注入后段的 condition 第一版默认关闭，若开启也只能是零初始化具名消融。`m/n/k/warmup` 必须进入 Stage2 实现计划与 manifest；讨论稿当前 `m=2,n=4` 只是暂定值，不得写死成模型常量。
- chunk 不是第一版默认；若启用，必须有 2-block×2-chunk 与 unchunked 梯度逐元素等价测试。
- frozen pattern 命中 0 必须 hard fail；冻结子树保持 eval。

Phase 1/2 各自都要有：synthetic forward、single backward、1-PDB/tiny-set overfit、validation、BEST/last、model-only phase handoff、失败重放和资源 profile。目标 CLI：

```bash
python -m stage2.train +experiment=stage2/phase1_O_only --cfg job --resolve
python -m stage2.train +experiment=stage2/phase1_O_only train.max_steps=1
python -m stage2.train +experiment=stage2/phase2_ABO init_from=... --cfg job --resolve
python -m stage2.train +experiment=stage2/phase2_ABO init_from=...
python -m stage2.calibrate_decoder --checkpoint ... --split calibration
python -m stage2.evaluate --decode-run ... --test-manifest ...
```

这些仍是目标接口。Stage2 当前没有代码；开始 S2D-01 时需另建 implementation plan/exec log，不应把本节当成已实现命令。

### S2-4：“相同验证集和指标”的正确落法

复用：

- 同一 PDB split/test-family manifest；
- 同一冻结上游 blob mask 与 metric implementation；
- Stage2 解码后保留 blob 的端到端 Dice/covF1/1to1F1。

不能直接复用：

- Stage2 不输出 mask，所以 Dice 不是 Matcher 自身的 loss/内在指标；
- Find top-K blob 与 Stage2 top-K `(blob,CCD slot)` 语义不同；
- 同一 blob 配给多个 slot 时，几何指标只能计一次，化学 pair 指标按 slot 计。

冻结 decoder 后，定义 accepted pair 集 `D={(blob_i,slot_s,CCD_j,pair_score)}`，再派生两个不同评价对象：

```text
accepted_unique_blobs = unique {i | exists pair in D using blob_i}
blob_stage2_score[i]  = max pair_score over accepted pairs using blob_i
```

- **Stage2 后几何指标**：对 `accepted_unique_blobs` 的原始上游 masks 计算 union Dice、covF1、1to1F1；同一 blob 多 slot 只计一次。
- **Stage2 后 geometry top3/4/5**：按 `blob_stage2_score` 排 unique blobs，再用 Find 同一 IoU 0.3/0.5 success 口径。
- **pair top3/4/5**：按 pair score 排 decoded pairs；成功要求 CCD/identity 正确且该 blob 与对应 occurrence 的 IoU 达 0.3/0.5。字段名必须带 `pair_`，不能冒充 Find blob top-K。
- 若 Stage2 没拒绝 blob、也没改变 unique-blob 排序，则几何指标只是上游复报；报告 delta=0，不把它宣传成 Matcher 改进。Matcher 的增益主要看 pair/identity 指标。

Stage2 自身还应报告：

- O 的 micro/macro average precision（或另行具名的 trapezoidal PR-AUC）、precision/recall/F1；不得把两种面积算法混名；
- A/B 回归 MAE、分位误差与分桶校准；Smooth-L1 只作为可选训练 loss，不冒充正式评价指标；
- identity 正确且 `IoU>=0.3/0.5` 的 decoded-pair precision/recall/F1；
- 假阳 blob 拒绝率；
- merge/split 成功率；
- seen/unseen CCD、count、candidate-list size 分层；
- 端到端 F1-baseline vs multi-threshold 的相同测试比较。

decoder/gate 只在 calibration 冻结；test 一次性运行。

## 11. 最短关键路径

```text
用户确认 P-loss/curriculum + origin/target/core 默认
```
