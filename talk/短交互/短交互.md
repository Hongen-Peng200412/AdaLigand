# Stage1 数据与训练入口的短交互式整理

## 本文解决什么问题

本文讨论接下来如何整理 AdaLigand Stage1 的训练数据与启动入口，不直接修改代码、数据或正在运行的作业。

当前目标不是复刻此前“一个 AI agent 从数据处理一直做到训练提交”的长任务，而是采用短交互式工作：每次只完成一个边界清楚、可以立即审阅的小任务；我交付代码或事实核查结果后立即停下，由用户检查、决定是否运行，再进入下一步。

当前结论是：

1. Slurm 作业 `321107`、`321540` 和 `321743` 是已经接受的基线实验。它们的代码、运行目录、进程、锁、配置、数据和输出均不得中断、替换或修改。
2. 后续实验不再把这些作业使用的临时脚本和临时目录当成正式入口，但可以把已经完成且能够核验的数据产物作为来源。
3. 后续实验使用一个明确命名的正式数据目录。该目录中的 `final_keep_list.jsonl` 和 `box_pool` 在训练开始前已经排除辅助标签缺失的少量 `pdb_id`；训练时不再通过 `excluded_pdb_ids` 临时排除这些结构。
4. 当前首选方案不是重新计算全部 `keep_list` 和 `box_pool`，而是最小修正已有产物：使用已经记录的 16 个 `pdb_id`，从已有 `final_keep_list.jsonl`、BOX 池发布清单和验证请求中一次性删除对应内容，再把剩余的单 PDB BOX 文件复制到新的正式目录。只有现有产物无法安全读取或内部索引无法保持一致时，才重新讨论全量计算。
5. 正式训练启动链路由对话 `019f999a-2b0a-7e70-bd7b-3c8e120d3c69` 负责。本对话暂时只负责训练数据产物及其必要工具，不与该对话同时修改同一文件。

本文是讨论文件，不是已经批准执行的 ExecPlan。16 个排除编号已经由本地配置和执行记录共同确认；正式源目录与目标目录仍由用户指定，不能把尚未实际生成的新产物写成已经发生的事实。

## 对当前方向的判断

这个方向是合理的，而且比继续修补临时训练链路更稳妥。关键不在于“所有数据必须从零重算”，而在于后续训练只依赖一组能够解释和复核的正式产物：

- `final_keep_list.jsonl` 明确列出 Stage1 preparation 接受的 `pdb_id`；
- `box_pool` 只包含该清单中分配给 train 和 validation 的 `pdb_id` 对应的 BOX；
- 辅助标签目录对同一组 `pdb_id` 完整可用；
- 配置直接引用正式目录；
- `Dataset` 和请求构造代码不再通过 `excluded_pdb_ids` 临时删掉结构；
- 产物附近保存来源、筛选规则、数量和核验结果，使以后不需要依赖本次对话才能理解。

“从已有数据最小复制和筛选”与“正式化”并不矛盾。正式产物的核心要求是来源清楚、内容固定、契约可验证，而不是必须重新消耗大量 CPU 证明计算过程足够昂贵。本轮不通过扫描 `ligand_dist.npz` 重新发现失败结构，也不重新生成 BOX 起点；只使用已经冻结的 16 个 `pdb_id` 修正清单、索引和文件集合。只有已有产物无法证明来源、文件已经损坏、或筛选后无法保持内部对齐时，才需要暂停并重新讨论。

需要特别警惕的是训练集合差异。旧版 `Find_0` 使用的 `pdb_id` 集合比新版 `Find_1` 和 `unet_c1` 略大，因此三项当前基线并非严格使用完全相同的训练样本。这个历史事实应当保留，不应修改正在运行的作业。后续新实验则应统一使用排除辅助标签缺失结构后的同一组正式数据。若以后需要严格比较旧模型与新模型，应当另行决定是否在统一数据上重跑旧模型；这不是当前数据整理必须顺手完成的工作。

### 短任务 3：编写最小的数据整理工具

下一步代码写在 Pocket_Plus，因为 `final_keep_list.jsonl` 到 BOX 池的长期字段契约、读取函数和测试都位于 `src/datasets/`。建议新建职责单一的 `src/datasets/stage1_preparation_filter.py`，主要入口暂定为 `materialize_filtered_stage1_preparation(...)`，命令行入口只负责解析源路径、目标路径和排除编号。正式写入前仍需按项目双线 Git 规则重新核对 `Learn/CUMULATIVE` 与工作区。

工具只完成已经批准的动作：

1. 读取指定的 `final_keep_list.jsonl`、BOX 池 `_COMPLETE`、`manifest.json`、`validation_selection.npz`、`config.json` 和 `summary.json`。
2. 接收明确传入的 16 个排除编号；代码不内置某次运行的 PDB 名单，也不扫描 `ligand_dist.npz`。
3. 保持 `final_keep_list.jsonl` 中其余记录的内容和顺序，只删除 `pdb_id` 命中的记录。
4. 保持 `manifest.json` 中其余 PDB 的划分和顺序，只删除命中条目；不重新运行 split，不让其他 PDB 改变 train 或 validation 身份。
5. 普通复制 manifest 保留的 `train/{pdb_id}.npz` 与 `validation/{pdb_id}.npz`，不重新计算 BOX 起点。
6. 从现有 `validation_selection.npz` 删除命中 PDB 的 center、bias 和 context 请求；保留其他请求及其顺序，并重映射 `*_pdb_index`。
7. 复制仍然适用的 BOX 生成配置，重新计算目标摘要；另写一份简短派生记录，保存源文件摘要、排除编号、各处命中数量和目标文件摘要。
8. 最后写入 `_COMPLETE`。目标目录已存在、源目录缺少 `_COMPLETE`、字段不符合契约或内部索引失配时直接停止，不覆盖文件。

工具不应顺便启动训练、生成新辅助标签、修改训练配置或接管 Slurm 作业。它是从一个已发布 Stage1 preparation 派生另一个已发布版本的长期数据工具，不进入训练调用路径。测试放在 `tests/datasets/`，使用小型临时 `final_keep_list.jsonl`、manifest、validation selection 和单 PDB NPZ，至少覆盖：

- 被排除 PDB 同时出现在训练池和验证池；
- 部分排除编号原本不存在；
- 验证 PDB 编号删除后的重映射；
- 保留请求、BOX 数组和文件字节不变；
- 目标目录已存在时拒绝覆盖；
- 源 manifest、selection 或单 PDB 文件不一致时拒绝发布；
- `_COMPLETE` 只在全部检查通过后出现。

本任务不增加缓存、数据库、训练期回退或多层版本系统。

### 短任务 5：核验正式产物

正式数据完成后，至少核对：

- 正式 `keep_list` 中没有任何已确认缺少辅助标签的 `pdb_id`；
- 正式 `box_pool` 中没有这些 `pdb_id` 对应的 BOX；
- 每个允许训练的 `pdb_id` 都具有训练配置要求的辅助标签；
- `keep_list` 与 `box_pool` 中的 `pdb_id` 集合符合约定，BOX 数量与筛选前后的差值一致；

- 训练集与验证集没有因为脚本错误而互相混入；
- 目标目录没有覆盖现有基线产物；
- 新产物可以被当前数据读取代码加载，但核验过程不启动正式训练。

核验应输出具体数量和差集，而不是只写“检查通过”。

## 数据落盘的建议

在用户指定正式目录前，不应创建新的数据目录。目录确定后，建议满足以下最小性质：

- 路径稳定，不包含 Slurm 作业编号、临时任务编号或一次性时间戳；
- 训练集与验证集的文件能从名称或相邻说明中明确区分；
- `keep_list`、`box_pool` 和辅助标签之间的对应关系明确；
- 旧产物只读保留，新产物写入新目录；
- 新产物的来源路径、原始数量、排除名单、目标数量和生成命令有一份简短记录；
- 训练配置只引用正式目录，不引用 `tmp/`、某次 allocation 或某个运行目录。

本轮默认普通复制保留的单 PDB BOX 文件，因为它最容易理解且不会让新版本随旧目录变化。只有核实 BOX 池大小后发现普通复制明显不可接受，才单独讨论硬链接或其他复用方式；第一版工具不同时实现多种存储策略。

## 需要避免的几种做法

- 不在训练时根据“辅助标签文件是否存在”动态改变样本集合；
- 不让 `Find_0`、`Find_1` 和 `unet_c1` 各自继续维护来源不明的清单副本；
- 不把当前正在运行的临时脚本直接改名后称为正式脚本；
- 不为追求“从零生成”而重复运行无法增加可信度的昂贵计算；
- 不只复制文件而不记录原始路径、筛选集合和数量；
- 不在正式目录中边运行边覆盖已有文件；
- 不让数据整理对话和启动链路对话同时修改同一配置或脚本；
- 不把本轮讨论中的假设直接写成数据契约。
