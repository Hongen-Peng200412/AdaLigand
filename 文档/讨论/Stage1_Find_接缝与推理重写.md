## §1 三处改动总览

Stage1 模型成熟、可直接训，本次只动三处，**改动全隔离在数据适配层与推理侧，模型架构与权重血统不动**：

1. **换新数据 / 新契约、模型不变**：训练适配器改吃 AdaLigand 新数据（第 1 层 density / 49 维受体特征 / 原子标签，经 BOX 契约的**共用 builder**）；模型输入形状/通道与 Pocket_Plus 原样一致。风险被隔离在数据适配层。
2. **推理 / 落盘重写**：两大改动 = **CPU 并行**（§3.1）+ **二阶段推理**（§3.2）；产物落盘接口见 §6。
3. **裁剪**：**CPC 第三阶段取消**（来不及调参；两个 F1 本就在无 CPC 下测得，取消对基线零影响）；推理侧不需要维持对多分类任务的支持（Stage2 只需 ligand-area / binding 概率 + blob，不需类别）。

## §2 数据进（吃新契约，模型不变）

- Stage1 训练/推理都经 **BOX 契约的共用 builder** 读第 1 层：exp/sim 密度（+ 现场算 56 通道）、49 维受体特征、binding/instance 原子标签、ligand_area / 质心。box 侧走 **materialize 扰动路径**（BOX §5.2/§5.3、§8 Stage1 对接）——Stage1 增广 ⟺ 只用第 1/2 层、不吃第 3 层 blob。
- **模型不变**：新数据只是换了 dataset 源与落盘契约，模型输入契约（通道/形状/坐标帧）保持 Pocket_Plus 原样。
- **F1 基线**：ligand-area≈0.55、binding≈0.65，均在**无 CPC** 下测得，是本次重训的参照下限。

## §3 推理重写

### 3.1 CPU 并行（训推共用 builder）

- **已证瓶颈在 CPU**（预处理 / 切 box / 装特征），不在 GPU forward。推理必须像训练一样**多核 CPU 预处理 + GPU forward 重叠**（DataLoader worker 式流水），训推**共用同一套 dataset/builder**（BOX §10 原则），杜绝推理程序另拍一套格式。
- **CPU 预算闸**与 featurizer 一致（`迭代运算 §4` featurizer 契约）：装特征在最大规模（PP≈8096、口袋 A≈3k 原始）下 CPU 要扛得住；扛不住的派生量退回预计算。

### 3.2 二阶段推理（近似中心化落盘）

全图推理走**两个 pass**，落盘的是第二个 pass 的结果：

- **pass-1（定位）**：一如既往全图**滑窗推理 + 后处理**，得到若干 blob / pred instance（各有中心）。
- **pass-2（中心化重推）**：以每个 blob 中心**重裁一个 box、再推一遍**；**落盘的是 pass-2 的 blob / la_voxel / coverage**。
- **动机**：保证落盘 blob 来自**近似中心化**输入，闭合训 / 推域差——训练用的 center/bias box 是围绕 GT 居中的，落盘量也应来自居中输入，二者同源。
- **落地**：pass-2 产的量落进 BOX 第 3 层的 `infered_box`（BOX §9.1 已相应细化为"pass-1 定位 + pass-2 中心化重推产落盘量"）。**冻结 box（center/bias/context）不走两阶段**——box 身份已定，Stage1 在该冻结 box 上单次跑。

## §4 打分与二次筛选（不删；存 / 用分离）

**主张**：两个 pass 后**只存、不删**。**"怎么存"和"用哪些存下来的 blob"是两个独立问题**（存/用分离，与 BOX 契约"阈值不烤进存储"同源）。

### 4.1 存：过量保存 + 套打分

- **过量保存**：比"最优 F1 截取数目"存**更多**（越过最优截取、留下边界 blob），只加一个**很松的 recall-first 下限**丢掉明显垃圾。理由：Stage1 本就 recall-first；边界 blob 是迷你网（§4.2）的训练料，也是它将来"救回真 blob"的前提；Stage2 自己会做 explaining-away / 拒假阳，带分数的假阳是它的本职。
- **套打分**：每 blob 附一个**可扩展命名分数集**（落 BOX §4.2 `scores`，"添油只增不改"用在分数上）：
  - **老的粗预测分数**（现成——老代码用来排序、被"最优 F1"阈值切的那个置信分）**必存**；
  - 记一下"**最优 F1 截取会切在哪**"当参考默认（复现老行为，但不硬删）；
  - 将来迷你网分数（§4.2）作为新条目**并列**，老分数一字节不动。
- 用 F1 还是偏 recall 的 F_α 只是**下游选择旋钮**（§4.3），不烤进存储。

### 4.2 迷你打分网（可选、可并行训）

- 一个**独立小二分类网**：输入 = 落盘 pred instance，**尤其其周围受体上下文**（空间分布 / Stage1 预测的 binding 概率 / 可选 Stage1 受体特征，落 BOX §4.5）；输出 = **该 blob 是否真实**。
- **不是必须**：v1 甚至不用它，直接套老的最优 F1 截取；它可**边训边做后面的 Stage2/3**，训好后其分数并入 `scores` 集、被同一个选择旋钮消费。
- **丢弃中间档**：不再手搓夹在"老最优截取"和"迷你网"之间的高斯核打分器——那档启发式不值得费心，只留两级（老粗分数 / 迷你网）。
- **载荷约束（现在就锁）**：无论 v1 用不用迷你网，**落盘必须记全它的输入（受体上下文，BOX §4.5）**——否则将来训它得重跑整轮推理。
- 现在的老管线只用体素级 ligand-area 概率、没用受体预测；本步**提前把受体用起来**（空间分布 / binding 概率 / 特征），受体信号在 blob 筛选（这里）与匹配（Stage2）各用一次，同源。

### 4.3 选择在消费侧

- **"用哪些 blob" = 消费侧 dataset/featurizer 的选择旋钮**（阈值 + 指标 F1/F_α + 可选一个 scorer），住在 `迭代运算 §4` featurizer 契约，**不进存储、不进 Stage1**。
- **三分**：**打分器（含迷你网）= 分数的生产者、归本文（Stage1）**；**截取 / 选择 = 分数的消费者、归 featurizer**；**添油只存分数、不做选择**。三种打分器（老最优截取 / 迷你网 / 未来任意）全走"产分数 → 下游截取"同一条管子，可热插拔、互不改结构。

## §6 落盘接口（指针 → BOX 契约）

产法/语义归本文，**存储 dtype/布局全在 BOX 契约**，此处只列接缝：

| 产物 | 语义（本文） | 存储（BOX 契约） |

| blob（mask / voxels / prompt / provenance / scores） | pass-2 中心化重推产、过量保存、套打分 | §4.2 |
