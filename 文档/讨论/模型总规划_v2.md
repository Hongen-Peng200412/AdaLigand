## §1 背景、术语、范式

### 1.1 术语表（自包含）

| 术语 | 定义 |
|---|---|
| **密度图 / map** | 冷冻电镜重建出的 3D 电子密度体，体素张量。Stage1 在其上找配体。 |
| **体素 / voxel** | 密度图的最小立方单元。本文体素网格轴序统一 `(C, Z, Y, X)`。 |
| **occurrence** | 密度图里**一个真实配体实例**（共价连通分子组分整体）。有全空间坐标、有 GT 密度区域 mask。主键 `(pdb_id, candidate_id)`。 |
| **CCD / 身份 / identity** | 配体的**化学身份**（去重后的化学对象，含原子图、键、参考构象 `ref_pos`）。一个身份在一张图里可出现 `N_j` 次（`N_j` 个 occurrence）。本文"身份"="CCD 对象"="`object_key`"。 |
| **count `N_j`** | 身份 `j` 在该图中的 occurrence 数。训练时由 GT 给出，推理时由用户给出。 |
| **ligand-area** | 配体占据的密度区域（以配体重原子为中心、半径 1.7Å 的体素并集）。Stage1 预测它，GT 也有它。 |
| **blob** | Stage1 预测出的**一个连通的 ligand-area 区域**。一个 blob 在后续等价于"一个 PP 簇"。blob 有体素 mask `b_i`、有空间位置。**blob 可能是假阳（无对应 occurrence），也可能与真实 occurrence 非一一对应（合并/分裂）**。 |
| **P** | Stage1 内部的**伪原子 anchor**（pseudo atom），点云形式，每 BOX ~512–1024 个，带 Stage1 算出的多套中间特征。 |
| **PP** | 为 Stage2/Stage3 重采样的**密度点集**（每 blob ~4096，可配到 8192），比 P 更密；其特征来自密度网格采样 + 对 P 的融合（见 §3.2）。 |
| **A**（受体点） | 某 blob 对应 **pocket 的受体原子**（receptor atoms），点云形式，按"到 blob 的 k-NN/半径"截断。**注意与覆盖矩阵 A 同字母不同义**，下文凡指受体点均写"受体点 A"。 |
| **S 源** | 同一个点可拼凑的**多套来源特征**（见 §3.1）。把"特征来源"做成一个张量轴 `S`。 |
| **prompt 点** | 交给 Stage3 的种子位置，取 blob 的 ligand-area mask 质心。 |
| **相对位置偏置** | 把两点的相对坐标（`x_a - x_b`）投影成一个加到注意力 logits 上的偏置项，使注意力带几何先验。 |
| **learned-query readout（可学习查询读出）** | 把一组 `[N, d]` 特征塌成一个向量/标量时，不用均值，而用**一个可学习的查询向量** `q_r` 去 cross-attn 这组特征，得 1 个向量再 MLP。即"学出来的加权池化"。 |
| **覆盖矩阵 A / B** | 本文要预测的核心对象（§5）。`A`=配体被 blob 捕获比例（recall 向），`B`=blob 被配体解释比例（precision 向）。 |
| **explaining-away（解释消去）** | 概率推理现象：某观测一旦被一个原因解释掉，别的原因概率下降。这里指：某身份的 count 预算被几个高置信 blob 占满后，剩余模棱两可 blob 属该身份的概率被压低。 |
| **匈牙利匹配 / `linear_sum_assignment`** | 二分图最小代价完美匹配的多项式算法（`scipy.optimize.linear_sum_assignment`），$O(n^3)$，本文只在每个身份内部、规模 `N_j` 极小处用。 |

### 1.2 三阶段范式与 Stage2 的位置

AdaLigand 使用 Find–Match–Build 三阶段流水线：

```text
Find  (Stage1)  ：从整图概率的多阈值组件森林产生并选择 Global Proposal（偏 recall，宁多勿漏）
Match (Stage2)  ：把“80³ Group-parent 物化中的候选稀疏特征视图”与“候选 CCD 集合（含每身份 count）”匹配，并拒绝假阳候选
Build (Stage3)  ：在选定 (Global Proposal, CCD, prompt 点) 上做扩散/流匹配生成配体 pose
```

**Stage2 的输入自然形态**：指定 `selection_run_id` 选中的全部 Global Proposal；每个候选通过所属 Group-parent BOX 的共享 voxel/P/receptor 表和自身行索引得到稀疏特征视图，再与该图的候选身份集合（每身份附 count）一起输入。**Stage2 的输出**：两张覆盖矩阵（§5），经解码（§8）转成若干 `(Global Proposal, CCD, prompt 点)` 交给 Stage3。**Stage2 不做候选 mask 精修，也不做 pose**；可选 selected-final 精修属于独立的 Stage1 后处理路径，Stage3 负责 pose 生成。

> 本文与既有 `模型总规划.md` 的关系仅是：后者给 Find/Build/BOX 的早期总览，本文是 Stage2 与共享基建的细化与修订。读本文无需先读它。

### 1.3 为什么 Stage2 不用 DETR 式匹配损失（跨身份层面）

DETR / Mask3D 的匈牙利匹配，前提是模型吐出**匿名、可互换、随训练漂移的 query**，匹配的职责是给这些无身份预测分派 GT 目标。Stage2 不是这个局面：blob 来自 Stage1（给定、有空间身份），CCD 来自候选表（给定化学身份）；**训练时 blob↔occurrence 的 GT 对应已知**。所以**跨身份不需要匹配损失**——不同身份靠化学区分，监督直接打在已知对上。

匈牙利只保留**唯一一处正当用途：同一身份内部、`N_j` 个先验不可分的副本之间**（§6）。这是唯一真存在的可交换性，也是唯一被许可的匹配。

### 1.4 反作弊核心不对称：blob 有位置、CCD 无位置

匹配判别力必须来自**化学/形状相容性**，不能来自"位置泄露"。因此：

- **blob 侧（PP、受体点 A）带 map 位置**，含 blob 间相对几何——合法且有用（判分裂、判共现、计数推理）。
- **CCD 侧只带内部构象几何**（`ref_pos` 的相对结构，经 PairFormer 进 pair 偏置），**绝不带任何 map 位置**。
- 因此 **blob↔CCD 的跨边注意只在特征空间做，不加跨帧位置偏置**（既不知 CCD 在 blob 里的朝向，也不准给它位置）。把 blob 点按质心中心化以获平移不变，几何只在各自一侧内部流动。

这条不对称是整个 Stage2 任务的结构指纹。

## §2 数据与 BOX 家族

### 2.1 BOX 尺寸约定

- **Stage1（Find）输入 BOX = 80³ @1.0Å**。
- **Stage2/Stage3 的基础候选来自 80³ Group-parent BOX**。Stage1 多尺度特征只在 Group-parent Global Proposal Mask 的稀疏 voxel 表上保存；P 与受体也使用共享变长表。可选密度 U-Net 可以另读 48³ 或其它配置大小的稠密 exp crop，但它只是附加调制源，不能成为基础输入成立的前提。

### 2.2 BOX 家族与落盘特征包（→ 详见 `文档/讨论/BOX-level数据契约.md`）

> **数据契约的唯一权威是 `文档/讨论/BOX-level数据契约.md`**；本节只留模型直接关心的语义与动机，存储/拆分/添油细节不在此重复（避免 drift）。

模型侧需要知道的三件事：

- **正式预测候选的唯一来源**：Stage1 全图概率组件森林中的 Global Proposal，经 CLG selector 和反链选择得到；它们只属于 `infered_box`。`center/bias/context` 只用于 Stage1 基础训练，不产生 Stage2 blob 或假阳。
- **无预测候选的试水训练**：由配置使用 GT ligand atom envelope 构造口袋，不伪造 blob。正式训练/推理读取某个 `selection_run_id` 的 selected Global Proposal。
- **共享特征包**：一个 CLG 的 `clg_group_parent` BOX 保存一份 parent voxel/P/receptor 表；每个候选用行索引取得自己的 mask、P 和 pocket 视图。F1 单阈值基线使用 `materialization_role=f1_baseline`。字段与 shape 见 `文档/讨论/BOX-level数据契约.md §4`。

## §3 共享表示层（tokenizer，Stage2/Stage3 共用）

每个 blob 表示成"PP 点集 + 受体点 A 集"，每个 CCD 表示成"原子集 + 身份摘要"。tokenizer 把落盘包变成**带 mask 的变长 token 集**，下游匹配器对点数不敏感。

### 3.1 S 轴：特征来源做成一个张量轴

同一个点可拼凑至多 5 套来源特征。把"来源"做成轴 `S`，每个点输入是 `[S, d]` + source-type 嵌入。

| 源 | 含义（Pocket_Plus Stage1 实测来源） | 在 P 上的情况 |
|---|---|---|
| ① | 初始编码特征 | P 为 0 |
| ② | Stage1 density-box 原始特征（`DensityCubeEncoder` 输出） | 与③几乎相同；与网格 gather 高度重叠 |
| ③ | embed head + density-box 调制特征 | 同上 |
| ④ | 分类头 cross-attn **之前**特征（`*_feat_before_interaction`） | **融合真正载荷** |
| ⑤ | 分类头 cross-attn **之后**特征（`*_feat_after_interaction`） | **融合真正载荷** |

**处理原则**：对 ~5 个**异构**来源用**轻量 fusion**（gated-sum 或 5-token 小自注意）把 `[S, d] → [d]`，**尽早在 tokenizer 内归约**，匹配器之后只见单向量 node 特征。**不上真 MSA/triangle**——那是为成百上千条可交换同源序列设计、$O(N^2 S)$、且会抹平 provenance（实测 Emap2lig 的 PairFormer 是单序列 trunk `S=1`，并无 MSA 行/列注意，故 S 轴是本文新建约定）。

**消融基线**：`S=1 且关掉受体点 A` ≡ Emap2lig 式表示。

### 3.2 PP 采样 + 对 P 的融合

```text
1) 从 selected Global Proposal 的稀疏 voxel 行采样：
   candidate rows = candidate_voxel_row[offset_i:offset_{i+1}]
   N_PP_i = min(K_i, N_PP_budget)
   按 parent_voxel_global_probability 取前 N_PP_i 行
   → 从 parent voxel 共享表 gather 坐标、Stage1 特征和可选密度 U-Net 调制特征
   第一版不在 Global Proposal Mask 外采背景，也不依赖 dense Stage1 feature grid
2) PP↔P 融合（同帧，几何可用）：
   PP（密，~4096）与 P（疏，~512–1024）KNN/radius 建图；PP 当 query 向邻近 P 做 cross-attn / 图消息
   → PP 吸收 P 的源④⑤（分类头交互特征，网格里没有；源②③与网格 gather 高度重叠，是冗余项）
   * 不做此步 = Emap2lig 式消融（Emap2lig 没有 P，天然是消融）
3) 该融合模块与 Stage3 逐字共用
```

> **融合的真正载荷是源④⑤**——"融不融 P"这个消融的本质就是"分类头交互特征值不值"。

### 3.3 受体点 A 的簇内图

受体点 A 取该 blob pocket（按到 blob 的 k-NN/半径截断；一个 80³ BOX 约 3000 原子，必须启发式截断）。其 level-1 簇内处理（§4）用**稀疏图**：边 = 真实共价键 ∪ radius 邻接，配一层带边特征的几何注意/消息传递。**新写一个干净小模块，不复用 Stage1 的 `atom_head`**（避免背上其 real/pseudo 双向、零初始化残差等包袱）。PocketXMol（图式几何网络、全原子受体带键、非 AF3、开源）仅作思路参照、不当依赖。

### 3.4 CCD 侧

ConformerEmbedder + PairFormer（复用 Emap2lig conf 路）→ CCD 原子节点特征 `[N_atom, d]`，化学键在 PairFormer 内部消化。无 map 位置（§1.4）。每身份附身份摘要 token，并挂数量 `N_j` 的可学习嵌入。可选 pooled 辅助头（预测分子量 / 原子数 / 回转半径）防特征塌缩。

## §4 三层注意力

匹配运算分三层（概念层；**具体算子、批量前向、塌缩开关见配套文档 `Stage2_Stage3_迭代运算设计_讨论.md` §4–§6**）：

- **level-1 簇内**：配体内部（化学图，复用 Emap2lig PairFormer）；密度点 + 受体点合成一张**异构稀疏图**（边集 = 密-密无 / 受-受键∪radius / 密-受radius），用 gated 消息传递更新（PP 内部默认无边、受体带真实键）。
- **level-2 blob ↔ CCD 匹配**：配体与 context 做跨集合 cross-attn，**双向读出两张覆盖矩阵**（§5.1 定义 A/B；读出机制见配套文档 §5）。
- **level-3 跨 blob 集合层**：blob/slot 的代表向量在整图上自注意 → explaining-away，并**实质参与监督**（反假阳等，见配套文档 §5/§8），带开关。

设计判据（要不要给某层加显式边）：**边只有携带 node+相对几何恢复不出、且对身份判别有用时才加**——据此 PP 内部图默认关（实测 Emap2lig 对采样点不做内部图），受体点带稀疏键图。注意 PP 内部图（默认关）与 PP↔P 融合（§3.2，默认开）是两回事。

## §5 匹配层与双覆盖矩阵

### 5.1 occurrence 级覆盖原语（监督的根，A/B 对称）

对 blob `b_i`（体素 mask）与 occurrence `o`（GT mask `g_o`）：

$$\alpha_{i,o}=\frac{|b_i\cap g_o|}{|g_o|}\quad(\text{recall：配体被捕获比例}),\qquad \beta_{i,o}=\frac{|b_i\cap g_o|}{|b_i|}\quad(\text{precision：blob 被解释比例}).$$

两者只是"固定分子、换分母"对调，角色严格对称。这是几何量，离线一次性算好、缓存在落盘包里（缝③）。

### 5.2 双向读出 = 两张覆盖矩阵（语义；运算见配套文档）

预测端用**两个分参数、分方向**的读出头，对称对应 §5.1 的 `α/β`：

- **A 方向（recall，`coverage_recall_logit`）**：配体当 query、在配体侧池化 → "配体被该 blob 捕获多少"。
- **B 方向（precision，`coverage_precision_logit`）**：密度点当 query、在密度侧池化 → "该 blob 被配体解释多少"。

自然副产物：错配 → A、B 都低；合并（blob 含两配体）→ A 高 B<1；分裂 → A<1 B 高，**无需额外打标**。

> **具体怎么算**（全×全 cross-attn + learned-query 读出、"半池化"的确切位置、逐原子/逐点辅助信号、批量网格实现、半池化输入备选）见配套文档 `Stage2_Stage3_迭代运算设计_讨论.md` §5。

### 5.3 对称覆盖矩阵 O（跨档统一的分类目标，替代旧 A'/B'）

A/B 不对称（固定分子、换分母），这是它们能天然区分 merge/split 的来源（§5.2），保留不动。但**二值分类**目标改用一张**对称矩阵 O**，原因是它能让纯受体档与全密度档**共用同一种损失形式**：

- **IoU 定义（有 blob / 密度档）**：$O_{i,o}=\mathbb{1}\big[\,\mathrm{IoU}(b_i,g_o)=\tfrac{|b_i\cap g_o|}{|b_i\cup g_o|}>\tau\,\big]$。
- **距离定义（纯受体 / 无 blob 档）**：$O_{i,o}=\mathbb{1}\big[\,\mathrm{dist}(\text{box 中心},\ \text{occurrence 质心})<\rho\,\big]$。

两种都对称、都二值，**损失形式一模一样，只换 O 的几何来源**。这就是"纯受体也能跑 Stage2"的钥匙：无密度时没有 blob，precision-B 没有原生定义，于是该档**只监督 O（+ 化学匹配/拒假阳），B 的损失 mask 掉**；A 用距离定义照样可监督。

**O 与 A/B 的分工（重要）**：

- O = 跨档统一的**分类**目标（替换旧的 A'/B' 两张二值矩阵，§8.1）。
- A/B = **连续回归**目标，**只在有 blob 的密度档激活**，把 merge/split 的几何重新捞回来（IoU 对称、看不出 merge/split，故不能只靠 O）。
- **凡损失里含 O，打分就把两方向的码都拼接**（细 + 粗，见 §8 与配套文档 §8）；**最终（密度档）监督是 A、B、O 同时上**。

> O 在纯受体档所需的几何原料（member 相交比例、box 中心到 occurrence 质心的距离、有 blob 时的 α/β）由数据侧备好；"用距离还是 IoU 定义、本批激活哪个标签"是配方/`loss_cfg` 选择，不烤进存储（见 `BOX-level数据契约.md` §3.2/§7）。

## §6 监督主线：occurrence 级覆盖 + 身份内匈牙利（Regime II / 方案 1）

### 6.1 为什么必须 occurrence 级（一个定理性的理由）

若把监督塌到身份级（每身份一列，"去重"），则 A、B 被迫用**不同算子**：

$$A_{i,j}=\max_{o\in O_j}\alpha_{i,o}\quad(\max),\qquad B_{i,j}=\frac{|b_i\cap\bigcup_{o\in O_j}g_o|}{|b_i|}\quad(\bigcup).$$

因为 recall 要"抓住某一个副本就算"（$\max$），precision 要"被所有副本合起来解释多少"（$\bigcup$）；同身份 merge 时 $\max_o\beta\approx0.5$ 但真值 $\approx1$，所以两者不可能同算子。

> **命题：A/B 的对称性 $\iff$ 监督在 occurrence 级。** 任何身份级去重都破坏对称，且"身份级 + 匹配"对 B 无自洽定义（匹配把 blob 配给单个 occurrence 会逼 B 取 $\beta_{i,\text{matched }o}$，与 $\bigcup$ 矛盾）。

因此主线走 occurrence 级，用**身份内匹配**处理同身份副本的可交换性。这保住对称、天然支持"给配体+count、k 个全对接"、并顺带解决同身份 merge。

### 6.2 形式化（身份内匈牙利）

身份 `j` 展开 `N_j` 个 **slot** `s=1..N_j`，每个 slot 是带索引嵌入 `e_s` 的 query，预测对全体 blob 的覆盖列 `Â[·,(j,s)], B̂[·,(j,s)] ∈ R^M`。

slot `s` 若被 occurrence `o∈O_j` 监督的代价：

$$\ell(s,o)=\sum_{i=1}^{M}\Big[L\big(\hat A_{i,(j,s)},\alpha_{i,o}\big)+L\big(\hat B_{i,(j,s)},\beta_{i,o}\big)\Big],$$

其中 `L` 是 §7 的逐 cell 损失。**匹配**（在双射 `π:{1..N_j}→O_j` 上）：

$$\pi_j^\star=\arg\min_{\pi}\sum_{s=1}^{N_j}\ell\big(s,\pi(s)\big)\quad(\texttt{linear\_sum\_assignment},\ N_j\ \text{极小}).$$

最终损失 `Σ_j Σ_s ℓ(s, π_j*(s))`。每个 slot 由它匹配到的 occurrence 的 `α, β`（及对称 O，见下）监督。

**O 同样被身份内匈牙利接受**：匹配只需要每 `(slot, occurrence)` 一个标量代价，把 `L(Ô_{i,(j,s)}, O_{i,o})` 加进 `ℓ(s,o)` 即可（O 是对称二值，照样 well-posed）。三种标签可按档共存于代价：纯受体档 `ℓ` 只含 O 项（距离定义，§5.3）；密度档 `ℓ` 含 A、B、O 三项。匈牙利对哪种标签都一样跑 `linear_sum_assignment`，`N_j` 极小。

**性质**：A/B 全程在 occurrence 级、对称地监督；`e_s` 只打破输入对称让 slot 能各自专精，**标号由 `min_π` 赋义、well-posed**（DETR 逻辑，不是硬钉死的 ill-posed 编号）；匹配**只在同身份 slot 内做**，跨身份从不匹配（与 §1.3 一致）；同身份 merge 天然解决（两 slot 都可在同一 blob 高覆盖 → 解码对该 blob 用两个 prompt 各对接一次）。

### 6.3 方案 1（第一版代码只实现这个）：早期 `e_s`、各 slot 独立 query

slot 分化的**力学**：`e_s` 必须在 cross-attn **之前**进入，才能"操舵"每个 slot 去 attend 不同的 blob（DETR query 即如此）。若 `e_s` 只在算损失前晚期线性注入到共享输出，则 `N_j` 个副本的预测列几乎是同一列、匈牙利无从区分、slot 退化——故那种"晚期分裂"字面形态**失能**，不取。

**方案 1**：每身份 `N_j` 个 slot 从一开始就是独立 query（身份原子特征 `⊕ e_s`），全程独立算。开销可控：同身份 slot **共享 blob 侧 K/V、共享身份原子特征，只差 `e_s`**，是"几组几乎相同的 query 复用同一份 K/V"，不是把 trunk 重算 `N_j` 遍；而 `Σ_j N_j` = 总 occurrence 数 ~ 几十。

关键效率点：同身份 `N_j` 个 slot **共享 blob 侧 K/V、共享身份原子特征，只差 `e_s`**，不重算 trunk；`Σ_j N_j`（总 slot）~ 几十。**带 shape 的批量前向（`[n_blobs, n_slots]` 网格、无循环）、读出与 Emap2lig 复用映射，见配套文档 `Stage2_Stage3_迭代运算设计_讨论.md` §5/§9。**

**后续可选优化（非 v1）**：混合版——重 trunk 对"身份当单一对象"只跑一次，再接轻量逐 slot cross-attn 头做晚期专精；与方案 1 是不同控制流，故先只写方案 1。

### 6.4 假阳与 no-match

slot 数 = `N_j`（= count），匹配是 slot↔occurrence 双射，**假阳 blob 不在 slot 轴处理、而在 blob 轴**：一个在所有列都低覆盖的 blob 就是 FP，无需 DETR 那种 `∅` dummy slot。caveat：推理期 count 由用户给，若给错（说 3 实际 2），第 3 个 slot 会被迫配一个弱 blob——这是 count 准确性前提，不是设计缺陷。

### 6.5 简化基线（仅消融，非主线）

身份级去重 + `max`(A)/`∪`(B) 是一个**无匹配损失的最简 baseline**，可作消融对照，但因 §6.1 的对称性破缺，不作主线。

### 6.6 两阶段训练课程（监督逻辑；机制见配套文档 §5/§11）

监督按课程分两阶段，把"全局匹配/拒假阳"和"精确覆盖几何"解耦先后训：

- **阶段一 = 只训粗分支（O 监督）**。粗分支便宜、先把全局匹配、explaining-away、O 预测训收敛。此阶段实际训练的是 **trunk + 粗分支**（trunk 给配体可学表示）。注意, 只用受体时就是只训阶段一, 若含有密度信息(如预计算的blob)就训阶段一+阶段二。
- **阶段二 = 粗细一起训（A/B/O 同时上）**。冻结阶段一的 trunk 与前段粗分支，新增的细分支补上 α/β 的精确覆盖（merge/split 几何）。

为什么冻结：细阶段贵，冻住阶段一表示可防止它被搅乱、并省梯度。一个已知风险——阶段一 trunk 只受过"池化后好用"的压力（梯度只从粗分支 readout 来），其 per-entity 细粒度特征对细分支可能偏弱；故阶段二允许后段**从头重建一份 trunk**、把阶段一 trunk 当（默认关闭的）零初始化 condition 注入。

> **这里只讲"什么时候监督什么、概念上冻什么"。** 具体的 Block 布局（前 m / 后 n）、trunk/粗/细 参数归属、pattern 冻结 + 零初始化门的实现，见配套文档 `Stage2_Stage3_迭代运算设计_讨论.md` 的 trunk 归属表、§5、§11。当前暂定 m=2、n=4（可调）。

## §7 count 与集合层（level-3）

- **count 表示**：每身份一对象 + 数量 `N_j` 的可学习嵌入；`N_j` 同时决定 §6 的 slot 数。硬 count 约束在解码期生效（§8）。
- **集合层（level-3）**：blob/CCD 摘要 token 上一层自注意（吃 `N_j` 嵌入），把每个 (blob, slot) 的打分从"只看本对"变成"看其它所有 blob 与 count 预算"，做软 **explaining-away**（某身份 count 被占满后压低剩余模糊 blob 的该身份分）。
  - 形式上：level-2 给出逐对原始 logit；level-3 自注意后给每 token 一个更新表示，再由小头输出对 `Â/B̂` 的偏置修正。
  - **几十 token、便宜；定位为校准 refinement 而非命门**（硬 count 已由解码兜）。**带开关可关**（关 = 退回逐对 + 解码硬约束）。

## §8 损失与解码

### 8.1 损失项（逐 cell，故训练可任意分块）

§6.2 的 `L` 展开为：

- **覆盖回归（A/B，密度档才开）**：对 `Â/B̂` 与 occurrence 级 `α/β` 做回归（smooth-L1 / MSE）。**只在有 blob 的密度档激活**。
- **对称分类（O，跨档统一）**：用对称矩阵 O（§5.3，密度档 IoU 定义 / 纯受体档距离定义）替代旧的 `A'/B'` 两张二值矩阵，对 `Ô` logit 施 **focal / CE**（处理 0 占绝大多数的不平衡；阈值附近标签有噪，focal 缓解）。**凡含 O 的损失，打分头拼接两方向（细 + 粗）的码**（§8 / 配套文档 §8）。
- 可选：§5.2 readout 前的逐原子/逐点辅助监督。

> **课程对应（§6.6）**：阶段一只开 O；阶段二 A、B、O 同时开。逐层/逐支的开关与权重挂在配套文档的 `loss_cfg`。

### 8.2 解码器（仅推理）

```text
输入：Â/B̂（已按身份内匹配训练）+ 每身份 count 预算
1) 由 Â/B̂ 合成每 (blob, slot) 的匹配分（A、B 组合 / 小头）
2) count 受限指派：每身份选 N_j 个 blob（greedy 软先验 或 匈牙利/OT 硬容量）
3) merge：一 blob 命中多身份/多 slot → 对该 blob 按不同 CCD 各调一次 Stage3
   split：一 slot 散多 blob → 解码期先并 blob 再交 Build
4) 为每对给 prompt 点（blob ligand-area mask 质心）→ 交 Stage3
5) （可选）Build 生成 pose 后用密度相关性 / fit 反向重排（EMERALD-ID 式）
```

> Stage3 只收 `(blob, CCD, prompt 点)`，**不收 merge 标志、不收覆盖矩阵**——矩阵只被解码编排器消费，Stage3 训练独立性不破（§9）。**训练不掺 fit 反向打分**（避免训练一个"会故意失败"的网络；理由见 §9）。
>
> **merge/split 依赖 A/B 不对称**：解码第 3 步判 merge/split 用的是 A 高 B 低 / A 低 B 高 的签名（§5.2），**对称 O 看不出**。故全图划窗那条密度推理链路必须有 A/B（密度档天然有 blob）；纯受体档无 blob、不做 merge/split 解码，只用 O 出匹配。

## §9 训练独立性与 Stage2↔Stage3 共享

- **三阶段训练独立**：Stage2 的正式路线读取 Stage1 selection run；Stage3（Build）可用 GT ligand atom envelope、真实 ligand 与 GT pose 独立试水训练，并假设配对正确。正式推理时再串联 selected Global Proposal；Stage1 不接 Stage2/3 梯度。
- **共享**：BOX 中的候选特征包、tokenizer（多来源特征融合、PP 稀疏采样 + P 融合、受体点 A 图）以及可选轻量密度 U-Net 调制接口（§10）。**PP/P 融合代码与 Stage3 逐字共用**。
- **拒绝 "InstanceSeg 当打分器"**：让条件分割模块兼做判别器，错配 CCD 的目标 mask 只能填"空"，但那块密度真实存在，是**几何上假的 0**，与本职冲突、训练不稳。对比覆盖矩阵的负目标 `α_{i,错}=0` 是**几何真零**、自然。"fit 即分数"的红利改到推理期反向重排兑现，训练不掺。
- **Emap2lig 锚点**：其 `InstanceSeg` 是"已知配体条件下的分割 + 采点"（无任何匹配）——即 AdaLigand 的 Stage3；其 `SelectedCrossAttention` 对 atom 坐标加位置编码，**Stage2 不可照抄**（CCD 无位置）。

## §10 可选轻量密度 U-Net 调制器

Stage1 proposal selector、Stage2 与 Stage3 共用一个可关闭的 **密度上下文调制器（Density Context Modulator）**接口。输入是第 1 层裁出的原始 exp 密度；轻量 U-Net 输出多尺度 voxel 特征。voxel 对象按网格位置 gather，P/受体原子等点对象按 BOX 内连续坐标做三线性插值，再用门控残差调制对象表示。该模块不更新坐标，也不改变 Global Proposal 身份。

- **基础路线不依赖它**：关闭后 Stage1 selector、Stage2、Stage3 必须完整可运行。
- **共享方式**：默认独立预训练并冻结，三阶段读取相同 checkpoint、输入归一化和特征出口定义。某阶段若单独微调，必须记录新的 checkpoint 身份，不能再视为共享权重。
- **现有化学 U-Net 是一种实现**：逐体素元素/部件分割（C/N/O/P/S/Metal/Ring 等）仍可作为预训练任务，也可加密度去噪。若其算力和输出合适，直接实现公共接口，不默认再造第二个 dense backbone。
- **计算与缓存解耦**：可在模型内现算，也可冻结后按 `BOX-level数据契约.md §4.5` 缓存为命名 feature source。两者不得改变 Stage2/3 的主输入契约。
- **首轮消融**：modulator off/on；只有确认下游收益后才决定正式缓存尺度和通道数。

具体算子、张量形状与 Stage1 selector 的使用方式见 `文档/规划文档/Stage1训练与多阈值推理.md §10.7`。

## §11 成本、显存与训练策略

规模事实：一张图真实配体 **1–25** 个，加 recall-first 假阳/merge/split，blob 几十~上百；CCD 身份几十；`Σ_j N_j`（总 slot）几十。matcher 是最便宜的一级（贵的是 Stage1 全图推理与 Build 扩散）。训练卡 A800(80G)/H200(141G)。

### 11.1 显存账（flash-attn O(N)；d=256、L=4、bf16；PP 可达 8192）

| 方向 | 承重项 | 说明 |
|---|---|---|
| A 方向 | K/V **按 blob 共享**（跨 slot/身份） | `blobs×N_pp×d` + 逐对小输出，几个 GB |
| B 方向 | 逐对 blob 侧输出 `pairs×N_pp×d` | **承重项**，PP 翻倍显存翻倍 |

- one-shot 整图前向+回传在 A800/H200 **可行**（前提 A 方向 K/V 按 blob 共享）；**PP 数目是显存旋钮**（512 / 4096 / 8192，仿 Emap2lig 可试 8192）。

### 11.2 训练策略：chunk 常态化 + 压缩摘要保全图视野

不把 pair-chunking 仅当极端样本兜底，而是**常态训练策略**：

- **level-3 集合层吃"每 blob/CCD 一个压缩摘要向量"的整图集合**（便宜，保住**全图视野**与 explaining-away）。
- **level-2 全×全只吃小 chunk、只对该 chunk 回传**（逐 cell sigmoid 独立，切块不改 loss）。

于是同时拿到全图视野 + 全×全逐原子丰富度 + 受控显存，PP 上到 8192 也扛得住。半池化输入留作"连 chunk 都嫌重"的备选。

### 11.3 数据调度

三阶段数据需求不对称：Stage3 的 GT 配对试水可以用 GT ligand atom envelope 独立训练，Stage2 也可以先做无预测候选试水。正式 predicted-blob 路线必须等待 Stage1 全图 proposal、Group-parent 物化和 selection run。全图推理可以与 GT-envelope 试水训练并行，但二者是显式配置的不同输入来源，不伪造 `center/bias/context` blob。

### 11.4 难负身份

训练时给候选表掺入额外难负身份（尺寸/化学相近、实际不在场）。因推理隐藏 CCD 位置，模型只能靠化学拒绝它们；同结构真实身份太少、太易。

### 11.5 same-sample 成批

一个 batch 的 blob 与 CCD 同源，贴近推理；跨样本配对是永不出现的假负，排除。

## §12 待定旋钮与消融清单

1. **PP 数目**：512 / 4096 / 8192（显存 vs 质量）。
2. **PP↔P 融合**：开/关（关 = Emap2lig 式）；消融核心 = 源④⑤值不值。
3. **受体点 A 边**：开/关（稀疏键 + radius）。
4. **监督主线**：Regime II（occurrence 级 + 身份内匈牙利，主线）vs 去重 baseline（消融）。
5. **集合层（level-3）**：开/关。
6. **A/B 方向**：共享权重 vs 分开；readout = learned-query vs 均值。
7. **level-2**：全×全（默认）vs 半池化输入。
8. **slot 展开**：方案 1（trunk 前，v1）vs 混合版（trunk 后，后续）。
9. **CCD pooled 辅助头**（分子量/原子数）：开/关。
10. **解码器**：greedy 软先验 vs 匈牙利/OT 硬容量；Build fit 反向重排开/关。
11. **阈值与 focal 参数**；难负身份配额。
12. **Global Proposal 自然假阳 + 难负 CCD 身份**：候选数量与难度配额由 validation 统计确定；Stage2 的假阳候选只来自正式 Global Proposal，不由 Stage1 训练 BOX 来源人工制造。
13. **监督标签集**：O 当统一分类 + A/B 密度档回归（主线，§5.3）vs 彻底只留对称 O（图省事、放弃自动 merge/split）vs 沿用旧 A'/B' 二值（消融）。
14. **两阶段课程**（§6.6）：阶段一 O / 阶段二 A/B/O vs 联合一阶段训；冻结 vs 不冻结 trunk。
15. **后段 trunk 的 m 层 condition 注入**（§6.6 / 配套文档 §5）：默认关（纯从头重嵌）vs 开（零初始化注入阶段一 trunk）。
16. **m/n 划分**：暂定 m=2、n=4，可调。
