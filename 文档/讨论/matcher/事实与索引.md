### 1.2 本文中的核心术语

- **配体实例（occurrence）**：一个 PDB 中一个真实出现的配体，主键是 `(pdb_id, candidate_id)`。
- **配体身份**：由 `object_key` 表示的去重化学结构，例如 `CCD:NAG`。同一身份可在同一个 PDB 中出现多次。
- **副本槽位（slot）**：Matcher 为某个已知配体身份的一个实例预留的位置。同身份的多个槽位在监督时只允许在该身份内部进行匈牙利匹配。
- **合成锚候选（synthetic anchor）**：当前训练路线从完整 BOX 池抽出的候选框；模型不读取候选来源类别。
- **bias 候选**：围绕真实 occurrence 预先生成的偏移 BOX，用于模拟正确检出与错误 split。
- **context 候选**：按 PDB 预先生成的背景 BOX，用于模拟假阳候选。
- **A**：以候选中心为中心、半径 18 Å 的受体原子实体及其图。
- **Map**：以候选中心截取的原生 48³ 实验密度；`Map_repr` 是密度骨干产生的摘要表示。
- **O / O′**：当前主任务的二值邻近目标与连续距离质量目标；具体公式见 §12 和 Question 103 之前的对应决定。
- **候选团块、producer、原始候选节点、重新定形候选**：均属于未来读取 Stage1 推理产物的增强路线术语，不是当前 `AnchorPocketDataset` 的输入。

### 4.1 A–G 数据流水线

正式数据根：

Stage G 候选记录总数为 **662,078**。Stage G 默认只分析，不自动生成一个训练用 canonical keep list；后来 Stage1 数据准备流程另行执行严格过滤、审计和物化，得到当前 `final_keep_list.jsonl`。这两种“候选清单”不能混称。

A–G 中 Matcher 直接需要的资源如下：

| 资源 | 主要字段或语义 | Matcher 用途 |
|---|---|---|
| `parse/{pdb_id}/occurrences.jsonl` | `candidate_id`、`object_key`、`type_tag` 等 | 槽位身份、同身份数量、实例主键 |
| `ligand_objects/{safe_object_key}.npz` | 结构化原子、化学键、参考构象 `ref_pos` | 配体 GatedGCN 的节点、边和参考几何 |
| `parse/{pdb_id}/ligand_coords.npz` | `coords_{cid}`、`present_{cid}`、真实质心 | 逐实例真实位置、距离和逐原子覆盖标签 |
| `parse/{pdb_id}/receptor_tokens.npz` | 坐标、49 维特征、`bond_index`、`bond_type` | 候选周围受体原子 A 与 A 图 |
| `labels/{pdb_id}/atom_labels.npz` | `binding_atom`、`instance_id`、`nearest_dist` | A 分支辅助监督 |
| `density/{pdb_id}/exp.npz` | 单通道实验密度、体素尺寸和世界坐标原点 | 候选中心 48³ Map |

`ligand_descriptors`、`sim`、`ligand_area` 和 `ligand_dist` 都是现有数据资源，但不是当前 O/O′ Matcher 的正式模型输入。它们可用于审计或未来任务，不能因为已存在就被 Dataset 自动读入。

必须保留的读取事实：

- `ligand_objects/*.npz` 含对象数组，需要 `allow_pickle=True`；
- 其它正式 NPZ 默认使用 `allow_pickle=False`；
- 配体模板的 `ref_pos` 只表示内部参考构象，不是该 PDB 中的真实位置；
- 真实位置必须取 `ligand_coords.npz` 的 `coords_{cid}`，并用 `present_{cid}` 排除模板中未观测原子；
- `ligand_area.npz` 的索引顺序是 ZYX，坐标使用体素中心：

```text
world_xyz = origin_xyz + (index_xyz + 0.5) * voxel_size_xyz
```

- 当前 Stage E3 的配体占据区域使用元素特异的范德华半径和精确体素中心谓词，不是旧讨论稿中的统一 1.7 Å 半径。

## 6. Stage1 到 Matcher 的真实落盘接口

> **未来增强路线。** 本节记录 Stage1 推理产物接口，不是当前 `AnchorPocketDataset` 的读取契约。当前首版从唯一 `receptor_tokens.npz` 读取 A，并从完整 BOX 池生成 synthetic anchor。

### 6.1 固定寻址

当前契约已经从旧的任意 `selection_run_id` 主寻址方式改为：

```text
stage1_outputs/
  {stage1_model_name}/
    calibration/
      thresholds.json
      metrics.json
    {split}/
      {pdb_id}/
        status/
          {output_role}/_COMPLETE
        probability/
          probability_map.npz
          geometry.json
        components/
          forest.npz
          clg.npz
          overlap.npz
          summary.json
        centered/
          F1_centered.npz
          CLG_centered.npz
          Selected_Refined_Centered.npz
```

selector 的训练、打分和选择结果另存：

```text
selector_outputs/{producer}/{variant}/{run_dir}/...
```

旧讨论稿中的 `selection_run_id` 可以作为 selector 运行身份存在，但不能再用它替代核心 Stage1 产物的 producer/split/PDB/role 定位。

### 6.2 五类 role

| role | 当前语义 | Matcher 可能用途 |
|---|---|---|
| `probability` | 完整图概率和网格几何 | 重新物化候选、核对来源 |
| `components` | 多阈值 forest、CLG、overlap 与摘要 | 原始候选集合和监督 |
| `F1_centered` | F1 阈值节点居中的观察结果 | 单阈值基线或早期适配 |
| `CLG_centered` | 成功 CLG 的 oldest node 居中 BOX；内含候选成员索引 | selector/Matcher 原始节点装配 |
| `Selected_Refined_Centered` | 选中节点重新定形后的最终居中结果 | 更接近 Stage3 的最终候选 |

### 6.3 V、P、A

centered 归档的共同输入层次：

- **V**：候选 BOX 内的权威成员体素；含 BOX 内局部 ZYX 坐标、当前 centered 重算概率和稀疏 `voxel_final`，不含固定多尺度 Stage1 V 网格；
- **P**：Find 模型的稀疏伪原子/点云特征及坐标；
- **A**：受体原子索引、坐标和 Stage1 原子特征。

`A_feat_L0` 已作为 float32 49 维表直接保存在每个 Find centered 归档中，并与 A 行逐项对齐。Matcher 直接读取该字段；`A_global_index` 继续回指 A–G 的 `receptor_tokens.npz`，用于原子身份与来源追踪，不要求为了模型输入再次加载原始特征。

对于 `CLG_centered`：

- V 和 A 有 candidate membership；
- P 没有 candidate membership；
- candidate membership 用于从共享 BOX 表中切出某个原始 forest 节点；
- selector 选中的同一个 forest 节点可能来自多个 CLG，正式恢复时按来源顺序做有序去重，只生产一次。

### 6.4 重新定形状态

`Selected_Refined_Centered` 对每个选中的来源节点恰有一个终态：

- `success`
- `empty`
- `no_overlap`

模型前向、字段读取或精修实现异常不是第四种终态；此类异常会阻止当前角色发布 `_COMPLETE`，修复后按续跑规则重新生产。

只有 `success` 有非空重新定形候选特征；其它状态保留来源与失败语义，但变长数组为空。Matcher Dataset 必须明确：

1. 非 success 是丢弃候选、保留为空样本、还是作为 selector/Stage1 失败统计；
2. 一个 PDB 所有 selected 均失败时是否仍进入损失分母；
3. 训练、验证、推理是否使用完全相同的策略。

这些策略当前没有冻结。

## 7. Matcher 标签：已有材料与缺口

> **历史调查。** 本节早期以 α/β/O 和 Stage1 候选为中心；当前 O/O′、Entity 与 FinePair 标签契约已经由 Questions 1–103 取代。仍有效的原始字段事实可以引用，但不得执行本节的旧目标定义。

### 7.1 当前目标定义

对候选团块 \(b_i\) 和真实配体实例 \(g_s\)：

\[
\alpha_{i,s} = \frac{|b_i \cap g_s|}{|g_s|}
\]

\[
\beta_{i,s} = \frac{|b_i \cap g_s|}{|b_i|}
\]

\[
\mathrm{IoU}_{i,s} =
\frac{|b_i \cap g_s|}
{|b_i| + |g_s| - |b_i \cap g_s|}
\]

当前设计意图是预测：

- `coverage_recall_logit` → α；
- `coverage_precision_logit` → β；
- `coverage_O_logit` → 对称二元覆盖/归属关系 O。

α 和 β 的数学定义已经清楚。O 的精确二值化策略尚未冻结：讨论稿同时提到 IoU 阈值与受体侧距离规则，但没有给出唯一的阈值、优先级和边界处理。

### 7.2 原始 forest 节点可直接复用的 overlap

`Pocket_Plus/src/component_lineage/overlap.py` 当前写出：

```text
candidate_occurrence_offsets
overlap_occurrence_index
intersection_voxel_count
occurrence_id
occurrence_voxel_count
```

其中：

- `occurrence_id` 是当前 PDB 排序后的 `candidate_id`；
- `intersection_voxel_count` 给出原始候选节点与真实实例的交集体素数；
- `occurrence_voxel_count` 给出真实实例体素数；
- 候选自身大小可由 forest/candidate membership 得到。

因此，如果 Matcher 消费的是 selector 选中的**原始 forest 节点**，α、β、IoU 不需要重新扫描完整 3D 网格。

### 7.3 重新定形候选必须重算 overlap

现有 `overlap.npz` 描述原始 forest 节点，不描述 `Selected_Refined_Centered` 中重新连通后的局部组件。若 Matcher 消费重新定形候选，应当：

1. 用该条目的 `box_start_zyx` 和 `voxel_index_local_zyx` 恢复完整图 ZYX 索引；
2. 与 `density/{pdb_id}/ligand_area.npz` 的 `mask_{candidate_id}` 做精确交集；
3. 重新生成交集数、候选大小、α、β、IoU；
4. 把 Stage1 产物身份、原始节点身份、重新定形状态和标签生成实现摘要写入 Matcher manifest。

不能把原始节点的 overlap 标签直接嫁接到 refined blob。

### 7.4 距离标签不能直接由 `ligand_dist.npz` 代替

`ligand_dist.npz` 保存的是“到该 PDB 所有实际配体原子的最近距离”，不是每个实例各自的距离。若 O 需要逐 `(blob, occurrence)` 的距离判据，必须从：

- `ligand_coords.npz` 的 `coords_{candidate_id}`；
- `present_{candidate_id}`；
- 候选体素中心或候选周围受体原子；

逐实例计算。当前 BOX 契约没有讨论稿引用的 `occ_distances` 字段。

### 7.5 逐配体原子覆盖标签尚未物化

迭代设计稿把逐配体原子覆盖指向 `BOX §4.3′ atom_coverage`，但当前 BOX 文档没有这一节或这一字段。若保留该辅助监督，需要明确：

- 使用真实坐标还是模板参考坐标；正确答案应是实际 PDB 的 `coords_{cid}`；
- 如何处理 `present=False` 的模板原子；
- 原子进入候选体素区域的精确几何谓词；
- 标签在线计算还是离线缓存；
- refined blob 与原始 blob 是否使用同一算法。

### 7.6 当前文档中的失效引用

`Stage2_Stage3_迭代运算设计_讨论.md §12` 当前引用：

- `BOX §4.3 coverage`
- `BOX §3.2 occ_distances`
- `BOX §4.3′ atom_coverage`

当前 `BOX-level数据契约.md` 中不存在这些 Matcher 标签字段。后续必须新增独立 Matcher 数据契约，或在 BOX 契约中建立真实存在的字段与章节，不能让实现依赖悬空引用。

## 8. Matcher 候选语义：必须先做的核心决定

> **已解决的历史问题。** 当前首版只使用完整 BOX 池上的 bias/context synthetic anchor；本节三路线比较不再是待决定事项。

### 8.1 三条可行输入路线

| 路线 | 候选来源 | 优点 | 代价/风险 |
|---|---|---|---|
| A. 原始 selected 节点 | selector `selection.npz` + `CLG_centered` candidate membership + forest/overlap | 与早期总体规划一致；overlap 可直接复用；来源节点身份完整 | Stage3 最终看到的形状可能不是该原始节点；不利用已实现的重新定形 |
| B. `Selected_Refined_Centered` | 核心 Stage1 role | 最接近 selector 之后实际交给后续阶段的候选；形状更干净 | overlap 必须重算；要处理四种终态；与早期“Stage2 不用 selected-final”文字冲突 |
| C. `F1_centered` | 单阈值 F1 节点 | 依赖少，适合适配器和基线 | 不是最终 selector 分布；不能代表正式 Matcher 输入 |

### 8.2 当前文档倾向与当前代码能力不同

`模型总规划_v2.md` 明确写过：

- Matcher 消费 selector 选中的原始 Global Proposal；
- selected-final 精修是独立 Stage1 后处理；
- Stage2 不做候选 mask 精修。

但更新较晚的 BOX 契约和当前代码已经把 `Selected_Refined_Centered` 做成正式核心 role。它是否只供 Stage3、还是先供 Matcher 再交给 Stage3，目前没有最终决定。

### 8.3 建议的决策标准

该选择不应只按“哪个文件更方便”决定，应当回答：

1. 推理时 Matcher 真正会看到哪个候选形状；
2. Stage3 应接收 Matcher 评分时的同一形状，还是再做一次形状替换；
3. refined 前后候选的 α、β、IoU 分布变化多大；
4. `empty/no_overlap/failed` 的比例是否足以改变训练宇宙；
5. selector 的误选和精修失败应由 Stage1 指标承担，还是进入 Matcher 鲁棒性训练；
6. 原始节点与 refined blob 是否都保留，形成“原始候选辅助头 + refined 主头”。

在这个决定冻结前，可以实现统一 `BlobRecord` 接口，但不应冻结最终 Dataset schema。

## 9. 现有设计意图与事实边界

> **历史设计来源。** 本节保留旧计划的来路，其中 PairFormer、P/V/PP、A/B 与旧规模假设均不属于当前首版；当前定义以 §12 和 Questions 1–103 为准。

### 9.1 当前三份讨论稿共同表达的目标

下列内容是当前设计意图，不是已运行事实：

- 每个 PDB 是一个 same-sample Matcher 样本；
- 配体身份和每个身份的实例数已知；
- 不做跨身份的 DETR 式类别发现；
- 同身份的多个副本槽位通过早期 slot embedding 区分；
- 只在同身份内部做匈牙利匹配；
- 输出 `[n_blobs, n_slots]` 的 α、β、O；
- 粗分支处理全局候选集合关系；
- 细分支保留候选与配体逐实体交互；
- Stage2 只匹配，不生成 pose；
- 解码后把 `(blob, CCD, prompt)` 交给 Stage3；
- 训练分为先粗/O、再粗细联合 A/B/O 两阶段；
- Stage3 是独立 builder，但与 Stage2 共享底层注意力、受体图和配体表示算子。

### 9.2 当前迭代设计中的主要模块

- `TypedAttention`：统一 typed query/key-value、分类 softmax、偏置 MLP 和 aligned/outer 两种批量模式；
- `SparseGraphInteraction`：受体原子 A 的化学键并 radius 稀疏图；
- `LigandPairFormer`：配体内部原子和原子对更新；
- `FusePtoPP`：把 Stage1 稀疏 P 信息融合到候选密度点 PP；
- coarse trunk：候选和槽位的压缩表示、集合推理；
- fine readout：在 `[n_blobs,n_slots]` 上做只读全实体交互；
- 两相反向：共享整图计算一次，超规模时只对逐对阶段分块。

### 9.3 尚未由真实分布证明的规模假设

迭代稿的目标预算是：

```text
n_blobs ≤ 200
n_slots ≤ 100
PP = 4096，备选 8192
A ≈ 256–512
```

当前不能把这些数当作数据事实：

- 正式 Stage1 候选尚未生产，无法统计 `n_blobs`；
- 正式全集的每 PDB 实例数、身份数和同身份最大重复数尚未汇总；
- Stage1 的每 epoch 50 实例采样上限不是 PDB 的真实实例上限；
- PP 和 A 的裁剪后分布尚未在正式 selected 候选上统计；
- 历史 `10ad` smoke 只有一个 PDB。

正式模型尺寸和“不分块默认可行”的结论必须在真实候选 manifest 上重新做分位数统计和显存 preflight。

### 9.4 图结构存在一处设计漂移

- `模型总规划_v2.md` 曾写成 PP 与 A 合成异构图，包含 A–A、PP–A 等边；
- 较新的迭代设计把 `SparseGraphInteraction` 收敛为 A-only，边为受体化学键并运行时 radius；PP 通过注意力读取或融合，不进入同一稀疏图。

第一版实现前应选择一个唯一语义。按较新的迭代稿，A-only 是当前更明确的默认方向。

### 9.5 分块策略也有版本漂移

- `模型总规划_v2.md` 把 pair chunking 写成常态；
- 较新的迭代稿把“不分块 + flash + KV 共享 + precision 融合 readout”设为默认，把分块作为必须正确但只在超规模样本启用的兜底。

无论默认策略如何，分块实现都必须通过“同一玩具网络分块与不分块的参数梯度逐元素等价”测试。
