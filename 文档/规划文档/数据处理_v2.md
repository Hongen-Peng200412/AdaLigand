# AdaLigand 数据处理实现计划 v2（纯数据 · 代码级）

> **定位**：本文是「数据从哪下、怎么处理、每步产物什么形式、落在哪」的**可直接写代码的实现规范**。工程师 / AI agent 据此应能无歧义实现整条数据侧。
> **边界**：本文产物到「整图级 / occurrence 级」为止，**不切 BOX**；模型阶段另行规划。旧版数据处理调研文档仅作历史背景，不作为当前实现规格。本文也 owns **身份级 / 受体级的预计算标签**（配体描述子 §5.3、受体 token（含键表 + 49 维特征）§5.4、centroid_atom §5.5）——即"辅助监督标签定义随生产方"里预计算的那一半；模型侧 `迭代运算 §12（监督全清单）` 只留指针，不重写定义。
> **权威层级**：实际代码 > 配置/checkpoint > 真实产物与日志 > 本文。

## §0 总流水线与产物总览

主键贯穿全程：**`(pdb_id, candidate_id)` + 共享世界坐标系（map 世界坐标，Å）**。`pdb_id` 一律小写存储。`candidate_id` 只在冻结的 source snapshot 内稳定；source revision 可能改变 atom serial 或候选排序并重排该 PDB 的 `candidate_id`，它不是跨 source 版本的永久 accession。发生重排时必须在释放下游前按同一 snapshot 完整重建该 PDB 的所有 candidate-indexed Stage C 产物。

| Stage | 脚本 | 输入 | 产物（形式） | 落盘位置（`${ROOT}=…/AdaLigand`） |
|---|---|---|---|---|
| A 枚举 | `a_enumerate.py` | RCSB Search API | `pair_list.jsonl` | `${ROOT}/raw/pair_list.jsonl` |
| B 下载 | `b_download.py` | pair_list | mmCIF / map.gz / meta.json / CCD | `${ROOT}/raw/{rcsb_mmcif,emdb_maps,ccd_cache}/` |
| C 解析 | `c_parse.py` | mmCIF(+CCD) | `occurrences.jsonl` / `receptor_tokens.npz`(受体键表 + 49 维特征 §5.4) / `ligand_coords.npz`(+`centroid_atom` §5.5) / `ligand_objects/*.npz` / `ligand_descriptors/*.npz`(§5.3) | `${ROOT}/parse/{pdb_id}/…`、`${ROOT}/ligand_objects/`、`${ROOT}/ligand_descriptors/` |
| D 原子标签 | `d_atom_labels.py` | C 产物 | `atom_labels.npz` | `${ROOT}/labels/{pdb_id}/atom_labels.npz` |
| E 密度+体素标签 | `e_density.py` | map + 去配体受体 + C | `exp/sim/ligand_area.npz` | `${ROOT}/density/{pdb_id}/…` |
| F 质量 | `f_quality.py` | map + 模型 + meta | `quality.jsonl` | `${ROOT}/quality/{pdb_id}.jsonl` |
| G 过滤 | `g_filter.py` | F | `keep_list.jsonl` | `${ROOT}/keep_list.jsonl` |

各 Stage 独立分片并行；阶段间唯一耦合 = 世界坐标系 + `(pdb_id, candidate_id)`。

## §2 全局约定（所有脚本共用）

### 2.1 坐标系 / 网格
- Pocket Plus `processedPDB_EMDB_binder/utils/mrc_tools.py` 是当前可信祖传基线（vendoring 时 HEAD `f4c3e5ce...`，该文件最后修改 commit `a8380721...`）。`load_map/make_cubic/normalize_voxel_size/rescale_real/rescale_fourier/make_model_grid` 六个函数必须逐函数原样隔离到 `code/mrc_pocket_legacy.py`，用源文件、vendored 文件、逐函数源码和 AST SHA-256 锁定；函数体不得在 AdaLigand 内重写。
  - `load_map(path, multiply_global_origin=True) -> (grid(Z,Y,X), voxel_size(3,), origin(3,))`：轴和 origin 完全沿用祖传语义。native EMDB 默认返回 `(header.origin + 按 mapc/mapr/maps 重排的 nstart) × voxel_size`；AdaLigand/Chimera 自己写出的 `nstart=0`、header.origin 已是 Å 的图必须显式传 `False`。
  - `make_model_grid(grid, voxel_size, origin, target=1.0)`：祖传 Fourier rescale + 偶数网格 padding + origin 平移；输出 `voxel_size = 输入物理长度 / 偶数输出 shape`，是接近 target 的**实际 XYZ voxel**，不得硬编码回 1.0。
  - `code/mrc.py` 只允许做 `Path/MapGrid/float32`、输入验收、generated-map origin mode 和标准 MRC writer 等薄适配。祖传 `rescale_real` 在“部分轴 shape 相等、部分轴变化”时会整体跳过；全量 22,274-EMDB header 审计只发现 2 张此类图，因此只允许在薄适配层对该分支使用与祖传函数相同的代码并把条件从 `np.all` 改为 `np.any`，模式必须落盘为 `pocket_plus_mixed_axis_np_any_compat`。祖传 vendored 函数仍零修改。
  - 祖传 Fourier 分支不补偿输入/输出点数，canonical 密度相对 native 的全局幅值比例固定为 `prod(even_input_shape_zyx) / prod(actual_output_shape_zyx)`。不得改变 Pocket grid；EMDB recommended contour 必须单独映射到 canonical 幅值空间，同时保存 native 值、比例和 canonical 值。全部差异必须在 `Data_Preprocessing/Ori_Data/README.md` 与 ExecPlan 逐条登记并由 parity/mask 测试覆盖。
  - Stage E 放行必须运行 `scripts/smoke_mrc_geometry.py` 或等价的受检入口，直接用真实 native map、正式 Stage C 受体和真实 Chimera `molmap onGrid` 验证非精确 1 Å actual voxel、非零 origin、标准轴、`nstart=0`、真三维内容及 canonical/sim 几何闭合；smoke 只写独立 run-scoped 证据，不写正式 `density/`。
  - Stage E3 的体素中心数值必须直接调用原样 vendoring 的 Pocket Plus `_build_voxel_center_coords_xyz`；`origin` 按网格/BOX 下角点解释，索引 `(x,y,z)` 的中心为 `origin_xyz+(index_xyz+0.5)*voxel_size_xyz`。不得另写“等价”中心公式或以旧 mask 的 roll/平移代替从原子坐标重建。
  - 共享世界坐标是成功样本的必验契约，不是对所有权威 source 的无条件假设。E/F frame preflight 使用 Pocket 物理 BOX 边界：`grid_lower=origin_xyz`、`grid_upper=origin_xyz+shape_xyz*voxel_size_xyz`；与合法、有限、非空的 Stage C 受体 XYZ 包围盒任一轴完全分离且超过 `1e-5 Å` 容差时记 `model_map_frame_mismatch`。这里判断的是物理 BOX 是否相交，不是用 E3 体素中心首尾替代 BOX 边界。空坐标、NaN/Inf、错 shape/dtype/voxel/origin 仍是 unknown，不得由该失败码兜底。
  - `world_to_voxel(coord, origin, voxel) = floor((coord-origin)/voxel)` 只表示下角点语义下的 cell 索引换算（返回 z,y,x）；E3 球内距离必须使用上述 Pocket 祖传体素中心，不得用 cell 下角点替代中心。
- 网格轴序统一 **`(C,Z,Y,X)`**。

### 2.2 主键 / 命名
- `pdb_id` 小写；`candidate_id` int ≥0；`object_key` 见 §5.2。

### 2.3 序列化（B6）
```python
def save_npz(path, **arrays):   # 默认原子写、不压缩
    tmp = path + f".tmp.{os.getpid()}"
    np.savez(tmp, **arrays)     # 注意: 不是 savez_compressed
    os.replace(tmp + ".npz" if not tmp.endswith(".npz") else tmp, path)  # 处理 np 自动加 .npz
```
- `atomic_save_npz()` 的全局默认保持 `np.savez`，不得为了 E3 改成压缩。
- E3 schema v3 是唯一窄例外：同目录 worker 独占临时文件使用 `np.savez_compressed`，替换前以 `allow_pickle=False` 重读、执行完整 E3 validator，并用 `zipfile` 验证所有成员确为 `ZIP_DEFLATED`；验证通过后才原子覆盖 `density/{pdb_id}/ligand_area.npz`。失败只清理本次临时文件，既有正式文件与兄弟 PDB/worker 不变。
- jsonl：每行一个 JSON 对象，UTF-8，`ensure_ascii=False`。

### 2.4 并行契约（B7，每个 stage 脚本都实现）
```text
CLI 通用参数:
  --root PATH                # ${ROOT}
  --part_id INT --total_parts INT   # SLURM --array 数据分片（默认 0/1）
  --n_jobs INT               # joblib loky 多核（默认 -1 全核）
  --overwrite / --no-overwrite      # 默认 skip-if-exists
机制:
  items = enumerate_items(); items = shard(items, part_id, total_parts)
  Parallel(n_jobs, backend="loky", verbose=10)(delayed(process_one)(x) for x in items)
  process_one 内部: skip-if-exists（除非 overwrite）+ 原子写 + try/except 写失败报告、不抛
```
- 提供 `sbatch/*.sbatch` 模板：`#SBATCH --array=0-(N-1)`，内部传 `--part_id $SLURM_ARRAY_TASK_ID --total_parts N --n_jobs $SLURM_CPUS_PER_TASK`。

### 2.5 复用 Emap2lig 配体流水线
`process_molecule` / `process_branched_ligand` / `Atom`/`Bond` dtype / `LigandObject` 字段沿用 Emap2lig 血统（但用 §2.3 不压缩落盘，不调用其自带 `savez_compressed`）。CCD reference Mol 使用本地 per-CCD pkl 缓存，缺失时从 RCSB ligand-CIF 获取并缓存；不使用 bulk CCD 字典主路径。

## §3 Stage A — 样本宇宙枚举（`a_enumerate.py`）

**RCSB Search API**（`POST https://search.rcsb.org/rcsbsearch/v2/query`）查询（terminal 组合，AND）：
```json
{"query":{"type":"group","logical_operator":"and","nodes":[
  {"type":"terminal","service":"text","parameters":{"attribute":"exptl.method","operator":"exact_match","value":"ELECTRON MICROSCOPY"}},
  {"type":"terminal","service":"text","parameters":{"attribute":"rcsb_entry_container_identifiers.emdb_ids","operator":"exists"}},
  {"type":"group","logical_operator":"or","nodes":[
    {"type":"terminal","service":"text","parameters":{"attribute":"rcsb_entry_info.nonpolymer_entity_count","operator":"greater","value":0}},
    {"type":"terminal","service":"text","parameters":{"attribute":"rcsb_entry_info.branched_entity_count","operator":"greater","value":0}}
  ]}
]},"return_type":"entry","request_options":{"return_all_hits":true}}
```
- 返回 PDB id 列表。逐条取 `rcsb_entry_container_identifiers.emdb_ids`（可能多个）→ **主 EMDB = 该 PDB 作为拟合模型对应的那个**。若只有一个 EMDB id，直接使用；若有多个，读取 EMDB `/entry/{emdb_id}` metadata，优先选择 `crossreferences.pdb_list.pdb_reference[].pdb_id` 明确等于当前 PDB 的 EMDB；无明确匹配时回到 RCSB 列表首个。
- 宽门 ligand 过滤在 Stage C 精确化；此处只要 `nonpolymer_entity_count>0`（branched 由 `branched_entity_count` 补充，二者任一 >0）。

**产物 `raw/pair_list.jsonl`**（一行一对）：
```json
{"emdb_id":"EMD-12345","pdb_id":"7abc","resolution":2.9,"resolution_info":{"selected":2.9,"status":"multi_candidate_consistent","selected_source":"emdb.final_reconstruction","selection_rule":"emdb_unique_preferred","n_candidates":2,"n_unique_values":1,"rcsb_disagree":false,"candidates":[{"source":"emdb.final_reconstruction","value":2.9,"units":"A","method":"final_reconstruction","path":"structure_determination_list...resolution.valueOf_"}]}}
```
`resolution` 是后续 Stage F/G 可直接消费的简化字段。`resolution_info` 记录候选来源、选择规则和状态：优先使用 EMDB final reconstruction；RCSB `rcsb_entry_info.resolution_combined` 只作 fallback 和一致性校验。常见状态包括 `single_unique`、`multi_candidate_consistent`、`ambiguous_emdb`、`fallback_rcsb`、`rcsb_disagree`、`missing`。每次枚举同时写 `reports/resolution_summary.json`，汇总本批样本的 resolution 状态分布。

## §4 Stage B — 下载（`b_download.py`）

| 资源 | URL | 产物 | 位置 |
|---|---|---|---|
| mmCIF | `https://files.rcsb.org/download/{PDB}.cif`（大写 PDB） | `{pdb_id}.cif` | `raw/rcsb_mmcif/` |
| EMDB map | `https://ftp.ebi.ac.uk/pub/databases/emdb/structures/EMD-{id}/map/emd_{id}.map.gz` | `emd_{id}.map.gz` | `raw/emdb_maps/` |
| 元数据 | `https://www.ebi.ac.uk/emdb/api/entry/{EMD-id}` | `{pdb_id}.meta.json` | `reports/meta/`（辅助；含 resolution 候选来源、recommended contour、PDB crossreference 等） |
| CCD | `get_ccd_mol(code)`（按需，pkl→RCSB ligand-CIF） | `{CCD}.pkl` | `raw/ccd_cache/` |

- 下载：3 次重试 + 指数退避；校验非空 / gzip 完整。`b_download.py` 默认下载 `mmcif,meta,map`，小样本验证可通过显式 `--resources mmcif,meta` 跳过 map。
- 复用判据保持低 I/O：既有 mmCIF 非空、去除前导空白后以 `data_` 开头，且前 1 MiB 含 `_entry.id` 即可复用；不得要求 `_atom_site.` 出现在固定窗口。完整 mmCIF 由 Stage C 实际解析。map 跳过路径只检查非空与 gzip magic，下载后再做完整 CRC/MRC 校验。
- legacy 失败仍写 `reports/_failed_download[.part_*].jsonl` 供诊断；正式状态写 `reports/runs/{run_id}/stage_b/status.part_*.jsonl`。`known_failed` 记录也必须保存逐资源 `resources`（`downloaded/skipped/failed`），避免失败样本丢失 source provenance。release gate 只消费 run-scoped 四终态，不以 legacy 文件是否存在判断本轮结果。

## §5 Stage C — 第一层统一解析（`c_parse.py`，核心）

用 `gemmi.read_structure` 读 mmCIF；**用沉积态非对称单元、`structure[0]`（第一个 model）、不做对称/assembly 扩展**（B5）。同时用 `gemmi.cif.read` 取 `_struct_conn` / `_pdbx_branch_scheme` / `_pdbx_entity_branch_link` / `_entity` / `_chem_comp` 表。可选 category 缺失时返回空表；真正的 category 读取异常不得吞掉，应暴露为解析失败。

### 5.1 junk 排除集（写死常量 `JUNK_RESNAMES`）
```
水/重水: HOH WAT H2O DOD
溶剂/添加剂: GOL EDO MPD PEG PG4 P6G TRS MES HEP ACT CIT EOH MOH IPA DMS DTT BME BU1 TBU
占位: UNX UNL UNK
惰性气体: XE KR
```
（来源 Make_Data `DEFAULT_EXCLUSION_RESNAMES`，可在 config 增删。）

### 5.2 C1 occurrence 解析 → `parse/{pdb_id}/occurrences.jsonl`

```text
1. 收集候选原子集合 HET = {所有 group_PDB==HETATM 或 entity.type in (non-polymer, branched) 的重原子},
   去掉 resname ∈ JUNK_RESNAMES；去掉与主链共价的修饰残基(归受体)。
2. 建并查集 UF over HET 原子。加边(共价, D24):
   a) CCD 模板内部键: 对每个残基, 取 get_ccd_mol(resname) 的 bond 列表, 按 atom_name 连其原子。
   b) _struct_conn 行 conn_type_id=='covale' 且两端都在 HET → union。
   c) _pdbx_entity_branch_link → union(糖链残基间)。
   * 排除 metalc/hydrog/saltbr。
   * covale 一端在聚合物(受体)残基 → 不 union, 给该组分置 is_covalent=True。
3. 连通分量 = occurrence。每个组分:
   - components = 该组分涉及的残基, 各记 (ccd_id, label_asym_id, label_seq_id, auth_asym_id, auth_seq_id, icode);
     组分内残基排序键 = (label_asym_id, label_seq_id)。index 从 1。
   - inter_bonds = 组分内"跨残基"的共价边, 表示成 [res_i_index, atom_i_name, res_j_index, atom_j_name]。
   - type_tag = derive_tag(components, entity, chem_comp)（见 5.3）。
   - 属性: is_covalent, polymer_length(组分残基数), n_heavy_atoms。
4. candidate_id: 全部 occurrence 按 (组分最小 label_asym_id, 最小 label_seq_id, 最小 atom serial) 排序, 0-indexed。
```

`derive_tag`（5.3，B3）：
```text
若 entity.type=='branched' 或所有残基 chem_comp.type 含 'SACCHARIDE' → 'sugar'
elif 任一残基 chem_comp.type 含 'PEPTIDE LINKING' → 'peptide_like'
elif 任一残基 chem_comp.type 含 'NA LINKING'(RNA/DNA) → 'nucleotide_like'
elif 单原子 且 element ∈ METAL_ELEMENTS → 'ion'
elif 所有残基 chem_comp.type=='NON-POLYMER' → 'small_molecule'
else → 'other'
```

**`occurrences.jsonl` 每行**：
```json

 "is_covalent":false,"polymer_length":3,"n_heavy_atoms":42,
```

### 5.2 C2 LigandObject 物化 → `ligand_objects/{object_key}.npz`

- `object_key`：单残基 = `CCD:<ID>`；多残基 = `BRANCHED:<comp ccd 序, '-' 连>:<bond_hash>`，`bond_hash = md5(sorted(inter_bonds) + comp 序)[:6]`。
- **全局去重**：若文件已存在则跳过（同 object_key 跨所有 PDB 只算一次）。
- 单 CCD：`m=get_ccd_mol(ccd); m=RemoveHs(m); process_molecule(m,…)`。
- BRANCHED：逐 component `get_ccd_mol` → 按 components 顺序拼 atoms/bonds → 追加 inter_bonds → `process_branched_ligand`。
- **落盘 = LigandObject 字段（不压缩，§2.3）**：`atoms`(Emap2lig `Atom` 结构化 dtype)、`bonds`(`Bond` dtype)、`atom_names(object S4)`、`residue_names(object)`、`smiles(str)`、`name=object_key`、`blobs=None`。单 CCD 的 `residue_names=[ccd_id]`；BRANCHED 的 `residue_names` 为 components 的真实 CCD 序列。落盘文件名使用 safe object name，即把 `object_key` 中路径敏感字符转义后的文件名形式。
- BRANCHED 物化时，跨残基键端点 atom name 必须能在对应 residue 的 LigandObject 原子中找到；找不到即 fail-fast，不写出缺键对象。

### 5.3 C2b 配体描述子（辅助监督标签，按 object_key 去重）→ `ligand_descriptors/{safe_object_key}.npz`

与 LigandObject **同 key、同全局去重**（一个 object_key 全局一份，跨 PDB 复用），为 `迭代运算 §12（监督全清单）` 的粗/细辅助监督备**预计算标签**。全从化学图 + `ref_pos` 算，去重后极廉价。定义在此写一遍（生产方），§12 只指针。

| key | dtype·shape | 含义 |
|---|---|---|
| `mol_weight` | float32 | 分子量（元素 → 原子质量求和） |
| `n_heavy` | int32 | 重原子数 |
| `n_rings` / `n_rotatable` | int32 | 环数 / 可旋转键数（RDKit） |
| `wiener_index` | float32 | Wiener 指数 = 键图全体原子对最短路（跳数）之和 |
| `graph_energy` | float32 | 图能量 = 邻接矩阵特征值绝对值之和（谱描述子，与 Wiener 成多尺度） |
| `radius_gyration` | float32 | `ref_pos` 的回转半径（3D 形状标量） |
| `atom_local` | (M, d_local) float32 | 逐原子局部拓扑：`[图偏心率, 1/2/3 跳邻居数, 到最近环跳数]`，行序对齐 `LigandObject.atoms`（挂 trunk 逐原子辅助） |

- **挂点（模型侧）**：全局量 → `CCD_repr` 粗辅助；`atom_local` → trunk `ligand_atom_features` 细辅助（见 `迭代运算 §12（监督全清单）`）。
- 元素/手性/环/键型/键环/键存在等**已在 LigandObject**（Emap2lig `AuxiliaryModule` 直接吃），本文件只补 LigandObject 里没有的拓扑/几何描述子。
- NPR / 其它谱描述子作扩展钩子（§12 的 4 类式实验），不进 v1。

### 5.4 C3 受体 token 表（含键表 + 49 维特征）→ `parse/{pdb_id}/receptor_tokens.npz`

- 受体原子 = `entity.type=='polymer'` 的重原子；排除水、ligand occurrence 原子、游离离子；共价修饰残基留作受体。
- altloc：每原子取空/A/1（按序首个）。
- 字段（逐数组、不压缩）：
```text
coords        (N,3) float32   世界坐标
element       (N,)  uint8      原子序数
res_type      (N,)  uint8      残基类型 id（见 RES_VOCAB）
is_backbone   (N,)  bool       原子名 ∈ {N,CA,C,O}(蛋白) / {P,O5',C5',C4',C3',O3'}(核酸)
atom_name     (N,)  S4
res_index     (N,)  int32      残基全局索引(0..)
chain_index   (N,)  int32
```
`RES_VOCAB`（固定顺序，写死）：`[ALA,ARG,ASN,ASP,CYS,GLN,GLU,GLY,HIS,ILE,LEU,LYS,MET,PHE,PRO,SER,THR,TRP,TYR,VAL, A,C,G,U,DA,DC,DG,DT, UNK]`（修饰残基映射到其标准母体；无法映射→UNK）。

**受体键表（新增，A 图"键"这半的来源）**：与上面逐原子数组并列，额外落一份受体**化学键**：
```text
bond_index  (2,E) int32   COO, 两端是 receptor_tokens 里的原子行下标
bond_type   (E,)  uint8   single=0/double=1/aromatic=2/backbone=3/disulfide=4/covale=5/triple=6
```
`triple=6` 只做向后兼容追加，既有 0–5 的数值语义永不改写；其他未声明键型继续 fail-fast。
键来源（**只化学键、不含 radius**）：a) 残基模板内部键（`get_ccd_mol`/标准残基模板按 atom_name 连）；b) 主链/骨架相邻残基间键（同 chain `res_index` 相邻：蛋白肽键 C–N / 核酸磷酸二酯 O3'–P）；c) `_struct_conn` 交联（二硫、共价修饰）。
- **与 D21 自洽**：D21"pair/KNN 不落盘"指**几何 radius 图**（运行时算）；**化学键是化学、照配体键一样落盘**（`LigandObject.bonds` 本就落）。A 图边 = 落盘键 ∪ 运行时 radius（`迭代运算 §2.1`）。

**受体 49 维特征（统一受体输入，整图算）**：

**所有模型统一的受体原子特征**（沿用 Pocket_Plus 已验证的工程；BOX 契约 §2.1 第 1 层"49 维受体特征"由此产）：
```
49 = 元素 one-hot(6) + 残基类型 one-hot(25) + 理化性质(8) + 原子质量(1) + 局部密度直方图(9)
```
- **必须整图算**：那 9 维"局部密度"是**原子堆积直方图**——每原子用 KD-tree 数它在 0–2, 2–4, …, 16–18 Å 各壳层内邻居原子数、再 log1p。它依赖**框外真实邻居**，BOX 内部现算会漏数、算错；故对**完整受体算一次**、存第 1 层，BOX 阶段只按 `atom_global_indices` 切片。
- 与密度图**无关**（纯几何/堆积描述子），纯密度/纯受体/统一三档逐位一致。
- 字段：`feat (N_rec, 49) float32`，行序对齐上面的受体原子数组。
- Stage1 运行时受体输入为 50 维：模型读取同一行的 `feat[49]` 与既有 `is_backbone bool`，把后者转换为 `float32` 后在最后一维拼接。该运行时拼接不修改 `receptor_tokens.npz`，也不把 `is_backbone` 重复写入 `feat`。

### 5.5 C4 per-occurrence GT 真实坐标 → `parse/{pdb_id}/ligand_coords.npz`

对每个 occurrence，把 `_atom_site` 真实重原子对齐到该 occurrence 的 **LigandObject 原子索引**（B4）：
```text
1. 逐残基按 (component.index, atom_name) 精确匹配 LigandObject.atom_names + residue_id。
2. 沉积里缺的模板原子 → is_present=False（合法）。
3. 若存在无法映射到 LigandObject 的沉积原子 → 该 occurrence resolve_failed（写失败报告, 不落盘该 occurrence）。
   * 不设容差百分比: 要么全部映射(含缺失标记), 要么整条作废。
```
产物（每 occurrence）：`coords_{cid} (M,3) float32`、`present_{cid} (M,) bool`（M = LigandObject 原子数，行序对齐 LigandObject；缺原子坐标填 `nan` 且 present=False）；外加 **`centroid_atom_{cid} (3,) float32 = mean(coords_{cid}[present_{cid}])`**（present 重原子几何中心，忽略 nan）。它是 BOX 契约 §2.2/§3.2 的 box↔occurrence 距离与 in-box 判定所用量，**已定物化、下游不再现算**。

### 5.6 当前 source 的受检迁移（仅 source-dirty 集合）

当 Stage B 刷新过 mmCIF、而旧 C 三件套来自更早 source 时，不得盲目覆盖，也不得把子集 C 状态写入正式全量 run。先冻结 source-dirty PDB 清单、数量、mtime 选择窗口和清单 SHA-256；使用独立 repair run 对**全集合**只读审计：

- `exact`：当前 mmCIF 重建的 occurrence、配体核心 `coords/present`、七个受体基础数组与旧 C 全部逐位一致；若旧 receptor 已是完整新 schema，则 `bond_index/bond_type/feat` 也必须与当前重建逐位一致。exact 不写文件。
- `atom_name_only`：只有 `receptor_tokens.atom_name` 不同，且 occurrence、配体坐标、`coords/element/res_type/is_backbone/res_index/chain_index` 全部逐位不变；当前 atom name 还必须非空、残基内唯一并被对应 CCD 模板完整覆盖，CCD cache 自报身份必须匹配，atom name 对应元素必须一致。若旧 receptor 尚无 `bond_index/bond_type/feat`，这只表示缺少派生比较基线，不额外阻断；当前完整重建仍须通过验证，apply 再补齐三项派生字段。若旧 receptor 已完整，则派生 delta 门禁照常严格比较。
- `blocked` / `failed`：出现任何其他差异、缺依赖或解析/契约错误；全集合中只要有一项即禁止进入 apply。

audit 同时冻结 mmCIF、旧 receptor、occurrences、ligand_coords、单样本 report 五个直接输入，以及所引用 LigandObject/CCD cache 依赖闭包和本项目 Python 实现的 SHA-256。ID 清单与 audit JSONL 均从同一份已哈希字节解析；audit 与 apply 之间禁止同步实现漂移。apply 前先做全局 preflight；每个 `atom_name_only` 样本再在独占 artifact lock 内复核、重建、commit 前 CAS，并仅原子替换 `receptor_tokens.npz` 的 `atom_name/bond_index/bond_type/feat`。六个其余受体基础数组、occurrences、ligand_coords 和额外 provenance key 必须保持不变。apply 中断后的恢复单位是重新执行完整 audit→apply；filtered smoke/repair 必须使用独立 run id，正式 Stage C 状态只能由无过滤全量 C 原子刷新。

若当前 source 让此前 `resolve_failed` 的 occurrence 首次成为可解析项，从而引用了已有 LigandObject、但对应 `ligand_descriptors/*.npz` 尚未物化，则必须在最终 audit 冻结前，用独立 run id、冻结 object-key 清单和 `overwrite=False` 显式补足并校验描述符；记录源 LigandObject、实现和最终 descriptor 的 SHA-256。该步骤只补足既有 Stage C 描述符依赖，不改变描述符 schema、occurrence 科学语义或迁移授权边界；最终 audit 开始后不得再改变这些输入。

## §8 Stage F — 质量度量（`f_quality.py` → `quality/{pdb_id}.jsonl`）

- **坐标帧前置门**：在 CC/MapQ 启动前复用 E2 同一函数、同一 E1 canonical 网格和 Stage C polymer receptor token 坐标（`receptor_tokens.coords`）执行 D31。该坐标是 E/F 共用 frame anchor，不等同于 E2 严格 ATOM-only Chimera 输入或 F 完整 ATOM+HETATM 模型。完全不相交时 F 也写同一 `known_failed:model_map_frame_mismatch`，不运行 Chimera/MapQ；禁止 PDB allowlist、猜平移或 fitmap。
- **全局分辨率**：取 `pair_list.resolution`；缺失值保留 provenance，在需要 molmap/MapQ resolution 的路径中记 `known_failed`，不猜默认。
- **四种全局 map-model CC（同一 PDB 的每行重复）**：实验 canonical 图必须作为 Chimera `measure correlation` 的第一张图。`cc_contour` 使用从 EMDB native recommended contour 按 E1 幅值比例映射得到的 `contour_canonical` mask、不减均值；`cc_contour_about_mean` 使用同一 mask、两图各自在 mask 内减自身均值；`cc_all` 使用实验图非零 grid mask、不减均值；`cc_all_about_mean` 使用同一非零 mask、两图各自在 mask 内减自身均值。contour 缺失时只允许前两项为 `null`，`cc_all*` 仍计算；所有非空 CC 必须有限且在 `[-1,1]`。
- **Q-score（MapQ via Chimera，B1）**：
```text
chimera --nogui 跑 MapQ(mapq_cmd): 输入 (emd_map, pdb_model) → 输出逐原子 Q (写 cif/txt)
解析逐原子 Q → 按 occurrence(用 C 的 components 残基集合) 聚合: q_score = mean(该 occurrence 重原子 Q)
同一次全模型逐原子 Q 上定义 occurrence 口袋：首 model/规范 altloc 的 group_PDB=ATOM 受体重原子中，
到该 occurrence 任一 present 配体重原子距离 ≤ 6.0Å 的原子并集；聚合 pocket_q_score，
并保留有序 pocket atom_site.id、逐原子 Q、mean/median/min/n_valid/n_atoms/radius，不预先过滤。
若包络内无 group_PDB=ATOM 受体原子，该 occurrence 仍保留：id/Q 数组为空、n_valid=n_atoms=0、
三种 pocket Q 聚合为 null，并记录 pocket_status=no_receptor_atoms_within_radius；不得连带淘汰整 PDB。
LIVQ: 留接口, 一期 null
```
- 每行：
```json
{"pdb_id":"7abc","candidate_id":1,"q_score":0.78,"pocket_q_score":0.74,
 "pocket_n_atoms":126,"pocket_radius_angstrom":6.0,"livq":null,"map_resolution":2.9,"n_present":40}
```
- **先算分布、不预设阈值**。

### §8.1 Stage G — 过滤（`g_filter.py` → `keep_list.jsonl`）
- G 只消费 F 已保存的 occurrence 聚合字段，不读取 `quality_atoms`、原始密度图，也不重新计算 CC 或 Q-score。`analyze` 先写分布和扁平 `candidates.pending.jsonl`；`filter` 只接受唯一 `schema_version=2` 的显式 map-level 配置。
- 过滤先按 `pdb_id` 聚合；eligible PDB 必须至少有一个 occurrence。同一 PDB 各行重复的 `map_resolution` 与所选唯一 CC 必须一致；所选 CC 合法为 `null` 时该 map 不通过，不能回退到其他 CC。
- 对每个 occurrence 定义 `pair_pass = (q_score > ligand_q_min) AND (pocket_q_score > pocket_q_min)`。两个 Q 均为严格大于；空口袋的 `pocket_q_score=null` 直接失败但仍计入分母。`qualified_fraction = n_pair_pass / n_occurrences`。
- map 仅在 `selected_cc >= cc_min`、`map_resolution <= resolution_max` 且 `qualified_fraction >= qualified_pair_fraction_min` 时通过。CC、分辨率和比例边界含等号；分辨率数值越低越好。
- map 通过后，`keep_list.jsonl` 保留该 PDB 的全部 occurrence，不再按 `pair_pass` 删除其中个别 occurrence。map-level 诊断必须保存 CC、resolution、总数、空口袋数、合格数、比例、三项 pass 与排除原因；配置和输入 manifest 均保存 hash。

## §10 QC 与失败处理

`reports/{pdb}.json` 逐样本检查：
- 每 occurrence 的 component CCD 可解析；`inter_bonds` 端点 atom_name 存在。
- LigandObject 原子数 == `ligand_coords` 行数；`present` 数量合理（`n_present/n_heavy ≥ 阈值`，如 0.5，否则记 `low_completeness`）。
- `exp/sim/ligand_area` 同 `(D,H,W)`、同 `origin/voxel_size`、轴序 `(C,Z,Y,X)`；E3 必须是 schema v3、Pocket 下角点+半体素中心、标准 ZIP_DEFLATED，且每个 mask/union/质心与当前 Stage C 原子坐标重建结果一致。
- Chimera `.err` 仅可接受 warning（无 `No such file/open failed/No atoms/Error/Traceback`）。
- 每个 stage 分片原子写 run-scoped 状态；每个 PDB 只允许 `success / skipped / known_failed / unknown_failed` 四终态。只有 `KnownFailureCode` 明确枚举的数据不适用情形可记 `known_failed`；普通异常、schema/source 漂移、Chimera/MapQ 输出异常均为 `unknown_failed`。
- `model_map_frame_mismatch` 只表示合法权威输入中无法证实共同世界坐标帧；它不是 MRC 重采样失败、外部工具失败或坐标修复。run-scoped detail 必须保留 map/model XYZ 包围盒、轴序、容差与 `no_transform_or_fitmap` 策略；G 排除该样本，但不阻断其他样本。
- gate 要求目标样本全集恰有一条终态；任何 unknown、重复、额外或 silent missing 都阻塞下游。legacy `_failed_*` 只供诊断，不参与本轮判定。
- `reports/summary.json` 与 run-scoped gate/analysis 汇总各 stage 计数、失败分布和输入 manifest hash。
