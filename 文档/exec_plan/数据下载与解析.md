Stage A 的输入是 RCSB Search API，输出 `raw/pair_list.jsonl`。Stage B 读取 pair list，下载 `{pdb_id}.cif`、`emd_{id}.map.gz`、`{pdb_id}.meta.json`。Stage C 读取 mmCIF 和 CCD，输出：

    parse/{pdb_id}/occurrences.jsonl
    parse/{pdb_id}/receptor_tokens.npz
    parse/{pdb_id}/ligand_coords.npz
    ligand_objects/{object_key}.npz
    reports/{pdb_id}.json

术语定义：

- `pdb_id`: PDB entry id，小写保存，如 `7d3f`。
- `emdb_id`: EMDB id，保留 `EMD-` 前缀，如 `EMD-30556`。
- `occurrence`: 一个 PDB entry 中由记录意义上的共价连接定义出的配体实例。单 CCD ligand 是一个 occurrence；branched glycan 整条共价连接糖链也是一个 occurrence。
- `candidate_id`: 同一 `pdb_id` 内 occurrence 的稳定 0-index 编号。
- `object_key`: 化学对象去重键。单 residue 为 `CCD:<ID>`，多 residue 为 `BRANCHED:<CCD-CCD-...>:<hash>`。实际文件名会转义 `:`、`/` 等路径敏感字符。
- safe object name: `object_key` 的文件名形式，转义 `:`、`/` 等路径敏感字符；例如 `CCD:NAG` 落盘为 `CCD_NAG.npz`。
- `LigandObject`: 沿用 Emap2lig 血统的配体参考对象，保存 `atoms`、`bonds`、`atom_names`、`residue_names`、`smiles`、`name`、`symmetries`、`blobs=None`。本轮在 Stage1 内复制生成逻辑，`.npz` 使用 `np.savez` 不压缩保存。AdaLigand 中 `name=object_key`；`residue_names` 保持真实 CCD residue 名。
- `label_atom_id`: mmCIF `_atom_site.label_atom_id`，指向 CCD 原子名，是配体 GT 坐标对齐到 LigandObject 原子顺序的主键。

本轮对 v2 中 D24 做一个用户确认后的修订：并查集边只来自 CCD 内部键、`_struct_conn.conn_type_id == 'covale'`、`_pdbx_entity_branch_link`。不做距离兜底，不做 repair 模式。`metalc`、`hydrog`、`saltbr` 等连接类型不参与 occurrence union。

## Idempotence and Recovery

所有脚本支持 `--overwrite`，默认不覆盖已有产物。写文件先写临时路径再替换，避免中断留下半文件。下载失败写失败 jsonl，不删除已下载成功的文件；若本轮无失败，会清除旧的 `_failed_download.jsonl`，避免旧失败误导检查。`mini-example` 是隔离根目录，可删除后重跑，不影响正式数据目录。

如果某个 PDB 解析失败，Stage C 只写失败报告并继续处理其它样本。若 occurrence 无法完成原子对齐，该 occurrence 记 `resolve_failed`，不写入最终 occurrence/coords 主产物。
