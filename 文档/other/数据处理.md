# AdaLigand 数据处理计划

> 本文是 AdaLigand 项目数据侧的总计划与决策记录。它解释：如何从零下载并统一解析「受体 + 配体」的坐标与特征、配体特有的必要单独项（如寡聚体用 `List[CCD]`）、如何打标签、如何处理密度，以及这些为什么这样定。
>
> 权威层级：实际代码 > 配置/checkpoint > 真实产物与日志 > 本文 > 旧探索记录。本文是导航与契约草案，落字段/ shape 时以实现与真实产物为准。

---

## 0. 一句话总览

AdaLigand 的数据侧分**三层**，三层都**从零新写**，旧仓库（Pocket_Plus `Make_Data`、`processedPDB_EMDB_binder`、`Ligand/rcsb_enrichment`）只作**逻辑参考**，不作输入契约：

1. **统一解析层**：RCSB full mmCIF → 受体原子 + 配体原子在**同一全原子 token 空间**里的坐标与特征；配体侧额外物化成 `LigandObject`（AF3/Emap2lig 血统）。
2. **标签层**：从第一层的统一距离/几何**派生** Stage1（Find）所需标签（结合原子、ligand-area 体素等）。因为第一层做充分了，这一层很薄。
3. **密度层**：EMDB / 模拟图 → 重采样对齐网格 → 切 BOX。密度**不预先 tokenize**（模型 runtime 编码），**不按 class 分文件夹**。

三层之间唯一的耦合是 **`(pdb_id, candidate_id)` + 共享世界坐标系**。

---

## 1. 背景与前因（为什么有这个项目）

### 1.1 三大模块

AdaLigand 是一个新项目，至少三个模块：

- **Find（Stage 1）**：类似 Pocket_Plus 最全模型（体素分支 + 点云分支 + Sparse Refinement）。输出：受体原子特征 + 是否结合原子的概率；体素特征 + 体素是否属于 Ligand Area 的概率。落盘 BOX 级输出。
- **Match（匹配器）**：吃 Stage 1 落盘的 BOX 级输出。训练时一个 batch 是同一样本的若干 BOX + 与之配对的若干 ligand，预测 BOX↔ligand 的对应关系。它替代 Emap2lig 里那个写死的「体素数/原子数比例」粗启发式。
- **Build**：Emap2lig 的 build 步骤，但多吃两样：(a) Find 输出的受体原子特征 + 结合概率，(b) Match 输出的匹配关系。要求**既能吃「受体+密度」，也能只吃「密度」**。直接参考：Emap2lig、PocketXMol。

### 1.2 与三个外部/既有项目的关系与张力

| 项目 | 角色 | 张力 |
|---|---|---|
| Pocket_Plus `Make_Data` | 受体解析 + 逐原子特征 + 点云标签的旧实现 | 配体被切成**逐残基** candidate；不保留 mmCIF entity/scheme 语义 |
| Emap2lig | Build 骨架候选 + **canonical 配体表示来源**（`LigandObject` / `get_ccd_mol` / `process_molecule`） | 它的「ligand 单元」是整分子（含 BRANCHED 整条糖链），与 Pocket_Plus 逐残基不一致；`LigandObject` 多一个 inference 期的 `blobs` 指针 |
| PocketXMol | Build 骨架候选 + 纯全原子受体+配体统一表示参考 | 无密度分支，帮不到 Find；若选它当骨架则是「PocketXMol + 加密度」而非「Emap2lig + 加受体」 |

**根因**：三者对「一个 ligand 是什么」「在什么坐标系/粒度里」「用哪套特征」各执一词。AdaLigand 的解法是**反转依赖**：我们定义自己的 canonical 表示，外部模型只提供骨架与 feature schema，通过薄适配器对接。

### 1.3 调研得到的、指导本设计的事实

- 旧 `Ligand/rcsb_enrichment` 已证明 `candidate → CCD → SMILES/InChI` 在 class-4 上可达 **99.9%**（19 万 occurrence）。说明「RCSB 单源 + CCD」是可靠权威源。我们复用其**方法与数据源**，但在 component 粒度重生成。
- SOTA 特征工程的横切结论（survey 见 §10）：**全原子已成主流**；**per-atom 特征要轻**（元素 + 电荷 + 几个 flag），信号在**几何 / pair 表示**；**参考构象（RDKit ETKDGv3 / CCD）做 `ref_pos` 是跨模型标准**；flow matching 接管 pose 生成但不改特征层。
- **AF3 / Boltz 的原子特征血统 = Emap2lig 的 `LigandObject`**（`ref_element / ref_charge / ref_pos / atom_name / residue_id`）。所以配体表示直接沿用，不自创。
- 「身份 + 组分」是整条链里**唯一不可外包**的难点（没有库直接输出「完整 ligand occurrence + candidate_id」）；其后的特征化是 RDKit 上的机械变换。

## 2. 关键决策记录（Decision Log）

| ID | 决策 | 理由 |
|---|---|---|
| **D1** | **配体单元 = 共价连通分子组分（整体），candidate_id 按整体命名，不是一残基一个** | 对接领域惯例：ligand = 整个连通分子（PDBbind/BioLiP 都合并多残基）；且 Match 按 BOX 配 ligand，BOX 粒度=ligand 粒度，逐残基会把一条糖链的单个密度 blob 劈成多个重叠实例，使 Match 成病态问题 |
| **D2** | **寡聚体/糖链（BRANCHED）= `List[CCD]` + 残基间键** | Emap2lig BRANCHED 需要 `residues`（List[CCD]）+ `bonds`（残基间键，带原子名）；这是表达多组分 ligand 的标准方式 |
| **D3** | **受体原子 + 配体原子在同一全原子 token 空间统一解析**（位置、特征、instance 标志） | SOTA 已收敛到全原子统一 token；这样「受体配体统一」在数据层天然成立，消除两套手工特征在 conditioning 口相缝的张力 |
| **D4** | **canonical 配体表示沿用 AF3/Boltz/Emap2lig `LigandObject` 血统**，不自创 | 它是事实标准且已在 Emap2lig 里实现（`get_ccd_mol` / `process_molecule`），复用代码即可 |
| **D5** | **不复用 Make_Data；三层全部重写。旧代码仅作逻辑参考** | 旧 Make_Data 逐残基、丢 entity 语义、且类别/标签逻辑与新设计不符；重写比兼容更省心 |
| **D6** | **密度管线独立、重写；不预先把密度构造成点 token；不按 class 分文件夹** | 密度该由模型 runtime 编码，预 tokenize 会把建模假设固化进数据；class 分文件夹是旧世界包袱 |
| **D7** | **class 从「过滤分区」降级为 token / occurrence 上的 metadata tag** | 训练单元应是 occurrence，不该被 class 切碎成多套数据；class 留作分析与可选 conditioning |
| **D8** | **mmCIF 为权威事实源**，工具链 = `gemmi` + `pdbeccdutils` + `RDKit` | mmCIF/CCD 是 wwPDB 归档与化学定义的主格式；这套库覆盖解析与化学图，无需自写化学规则 |
| **D9** | **EMDB 从零重下，更换分辨率准则**（旧的 cc/qscore>3.5Å 过滤不好） | 原始动机之一；只影响密度层的输入 map 集与 split，不影响解析逻辑 |
| **D10** | **`LigandObject.blobs` 指针在训练数据里置 `None` / 丢弃** | 它是 inference 期的 density blob 绑定，与训练身份/表示无关，属脏字段 |

> 注：D1/D2 是上一阶段「Pocket_Plus instance ↔ Emap2lig LigandObject 映射」探索的直接结论——映射主键是 `(pdb_id, candidate_id)`，而 candidate_id 必须升级到 component 级。

## 4. 第一层：受体 + 配体统一坐标与特征解析

这是整个项目唯一不可外包的难点，其余都简单。

### 4.1 输入与工具链

- 输入：`{pdb_id}.cif`（RCSB full mmCIF，`https://files.rcsb.org/download/{PDB}.cif`）；CCD 模板按需拉取/缓存（复用 Emap2lig `get_ccd_mol`：bulk dict → 本地 pkl → RCSB CIF）。
- 工具：`gemmi`（读 mmCIF category、原子/entity/连接）、`pdbeccdutils`（CCD → 带 atom/bond 的 RDKit mol）、`RDKit`（化学图、SMILES、构象、立体/键级补全）。

### 4.2 mmCIF 权威 category 角色

| category | 作用 |
|---|---|
| `_atom_site` | **全结构**所有原子（ATOM + HETATM）：坐标、元素、label/auth chain & seq、atom name、altloc、occupancy |
| `_pdbx_nonpoly_scheme` | 普通单组分 ligand 的 residue 级映射（ATP/HEM/GDP…） |
| `_pdbx_branch_scheme` | 糖链/branched entity 的 residue 序映射 |
| `_struct_conn` / `_pdbx_entity_branch_link` | 残基间/共价连接；筛出 ligand **内部**键用于拼 BRANCHED |
| CCD（chem_comp） | 每个组分的标准 atom/bond 模板（键级、芳香性） |

口诀：**scheme 表定义「谁和谁组成一个 ligand」；`_atom_site` 给坐标与原子实例；CCD 给化学图模板。**

### 4.3 配体 occurrence 解析（身份 + 组分）—— 核心

对每个 PDB：

1. 读 `_atom_site`，连同 nonpoly/branch scheme，枚举所有候选 HETATM 残基（排除水、结晶/缓冲添加剂等 junk；排除与主链共价连接的修饰受体残基）。
2. **连通组分分组（union-find）**：在共价键图上合并属于同一 ligand 的多个残基。
   - 边来源：单 CCD 内部键（CCD 模板）+ 残基间键（`_struct_conn` covale / `_pdbx_entity_branch_link`）。
   - 单残基 ligand → 单组分；糖链/共价多残基 → 一个组分。
3. **candidate_id = 组分级**，稳定排序（如 nonpoly 按 chain/seq，branch 按 entity/asym/起始 seq），保证可复现。
4. 对每个组分产出：
   - `components`: `List[{index, ccd_id, chain_id, res_id, insertion_code}]`（按稳定顺序）
   - `bonds`: 残基间键 `List[(res_i, atom_i, res_j, atom_j)]`（atom 用 CCD 原子名）
   - `coords`: 该组分全部重原子的 GT 坐标（世界坐标系）
   - `type_tag`: small_molecule / sugar / peptide-like / nucleotide-like / ion / cofactor（粗分类，仅 metadata，见 D7）

### 4.4 LigandObject 物化（沿用 Emap2lig）

对每个 occurrence 的 `object_key` 去重后物化（同一化学对象只算一次）：

- `object_key`：单 CCD = `CCD:<ID>`；BRANCHED = `BRANCHED:<NAG-NAG-BMA>:<bond_hash>`（bond_hash 编码残基间连接拓扑，使同拓扑糖链共享对象）。
- 单 CCD：`get_ccd_mol(ccd)` → `Chem.RemoveHs` → `process_molecule()` → `LigandObject`。
- BRANCHED：对每个 component `get_ccd_mol()` → 按 `components` 顺序拼 atoms/bonds → 追加 `bonds` 残基间键 → `LigandObject`（`smiles=""`，`residue_names=List[CCD]`，原子带 `residue_id`）。

`ref_pos`（参考构象）来自 CCD ideal / RDKit ETKDGv3，是几何先验，不是 GT pose；GT pose 单独保存（§4.6）。

### 4.5 受体原子解析与特征

- 从 `_atom_site` 取受体（ATOM + 非 ligand HETATM 中的受体部分）全原子坐标。
- 受体原子特征（轻）：元素、所属残基类型（氨基酸/核苷酸 one-hot）、`is_backbone`、（可选）atom name。**不上 residue-level ESM**——我们要全原子且有密度，不只是序列。

### 4.6 统一 token 表 schema（受体原子 + 配体原子共用）

一个样本一张 token 表，**每行一个原子，受体与配体共用核心列**，用 mask 区分上下文块：

| 列 | 适用 | 含义 |
|---|---|---|
| `pos` (3,) | 全部 | 世界坐标 |
| `element` | 全部 | 原子序数 |
| `charge` | 全部 | 形式电荷 |
| `is_ligand` | 全部 | 受体 / 配体 |
| `instance_id` | 全部 | **instance 标志**：配体原子=自身 component candidate_id；受体原子=最近 ligand instance（或背景 -1） |
| `type_tag` | 全部 | 粗类型（见 D7） |
| `atom_name` | 全部 | 4 字符原子名 |
| `res_type`, `is_backbone` | 受体块 | 氨基酸/核苷酸类型、主链 flag |
| `chirality`, `in_ring`, `residue_id`, `ref_pos` | 配体块 | 手性、环、组分内残基号、参考构象坐标 |

- **轻特征、重 pair**：原子特征别堆；几何信号放在 pair / 距离表示（Gaussian/RBF 距离核 + 配体内部 bond 特征），由模型层构造。
- **GT pose**：配体原子的 `pos` 即 GT（来自 `_atom_site`）；`ref_pos` 是另一套参考构象列，二者分开。

### 4.7 配体的「必要单独项」（受体没有的东西）

每个 ligand occurrence 还要单独保留（落在 ligand 对象表 / candidates 表里）：

```text
candidate_id          # 组分级整体 ID（D1）
object_key            # CCD:X 或 BRANCHED:...:bondhash（去重键）
kind                  # CCD | BRANCHED
components            # List[{index, ccd_id, chain_id, res_id, icode}]  ← 寡聚体的 List[CCD] 就在这里
residue_names         # List[CCD]，单分子=1 项，糖链=多项（D2）
bonds                 # 残基间键 List[(res_i, atom_i, res_j, atom_j)]
smiles                # 单 CCD 有；BRANCHED 为 ""
atoms / atom_names    # 化学图（element/charge/ref_pos/residue_id + 名字）
symmetries            # 对称性（Emap2lig 口径，可暂空）
type_tag              # metadata（D7）
coords_key            # 指向该 occurrence 的 GT 重原子坐标
# blobs: 丢弃 / None（D10）
```

## 5. 第二层：标签（服务 Find / Stage1）

Stage1 训练仍然需要**结合原子标签**，外加体素级监督。因为第一层已给出受体原子与配体原子在同一坐标系下的位置，这一层只是几何派生，很薄：

- **结合原子标签（per 受体原子）**：受体重原子到任一配体重原子距离 ≤ 阈值 → 结合原子。（阈值待定，旧实现按类别 4–5Å。）
- **instance 标签（per 受体原子）**：最近 ligand 的 component candidate_id（独占分配，背景 -1）。
- **体素 ligand-area（per voxel）**：靠近配体原子的体素为正；用于体素分支监督。
- **（可选）ligand 距离图**：每体素到最近配体原子的距离，可不再按 class 分通道（见 D7）。

**class 处理（重估）**：不再用 class 把样本切成多套、也不分文件夹；class 只作为 occurrence / token 上的 `type_tag`，需要时供模型 conditioning 或评测分组。

## 6. 第三层：密度管线（独立、重写）

逻辑很简单，旧 `processedPDB_EMDB_binder` 仅作参考：

1. 准备 `EMDB–PDB` pair list（新分辨率准则，见 D9）。
2. 下载 EMDB 实验图（按需 + 模拟 receptor 图）。
3. `load_map` → `make_model_grid` 重采样到目标 voxel size（如 1.0Å），得到与第一层世界坐标系**对齐**的 `grid / origin / voxel_size`。
4. 围绕每个 occurrence（component 中心）切 BOX，保存 `grid + x/y/z_range + voxel_size + origin`。
5. **密度不预 tokenize**：BOX 是体素网格，模型 runtime 用体素/点分支编码；不预先采样「密度点 token」塞进第一层 token 表。
6. **扁平 BOX store**：`box/{pdb_id}/{candidate_id}/...`，**不按 class 分文件夹**（重估 D6/D7）。
7. 负样本/背景 BOX 单独标记（`candidate_id = -1`），不依赖 class 目录。

**JOIN**：一个 Build/Match 样本 = `BOX(pdb_id, cid)`[密度] ⊕ 落在该 BOX 世界范围内的 token[受体+配体] ⊕ `LigandObject(cid)`[参考图] ⊕ GT pose。Match 的 GT 指派 = 同一样本内 `{BOX} × {ligand}` 在 candidate_id 上的恒等。

## 8. 三模块如何消费这套数据

- **Find（Stage1）**：吃 `density/box`（实验+模拟）+ `labels`（体素 ligand-area、结合原子）+ 第一层受体 token 的位置。落盘 BOX 级特征/概率，供 Match/Build。注意暴露偏差——训练后期需落**预测 BOX**，不只 GT BOX。
- **Match**：靠 JOIN 把 `{BOX}` 与 `{LigandObject}` 配起来；标签来自 candidate_id 恒等，免费。
- **Build**：靠 JOIN 取 `BOX + 受体 token + LigandObject + GT pose`；受体/匹配关系作为新增 conditioning；密度走模型 runtime 编码。骨架（Emap2lig+受体 / PocketXMol+密度）通过薄适配器从统一 token 表取数。

## 9. 待实现时敲定的参数（开放项，不阻塞架构）

1. **配体类型范围**：默认「所有非 junk 连通组分都是 occurrence，带 `type_tag`，训练时按需取子集」。是否一期只训 small_molecule + sugar + cofactor，待定。
2. **结合原子阈值 / ligand-area 定义**：默认 4–5Å 区间，待定具体值与是否按 type 区分。
3. **目标 voxel size 与 BOX 尺寸**：默认 1.0Å；BOX 边长需覆盖「最大 occurrence + 口袋上下文」，具体待定（旧为 80³@1.0Å）。
4. **EMDB 新分辨率准则**：替换旧 cc/qscore>3.5Å 的具体阈值/指标，待定。
5. **是否保留模拟 receptor map** 作为输入或对照，待定。
